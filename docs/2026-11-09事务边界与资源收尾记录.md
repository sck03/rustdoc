## 修复范围

- 单一窗口提交、回执导出使用授权读快照取得输入，在写事务外解析 XML、核对摘要及生成 ZIP；短写事务重新验证身份、来源、草稿、提交版本及持卡机档案后登记结果。首次隐式创建草稿使用事务内重新读取的默认值，避免读取后来源发生变化仍保存旧值。
- 提交版本由 Storage 执行数据库聚合，按来源、业务类型和本地来源标记筛选；导出与回执写回共用该入口，不再加载所有批次及其历史正文。SQLite 与 PostgreSQL 共用查询合同。
- 派发收尾校验操作编号，只有 `ClientDispatching` 可转为派发成功或失败，保留同时到达的受理、审批或退回业务状态。尝试标记继续防止不确定的交接自动重放。
- 单一窗口普通读取和预检使用授权读快照，保存、解锁和修复进入写事务。
- 发票列表单一窗口操作复用 `useScopedSave`，统一取消、同步防重及异步步骤之间的有效性检查；关闭、切换、卸载或权限变化后，迟到预检、修复、下载和错误不能回写旧面板。预检结果不再进入 React Query 变更缓存。
- 发票复制、Excel 导入和单据包操作分离到列表操作 hook，共用 `useScopedSave` 传播取消、检查操作身份和防止重复提交，列表刷新后再次检查才能跳转。选择新包立即清除旧预检，失败时不能拿旧预检提交新文件。关闭面板及导入完成释放文件引用；临时文件和预检不再进入变更缓存，StrictMode 重挂载正常工作。
- 输入框带图标外壳时，由外壳统一绘制边框和聚焦提示，移除 HS 页面覆盖共用控件的重复边框规则，修复登录、业务资料、单一窗口、HS 税则/联网补充、基础资料的内外双框。保留鼠标、Tab 和高对比度模式的焦点可见性。
- 共用 Field 使用顶部内容对齐，说明文字只增加自身字段高度，不再拉开相邻标签与控件的间距；修复单据设置“默认显示备用列数”和“明细空白行数”错位，窄屏仍按阅读顺序纵向排列。设置分类按钮明确使用透明实线边框，取消浏览器默认凸起边框。

SQL 仍属于 Storage，事务授权和业务状态属于 Engine，纯业务校验属于 Domain。没有新增数据库、运行依赖、持久化前端缓存、旧库迁移或兼容层，数据库继续使用全新 schema 16。
