# 单一窗口字段映射清单

> 2026-10-08 整理。保留既有官方样例/XSD 的字段对照，移除旧 C# 实现流水和重复字段清单。表内来源是业务对照名，不是 Rust 字段名或全部字段已验收的声明；实际 DTO、映射、校验和输出须逐项核对。旧说明见 [Git 历史](https://github.com/sck03/rustdoc/blob/b44fbb6/docs/单一窗口字段映射清单.md)。

## 1. 使用与来源

本表维护 COO/ACD 节点、含义、来源及格式，不维护数据库表结构、客户端路径或产品版。协议和操作顺序见[单一窗口设计](./单一窗口对接代码级设计.md)，运行与数据库见[架构事实](./当前架构事实.md)。

官方入口：[COO 字段](https://www.singlewindow.cn/#/documentDetail?cid=COO-coo-chart&ctype=1)、[COO 样例](https://www.singlewindow.cn/#/documentDetail?cid=COO-coo-xml&ctype=1)、[ACD 格式](https://www.singlewindow.cn/#/documentDetail?cid=DEC-acd-format&ctype=1)、[ACD 字段](https://www.singlewindow.cn/#/documentDetail?cid=DEC-acd--field&ctype=1)、[ACD 样例](https://www.singlewindow.cn/#/documentDetail?cid=DEC-acd-xml&ctype=1)；本地 [coo.xsd](../coo.xsd) 与 [AcdAgrInfo_ImportSave.xsd](../AcdAgrInfo_ImportSave.xsd) 是保留的对照资料。本次未重新验证官方在线版本、现场卡或客户端行为。

新增/修改字段时同时核对 XSD 顺序、长度、枚举、必填条件、草稿锁定、界面、导出审查和实际 XML。必填底色不代替服务端校验；“新增业务字段”指独立申报草稿字段，不表示本轮要新增表或复用发票备用字段。

## 2. 当前 Rust 落点与重要区别

- [Domain 映射](../crates/export-doc-domain/src/single_window/mapping.rs)、[草稿](../crates/export-doc-domain/src/single_window/draft.rs)、[校验](../crates/export-doc-domain/src/single_window/validation.rs)和[XML 规则](../crates/export-doc-domain/src/single_window/xml.rs)分别维护纯业务规则。
- [Engine](../crates/export-doc-engine/src/engine/single_window/mod.rs)管理授权、词典/草稿、导出审查、事务与包/回执；[协议 crate](../crates/export-doc-single-window/src/lib.rs)管理受限包和认证。
- .swpkg 当前为 **schema 4.0**，导出时绑定目标机器/档案/卡并认证；旧 schema 3.0 说明失效。数据库版本另按 Rust 有序迁移维护。
- 参考目录覆盖保存在业务库 `sw-reference-catalog` 设置；没有覆盖时使用内置数据，不写旧 override.json。持卡机身份和档案同样入库，最多 100 个档案、一个活动档案，交接路径限制在 DataRoot 内。
- COO 国家、字母币制、贸易方式与 ACD 的 GBDQ/BZHI/JGFS 码表分开。ACD 货名优先取中文再回退英文；海关 10 位代码不能用统一社会信用代码兜底。
- 源发票、独立草稿、提交批次及回执分层；修改申报字段不回写源发票。手工锁定字段保留，未锁定字段按当前源资料重新装配。

## 3. 海关原产地证映射

### 3.1 结构校核

既有官方样例结构:

- 根节点: `Certificate`
- 命名空间: `http://www.w3.org/2000/09/xmldsig#`
- 主体结构:
  - `CertificateHead`
  - `CertificateList/Goods`
  - `ModCertificate`
  - `NonpartyCorpList/NonpartyCorp`
  - `OriInvs/OriInv`
  - `AplPromise`
- 附件使用独立根节点: `File`

## 6. 维护与验收边界

贸易方式、国家/币制、单位、运输方式、港口和原产标准优先使用[参考目录](../Resources/SingleWindow/singlewindow_reference_catalogs.json)及 Domain 规则。自然日严格解析，金额使用精确十进制；XML 按各业务格式输出。未知编码和官方特殊条件须由实际样例验证，不能凭相似字段名猜测。

操作员口令、系统路径、数据库查询和文件对话框不进入字段映射层。生产企业、附件与单据使用已有独立模型，不再用 Spare 或 CustomFieldsJson 建立过渡兼容链路。官方业务授权范围不能用旧文档中建议的界面权限表代替本应用生成的 endpoint metadata。

本清单保留原有报文对照内容，不以整理文档宣称 TradeAgreementCode、所有协定特有字段、回执变体或真实签名已完成。现场验收须覆盖正常/退单/技术失败回执、错误绑定、重复导入、源资料变化、金额/日期及中文内容；结果写入带日期的[实施进度](./程序改进重构进度文档.md)。
