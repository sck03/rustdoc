# 可视化模板设计器

> 2026-10-06。本文件名保留以维持入口，内容只描述当前 React + Rust 设计器。票面验收见[PDF 方案](./Rust统一V3模板与原版PDF验收方案.md)。

## 编辑与输出

报表管理在 `#/reports/templates/manage`，设计在 `#/reports/templates`。文件、个人及共享模板共用目录选择；设计器负责画布、预览与保存。六类内置模板都可以打开，修改内置内容创建 DataRoot 下的副本。

唯一文件格式为 `.dtpl`，内部 schema 版本 3；界面不把版本号当作产品名称。API 传递可编辑 JSON，磁盘容器带长度及 SHA-256 校验。没有高级 HTML、V2 转换或任意脚本/CSS 入口。

参考[锐浪官方报表设计说明](https://www.rubylong.cn/gridreport/fun-design.htm)的样本修改、直接编辑、拖放和撤销方式，入口提供可展开的三步指引：选内容、调排版、预览并保存。继续使用本项目 React/Rust 排版与 `.dtpl`，未引入商业报表引擎。

2026-10-05 再次核对上述锐浪说明及[帆软 FineReport 官方产品说明](https://www.finereport.com/product/)。锐浪的“在样本上修改、即时编辑、拖放、撤销”适合本项目日常单证；帆软的类 Excel 单元格合并、对齐与扩展适合现有高级表格。借鉴交互方式，不复制其代码、图标或商业引擎，也不将 SQL、数据连接、公式编程和 BI 配置交给普通制单用户。当前继续采用六份内置样本、中文字段、自由画布和默认收起的高级表格；不增加第二种模板格式或第二套排版器。

搜索无结果时显示“没有找到匹配字段”，可一键清空并继续输入。点击、拖放和工具栏插入共用目标图层、容量与商品排版检查；失败明确提示并保留草稿，粘贴冲突整批拒绝。自由商品字段和高级明细表的互斥在两个方向都生效，不必等到保存时才发现无法输出。页眉“仅首页输出”、页脚“跟随正文”可单独修改并撤销，改名、显隐等其它图层操作保留这些打印设置。

“图层”面板可搜索已放置的标题、中文字段、字段路径，查找重叠或隐藏内容。高度和打印行为收进“图层设置”，切换资源页签保留搜索与展开状态。画布上方独立显示各图层名称、角色、数量及隐藏/锁定状态，颜色与画布边界对应；点击定位实际设计带，仅滚动画布，不把工具栏卷出窗口。选中内容同时显示在固定字号的提示栏。

默认“适合宽度”（最高 100%），优先保证编辑可读性；“适合窗口”查看整页，手动缩放不被窗口变化覆盖。“组件边界”可开关，不进入模板或影响打印；缩放手柄保持屏幕尺寸并位于组件外侧，短字段中心仍可拖动。文本限制在组件范围内，选中表格的手柄不再被裁剪。图层高度拖动采用松开时的最终位置，失焦/取消恢复原稿，不变高度不增加撤销步骤。

栏位按设计器自身可用宽度调整；空间不足时属性栏移到下方，避免应用主导航占宽后仍挤成三栏。更小屏幕继续使用面板切换。

工具栏“多选”支持逐个点击选中/取消，触屏无需 Ctrl 键；选中后统一对齐、分布和大小，一步撤销。小屏通过“添加内容 / 画布 / 属性”切换面板，保留同一编辑实例、草稿和选择；权限仍由服务端与模板状态控制。视图变化不发布草稿，文档只在修改后序列化一次。

页面固定为 A4 横/竖版，内部坐标为 1/100 mm。Header、Body、Footer、Overlay 图层共享文字、字段、图片、线条、矩形和页码组件；Flow 支持普通行、固定网格、条件、循环明细及分页符。前端维护编辑结构，Rust 负责正式测量、分页和 SVG/PDF 输出。

## 表格与分页

常规设计使用独立商品字段：左侧分为“普通字段”和“商品明细字段”，把中文字段名称拖到纸上，各字段分别移动或缩放，键盘微调、吸附和撤销照常生效。画布只显示一件商品的设计行，上下虚线表示重复范围；正式输出按相同列位逐件重复。选中商品字段可直接修改位置、大小、字号、对齐和最小行距，标签、颜色/边框、旋转和输出等低频设置折叠。长内容撑高后，同列下方字段顺延，底部对齐字段保留设计时的相对偏移。发票号、唛头等普通字段不加入商品循环。

字段、文本及页码的字体可直接选择三份随包字面：Noto Sans CJK SC 常规/粗体、Noto Serif CJK SC 常规。它们是两个家族、三份文件；选择粗体明确使用已有 Sans Bold，不引入系统字体或不存在的 Serif Bold。字体、字号和位置进入同一份模板，保存回读及撤销保留选择。

点击商品字段列表中的已有字段直接定位选中；新增字段自动寻找商品行内空位，不再堆叠到纸张右边。**自动排位只决定初始位置，不会锁定字段**：添加后仍可手动拖动、缩放、方向键微调并撤销。空间不足时保留草稿并提示调整或直接拖放。箱数、数量、金额列移动后，可点“合计与明细同列对齐”，一次调整对应合计的对齐边，并可一步撤销；不会建立永久位置绑定，合计仍是普通字段，可单独编辑。日常操作无需配置组合片段或输入坐标。

默认发票已经使用独立的货名、PO、款号、箱数/单位、数量/单位、单价和金额字段，表头与表格线另行编辑。TOTAL、总箱数、总数量和总金额同一行，合计与对应明细同列，放在跟随正文的末页合计图层；币种与金额直接连写。其他内置模板及既有用户高级组合模板保持原结构，不自动转换或删掉原排版；使用新版默认发票后另存副本即可采用独立字段。

多列行、普通表格、条件、分组明细表和分页符统一放在默认收起的“高级排版”。常用发票无需先插入整块明细表；高级组件继续承担已有模板的组合、合并和分组需求。同一模板不能同时放自由商品字段和高级循环表。

高级明细表按“商品列／表格样式／分页与高级”组织，选中表格先显示内容编辑，位置及图层输出默认收起。“商品列”只挂载当前列的编辑器，提供标题、字段、列宽、对齐和复制/删除；中文标题完成输入后一次提交，可一步撤销。“组合排版”和“跨列表头与边框”默认收起；复杂列保留中文字段显隐开关，组合排版一次编辑一个片段。切换单项/组合保留原绑定和已有组合，复制列保留全部列配置以及对应的首页说明、合计和小计单元格。

“表格样式”直接选择表头或商品正文并修改字号、对齐及加粗；文字间距、边框和列宽分布分别折叠。列边框可以单独恢复沿用整表边框。“分页与高级”集中放置打印行数、唛头侧栏、分组、小计、末页合计和首页说明；合计一次编辑一列，处于左侧合并区域时明确提示输出位置。页签切换保留选中项、展开状态和草稿；字段选择继续使用当前报表完整的中文目录，保留复杂模板已有的绑定能力。未识别绑定继续显示并允许修正，不自动替换。

- 普通网格可增删行列、合并拆分、设置列宽/行高、四边、虚线、斜线表头、竖排文字、标签位置和勾选。
- 自动明细表支持表头、组合内容、分组和汇总、唛头旁栏、首页/续页最大行数。
- 合计字段可编辑“单位/后缀”，数值继续使用原精确汇总格式。默认装箱单总毛重/净重附 KGS，总体积附 CBM；画布、保存回读和正式 PDF 使用同一配置。
- “边框延伸到表格底部”让竖线及底边至少铺满画布中设置的表格高度，并受当前页可用空间约束；拖动下边调整高度时，结构预览和 Rust 输出同步。合计行可单独设置四边与线型，或恢复沿用表格边框。默认装箱单仅保留外框与唛头分隔竖线，延伸到设计底部；货品各列不画内部竖线，合计上边使用虚线。默认发票和装箱单的右上方标签统一右移并右对齐；旧用户模板保留原设置。
- “商品之间显示横线”独立控制正文行分隔，表头、外框和合计边界保留。正文垂直对齐同时作用于单元格和分栏片段；默认发票金额与单价同一基线，装箱单箱数、数量、毛净重和体积下移到描述末行。
- 组合内容可逐段隐藏；ColumnBreak 使用递增百分比划分独立区域，长款号不能挤压箱数、数量或单价。空 PO/款号行可收起。
- 页眉/页脚可重复、仅首页、只在末页或跟随正文；页脚占位与实际输出页保持一致。内容放不下时明确提示，不静默覆盖邻格。
- 发票和装箱单每页重复抬头/表头，唛头仅首页，总计仅末页；合同续页从明细表头开始，末页接条款签字；报关单首页 6 项及申报区，续页最多 15 项并连续编号。

图层选中、锁定和隐藏会约束插入、拖动、缩放、复制、对齐和粘贴。工具不能把当前锁定图层的插入操作偷偷转移到另一层。普通坐标/样式修改和撤销使用同一状态模型，草稿比较只在文档变更时重新计算。

## 草稿与多用户

草稿与撤销历史仅在页面内存。预览往返保留编辑实例；远端刷新、读取失败、保存冲突或校验失败均保留本地草稿。保存中暂停编辑，图片上传中禁止提交，离开前按脏状态确认。

“重新载入”在存在修改时须明确确认放弃，取消保留草稿；图片上传期间禁止重新载入。状态提示区分未保存修改、上传中和与已载入模板一致，不把内存草稿显示为已保存。

模板日常流程为：选择内置或公共模板 → 填写名称并复制到“我的模板” → 打开设计器调整 → 保存 → 在单据打印或导出时选择自己的模板。保存后的私人模板仅本人可用，无需发布或共享；内部沿用 Draft/Private 状态，区别于尚未保存的页面草稿。即使管理员可以维护模板记录，也不会把他人的私人模板列入自己的输出目录。

内置原稿保持只读；公共文件模板的新建、覆盖、改名、删除、导入以及全局默认选择仅管理员可办理。普通用户即使被授予较大的发布或导入数据范围，也不能改动公共文件或全局默认。用户模板的内容和生命周期由所有者及管理员维护，不能凭公司/全局数据范围停用、归档或恢复他人的模板。

团队共享是可选流程：有发布权限时先发布，再明确选择部门、公司或全体团队范围；发布本身不自动共享。共享原稿只读，更新建议先复制、修改、预览，再发布新模板；若要修改原稿，须先明确收回共享。全局默认只允许公共文件或已发布且全体共享的数据库模板，修改、停用、归档或收回该模板前必须先更换默认，避免影响其他人的输出。停用/归档模板不进入可用目录；归档恢复及恢复历史内容形成私人模板，保留历史版本。

数据库模板命令使用 ExpectedVersion；复制和创建切换模板前确认未保存修改，冲突和失败不覆盖草稿。模板查看权限、源业务域和分享受众都必须满足；知道模板/图片 ID 不能越权读取。保存、复制和状态变更同时刷新管理目录与输出目录。

文件模板变更使用 revision 和共同存储锁，显示名称与物理文件名分别维护。模板包传递可移植的文件默认引用，数据库模板编号不跨库导出。导入失败回滚本次文件和清单，不覆盖无关设置。

图片为受控 PNG/JPEG，上传归属和内容保存在业务库中，按摘要去重。用户、数据库模板与历史、文件模板的有效引用共同决定读取和回收；仍被引用的图片不可回收，付款图片不能通过出口模板权限绕过业务域校验。

## 维护入口与验收

- 模板源：`scripts/lib/default-report-designs.mjs`；生成：`scripts/generate_default_dtpl_templates.mjs`。
- 前端：`features/report-designer`、`features/reports`；DOM/CSS 只负责交互和设计预览。
- 领域：`export-doc-domain::{designer,template}`；渲染：`export-doc-report`。
- 用例：`engine::{report_templates,report_template_files,report_assets,reports}`。

验证必须覆盖编辑后保存回读、409 草稿保留、跨用户授权、图片回收、模板包默认项、单页和多页实际 PDF。Windows 原生输入法、其它 OS/架构及打印机需要单独运行证据。未测项目保持待验，不把旧 .NET 或浏览器 HTML 结果算作 Rust PDF 通过。
