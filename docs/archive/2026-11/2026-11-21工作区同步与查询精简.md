# 2026-11-21 工作区同步与查询精简

续接 2026-11-20 的全项目缺陷、性能及前后端一致性审查，基于 `1658f273` 完成同一批实施与集中验收。桌面继续使用 Tauri 2、共享 React 和 Rust/SQLite，团队使用 Rust/PostgreSQL 18；没有新增依赖、API、数据库版本、持久化缓存或旧版兼容链。

## 实施范围

- 会议室、物品申请的展开详情随父列表版本推进重取。后台失败显示重试入口并保留已读详情；打开的中文草稿固定原版本，不被刷新覆盖，也不擅自提升提交版本，后端继续明确拒绝并发覆盖。
- 两类资源的状态筛选复用共同选项，补齐 `Suspended`、`Terminated`。办公命令及发票存入商品库复用 `useScopedMutation`，删除各自重复的生命周期处理；换客户端、换记录、撤销编辑资格后旧确认/结果不能写入或反馈到新作用域，Mutation 缓存不保留大输入和结果。
- 模板预览来源查询独立到 `useReportTemplatePreviewSources`，复用现有发票/付款分页 API、共享表单和翻页控件。每页 50 条，支持防抖检索、取消旧请求、服务器页码修正和跨页保留已选记录；演示/设计模式及无来源权限时不发起真实单据目录查询。
- 在途职责与任务区域展开后才查询；审批单模板设计器按需加载。独立 API 类型检查继承主 TypeScript 配置，移除与生成客户端不一致的 ES2020 配置，不添加旧环境兼容包装。
- CRM 客户/联系人数使用共用授权筛选的纯计数，去掉 `i64::MAX` 假分页。未完成跟进由 Storage 返回类型化计数及八条轻量提醒，聚合保留原记录/父客户范围、空提醒、时区偏移和纳秒边界；Engine 不拼 SQL。商机精确金额和发票工作台仍按有界批读处理，没有以 SQLite 浮点聚合替代十进制，也不宣称查询 CPU 成本与数据量无关。

原审查“近期跟进只按 ID 排序”的结论有误：既有查询在后续分支已覆盖为完成状态、提醒空值、精确时刻和稳定编号排序。现有双库合同覆盖混合偏移和纳秒；本批保留该规则，不将它计作已修复缺陷。静态引用缺失不足以认定 OA 动态方法、健康探针或下载入口无用，未据此删除业务模块。
