# 2026-11-26 审批一致性与资源优化

## 范围与架构

承接本次项目审查和后续 OA 问题，保持 React 19 / Tauri 2 / Rust、桌面 SQLite / 服务器 PostgreSQL 18、schema 18 和现有设计令牌。没有依赖升级、SQL 或数据库结构改动，不维护旧 API 兼容分支。

| 问题 | 本批处理 |
| --- | --- |
| 审批详情临时刷新失败卸载弹窗 | 有缓存的临时错误保留详情和草稿，显示重试；403 等永久错误仍移除详情 |
| 后台刷新静默替换审批版本 | 审批及移交弹窗固定打开时的记录版本，冲突由服务端返回并要求重新核对 |
| OA 和资源移交权限判断重复，七个重复入口 | 共用权限函数及单位任务移交接口；删除七个旧 OA 路由、无调用包装与 DTO，保留历史移交事件 |
| 提交历史与审批单重复请求／长期缓存 | 共用身份、申请、提交版本和记录版本查询键；单次读取快照，关闭后释放大对象 |
| 变更缓存持有记录和注册输入，离页仍继续请求 | 基础档案删除、许可证注册、模板目录检查复用作用域命令及取消信号 |
| 设置校验级别大小写不一致、无效自动修复入口 | level 约束为 error/warning/info；去掉 isAutoFixable、canAutoFix、hasWarnings、normalizedSettings 及对应 UI |
| HS 数字编码搜索加载整个年度与无用证据 | 使用现有 Storage 年度／前缀查询，跳过不使用的反馈、替代关系和文本评分；保留名称查询语义 |
| 浏览器 TIFF 不能直接预览 | 增加有界上传预览，复用现有 OCR worker 解码及 JPEG 输出；识别仍接收原图，预览不加载 ONNX 模型 |
| 公司负责人节点被后续依赖锁住无法删除 | 纯图模型删除普通节点并重接前置关系、去重；支持撤销／重做，明确分支目标、配对、并行结构和最后审批节点限制 |

统一移交保留七类流程各自的定义、发布版本、任务资格和审计；后端在事务内校验目标单位身份、待办任务与 expectedVersion。OCR 上传上限 25 MiB，worker 20 秒、端点 30 秒，转换输出上限 32 MiB，下载预留 64 MiB 后收缩；现有处理许可与受控进程负责取消及资源回收。图片单边最多 16384、总像素最多 4000 万，解码分配限制 256 MiB。这些是处理边界，不能作为进程 RSS 的承诺。

原生契约生成后为 **752 operations / 718 OpenAPI schemas**，客户端生成器报告 711 个投影 schema；`generate-api-client.ps1 -Check` 已通过。冻结契约未手改；独立差异夹具逐项声明删除／新增及设置字段变化，其余契约继续核对。生产模块总量仍在原增长限额内；必要 Rust 测试／示例最终实测 37801 行，在本批审查基线 37793 行上增加 8 行；单文件上限和 120 行增长额度保持不变。

## 负责人兼任与配置

同一自然人兼任部门和公司负责人且允许兼任时，为普通员工分别完成两个审批任务；不会因为第一次签署就直接批准。申请人本人审批仍被禁止；要求独立自然人的节点拒绝重复审批人。配置步骤及适用范围见[负责人兼任与节点配置](../../OA负责人兼任与节点配置.md)。

另配人员入口为“申请与审批中心 → 流程管理 → 流程定义 → 节点图 → 步骤列表 → 责任人来源：指定人员 → 责任账号”，保存后仿真并发布。七类流程分别维护；当前没有仅负责人本人申请才自动切备用人的专门选项。修改定义只影响新提交，已提交实例保留快照，未完成任务通过统一移交调整。

移除公司负责人节点后，若部门负责人本人也要申请，仍须有实际独立审批人。本人回避、必经复核及发布仿真不能被前端节点删除绕过。
