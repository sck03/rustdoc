# 人员、组织、权限与 OA 操作手册

更新日期：2026-10-31。适用于 schema 11 的 Full；Document/Sales 的个人制单和销售操作保持独立，不要求先配置 OA。真实验收范围见[本轮台账](./OA重构验收与功能保留台账.md)。

## 管理员开通

1. 使用新的 DataRoot 或 PostgreSQL 数据库启动。旧库和旧备份不能直接打开；保留需要的原程序与数据，禁止自行修改数据库版本标记。
2. 在“人员与组织 → 组织与任职”建立经营单位、部门和岗位。公司/部门负责人、行政汇报和职能汇报分别设置，名称和职位不自动授予权限。
3. 建立人员公开档案，录入单位工号和任职；联系及证件等私密资料仅由获相应权限的人事维护。首次建档不等于自动创建登录账号。
4. 在“系统管理 → 账号与权限”建立账号并关联人员，选择独立授权或具体的已发布权限方案。空独立权限表示没有业务权限。维护账号单独保留，不用它签署业务审批。
5. 在单位授权中分配业务任职、临时协作或管理身份，设置期限和授权上限；组织、任职、流程、授权、统计分别分工。一个人可有多个身份，每次操作只使用页面顶部选定的身份。
6. 在“流程管理”设置负责人/职责来源、工作日历、办理分工和各类流程，模拟后保存并发布。首次未发布的定义不能提交申请；修改草稿不改变已发布版本和在途流程。

权限方案可以先保存草稿，检查差异和影响，再发布并选择需要切换的绑定。对账号或单位身份设置显式限制时填写原因；禁用模块或收紧范围不会由其它岗位名称补回。修改有效权限后，旧会话需要重新验证身份。

## 员工申请与跟踪

“工作台 → 申请与审批”提供三个入口：“审批与进度”“待我办理”“发起申请”。请假、加班、报销、出差、采购、通用及人员变动在申请页填写；会议室和物品先选择资源。列表保留查询条件，可通过申请编号直接进入详情。

填写常用字段后，按需展开附件和低频内容。申请人员来自当前单位的有效任职，管理员代填会同时记录提交人和实际申请人。保存草稿后可预览审批路径；提交时冻结发布版本、材料和实际责任人。缺少负责人、任职失效或权限不满足时会说明原因，不能通过更换显示姓名解决。

申请草稿、退回修改和正式提交是不同状态。退回修改后更新材料并重新提交会形成新提交版本，旧意见和原件保留。离开未保存表单会提示确认；切换身份前先处理草稿，切换后按照新身份重新查询。

## 审批与异常处理

在“审批与进度”进入当前分配的任务，核对获准字段和附件，填写要求的核验项目与意见后批准、退回或驳回。批准只代表审批结果；财务接收、采购验收、物品发放等在后续办理中记录。

同一节点的会签、或签、比例通过和否决方式由发布政策决定；本人不能审批自己的申请，独立复核不能由已签署的同一个人通过另一身份或代理绕过。代理只接受当前有效的直接代理，并保留原责任人和实际签署人。

详情中的“流程操作”只显示当前允许的动作。加签选择本人可控制的节点及合格候选；候选分页加载。减签不能删除已签意见或破坏必经职责、最低人数、独立复核。指定节点退回保留历史，以新执行代次重审受影响节点。暂停、恢复、终止由获流程管理授权的人填写原因，不能以操作按钮伪造审批签名。

网络中断时先查看当前状态或操作回执；同一操作重试使用原命令键，避免重复签署和重复扣减。版本冲突时保留输入，重新读取最新结果后再判断，不连续重试旧版本。

## 人员变化与生效

正式入职、转正、调岗、离职、返聘统一从“申请与资源 → 人员变动”办理。单位任职页提供公开记录和“申请任职变更”入口；没有人员变动申请权限时只读。普通档案维护不直接改变正式任职，首次建档及未使用误建纠错有独立受控边界。

已经到生效日的变动在最终批准时完成。未来日期获批后显示“已批准，等待生效”，到期后台重新核对人员版本、执行身份和交接状态。出现“人员变动执行受阻”时按原因处理；获批准执行权限的在职人员可重新核验。人员事实已经改变的，应取消尚未生效的变动并重新申请；取消保留原签署历史。

离职或结束任职前查看未结审批、办理分工、会议和借用品，以及原业务的数据归属影响。审批任务使用受控交接；原业务按原模块既有归属功能处理。紧急停用用于立即撤销访问，之后继续处理交接，不修改历史创建人和签署人。返聘沿用人员身份，但新任职期间生成新身份，不自动恢复旧账号和旧授权。

## 资源、归档与原业务

会议室预约按时段和容量规则校验，钥匙领用/归还分别记录。物品申请、预留、发放、分次归还和库存流水使用版本与幂等保护。现实交付已经发生时，通过对应补偿/归还操作处理，不能靠终止审批抹去库存变化。

审批单由统一 V3 报表生成，包含真实材料与签署；下载 PDF 和原件 ZIP 使用当前身份的材料权限。隐藏字段不会因打开历史、通知或下载原件包重新出现。没有签章服务时，审批签署记录不表示电子印章认证。

销售客户/供货商与制单基础资料分别维护；同名不自动关联。Excel/托单导入和手工制单继续使用原入口。OA 报销不创建或改写付款打印单，财务接收不表示实际付款，原付款打印也无需绑定 OA。

## 维护与恢复

只恢复同 schema 11 且模型一致的备份。恢复前停止程序并保留现有数据和备份；PostgreSQL 由维护连接执行。恢复后核对人员/权限、在途任务、附件、未来变动及原独立业务，不重新发送结果不明的邮件或申报。

过期隔离测试输出可按清单清理；实际业务库、用户备份、程序资源和仍在使用的缓存继续保留。被占用的废弃测试文件集中移到待手动删除目录，移动只减少项目目录体积，手动删除后才释放磁盘空间。
