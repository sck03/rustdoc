# 依赖更新与安全检查

2026-11-12：`.github/dependabot.yml` 为 Cargo 三个工作区、Web/Tauri npm 清单和 GitHub Actions 每周提出版本更新 PR；安全更新由 GitHub Dependabot 告警触发。每日 `dependency-governance.yml` 刷新安全公告并审计。自动更新以可审查的 PR 交付，主分支合并前仍须完成以下核对。

- 修复版本必须支持当前 Rust、React 19、Tauri 2 和应用实际 API。无旧版本兼容要求不等于允许无验证跨大版本升级。
- SPDX 表达式必须语法完整，每个许可证及例外均已审查；未知、商业限制或许可证改变阻断发布。AND/OR 的全部备选条款采用保守审查；当前仅接受已核对的 Apache-2.0 WITH LLVM-exception 例外组合。
- npm 生产审计区分通过、低/中危警告、高/严重阻断及执行失败；超时、无效 JSON、网络错误不当作通过。RustSec 阻断漏洞、unsound 和 yanked；现有 GLib 例外继续由专用脚本核对。
- 更新锁文件后生成并审查 notices/SBOM，执行 `node scripts/generate-dependency-governance.mjs artifacts/dependency-governance --release --write-repository --verify-repository`。Dependabot 不替代许可证审查，也不会自行维护 notices；未同步的 PR 会被治理门禁阻断。
- Tauri 的 Cargo/npm 核心、构建工具及插件需要联合核对；Dependabot 的分组按生态工作，不能保证两个生态同时升级。受审查的 calamine 源码补丁与 PDFium/ONNX 原生归档仍需专门核对来源、校验和、许可及打包资源。
- 依赖修改独立提交；通过对应 locked 构建、功能回归、桌面依赖树和许可门禁后合并。Actions 的完整 SHA、Node 26 政策继续由工作流验证器约束。

本批 rustix 1.1.5 → 1.1.6 修复 RUSTSEC-2026-0486，许可保持 Apache-2.0 WITH LLVM-exception OR Apache-2.0 OR MIT。新增构建期 spdx-expression-parse 5.0.0（MIT），spdx-license-ids（CC0-1.0）与 spdx-exceptions（CC-BY-3.0 标识符数据）；后者允许商业使用与再分发，须保留 Linux Foundation 归属和许可链接，已纳入 notices。它们不进入应用前端运行包。

CI 固定 cargo-audit 0.23.0 并缓存工具；公告数据库每次运行更新，工具缓存不会冻结漏洞信息。仓库设置中的 Dependabot alerts/security updates 必须启用，权限不足时应记录外部设置未完成，不能声称仅提交 YAML 就已启用安全修复 PR。
