## 发现与修改

前批输入法保护覆盖了字段和发票单元格，但页面查询、部分保存快捷键、参考目录、分页、导航和弹窗仍有旁路。综合查询在表单按键处理已经跳过组合输入之后，仍执行自己的 `runSearch`；参考目录会用候选确认键打开别名编辑器，弹窗和导航会用候选取消键关闭或清空内容。

这些入口统一复用 `ui/keyboardEvent.ts::isComposingKey`，同时识别原生 composition 状态和确认键 229。窗口级快捷键和共享弹窗尊重已处理的事件；别名编辑器删除重复的 Esc 关闭逻辑，由共享弹窗负责关闭、焦点恢复与取消边界。没有新增按键解析器、兼容层、持久化状态或运行依赖。

新增 `test:input-method-ui` 使用真实 React 组件检查查询、参考目录、导航、弹窗、分页及色值输入。将同一夹具绑定到修改前的源码，8 组场景分别复现误查询、打开编辑器、清空搜索或关闭弹窗；修改后 8 组全部通过，并验证普通 Enter、Esc、Ctrl+Enter 仍执行原有动作。该测试进入 Chromium 编辑回归任务；它验证 Web 输入事件，不冒充操作系统候选窗口验收。
