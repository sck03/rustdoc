# 报表设计器 V3 现行设计与实施事实

> 最近更新：2026-09-01
>
> 本文只描述当前 V3 设计器的契约和已落地能力。部署、数据库、API、运行目录和依赖版本以[《当前架构事实》](./当前架构事实.md)为准；旧日期文档只用于追溯，不能覆盖本文或当前源码。

## 1. 当前结论

V3 是项目唯一的可视化模板设计器运行时：前端使用 React 19 + TypeScript 自研自由画布，后端继续使用 .NET 10 C# 提供模板读写、字段目录、预览和最终 HTML/Scriban 安全校验。V3 不依赖 Luckysheet、iframe 设计器、GrapesJS 或商业报表格式，也不把设计器后端改成第二套 Rust 服务。

画布固定为物理 A4 页面，支持两种方向：竖版 `210 × 297 mm`、横版 `297 × 210 mm`。内部坐标统一为 `1/100 mm` 整数，导出时再转换为毫米，避免浮点累积造成打印偏移。页面由 Header、Body、Footer、Overlay 四个图层组成；图层和元素都可以显示/隐藏、锁定、调整层级，并具有受控打印行为。

当前 V3 交互入口为 `ReportDesignerV3Workspace` 及其子模块。源码模式仍保留给高级维护人员查看和编辑经典 HTML，但不是普通用户的可视化路径。V3 生成的 HTML/Scriban 与结构化 schema 一起保存，schema 只作为 HTML 注释中的单一设计事实源，不创建第二个数据库或 sidecar 文件。

2026-09-01 最终复核已确认：路由 `reportType` 优先于嵌入 schema 的报表类型；旋转元素采用局部坐标包围盒进行夹紧和缩放，Inspector 可编辑角度；Body 静态/Flow 重叠会提示修正。V3 合同和 4 页 Chromium 打印回归、Web 构建 `2233 modules` 及全量 .NET `1099/1099` 已通过。Firefox/WebKit 手动验收、真实 PostgreSQL/Docker、多平台真机和打印机校准仍未完成，不以本机结果替代。

## 2. V3 契约

| 契约 | 当前规定 |
| --- | --- |
| 页面 | 仅 A4；竖版 `21000 × 29700`、横版 `29700 × 21000`（单位为 1/100 mm） |
| 图层 | Header、Body、Footer、Overlay；最多 16 层、每层最多 1000 个元素、总数最多 4000 个 |
| 基础元素 | Text、Field、Image、Rectangle、Line |
| 结构化元素 | Flow：Row、Grid、Conditional、DetailTable、PageBreak；复用既有受控 block AST 和 renderer |
| 排版操作 | 拖动、八方向缩放、多选、复制、删除、对齐、水平/垂直均匀分布、键盘微调、网格吸附、图层和撤销/重做 |
| 打印属性 | Header/Footer 重复、最小高度、保持整段、页脚贴底；Body 明细表跨页表头、行避免截断、受控分页 |
| 数据域 | `ExportDocument` 只能使用出口单据字段；`PaymentVoucher` 只能使用付款/报销字段；交叉字段在保存前阻断 |
| 图片 | 只接受字段绑定或受控 `resourceId`；当前 `resourceId` 没有上传服务时显示安全占位，不接受任意 HTTP、文件路径或静态外链 |
| 表达式 | 只允许字段路径和受控条件、汇总结构；不向普通用户开放任意 Scriban、CSS、脚本或动态求值 |
| 保存 | 先做 schema 标准化和阻断校验，再复用既有模板保存 API；原子写入并保留模板域和并发冲突语义 |

V3 层的自由定位只负责对象几何和对象关系；明细循环、分组、小计、跨列表头、票据格合并、分页和页眉页脚打印语义仍由 Flow 内部结构化 AST 表达。这样可以自由移动对象，又不会把业务规则重新复制到画布代码中。

## 3. 已完成能力

- 组件库、字段目录和图层/对象树三段面板；普通用户可点击或拖入组件、字段，也可在对象树中跨图层重排。
- 文本、字段、图片占位、矩形、水平/垂直线的自由移动和精确坐标编辑；锁定元素和锁定图层不能被间接修改。
- 多选后整体移动、八方向缩放、左/中/右、上/中/下对齐，以及水平/垂直均匀分布；所有批量操作都受页面边界、最小尺寸和锁定状态约束。
- Row 多列行和 Grid 固定票据格：列宽调整、单元格增删、合并、边框、样式、勾选组和竖排文字。
- DetailTable：`Invoice.Items` 循环、唛头侧栏、分组表头、分组小计、表尾合计、组合单元格、跨列表头、列拖拽排序和列宽可视化调整。付款/报销模板不能插入出口明细表。
- Header/Footer 重复、保持整段、最小高度、页脚贴底、分页符和 Chromium print/PDF 回归；导出器显式建立绝对定位页面壳和流式明细区。
- 样例数据、长明细样例和已保存当前单据预览；样例只在浏览器内存中生成，不写数据库、LocalStorage 或文件。
- 损坏 schema 安全草稿、V2/经典 HTML 显式迁移确认、数据域隔离、字段白名单、图片资源边界和导出阻断。
- 历史记录有界，结构化变更可撤销/重做；键盘支持 Delete/Backspace、Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z、Ctrl/Cmd+Y、Ctrl/Cmd+D、方向键和 Shift 方向键。

## 4. 经典模板适配边界

经典模板可以继续使用。旧 HTML 仍由现有服务端 renderer/PDF 链路读取；它不会因为启用 V3 而被重写。没有 V3 schema 的旧模板打开时只生成内存中的迁移预览，用户明确点击“开始 V3 编辑”后才建立 V3 草稿；应用或保存前还会再次确认覆盖，原 HTML 在确认前保持不变。V2/缺版本/损坏 schema 也遵循同一显式确认原则，不保留多套运行时互相兜底。

V3 只承诺 A4 横/竖版。旧模板中存在 A5、自定义纸张或复杂 HTML 分页时，可以继续走源码/经典渲染路径；转换到 V3 时会按 A4 契约提示尺寸变化，不静默伪造原纸张尺寸。转换后需要以 PDF、字体、线条、换行、分页和打印机偏移逐类复核。

本轮以六类经典版式作为 V3 能力边界：

| 类型 | 版式关注点 | V3 组合方式 |
| --- | --- | --- |
| 报关单 | 横版固定表头、复杂表格、明细和印章 | A4 横版 + Grid/DetailTable + 受控图片字段 |
| 付款单 | 竖版票据格、复选框、审批签字区 | A4 竖版 + Grid + Field/Rectangle/Line |
| 报销单 | 费用项目、金额合计和签字区 | A4 竖版 + Grid/Row + Payment 域字段 |
| 发票 | 多页明细、重复页眉/表头、页码和总计 | Header + DetailTable + Footer/PageBreak |
| 合同 | 中英双语、条款表格和印章 | Text/Field + Row/Grid + 受控图片字段 |
| 装箱单 | 唛头侧栏、数量/重量合计和印章 | DetailTable.sideBand + summary/grouping + 图片字段 |

图片异常、缺失字体、扫描件或不受控外链不会用“看起来能显示”的降级补丁掩盖；必须回到字段图片或受控资源合同并在预览/PDF 中确认。

## 6. 质量和安全口径

- V3 导出不生成脚本、iframe、任意外链或动态求值；服务端仍在保存、导入和渲染前复核最终 HTML/Scriban。
- 所有异步预览和保存沿用现有取消、超时、资源上限和 409 并发语义；设计器不创建第二数据库、LocalStorage 持久状态或默认图片目录。
- 画布和面板使用公开 React 19 API；触摸拖动、键盘选择、缩放、减少动效和基本无障碍属性纳入前端合同测试。
- 设计器资源、测试 PDF、Chromium 输出和截图只写仓库 `.codex-runtime/` 或 `artifacts/` 可清理目录，不进入 Git、AppData、ProgramData 或客户 DataRoot。
- 系统级 Windows Authenticode、macOS Developer ID 和 Apple 公证不在本项目范围；若启用 Tauri updater，更新包签名和公钥信任仍必须保持。

## 7. 发布前仍需现场验收

本机门禁可以证明代码、契约和 Chromium 主路径，但不能替代真实部署验收：PostgreSQL 18 多用户并发、Docker/Nginx、Windows/Linux/macOS/ARM64 桌面包、Firefox/WebKit、不同字体、真实打印机偏移、长明细压力和断电/进程崩溃恢复，均需按《当前架构事实》和发布清单在目标环境复验。只有典型模板批量通过 PDF/打印校准后，才可把 V3 宣称为商用稳定。

## 8. 存储边界

V3 schema 随模板 HTML 注释保存到既有 `Templates/` 受管路径；模板包使用现有 `DataRoot/Cache/TemplatePackages` 暂存并通过 `1.3` manifest 的逐文件摘要校验。设计器不会复制经典 PDF、业务图片、数据库记录或用户文件，也不会偷偷把内容写到系统临时目录。
