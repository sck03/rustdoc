## 行为与架构

- 供货关系和评价页面仅组合控件，草稿规范化、分页查询、作用域命令分别封装，复用版本草稿、未保存保护、串行确认及后台刷新。保存时允许续编，返回新编号/版本后继续更新；客户端、权限或供应商变化及卸载取消旧写入和查询，不保留历史 mutation 输入/响应。
- 供货参考价采用可带正负号和前导零的普通十进制文本，Domain 共用精确十进制解析器并规范化，不经浮点数。前端、API 与 Domain 支持 `-1000`、`+001.00`，同时拒绝下划线、科学计数和超出精度的写法；编号/版本/交期/评分采用严格整数。供货/评价写入使用生成契约检查请求结构，关联记录复用共享编号解析器并拒绝正文与路径的非零编号冲突。超出 JS 安全整数的大金额包括负号也保留精确值。
- 发票销售单价、行金额、采购价和采购额允许负数，修复 Rust 通用数字解析及重算结果误拒绝负金额的问题；数量、每箱数量、箱数、尺寸、重量和体积仍非负，退税率在 0–100，OpenAPI 按字段投影规则。金额调整行继续支持正负数。共用 Rust/React 计算夹具增加负数及中点舍入，桌面验收覆盖 `-1000` 编辑、保存回读、负采购额和实际 PDF。
- `ListSupplierAssessments` 保留操作名和 URL，直接返回分页；新增 `GetSupplierAssessmentAnalytics`。Storage 复用同一父级和草稿可见性筛选，在同一读事务内统计全部可见记录并取最近 12 条。聚合表达式在外层 SELECT 计算，再由两库 JSON 对象函数输出，不进入逐行投影子查询；回归覆盖空集合、普通用户及审批权限。React 只在分析视图读取统计，均值不由最近窗口推断。
- 原生契约生成 JSON 容量元数据：命令回执/供应商单记录 64 KiB，评价统计 1 MiB，其余最多 64 MiB。Engine 共用有界编码器，HTTP 写入前预留容量，读取在缓冲增长前准入，发送结束/断线后释放。仅成功 204 及文件输出不进入 JSON 作用域。预算是受管缓冲容量，不能据此宣称限制全部 JSON Value、数据库驱动内存或 RSS；独立能力的已编码返回值仍走发送前兜底准入。
- 八个 nullable schema 从重叠的 oneOf 改为 anyOf，删除旧 .NET 空值例外；独立演进对照覆盖正式 schema、权限、响应和容量投影。生成客户端与服务端同时更新，禁止手改生成物。
