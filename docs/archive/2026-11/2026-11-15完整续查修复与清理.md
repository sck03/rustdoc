# 2026-11-15 完整续查修复与清理

## 实现

- HTTP 从最终运行契约读取期限，统一附件上传、下载准备与生成客户端的值；回归逐项比较全部端点。
- `invoice_status_history` 保存不可变状态事件：发票/版本复合主键、前后状态、原因、操作账号 ID 和登录名快照、RFC 3339 时间。事件与状态更新同事务提交，陈旧版本不会新增事件。与通用审计相同，历史不通过外键随发票清除。Storage 负责双库 SQL，Engine 复核当前权限，React 展开后每页 50 条读取；API 接受 `beforeId`/`limit`，每页最多 200 条。
- 邮件服务状态允许 `send` 或 `view-delivery`，投递历史保持原权限。发送和完整备份恢复复用 `useScopedMutation`，取消及迟到响应遵守客户端作用域，不保留 mutation 输入/结果缓存。移除“旧备份逐步升级”文案。
- 利润分析使用 `useTransientPreview`，草稿、客户端或可用状态变化后清空并取消；过期响应不再覆盖当前界面。
- HS 知识包接入现有下载入口，在分配前预留工作容量，返回时保留 Vec 实际容量预算直到发送或取消结束；移除 HTTP 重复封装分支。
- S3 缓存限制 256 MiB/1024 条，使用顺序索引淘汰；文件打开、核验和回收不持缓存状态锁，引用所有权保护正在打开的文件。
- 磁盘写入按 1 MiB 块预留；审批 ZIP 与备份归档使用 64 KiB 缓冲并显式检查 flush 错误。移除已无生产调用的通用历史包装及前端历史参数传递链。

数据库保持全新 schema 18，模型指纹随正式基线更新；不添加迁移链、依赖、第二数据库或后台服务。冻结契约的变更通过显式演进记录审核，不直接复制当前输出作为预期。
