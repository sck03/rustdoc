# 2026-11-17 装柜一致性与关联查询优化

## 实施范围

- 装柜分析结果与输入快照共同保留，输入变更后旧预览不参与 PDF；PDF 命令取消覆盖文件对话框、下载和卸载，采用现有作用域命令，不保留 mutation 大对象。
- 柜型命令独立为 `useContainerPackingTypes`，保存与删除串行，回写核对客户端、权限、项目和柜型；成功后更新目录缓存，刷新失败仍保留已提交版本。
- 装柜目录由固定 100 条改为分页/搜索，使用共享 Pagination 和现有布局控件。原生契约统一生成参数、页元数据及客户端；冻结契约只声明这一变更，其它认证、授权和错误元数据继续比较。后端只返回目录摘要，明细按需加载。
- 权限方案拆分草稿模型、工作区 hook 和展示，统一作用域命令；删除条目从缓存移除，迟到确认和回调不触发后续操作。
- 发票维护按 `sourceId` 过滤，仅投影编号/版本，每批最多 200 条，取消检查和整批事务保留。SQLite/PostgreSQL 新增部分索引 `records_source_page`，仅覆盖有来源的记录。schema 仍为 18，模型指纹随完整基线变化；不维护旧实验库转换链。
- OA 可见性与待办处理复用同一记录的 `ReviewSnapshot`，保留原权限规则；不增加长期权限缓存。通用持久化的身份/范围准备从事务协调器抽出到 `store::record_policy`。
- 删除无消费者的 `packing_view` 导出及 JSON 克隆降级分支；当前浏览器/WebView 基线统一使用公开 `structuredClone`。
- 截图审查发现装柜“分析”按钮依赖未加载的其它页面样式，改为共享 `command-button`，沿用统一设计令牌。

### 两库性能对照口径

`test-native-postgres.ps1 -Scope QueryPerformance` 分别以 `EXPORTDOC_QUERY_BENCH_MODE=baseline/current` 执行，每次新建隔离 PostgreSQL 18 集群；SQLite 与 PostgreSQL、两种策略分别运行于独立 Windows 测试进程，Debug 配置、同一源码与新 schema 18。baseline 仅在测试中复现 c3639787 的全量读取和重复快照调用，不在产品中保留兼容分支。两库查询计划均实际使用 `records_source_page`。

- 审批：通过真实人员、发布流程和提交申请建立待审批事项，100 次分派可见性与任务读取，5 轮中位数；计数为存储适配器读取调用，不是逐条 SQL。该场景不获取写锁，写等待为 0。
- 关联清理：`sw-coo/sw-acd/sw-batches` 各 3,000 条、每条 8 KiB 匿名重复载荷，其中各 205 条关联目标。对关联删除段执行 5 次事务回滚对照，并同时排队另一个写事务，统计这一段连同身份刷新、回滚和排队写完成的耗时。不是整个清理 HTTP 请求的延迟，也不代表生产容量。
- 内存为 Windows 测试应用进程 `PeakWorkingSet64`，包含初始化阶段，不含 PostgreSQL 服务端；不是堆内存精确峰值。绝对耗时受本机负载影响，保留所有样本及查询计划于本地 `artifacts/project-hardening-20261117/performance.json`。

分页多执行了小查询，但读取范围从全部 9,000 条完整载荷收敛为目标 615 条的编号/版本。每批至多 200 条；原子事务和失败回滚保留，所以删除仍会持有写协调器，不能据此声称无锁等待。审批快照仅在当前记录/事务中复用，后续请求仍重新核对权限。两策略的总适配器调用分别为 621/627（包含 615 次删除及身份刷新）；不能把总调用数当作只读查询数。

PostgreSQL 18.6 的 `-Scope All` 已通过存储、关联查询、恢复/发布以及完整团队/组织流程合同，退出码 0；团队用例耗时 1738.33 秒，隔离集群正常关闭。证据位于 `.codex-runtime/native-postgres-tests/45c1d8cec5bb40e59037370f7b746ff9/result.json`。新增的两个手动性能测量测试分别执行，不计入前述工作区常规测试数量；中断或失败的早期尝试不作为通过证据。

## 清理与交付

清理前普通候选约 68,447 MiB，其中 Rust target 约 68,380 MiB；未直接使用包含整个 target 的默认删除计划。核对 Cargo 指纹与源码时间、测试入口、隔离集群初始化/结束证据后，定向删除 2,662 项，文件逻辑大小合计 30,925,057,999 字节（28.80 GiB）。其中 2,642 项为完成的测试可执行文件/附属文件及被当前源码依赖失效的项目编译输出；其余为 4 个隔离 PostgreSQL 测试库、匿名 UI/HTTP 测试输出及历史日志。当前批次的结果日志、桌面截图和 PDF 保留。

所有路径在工作区内，已核对无链接、嵌套 Git、受跟踪源码或运行进程占用。删除旧浏览器测试目录时首次遇到 Windows“目录不是空的”，停止后对原清单剩余文件重新核对大小/时间并重试完成。删除前后 1,040 个保留文件哈希一致，涵盖当前 Full 程序、业务目录、资源、用户备份和私有补丁；第三方依赖、下载和 incremental 缓存保留。最终 E 盘可用 100,531,916,800 字节（约 93.63 GiB）。文件逻辑大小不等同物理回收量；首次中止前未持久化空闲空间基值，不以逻辑大小声称实际释放量。

本地证据为 `artifacts/project-hardening-20261117/cleanup-plan.json`、`cleanup-paths.json` 和 `cleanup-result.json`。清理后检查 Git 状态、worktree 及差异；本批源码、契约、测试脚本和文档按普通快进交付 `main`，仅保留本地/远端 `main`，不提交数据库、程序包、截图、日志或一次性清理脚本。
