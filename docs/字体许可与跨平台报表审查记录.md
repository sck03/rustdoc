# 字体许可与跨平台报表审查记录

2026-11-06：Sans Medium 500 已接入 React，文件来源、Git blob、SHA-256、内部名称和 OS/2 字重均已核验。UI 使用真实 Sans 400/500/700，Serif 400 按需加载；不再依赖 600 匹配。四份 OTF 转为完整 WOFF2 供网页使用，逐字体表与摘要验证通过，合计减少 22,548,100 bytes（30.26%）；PDF 保留 OTF。许可、构建及实际验收见[本次记录](./archive/2026-11/2026-11-06重构实施与验收记录.md)。

2026-11-05 补核：邮件正文预览复用主界面已经注册的三份 FontFace，不创建另一套字体文件或下载链。浏览器返回的 CSS 字体族名称先去掉序列化引号，再按批准的族名共享；真实预览和脚本禁用回归已通过，详见[二期记录](./archive/2026-11/二期重构验收与清理记录.md)。

> 2026-09-23。当前报表由 Rust 测量、krilla 编码；旧 Chromium/.NET 字体验证不作为当前运行证据。

| 文件 | 用途 | 许可证 |
| --- | --- | --- |
| NotoSansCJKsc-Regular.otf | 全部应用界面、发票/装箱单/合同正文及设计器默认 | SIL OFL 1.1 |
| NotoSansCJKsc-Bold.otf | 界面/报表标题、表头、重点金额及所有粗体 | SIL OFL 1.1 |
| NotoSerifCJKsc-Regular.otf | 报关、付款、报销的衬线正文 | SIL OFL 1.1 |

当前报表使用上表三份资源；受管资源清单另包含UI 的 Sans Medium 500，共四份字体。均允许商业使用、随应用分发和 PDF 嵌入，随包保留许可原文。来源、版本和 SHA-256 以 [font-manifest.json](../Resources/Fonts/OpenSource/font-manifest.json) 为准；二进制由构建阶段下载核验，不提交 Git。

没有 Serif Bold 文件；需要粗体时使用已有 Sans Bold。不把参考 PDF 中的微软雅黑、宋体或其它系统字体复制进程序。字体替换后仍要核对列宽、行高、数字、混合中英文、换行与分页。

Rust 从 RuntimePaths 指定的程序资源根加载字体，React 设计画布使用对应受控字体。字体名称相同不能单独证明实际加载或测量一致；最终验收使用真实生成的 SVG/PDF。

2026-11-05：主入口通过共用 typographyPolicy 注册上述三份字体，Vite 从原受管文件生成带摘要名的前端资源，文件字节与 manifest 保持一致。正文及控件不再优先使用 Segoe/微软雅黑等系统字体；启动骨架同样不残留覆盖正文的旧字体。页面字形通过 Chromium 的 `CSS.getPlatformFontsForNode` 检查 `isCustomFont` 与实际 glyphCount，字体声明和打包清单检查不能代替此项。

维护命令：

```powershell
node scripts/provision-report-fonts.mjs
node scripts/verify-font-license-policy.mjs --require-files
```

每次字体或排版变化后重新生成受影响的匿名 PDF，检查嵌入字体与逐页图像。六类模板及多页规则见[PDF 方案](./Rust统一V3模板与原版PDF验收方案.md)，准确执行证据见[进度](./程序改进重构进度文档.md)。其它 OS/架构、浏览器和实体打印仍分别验收。
