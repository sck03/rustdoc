# 项目程序操作说明

ExportDocManager · 从首次使用到业务归档

制单 / 销售 / OA 协同 / 文件输出 / 系统维护

版本日期：2026-11-24　适用程序：0.1.2　数据库基线：schema 18

本说明面向日常操作人员和负责开通的管理员。按当前界面导航介绍操作顺序；实际可见功能由产品版本、许可证、已启用模块及当前账号权限共同决定。

先阅读第 01-03 节完成入门，再按工作职责阅读对应章节。完整 OA 配置与案例见《OA 系统管理员手册》；申请、审批和办理的细节见《OA 系统用户手册》。本说明中的项目，是 OA 中用于人员分工和审批范围的有限项目，不等同于完整的工程项目成本管理系统。

## 01 选择正确的运行方式

| 形态 | 适用工作 | 数据与协作 |
| --- | --- | --- |
| Document 单证桌面版 | 出口制单、单证资料和已提供的工具 | 本机 SQLite，按单机方式使用 |
| Sales 业务员桌面版 | 客户、跟进、商机等个人外贸工作 | 本机 SQLite，入口按产品能力裁剪 |
| Full 网页/Docker | 多人单证、销售与 OA 协同 | 统一 Rust 服务连接 PostgreSQL 18 |
| Full SQLite 测试便携包 | 完整界面培训和隔离验收 | 独立测试包，不能替代正式多人部署验收 |

桌面包解压到可写的专用运行目录后启动程序；保留随包资源，不单独移动主程序。多人使用由管理员提供服务地址，员工在浏览器访问，不需要也不应获得数据库账号。

首次启动按页面完成管理员初始化，再配置普通工作账号。数据库不存在时才允许初始化；已有文件、损坏库、旧版本库或未知版本出现错误时，应保留现场并由管理员处理，不能删库后反复尝试。

本次操作说明按当前实现编写。Windows x64 为本机验收平台；其他系统的实际交付以对应平台验收记录为准。软件更新仅使用受信任的正式更新配置，具体渠道是否可用以版本发布说明为准。

## 02 登录、身份与工作台

1. 使用自己的账号登录。Full 中核对当前单位和身份；同一人的不同任职不能混用。
2. 从“工作概览”查看获准的单证或销售统计；统计没有包含的数据，先核对筛选条件与权限。
3. 从“我的待办”进入需要处理的事项，从“通知与公告”查看业务消息。
4. 使用左侧业务分组或导航搜索定位页面。入口隐藏时，核对产品能力和授权，不通过修改地址绕过。
5. 完成工作后保存草稿，离开共用设备前退出账号。

| 导航分组 | 常见内容 |
| --- | --- |
| 工作台 | 概览、待办、通知、申请与审批、文件任务 |
| 客户与供货商 | 客户与跟进、商机与报价、供应商 |
| 单证与申报 | 发票、付款报销打印、统计、业务资料、单一窗口 |
| 行政与人事 | 通讯录、人员档案、组织任职、会议室、物品 |
| 资料与工具 | 基础资料、报表模板、Excel、识别和辅助工具 |
| 系统管理 | 设置、备份、维护、账号权限、流程、审计和支持 |

页面的查看、新建、保存、审批和导出是不同动作权限。能进入页面，不代表可以执行所有操作；收到通知，也不代表取得全部材料权限。

## 03 通用操作习惯

列表先筛选，再翻页；确认单位、状态、日期和检索词后打开记录。大量记录不要通过反复刷新来查找。组织项目和部门选择器支持按名称/代码检索，已选内容在翻页后仍保留。

表单常用信息默认展示，低频资料在可折叠分区中。收起分区不会删除已填写内容；保存失败时查看错误字段，展开对应分区继续修正。中文输入时先完成候选文字，再确认保存或切换行。

金额、数量、币种、单位和日期均按明确字段填写。业务日期使用年-月-日；不要把其他币种金额直接相加当作统一金额。批量粘贴或导入后抽查数值精度、空值和明细对应关系。

保存成功后核对状态或重新打开记录。发生版本冲突时，保留自己的输入并读取最新版本，再决定如何合并；不要连续提交旧版本。页面跳转或请求取消不保证服务器已经完成的动作被撤销。

异步导入、导出和报表任务在“文件任务”检查状态、失败原因与结果。下载后实际打开文件核对；“下载已开始”不代表内容完整。删除、取消、停用和归档含义不同，以当前确认提示为准。

## 04 基础资料与业务准备

开始制单前，在“基础资料”维护业务需要的客户、出口商、商品、港口和计量单位。填写稳定代码和清晰名称，核对地址、联系人、银行及运输信息。

1. 查找是否已有相同主体，避免重复建档。
2. 新建或编辑基础资料，先填常用字段，再按业务补充地址、银行等低频内容。
3. 保存后重新打开，核对中英文名称、地址换行、币种与代码。
4. 在发票中选择资料后，检查本笔业务的实际内容，不仅依赖默认值。

供应商在“供应商管理”维护联系人、产品与评价；销售客户在“客户与跟进”维护。不同模块的档案用途不同，不要仅凭同名推断为同一条记录。导入出现多个匹配主体时，先消除歧义，不能随意选第一条。

“HS 编码知识”和申报词典用于维护参考信息。涉及真实申报时，由具备业务资质的人员核对现行要求及实际货物，程序中的参考资料不自动替代业务审核。

## 05 HS 编码查询与年度导入

在“单证与申报 → HS 编码知识”查询本地目录、申报实例或联网参考。查看、采集和保存有独立权限；联网结果仅供核对，当前有效税则通过年度导入维护。

1. 打开“年度税则导入”，填写资料来源及已生效的适用年份，选择 Excel 文件。
2. 零散更新选择“增量资料”。未提供的列保留原值；可选字段有对应列但单元格为空时，将清空该值。
3. 只有确认整份资料完整时选择“完整年度库”。该模式按完整行覆盖，缺列使用空值；缺失的原有效编码标记为疑似作废。
4. 等待预检摘要，核对新增、更新、疑似作废和需处理数量。此时尚未写入正式税则。
5. 按“变更类别”筛选并翻页，展开“变更”查看字段修改前后的值；“（空）”表示空值。同时核对表头映射和警告。
6. 确认内容后点击“确认导入”。完成后回到目录抽查名称、税率、申报要素、备注及年度。

**确认导入提交该次预检的全部有效行；筛选和分页仅用于查看。** 预检 30 分钟内有效且只能提交一次；到期、身份变化或记录版本冲突时重新预检，保留原资料进行核对。

已有本地参考资料的联网保存需要确认并使用读取时的版本。重复新建不会覆盖原记录，远程未提供的字段不会清空本地维护值。疑似作废先核实再确认；历史单据继续保留原编码。

## 06 发票与单证明细

1. 打开“发票管理”，新建发票或进入已有草稿。
2. 核对编号、客户、出口商、日期、币种及必要的运输信息。
3. 在商品明细填写品名、规格、数量、单位、单价及包装资料；按需要补充标记、重量和体积。
4. 检查合计、舍入、币种与明细一致性，处理界面提示的必填或格式问题。
5. 保存草稿后，再进行信用证核对、装柜辅助或单据输出。
6. 输出前检查模板、抬头、地址、签章、页码和续页，生成后打开 PDF 复核。

表格编辑时先完成当前单元格输入，再切换行或执行保存。修改基础资料不应被当作已确认单据的人工复核；每笔发票仍需按实际内容检查。

根据页面提供的状态流转执行确认、撤回或其他操作。已被其他用户修改时重新读取最新版本。批量操作前核对所选记录与筛选范围；不要把永久清理当作日常撤销。

## 07 信用证导入与核对

在发票编辑页面展开信用证分区，选择界面支持的文件导入。PDF 可包含原生文字、扫描页，或同页的文字与图像；程序逐页提取，必要时使用 OCR。该功能使用发票操作权限，不要求额外取得报表模板设计权限。

1. 选择正确的信用证文件，等待提取结束。
2. 对照原件核对证号、金额/币种、有效期、装运条款及要求的单据。
3. 特别检查 OCR 容易误读的字母数字、日期、小数点及多行条款。
4. 按页面提供的审核和保存动作处理结果，再核对发票与单据内容。

信用证 PDF 的当前边界为 25 MiB、最多 50 页及 50 万提取字符；超限时按业务合理拆分。PNG、JPEG、BMP、WebP、TIFF 等图片按页面接受类型选择，GIF 不在信用证支持范围内。普通附件的容量规则与信用证提取不同。

扫描文件需要可用的 OCR 资源；缺资源或提取失败会明确报错。不要把空结果当成“没有条款”。取消后先确认页面状态，再重新导入。机器提取和审核提示用于辅助核对，最终以实际文件和业务确认结果为准。

## 08 装柜、统计与业务资料

装柜辅助先核对箱型、货物件数、单件尺寸、重量和允许的摆放条件，再计算布局。检查未装入货物、容量限制和结果说明；有约束冲突时先调整输入，不靠多次点击计算解决。

装柜示意用于业务辅助，真实装载仍需核对箱体、承重、包装强度及现场条件。尺寸和重量的单位必须与输入栏一致；不能用外观图替代数据检查。

“统计查询”按日期、客户、商品等条件检索业务明细，先检查条件和统计口径，再导出。不同币种应分别核对，没有明确汇率口径时不要合并解释为同一种货币。

“业务资料”保存原始资料、确认文件和交付文件。替换文件按版本操作并填写必要原因；历史版本用于追溯，不能随意清除。下载资料时核对归属记录、文件名和版本，避免把旧版重新交付。

网页版点击“下载原文件”后，在浏览器下载列表查看进度与结果；下载链接不能直接转发给其他人使用。桌面版选择保存位置后另存为，原件预览与下载分别操作。

在资料目录选择“资料分类”后检索或翻页；清除分类可查看全部获准资料。上传的新版本需要另行确认为有效版本，上传完成不会自动替代当前交付版本。单文件限制和组织配额按管理员设置执行，历史文件继续占用容量，停用资料不释放容量。

“付款报销打印”用于制作付款单/报销打印单。需要正式 OA 审批时，使用费用报销等申请流程；打印单或 PDF 本身不表示审批已通过或款项已支付。

## 09 报表模板、Excel 与文字识别

报表模板先从现有模板选用，再按需要进入设计器修改。检查字段绑定、字体、线条、图片、表格列宽及分页。空白设计和内置模板使用同一输出规则；画布显示正常后，还须生成实际 PDF 检查。

导入模板文件时，数字字段必须是合法数值。出现非法格式、整数或范围错误时按提示修正，不把部分解析成功的内容当成合法模板。重要修改先保留可回退的模板版本，再保存并重新打开。

图片资源的查看、上传和回收分别授权。没有回收权限、图片归属不符合要求，或图片仍被模板/历史版本引用时，不能回收；按界面显示的可用动作处理。

Excel 操作推荐使用程序导出的填写模板。保留表头与必要结构，填写后检查商品行、单位、日期和金额；先预览识别结果，再确认正式导入。预览不会自动写入正式业务记录。

Excel 转托单时核对主体识别和字段对应。多个出口商名称无法唯一判断时应明确选择或修正资料；不要依赖首条档案自动决定业务主体。

“文字识别”用于提取图片文字，完成后人工核对。上传错误、空白图片、资源不可用和超时需要分别处理；识别结果不直接等于已保存业务数据。

## 10 客户、商机与邮件

在“客户与跟进”维护客户和联系记录，登记沟通内容、下一步事项及时间；在“商机与报价”按业务进展更新阶段、报价及相关信息。跟进记录应具体到已发生的动作，避免仅把阶段改成“完成”。

邮件先由管理员或获准用户配置账号与服务参数，测试可用后再处理正式发送。使用邮件模板生成草稿时，逐项检查收件人、主题、正文、语言和附件，尤其注意模板变量是否替换完整。

发送前再次核对附件版本和接收对象。发起发送后查看投递记录与具体结果；网络故障时先确认是否已成功，不要直接重复发送。客户资料、信用证和内部审批材料按授权范围共享。

程序内的客户、商机和邮件记录提供工作支持；不同产品版与账号的入口可能不同。需要团队协作时使用正式多人服务，不通过多人共用同一桌面数据库实现协作。

## 11 单一窗口资料与交接

在“单一窗口”的申报业务中准备数据，核对主体、商品、代码和必填字段，再按当前支持的业务能力生成交接批次。申报词典用于维护字段选项和参考代码。

官方客户端 COO/ACD 的 OutBox、SentBox、InBox、FailBox 可检测或手选现存目录。核对目录对应的官方客户端和用途；这些目录是外部交接位置，不随本程序数据根目录迁移、备份或清理。

程序只读取所需的官方配置，不要求提取或保存 PIN。交接后检查发送、接收和失败目录及回执状态；“已生成文件”或“已交接”不能解释为海关已经受理或业务已经放行。

发现失败回执时按具体错误修正数据并保留批次关联，避免随意移动、覆盖或删除官方目录中的文件。未提供的能力按明确“不支持”处理，不假定所有申报业务都已经实现。

## 12 OA：申请、审批与实际办理

Full 中进入“申请与审批”，选择已发布且本人适用的事项。核对单位与申请任职，填写材料，保存草稿，再提交审批。项目业务还需选择当前任职有资格参与的项目。

已保存草稿从列表的“编辑 / 提交”继续处理；待审批和待办理卡片有独立入口。从未提交的普通 OA 草稿可由原申请身份在详情删除，附件一并移除；已有审批历史的申请保留。默认流程在部门负责人本人申请时跳过允许回避的部门节点，转公司领导审批，并记录原因。

审批人从自己的待审批入口进入，阅读获准材料、填写意见并执行当前节点动作。审批通过后，若存在财务接收、采购验收、行政执行等办理节点，实际责任人仍需完成对应操作。

| 阶段 | 操作重点 |
| --- | --- |
| 草稿 | 填全材料、附件、任职和项目 |
| 提交 | 确认当前流程及实际审批路径 |
| 审批 | 当前任务、当前权限、禁止不当自审 |
| 退回 | 按意见修正后重新提交，保留旧轮次 |
| 办理 | 登记现实执行结果，不用审批意见替代 |
| 归档 | 检查状态、历史、审批单和必要材料 |

会议室按预约、交接和归还处理；物品按预留、实际发放和归还处理。已经发生的现实动作不会因取消审批自动消失。审批单 PDF 记录流程事实，不等于电子印章认证或实际付款凭证。

资源申请首次保存后固定申请人、任职和项目，只在草稿阶段允许修改正文或附件。已归还物品属于办结状态，再次借用需新申请。普通 OA 的“退回修改”可按意见续编重提；详情中的提交版本保留原正文、附件和审批单。

## 13 项目职责与账号权限怎样配合

项目限定职责负责“这笔项目业务找谁”，账号权限负责“此人能否执行相应动作”。两者缺一不可，当前流程节点也必须已经分派给本人。

例如张三承担项目 A 的采购审核，李四承担项目 B 的采购审核。两人分别具有采购查看和审批权限；采购流程选择“业务职责”并指定“采购审核”。项目 A 的申请解析到张三，项目 B 的申请解析到李四。普通项目成员身份不会自动授予审批权。

管理员的配置顺序：建立有效人员/任职 → 建立项目及成员/负责人 → 在业务职责中分配任职并选择项目 → 设置账号动作权限和范围 → 在流程节点选职责来源 → 带项目仿真并发布 → 用普通账号实际跑完流程。

“不限定项目”的职责分配可能同时参与多个项目，不会被专属项目分配自动覆盖。若流程选择“项目负责人”，则按项目负责关系找人；直接指定账号的节点按其指定规则执行。

明确项目范围限制用于进一步收紧数据访问，不能代替职责分配。项目职责也不会自动限制发票、客户等全部模块。人员到期、项目停用或权限收紧时，旧任务仍须检查最新资格；先处理交接，保留历史签署。

## 14 账号、备份与维护

管理员通过“账号与权限”建立账号、关联人员，选择独立授权或已发布权限方案。空权限不是默认全权。分别核对资源、动作、范围、模块开关和单位身份；发布权限方案与应用到账号是不同步骤。

个人操作统一从右上角头像／姓名打开账号菜单：修改密码、我的权限来源、退出登录。修改密码须验证原密码并两次输入 8–128 字的新密码，成功后重新登录；桌面初始空密码可留空验证，忘记密码由管理员重置。业务草稿确认及会话清理沿用现有流程。

财务方案的费用报销查看与财务接收均为公司范围，不默认包含审批决定。财务兼任部门负责人时组合部门审批方案，审批范围仍为部门；已有组合方案需要保存、发布并应用修正后的版本。自动办理来源不加入系统管理员，维护接管须明确配置。

单位授权与账号权限共用方案发布机制，单位专用方案仅供本单位身份。模块默认显示全部分类，继承权限按所选发布版本显示。部门层级表格随窗口调整，行末上移、下移图标直接保存同级顺序；并发调整须重新加载后重试。

负责人可选内置“部门审批人员”或“公司审批人员”方案。兼任销售的部门负责人组合“业务人员”（管理部门销售时选“销售主管”）＋“部门审批人员”；综合部负责人组合“行政管理员”＋“人事管理员”＋“部门审批人员”。在权限方案中新建并选择“组合多个职责方案”，核对各动作范围，保存、发布再分配账号。同一动作取较大范围，行政/人事的公司范围审批需要按实际职责逐项收紧。角色和职位名称不自动追加权限；负责人仍须有在职人员、有效任职及明确任务来源。

备份计划按业务频率配置，并定期验证恢复。备份包、密钥和异机副本应按制度保管。PostgreSQL 的数据库 dump 不等于包含全部附件、模板和主密钥的完整迁移包。

恢复只接受当前数据库基线且模型一致的备份。服务器恢复需要停机并使用独立维护账号；按正式恢复指南执行，失败时保留待恢复标记和安全副本。不要直接覆盖运行中的数据库。

试运行版本提示数据库模型不一致时，先保留原数据和备份，再显式选择新数据目录或新数据库。相同 schema 版本号不代表不同试运行模型可以互相覆盖。

“文件与存储”用于容量、完整性和受管存储检查。不要手工移动对象文件或清空缓存以外的业务目录。官方单一窗口交接目录、用户备份和历史材料应单独保护。

空间清理先盘点来源，确认程序退出，只删除已结束的隔离测试包、测试库、截图和日志。保留当前实际程序、业务数据库、模板、OCR 资源及可复用依赖缓存。永久清理发票等业务维护操作必须按界面范围和确认要求执行。

## 15 常见问题与每日检查

| 情况 | 建议处理 |
| --- | --- |
| 找不到页面或按钮 | 核对产品版、模块、当前身份、动作权限和记录状态 |
| 保存失败/字段错误 | 按提示展开分区，修正必填、格式及数值范围 |
| 无可用审批人 | 核对流程来源、项目、有效任职、职责期间和账号权限 |
| 版本冲突 | 保留输入，读取最新记录，再决定修改 |
| 繁忙或请求排队 | 稍后重试，并先核对操作是否已有结果 |
| 依赖不可用或超时 | 保留错误时间与任务编号，检查资源和服务状态 |
| PDF 空白、缺页或乱码 | 核对模板、字体、附件及实际输出，停止流转错误文件 |
| 下载/发送后不确定结果 | 查看文件任务、投递记录和最终文件，避免重复动作 |

每天结束前检查：未保存草稿、待审批/待办理事项、失败文件任务、未确认投递和备份结果。人员或流程变化后，再检查在途任务与授权范围。

求助时提供程序版本、操作时间、当前单位/身份、记录或任务编号、复现步骤和完整错误文字。截图遮盖无关私密信息；不要提交密码、令牌、PIN、主密钥或整份业务数据库。

手册正文与 PDF 同步维护。遇到界面差异时先确认使用的是当前程序与对应产品版，再由管理员依据实际配置和验收记录处理。
