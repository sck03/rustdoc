# 2026-11-25 稳定性、资源与契约收敛

本批承接六项审查结论。用户授权一次性实现、修正文档、仅做必要验证、清理已失效的测试输出并以普通快进交付 GitHub main；不维护旧软件或旧数据库兼容链。

## 实现

1. 下载：首次无 Cookie 的并发签发在同一个有界票据锁内复用认证会话的现存随机绑定，避免最后一个 Set-Cookie 使其他票据失效。不同会话继续隔离；Cookie 的 HttpOnly／SameSite／Secure、操作绑定、有效期和退出撤销保留，没有新增长期缓存。
2. 时间：前端共享解析器检查偏移切换两侧，拒绝新输入的重复／跳过时段，覆盖半小时夏令时与跨日跳时；使用完整年份构造消除 0–99 年偏移。公告、加班、CRM 跟进及代理编辑传入原始时间，字段没变时原样保留秒、亚秒及明确时区，避免只改正文也改变时间点。
3. 自然日：Rust 时钟和按日范围使用首个有效时间点，跳过整日得到空范围；会议室 React 日期查询采用相同规则。预约输入保持严格，不将“日期边界顺延”混入用户预约校验。
4. PDF：上传输入在 HTTP 请求预算释放前转存受管匿名文件，使用既有磁盘空间预算；后台任务持有文件句柄，受控进程共用流式输入和取消／超时／进程树清理。删除父进程完整协议拼接缓冲，合并获取既有重型渲染许可，保留文件数、输入／输出容量和发布前权限复核。临时文件随所有权释放，没有新增持久化目录或另一套进程管理器。
5. OA：从原生定义删除请假、加班、付款报销、出差、采购和通用申请六个重复 `/complete` 端点，生成 OpenAPI、Rust 元数据与 React 客户端，唯一办理入口为 `/fulfillment`。删去前端不可达的旧完成动作和服务分派别名；`complete` 仍是有效业务权限／历史动作，审批版本、办理节点及审计数据继续保留。
6. 弹窗：独立 `confirmationContext.ts` 管理类型、上下文与 hook，Provider 负责显示和结算；消费方直接依赖上下文，移除 Dialog → 草稿保护 → Provider → Dialog 的运行时依赖环。Provider 卸载时以取消结束未决确认；界面布局、设计令牌、可访问名称和操作文案继续沿用共享组件。

没有更改 SQL、schema 18 指纹、第三方依赖、正式发布形态或权限模型。没有把健康探针、历史流程与审计夹具当成无效代码删除。

## 实际验证

- Contracts：冻结契约差异测试通过，明确只删除六个重复路由，其余 schema、认证、错误、权限等元数据继续对照；生成器 `--check` 确认 **757 operations、713 schemas** 同步。
- Rust：时钟 3 项、PDF 输入协议 2 项、受控进程 5 项、下载票据 3 项、HTTP 文件 3 项、通信与重启持久化 2 项通过。受控进程回归覆盖 4 MiB 分块输入、输出限额、管道阻塞取消及超时。
- 时间／业务模型：`test_business_time_model.mjs`、`test_office_model.mjs` 通过，覆盖纽约／柏林重复时段、Lord Howe 半小时回拨、Santiago 跳过零点、Apia 跳过日期、Havana 重复零点、无效日期、0099 年和未修改字段的精度保留。
- React：Web TypeScript 与 Vite 构建通过；编辑恢复真实浏览器 5 场景通过；实际 HTTP／React 审批权限专项通过，确认审批不授予办理权限；API 客户端取消／超时／上传合同通过。
- PDF 实际联调：新建隔离 SQLite DataRoot，使用本批 locked build 的 `office_review` 与已验证 PDFium，对两份匿名 PDF 经真实 HTTP 上传、任务执行、票据下载后重新打开，结果为 4 页；两次无 Cookie 的并发票据使用最后响应的同一 Cookie 均可下载。样本总输入 65,024 字节，输出 65,042 字节，只证明流程及内容可读，不是性能基准。
- 前端运行时静态依赖扫描覆盖 792 个 TS／TSX 模块，没有发现循环依赖。`cargo fmt --all --check`、源码规模、测试登记、公开源码及 `git diff --check` 通过。

按用户要求未运行全工作区测试／全 features 检查、PostgreSQL 实库、完整 Tauri 界面、跨平台矩阵、安装升级或长时负载测试。不声称整项目无 BUG；PDF 内存优化结论来自消除明确的缓冲副本及输入所有权变更，未测量 RSS 降幅。

源码规模记录本批实际前端生产 89,453 行、原生生产 118,317 行，原生统计包含同文件并发、时钟及协议回归；移除重复偏移算法和失效路由后，仅推进这两个合计基线，所有单文件上限及原有 200／75 行后续增长余量保持不变。新增时间模型测试已进入现有业务日期测试入口与测试登记检查。
