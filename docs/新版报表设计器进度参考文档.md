# 可视化模板设计器

> 2026-09-25。本文件名保留以维持入口，内容只描述当前 React + Rust 设计器。票面验收见[PDF 方案](./Rust统一V3模板与原版PDF验收方案.md)。

## 编辑与输出

报表管理在 `#/reports/templates/manage`，设计在 `#/reports/templates`。文件、个人及共享模板共用目录选择；设计器负责画布、预览与保存。六类内置模板都可以打开，修改内置内容创建 DataRoot 下的副本。

唯一文件格式为 `.dtpl`，内部 schema 版本 3；界面不把版本号当作产品名称。API 传递可编辑 JSON，磁盘容器带长度及 SHA-256 校验。没有高级 HTML、V2 转换或任意脚本/CSS 入口。

页面固定为 A4 横/竖版，内部坐标为 1/100 mm。Header、Body、Footer、Overlay 图层共享文字、字段、图片、线条、矩形和页码组件；Flow 支持普通行、固定网格、条件、循环明细及分页符。前端维护编辑结构，Rust 负责正式测量、分页和 SVG/PDF 输出。

## 表格与分页

常规设计使用独立商品字段：左侧分为“普通字段”和“商品明细字段”，把中文字段名称拖到纸上，各字段分别移动或缩放，键盘微调、吸附和撤销照常生效。画布只显示一件商品的设计行，上下虚线表示重复范围；正式输出按相同列位逐件重复。选中商品字段可直接修改位置、大小、字号、对齐和最小行距，标签、颜色/边框、旋转和输出等低频设置折叠。长内容撑高后，同列下方字段顺延，底部对齐字段保留设计时的相对偏移。发票号、唛头等普通字段不加入商品循环。

字段、文本及页码的字体可直接选择三份随包字面：Noto Sans CJK SC 常规/粗体、Noto Serif CJK SC 常规。它们是两个家族、三份文件；选择粗体明确使用已有 Sans Bold，不引入系统字体或不存在的 Serif Bold。字体、字号和位置进入同一份模板，保存回读及撤销保留选择。

点击商品字段列表中的已有字段直接定位选中；新增字段自动寻找商品行内空位，不再堆叠到纸张右边。**自动排位只决定初始位置，不会锁定字段**：添加后仍可手动拖动、缩放、方向键微调并撤销。空间不足时保留草稿并提示调整或直接拖放。箱数、数量、金额列移动后，可点“合计与明细同列对齐”，一次调整对应合计的对齐边，并可一步撤销；不会建立永久位置绑定，合计仍是普通字段，可单独编辑。日常操作无需配置组合片段或输入坐标。

默认发票已经使用独立的货名、PO、款号、箱数/单位、数量/单位、单价和金额字段，表头与表格线另行编辑。TOTAL、总箱数、总数量和总金额同一行，合计与对应明细同列，放在跟随正文的末页合计图层。币种为普通字段，显示在金额列上方。其他内置模板及既有用户高级组合模板保持原结构，不自动转换或删掉原排版；使用新版默认发票后另存副本即可采用独立字段。

多列行、普通表格、条件、分组明细表和分页符统一放在默认收起的“高级排版”。常用发票无需先插入整块明细表；高级组件继续承担已有模板的组合、合并和分组需求。同一模板不能同时放自由商品字段和高级循环表。

高级明细表按“商品列／打印样式／高级设置”组织。一次只编辑选中的一列，组合字段可按中文名称勾选；跨列表头、组合片段和列边框默认收起，分组、小计、合计和首页说明在高级设置中。切换页签保留本次展开状态和草稿。

- 普通网格可增删行列、合并拆分、设置列宽/行高、四边、虚线、斜线表头、竖排文字、标签位置和勾选。
- 自动明细表支持表头、组合内容、分组和汇总、唛头旁栏、首页/续页最大行数。
- “商品之间显示横线”独立控制正文行分隔，表头、外框和合计边界保留。正文垂直对齐同时作用于单元格和分栏片段；默认发票金额与单价同一基线，装箱单箱数、数量、毛净重和体积下移到描述末行。
- 组合内容可逐段隐藏；ColumnBreak 使用递增百分比划分独立区域，长款号不能挤压箱数、数量或单价。空 PO/款号行可收起。
- 页眉/页脚可重复、仅首页、只在末页或跟随正文；页脚占位与实际输出页保持一致。内容放不下时明确提示，不静默覆盖邻格。
- 发票和装箱单每页重复抬头/表头，唛头仅首页，总计仅末页；合同续页从明细表头开始，末页接条款签字；报关单首页 6 项及申报区，续页最多 15 项并连续编号。

图层选中、锁定和隐藏会约束插入、拖动、缩放、复制、对齐和粘贴。工具不能把当前锁定图层的插入操作偷偷转移到另一层。普通坐标/样式修改和撤销使用同一状态模型，草稿比较只在文档变更时重新计算。

## 草稿与多用户

草稿与撤销历史仅在页面内存。预览往返保留编辑实例；远端刷新、读取失败、保存冲突或校验失败均保留本地草稿。保存中暂停编辑，图片上传中禁止提交，离开前按脏状态确认。

数据库模板的保存、发布、共享、停用、归档和恢复是独立命令，使用 ExpectedVersion。只读共享模板先复制为个人草稿再编辑。模板查看权限、源业务域和分享受众都必须满足；知道模板/图片 ID 不能越权读取。

文件模板变更使用 revision 和共同存储锁，显示名称与物理文件名分别维护。模板包传递可移植的文件默认引用，数据库模板编号不跨库导出。导入失败回滚本次文件和清单，不覆盖无关设置。

图片为受控 PNG/JPEG，上传归属和内容保存在业务库中，按摘要去重。用户、数据库模板与历史、文件模板的有效引用共同决定读取和回收；仍被引用的图片不可回收，付款图片不能通过出口模板权限绕过业务域校验。

## 维护入口与验收

- 模板源：`scripts/lib/default-report-designs.mjs`；生成：`scripts/generate_default_dtpl_templates.mjs`。
- 前端：`features/report-designer`、`features/reports`；DOM/CSS 只负责交互和设计预览。
- 领域：`export-doc-domain::{designer,template}`；渲染：`export-doc-report`。
- 用例：`engine::{report_templates,report_template_files,report_assets,reports}`。

验证必须覆盖编辑后保存回读、409 草稿保留、跨用户授权、图片回收、模板包默认项、单页和多页实际 PDF。Windows 原生输入法、其它 OS/架构及打印机需要单独运行证据。未测项目保持待验，不把旧 .NET 或浏览器 HTML 结果算作 Rust PDF 通过。
