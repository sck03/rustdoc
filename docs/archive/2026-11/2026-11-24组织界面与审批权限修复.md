# 2026-11-24 组织界面与审批权限修复

从 74e56849 的干净 main 开始，按用户截图和兼任权限补充要求实施。用户明确要求必要回归，不执行整轮工作区/桌面门禁。

## 修改

- 账号管理说明缩短，操作栏保留完整宽度；部门表格去掉固定最大宽度，按容器伸缩，五个操作按钮按实际宽度计算。部门及商品明细“操作”表头居中。
- 同级排序改为行末直接上移/下移，首末行禁用对应方向；搜索、收起仍使用完整同级集合。独立 hook 复用当前客户端/单位的作用域命令、取消、刷新与错误，原有 ID/版本事务和并发保护不变。删除排序弹窗。
- 部门节点条件摘要、配置及图示共用本人回避展示模型，显示负责人本人跳过，或独立/必经复核阻断。实际有效人员解析、后续独立领导校验及冻结分流原因继续由既有 Domain/Engine 承担，没有添加可绕过权限的通用条件。
- 唯一原生权限目录增加部门/公司审批人员两种初始方案，保留原有八种职责；OA 查看/审批分别采用部门/公司范围，自助申请仍限本人，不包含私密人事维护、实际办理或系统管理。管理员成功登录同事务补齐缺项，不改写已有草稿、发布版本或账号绑定。
- 新建预置方案复制服务端配置，删除前端重复审批预置构造器。组合职责独立保存，按资源/动作采用较大范围；业务部组合销售与部门审批，综合部组合行政、人事与部门审批。界面帮助及手册明确核对原有公司审批范围。
- 发布解析错误保留具体身份拒绝原因；没有候选身份时指明责任人、单位、申请资源与动作。岗位和角色不自动追加授权，平台维护账号不能签署普通业务。

保持 Tauri 2 + React 19 + Rust 分层，SQL、数据库 schema 18、依赖及锁文件不变。权限元数据和两端契约从原生定义生成，独立冻结契约比较明确声明两种新增方案，保留原八种方案及其余认证、错误、权限和容量验证。
