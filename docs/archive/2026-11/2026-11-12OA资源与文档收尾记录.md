## 修复与职责调整

- 自定义 OA 的适用部门改为搜索、分页与多选，避免逗号输入被即时解析吞掉。保存稳定编号；草稿中的人员/部门显示名称与原始编号配对，明细行移动后不会串用旧位置的名称。
- 流程管理拆出定义列表、计划发布面板、纯表单模型和事项创建模型；展开拥挤单行代码，分清展示、状态和操作。仿真窗口将规则及发布意图保存在同一个状态对象中。
- OA、公告、通知及办公查询复用轮询策略：正常 30 秒，后台页不轮询，永久错误停止，临时失败有界退避至 5 分钟。已批准但尚待办理继续更新；包括财务已接收在内的终态停止详情轮询。异常队列提供显式重试。
- PostgreSQL 维护页面拆出命令 hook，维护与装柜命令共用作用域保存边界，不在 MutationCache 中保留密码、File 或大结果。离开/切换身份后拒绝迟到结果和后续上传；成功清理敏感草稿，后台目录刷新不延长写锁。
- 装柜保存和删除共用类型化命令；保存保留续编、版本和新建后的编号转换。重新加载同一方案也会取消旧保存的刷新反馈，避免迟到错误覆盖新结果。
- 数据写入及任务发布使用同一个通知等待锁，替代 5/10 毫秒轮询。保留取消、期限、poison 和发布故障锁定；写者等待期间阻止新读者持续抢占。内置办理节点直接构造 `ApprovalStage`，流程修订种类不再 JSON 往返。

源码行数增加主要来自展开原来压缩的 OA JSX、职责拆分及回归。体积门禁按起点的真实净变化更新：Web +2147、Rust 生产 +188、工程脚本 +204、工作流 +17 行；工作流属于工程脚本统计子集。保留原单文件上限、增长余量和已占用余量，没有压回单行来通过门禁。

## GitHub 计划与 GLib

Cargo、npm 和 GitHub Actions 普通 Dependabot 更新改为每月，上海时间 02:00。完整依赖治理在每周一 10:23（上海时间）、相关改动和手动运行时执行，其余日期 10:23 保留漏洞审计。每日作业不安装前端依赖或重建全部 SBOM；锁文件审计覆盖 Web 与 Tauri，Cargo 源码与审计工具复用缓存。

GLib 0.18.5 仍由 Tauri 的 GTK3 依赖链约束，不能直接把锁文件改到修复版本。普通更新的 monthly 设置不控制 GitHub 动态安全更新任务；其重复失败并不表示本次计划未生效。保留有条件核验的 RUSTSEC-2024-0429 单项例外，未将漏洞标记为已修复，未关闭安全告警。

工作流通过 Actionlint 与 59 项 Action 引用治理。Actionlint 发现并修正了星期范围使用 7 的错误，最终使用 GitHub 接受的星期日 0。
