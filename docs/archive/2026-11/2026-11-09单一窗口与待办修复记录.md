# 2026-11-09 单一窗口与待办修复记录

## 实现范围

本批修复此前核实的六类问题；继续采用 schema 14，不维护旧库/API 兼容链，没有升级依赖或新增持久化缓存。

| 问题 | 修复与职责 |
| --- | --- |
| 代理委托、原产地证保存覆盖续编；工具与字段锁定缺少统一作用域 | 两页共用 `useSingleWindowDocumentWorkspace`，复用作用域保存锁和字段合并；保存立即推进基线/版本，后续读取失败不回退。切换单据、客户端、权限和卸载取消旧请求。附件选择与企业资料操作检查同一业务作用域。 |
| 目录、生产企业、装柜方案/柜型并发覆盖 | 原生契约生成修订号及预期版本；Storage 对设置执行原子 CAS；更新/删除核对客户端读取时版本。同名柜型创建返回冲突，不转成更新。前端保留编辑版本，后台刷新不提升旧草稿版本。 |
| 待办使用读取前的旧身份 | 在授权只读快照内重新读取当前账号及权限，撤权回归必须拒绝。 |
| 待办全量物化、重复 COUNT/OFFSET、逐客户补查 | Storage 先筛选活动候选、权限和字段，按物理 ID 连续扫描；客户可见性及名称在同次查询取得。Engine 逐条计算业务条件，按来源用堆保留所需页前缀。删除无调用的旧 OFFSET 查询边界。 |
| 参考目录 GET 占写事务，企业目录全量排序 | GET 使用授权只读快照；企业搜索、更新时间排序、计数和分页由 Storage 执行，前端默认每页 50 条并修正越界页码。 |
| Excel 目录预览跨类别迟到回写、变更缓存保留大结果 | 复用 `useTransientPreview`，类别、文件、映射、参数及权限变化使旧结果失效；预览不进入 mutation cache。 |

Contracts 仍是唯一 API 定义来源，冻结契约通过显式差异测试核对；生成操作数仍为 749，schema 数仍为 685。目录 JSON 导入与重置要求 `expectedRevision`；企业和装柜删除要求 `expectedVersion`。创建与更新共用请求模型时，更新在 Engine 强制校验版本。

“新文件会沿用上一文件映射”的推测没有得到复现，不将其列为已确认缺陷。

全量回归另发现内置监管方式 5000/5100/5200/5300 把共同用途说明“用于区内外非实际进出境货物”同时列为别名，使默认目录原样保存/重置失败，并可能按首条错误解析。保留四条说明与各自名称，移除四个歧义别名；Domain 回归验证完整内置目录合法、名称分别解析正确且共同说明不映射代码，不放宽别名唯一性规则。

## 性能与验收边界

待办取消了全量完整 DTO 列表、逐批计数和递增 OFFSET；每批最多读取 200 个普通候选或 100 个 OA 候选。精确的跨来源计数和审批规则仍需扫描当前授权活动候选；每个选中来源最多保留 `pageNumber × pageSize` 条，深页内存随页码增长。这是结构性改进，没有据此承诺延迟百分比、恒定内存或全部 SQL 聚合。

本批没有重新验收 Linux/macOS/ARM64、Firefox/WebKit、Docker 部署或正式 OCR 发布包；它们继续沿用独立 runner/设备验收边界。
