# 提交与查询一致性（2026-11-18）

## 行为与资源边界

- 返回 JSON 的写请求在执行业务前预留 64 MiB 响应额度，编码后按实际缓冲容量释放多余额度。128 MiB 实例预算可同时容纳两个满额预留。文件下载单独计数。客户端断线后仍需核对业务结果，该预算只覆盖响应缓冲。
- 商机预计金额在编辑、保存、历史和看板汇总中使用十进制文本，Rust 使用 Decimal 运算。查询契约、页面路由与导航同时要求商机和产品查看权限，事务继续校验客户与商机的数据范围。
- 看板从业务自然日起取 30 天。SQLite 与 PostgreSQL 都在排序和截取前按同一半开区间过滤。
- HS 只读用户可搜索联网数据，也可查看候选池。管理者可采集、确认和忽略候选。单条操作和多选操作共用批量审核接口。忽略跳过税则查询，确认只核验批次中不同的待确认编码。
- `/livez` 和 `/readyz` 均按 GET、HEAD 分别生成操作、路由和客户端。同步生成的权威契约共 759 个操作、711 个 schema。

## 本批验收

- HTTP 实例耗尽响应额度后，新增客户返回 429，数据库仍为零条。释放额度后重试返回 201，数据库恰有一条。慢客户端断线后释放缓冲，文件下载名额可用。
- Windows Full + SQLite 桌面 Release 包通过商机专项与完整桌面验收。大金额 `10000000000000.0001` 经界面保存后逐位一致。完整流程包含中文输入、表格编辑、OCR 和实际报表输出。
- 前端生产构建、无障碍契约、198 个缩放场景、84 个视觉场景、19 个商机场景、10 个 HS 场景及导航权限通过。Rust 格式、全功能编译、生成物一致性、生成器的 4 个测试及依赖治理通过。治理覆盖 840 个组件。
- Rust 工作区执行至 doc-test。全量回归的两条失败用例经修正后在 Engine 库及商机集成测试中分别通过。另在隔离 PostgreSQL 18.6 上运行 `Workflows`，实际执行网络取消、约束、存储契约及团队业务流程，验证后正常关闭实例。本轮桌面实机范围为 Windows x64。
