# Rust `.dtpl` 模板与 PDF 验收

> 2026-10-15。当前职责以[架构事实](./当前架构事实.md)为准，编辑操作见[设计器说明](./新版报表设计器进度参考文档.md)，每批实际结果见[实施进度](./程序改进重构进度文档.md)。

## 一套文档与输出链路

六份默认模板由 `scripts/lib/default-report-designs.mjs` 生成 `.dtpl`；Builtin 与用户模板使用同一 V3 文档、Domain 校验和 Rust 排版。模板之间的差异来自字段、坐标、样式及分页设置，不按模板名维护另一套票面。

React 负责画布、字段选择、草稿与撤销；`export-doc-domain` 校验结构、数据域和资源；`export-doc-report` 统一测量、分页及生成 SVG/PDF；Engine 负责授权、版本、数据和任务。预览使用 Rust SVG，krilla 编码正式 PDF，PDFium worker 负责已有 PDF 的页图、提取和合并。设计器中的最终 PDF 页图预览仍待接入。

唯一文件格式为 `.dtpl`，容器保存长度与 SHA-256，内部文档版本为 3。API 沿用 `contentHtml` 等契约字段名传递结构化 JSON。旧 HTML、V2、裸 JSON 文件、损坏容器和未知扩展名在导入边界拒绝。

数据源按用户要求保持单证与付款报销两个授权域。通用纸张、图层、网格和字段组合用于设计不同版式，业务授权和字段上下文继续校验；没有新增外部数据库连接或脚本解释器。

## 六类票面的验收重点

| 票面 | 组合结构 | 输出核对 |
| --- | --- | --- |
| 发票 | 普通表头、商品明细表、可选金额调整、末页合计与条件条款 | 与装箱单共用组件；多个正负调整行及换行说明、调整后 TOTAL、空调整不占位、长内容分页、签章与金额列对齐 |
| 装箱单 | 组合明细列、唛头侧栏、合计与跟随正文的签章 | 箱数/数量/重量/体积与单位，长款号换行，外框延伸，末页合计及签章随实际内容定位 |
| 合同 | 明细表、交货/付款/签字网格 | 默认不含特殊条款；续页从明细表头开始，末页接付款条件与签字，印章保持独立区域 |
| 报关单 | 横版合并票头、组合明细、首页申报区 | 首页最多 6 项、续页最多 15 项，同时受实际高度限制；编号连续，声明和报关章仅按设置输出 |
| 付款单 | 合并网格、竖排、勾选、大小写金额及签字 | 银行信息无内部横线，付款方式和备注分隔正确，空字段与长字段保持明确行为 |
| 费用报销单 | 斜线表头、八项费用、附件/备注、大小写金额及签字 | 各费用列和合计精确；2026-10-12 按用户要求取消“报销净额”与“小计”之间的竖线 |

新建与默认模板为 A4，另支持 A3、A5、Letter、Legal 和 40–600 mm 自定义纸张。实际 PDF 使用文档中的宽高、方向和坐标。页边距、图层占位、组件高度和文本测量共同影响分页，不能把某个样本的页数当成所有数据的固定页数。

## 从空白设计与保存回读

六份默认模板所需的基础组件、字段、图层和打印设置由公共编辑模型提供。普通网格可直接设置行列、用矩形选区合并/拆分、批量设置文字与框线，并保持字段和未修改属性。合并存在多份内容时保留原稿并提示，避免设计过程中丢失内容。

验收分别记录以下证据：

1. 从空白通过公共编辑模型插入组件，配置图层、坐标、网格和打印属性，核对完整文档及堆叠顺序。
2. 在真实 React/Tauri 界面完成选区、字段、中文录入、撤销、保存、重开及草稿预览，核对服务端回读内容。
3. 使用相同匿名数据比较原始默认文档与重建文档的 Rust 预览，再生成并渲染实际 PDF。

2026-10-15 重新执行六类空白重建、普通/72 行长明细输出对照及 Windows Tauri 空白设计。最终十份重建 PDF 共 28 页，与本轮修改前同数据结果逐页比较，长发票/装箱单/合同/报关单仍为 7/6/3/6 页。发票、常规装箱单、报关单、付款单、报销单的渲染一致；合同及长装箱单末页去掉合计行多出的空白，后续内容或外框略上移，未丢失商品、合计或签章。三个商业模板的 `TOTAL:` 均保持左对齐，数值沿用各列对齐。另检查十份桌面 PDF，包括带贸易条款、调整款和印章的默认票面，以及空白明细、网格和自定义纸张。具体路径与结果见实施进度；模型重建和局部界面流程不写成六张票面均已逐格人工重绘。

六份默认模板没有配置跨列表头。通用跨列表头、说明/合计/小计合并、空分组与分组标题分页通过 Rust 回归；默认发票的首页说明跨四个商品列，实际 PDF 使用同一合并和边框规则。模板内容保持原 V3 文档，新增行为不依赖票面名称。

## 字体与视觉检查

报表使用 [font-manifest.json](../Resources/Fonts/OpenSource/font-manifest.json) 中的三份随包字体：Noto Sans CJK SC Regular/Bold、Noto Serif CJK SC Regular。均为 SIL OFL 1.1，许可原文随包保留；需要加粗时使用已有 Sans Bold。字体缺失明确失败，不依赖宿主安装字体或引入未声明字面。

核对纸张尺寸/方向、边框锚点、列宽/行高、换行、对齐、唛头、签章、日期、精确金额和单位。预览与 PDF 共用排版及字形资源；字体栅格化的小差异与数据、位置和分页错误分别评估。

正式 PDF 需用独立阅读/渲染工具逐页检查，并查看重点页原尺寸。文本提取和页数检查不能替代视觉核对；画布截图也不能单独证明 PDF 已正确输出。

## 后续验收边界

- 按模板覆盖空值、单行、分页临界行数、长中文/英文、混合单位及多页末段；新增样式或分页能力时补充对应场景。
- 保存冲突、权限不足、资源缺失、取消和输出失败保留草稿及错误，不发布半成品。文件、私人/共享模板、批量输出与邮件附件继续共用正式结果。
- 客户真实数据签字、实体打印、系统中文输入法、其它 OS/架构与 GPU/打印驱动分别记录；本机 Windows GNU 测试不替代 MSVC 或跨平台交付验收。
