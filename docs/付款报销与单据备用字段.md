# 付款报销与单据备用字段

付款报销与发票分别保存内容。“发票号／业务参考号”用于人工核对，不会自动带入或修改报关明细；同一中文品名、不同成分的报关行可在付款中合计填写。

## 付款填写

新建与编辑共用“基本信息、业务与备用字段、金额与费用、预览与导出”四个页签。基本信息填写付款单号、参考号、付款／收汇日期及收付款单位和银行账号；业务页填写部门、项目、贸易方式、退税率、货物品名、数量、单位、出运国家、出运日期及备注。数量和退税率保留自由文本，允许按票面填写附加说明或“其他”，不参与报关数量及税额计算。费用合计自动汇入 CNY 金额，预览首次进入时加载；切换页签保留草稿，可在任意页签保存或使用 Ctrl／Command+S。

付款方式保留“支票、电汇、预付”。点击旁边的“新增选项”，填写名称并“添加并选择”，之后的单据也能直接选用；重复名称会选择已有项。添加失败时保留输入并显示错误，当前付款草稿不受影响。只读账号不能添加选项。收汇日期在表单、服务端校验和报表设计器中使用同一名称，现有字段绑定仍为 `Payment.ReceiptDate`。

| 工厂付款单票面 | 表单／设计器字段 |
| --- | --- |
| NO. | 付款单号 |
| 业务部门／名称 | 部门 |
| 出口发票号 | 发票号／业务参考号 |
| 货物名称及数量 | 货物品名、数量、数量单位 |
| 出运国别、收汇日期 | 出运国家、收汇日期 |
| 贸易方式、退税率 | 同名字段，可作为表格勾选条件 |
| 收款单位、开户行及账号 | 收款方、银行、账号 |
| 小写金额／人民币大写 | CNY 金额／金额换算中的人民币大写 |
| 其它票面内容 | 付款备用字段 |

## 备用字段与模板

- 发票基础信息中展开“发票备用字段”，填写表头补充内容。
- 商品明细的“备用 1—10”分别随每行保存，用于款式、包装或客户要求等附加内容。
- 付款业务信息中展开“付款备用字段”，填写本次付款的附加内容。
- 每类固定十项，每项最多 500 字；未填写时输出为空，三类字段不相互同步。
- 管理员在“系统设置 → 运行与数据库 → 单据字段名称”分别配置三类名称，例如将发票“备用 1”命名为“船名航次”、商品“备用 10”命名为“客户货号”。每个名称最多 40 字，同组不能重复，留空恢复“备用 N”；保存后连接本服务的账号和各端共用，重新进入或刷新页面读取。普通账号可读取名称，不能修改设置。
- 编辑器、商品列标题与显示列菜单、设计器字段目录使用统一名称。固定数据键仍为 `Invoice.SpareN`、`item.SpareN`、`Payment.SpareN`，名称变化不改写单据内容或模板表达式。
- 在可视化设计器的“单据备用字段”“明细备用列”“付款备用字段”分组中按新名称查找和选择。单据字段可填入普通表格，明细备用列用于循环明细表；已有模板的文字标题仍由设计器编辑，不因系统改名自动重排。

建议同一套模板为备用编号约定稳定用途。备用文本不代替金额计算、审批状态或公司／部门授权归属。

系统设置与报表导出默认设置都校验保存版本。旧页面不会覆盖其他管理员的新设置；冲突后可取消重新加载以保留草稿，或确认加载最新版本再编辑。读取失败继续保留草稿，不把缓存内容当作刷新成功。

十个明细备用列在没有内容时默认隐藏。管理员可在“系统设置 → 运行与数据库 → 发票录入默认值”选择默认显示前 0—10 列，保存后用于当前运行环境的新建和编辑发票。已有内容的备用列自动显示，清空最后一个值时会保留该列以便继续编辑。明细表的“显示列”可临时勾选任意列，也可“恢复默认”或“全部显示”；这些操作只改变视图，不删除备用数据或改变报表输出。

## 发票录入分区

新建与编辑共用“基本信息、商品明细、运输与报关、利润与信用证、预览与导出”五个页签。先填发票号并选择客户／出口商，再录入明细；地址、通知人、银行、印章和报关补充字段按需展开。汇率与币种放在一起，金额和商品数在保存栏汇总。

切换页签保留草稿及已打开工具的状态；预览在首次进入时加载。可在任意页签保存，缺少必填内容时自动返回对应页签并聚焦字段。左右方向键、Home／End 可切换页签，Ctrl／Command+S 保存；明细工作台关闭后回到商品明细。界面规划参考 [Odoo 19 客户发票说明](https://www.odoo.com/documentation/19.0/applications/finance/accounting/customer_invoices.html) 中的明细／其他信息分区、档案自动填入和草稿流程，并保留本项目的单证与报关业务边界。

## 数据基线

正式空库基线为 v19。按本项目尚未投产的规则，不为旧开发库增加兼容迁移；需要保留的数据应先备份，验证新版本时使用独立空数据目录。开发和验收不会自动删除已有业务库。
