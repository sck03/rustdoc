# 2026-11-09 客户端目录检测与回执核查

## 实现范围

官方客户端“目录/任务管理”允许分别修改发送、已发送、回执和失败目录。原实现只保存共同根目录并拼接固定子目录，无法覆盖该配置。现在 COO/ACD 各保存四个绝对路径，API 使用 `customsCooDirectories` / `agentConsignmentDirectories`，对象字段为 `outBox`、`sentBox`、`inBox`、`failBox`；回执收集结果改为 `receiptDirectories` 数组。旧字段删除，不保留双轨兼容。

Windows Tauri 只读当前用户的官方客户端配置，提取 ACD、COOIMP 任务，协议模块负责受限 XML 解析；UI 自动填入新档案的空目录，可重新检测或逐个手工输入/选择。读取失败不阻断手动配置。不会修改官方客户端配置，不提取或返回卡 PIN、加密设置和通知凭据；损坏、重复任务、DTD、超限输入拒绝解析。

操作入口为单一窗口“操作中心”的“公司与操作卡档案”。首次新建自动填入目录，填写公司与操作卡后保存；官方客户端改过目录时点击“重新检测目录”，也可以逐项输入或点击文件夹按钮重新选择。保存已有非当前档案后保持原编辑对象，“切换为当前操作卡”单独控制启用，避免误切换。

已启用业务的四个目录必须存在；保存、派发和收集分别验证路径，拒绝根目录、相对/跳转路径、链接和业务/用途重叠。派发直接使用 OutBox，收集递归读取 InBox、FailBox（含日期子目录）。多个卡档案可以共用官方任务目录，仍须切换到批次绑定的当前档案。

官方外部目录是用户本次明确授权的集成例外，数据库/日志/缓存仍遵守 DataRoot 规则。外部客户端文件不随 DataRoot 备份、迁移或清理。持久化档案模型变化后使用全新 schema 16，SQLite 与 PostgreSQL 同步；旧库/旧备份拒绝使用并保留原件。提交/回执包仍为 schema 5.0。

## 真实客户端与业务回执

本机联调客户端 1.0.0.178 配置 ACD 为 `F:\ImpPath\Acd` 下的四目录、COOIMP 为 `F:\ImpPath\Cooimp` 下的四目录；PCOOIMP 为另一任务，不作为 COOIMP 路径。配置已启用 `StpReceipt2File=true`，连接目标属于 apptest / rmqssltest 测试环境。

复核日志最近 3000 行：119 次 ReceiveAsync、0 条 ERROR、0 条 Exception、0 条“连接失败”。两项业务的 InBox/FailBox 均无 XML。前批七份匿名样例有“已经发送成功”及 SentBox 归档证据，详见[前批记录](./2026-11-09独立申报与联调记录.md)。日志统计不记录原始认证内容。

因此，不能确认“测试客户端不支持接收回执”。当前证据只说明发送与接收轮询存在，尚无官方业务处理结果。需结合测试平台是否开通对应业务、测试卡/企业身份与路由、测试数据有效性以及服务端处理日志排查。匿名企业编号和暂存样例不足以证明正式业务受理或签发；模拟回执解析测试也不能代替官方回执验收。

本批真实项目于 12:58 向检测出的 ACD OutBox 派发一份匿名 XML，目录检测、手工改选及保存均通过。等待 90 秒未归档后确认官方客户端进程当时已退出，报文仍完整在 OutBox；随后启动客户端并读取其界面。当前 Windows 自动化的截图接口返回 `0x80004002`，控件点击返回 `coordinate input geometry is unavailable`，键盘尝试未能进入导入控制，已请用户手动启动导入和接收。该次外部发送尚未确认，不能据此判定报文错误或测试平台不支持回执；也没有重复派发同一批次。
