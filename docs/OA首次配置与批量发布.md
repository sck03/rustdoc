# OA 首次配置与批量发布

更新日期：2026-11-27。本页对应 schema 19 的现行操作；验证范围及 Git 交付见[本批记录](./archive/2026-11/2026-11-27通用申请与存储灾备重构.md)。

## 首次启用

进入“流程管理”，首次没有已发布流程时展开“首次启用流程”。按页面入口依次核对组织负责人/职责、人员任职与关联账号、办理事项、审批节点。已有组织、人事和权限模块继续作为唯一来源。

1. 在组织架构中指定负责人、有效职责；在人员档案中核对有效任职及关联账号。审批权限与实际办理权限分别授予。
2. 在“办理分工”添加事项，选择中文类别、名称和 1–10 位办理人员。目录支持搜索、类别/状态筛选、分页；逐项保存，不再整体提交 100 项设置数组。更换人员会交接未完成的办理义务，记录与历史名称保留。已有业务引用的事项只能停用，不能删除或换类别。
3. 在流程定义中核对审批节点并保存。通用申请条件可以选择中文业务类别或具体办理事项，无需输入内部编号。
4. 点击“批量发布”，选择 1–50 个流程和一个真实申请人员任职，先预检。通用申请逐项检查各启用事项和办理人员；条件路线未覆盖时指出节点/分支，须在单项仿真中补充样例。
5. 核对逐项结果后确认发布。执行时重查流程修订、目录修订和实际权限；本批任一流程失败，整批事务回滚。可明确选择“仅选择通过项并重新预检”后再执行。

基础样例适用于简单流程。含项目、特殊任职、自定义表单或复杂金额条件时，需要相应的真实样例，不能将一个基础样例视为全部业务情况的证明。预检不会创建正式申请、审批任务或通知。

## 批量停用

“批量停用”仅列出已启用流程，支持搜索和选择。停用后不再接收新提交，在途申请仍按提交时冻结的发布版本审批、办理，历史签署保留。停用流程不等于取消或强制终止所有实例；个别在途申请使用现有有权限、有原因和版本检查的运行管理动作处理。

网络中断时先查看发布状态或同一操作回执。客户端保留同一次提交的 commandKey 和正文，重复请求不会重复创建发布版本；修改选择或预检结果后重新形成操作。

## 通用申请

用印、证明开具、IT 支持、维修、其他事项默认均要求办理；只有“其他事项”允许管理员在发布版本中设为“仅审批”。需要办理的申请先审批、再办理；仅审批的其他事项通过审批后直接办结，不伪造办理动作。

新建或换类别时，如果当前类别恰好只有一个启用事项，界面自动选中；多个事项可搜索分页选择。已保存但失效的事项保留回显，不自动换成另一项。服务器在提交时检查事项版本、当前启用状态、人员任职及动作权限。

## 架构与验证边界

- `native_contract` 生成全部接口、类型和中文类别目录；纯办理政策与条件规则位于 Domain，解析/发布/交接位于 Engine，事项与成员索引位于 Storage。
- 新增部署预检/执行接口及独立事项列表、保存、删除接口；旧设置对象中的 `handlingServices` 已移除，不保留双写兼容链。
- 统一复用设计令牌、对话框、表格与操作状态组件；未添加本地持久化或另一套前端设计系统。
- 本轮只进行受影响范围的契约、SQLite/PostgreSQL 和 React/HTTP 检查，具体通过记录写入重构进度文档；未完成的设备或平台验证不得视为通过。
