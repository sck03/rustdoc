# 导航与页面简化说明

> 2026-09-12。产品能力和最新验收结果以《当前架构事实》为准。

## 全功能版包含行政功能

单机 Full 使用与 Administration 相同的行政登记模式，包括人员档案、会议室预约、钥匙交接、物品领用、库存和归还。先建立人员档案，再选择人员登记预约或领用；单机不需要员工登录和双人审批。未结清钥匙或借用物品仍会阻止离职。个人待办按权限汇总行政交接和人事到期事项。

Full 的默认首页仍为单证概览，独立行政版默认进入人员档案。Document、Sales 单机版保持各自产品范围。团队版继续使用 PostgreSQL 申请与独立审批流程。

## 按任务查找功能

主导航保留六组，将全量菜单从 33 项收拢为 28 项。概览、邮件和关于支持各自聚合入口，申报词典纳入单一窗口；具体业务能力仍由各自的页面和权限控制。

| 分组 | 内容 |
| --- | --- |
| 工作台 | 我的待办、工作概览、文件任务 |
| 客户与供应链 | 客户与跟进、商机与报价、供应商管理、邮件中心 |
| 单证与申报 | 发票管理、统计查询、付款报销、业务资料、单一窗口、HS 编码知识 |
| 公司行政 | 人员档案、公司通讯录、会议室预约、物品领用 |
| 资料与工具 | 基础资料、报表模板管理、Excel 模板与托单、文字识别、装柜模拟、今日汇率 |
| 系统管理 | 系统设置、账号与权限、组织架构、审计日志、关于与支持 |

实际菜单只显示当前产品、运行模式、可用模块和账号权限允许的功能。聚合入口打开其第一个获准页面；只有申报词典权限的账号也能通过“单一窗口”直接进入词典。工作概览按权限提供单证、销售视图；关于与支持按权限及运行端提供关于系统、软件更新和授权注册。

顶部“查找功能”支持业务名称和“任务中心”“主数据维护”“智能 OCR”等熟悉名称，也能直达单据字段名称、WebDAV、日志、数据归属、权限方案、写邮件和投递记录。结果显示所在分组和页面，搜索沿用同一权限过滤。

默认只展开当前分组，切换分组收起上一组。精简导航栏显示六类分组及文字，点击即可展开；手机继续使用可关闭的抽屉，支持搜索、Escape、键盘焦点循环和返回页面。

## 页面操作简化

- **客户与供应商：** 页面级只放客户目录／跟进记录、供应商目录／采购概览。打开对象后才显示资料、联系人、跟进或供应产品／评价；新增、导入和导出由工具栏发起。商机目录打开所选记录后提供资料与报价／阶段历史，避免把目录、详情和操作放在同一排页签。
- **邮件中心：** “写邮件、投递记录、邮件模板”集中在同一工作区。写邮件与投递记录切换保留邮件草稿，返回历史保留筛选和页码；跨模块离开仍检查未发送内容。投递历史按收件人／主题和状态查询，使用服务端分页及数据范围校验，不再限制为最近 50 条。SMTP、发件人和外发规则仍由管理员在系统设置中维护；发票继续从本单据发起附件邮件。
- **HS 编码知识：** 税则目录与智能查询、实例、历史学习、联网补充、年度导入和知识库导入导出使用一套导航。基础资料只提供税则目录快捷入口；流程说明按需展开，不把当前页面伪装为业务完成进度。单一窗口内统一使用“申报词典”名称。
- **人员与业务资料：** 人员档案进入独立详情地址，资料、照片与证件、任职历史和交接事项各有分区；编辑和短操作继续使用弹窗。业务资料打开后集中显示该对象的版本与预览，返回列表保留原查询位置。
- **发票编辑：** 基本信息、明细、运输报关、辅助分析和输出各有页签，切换保留草稿。常用字段直接填写，地址／银行／印章等按需展开；保存栏集中显示金额和保存状态。明细的十个备用列默认隐藏，可在系统设置中指定默认显示数量。
- **组织架构：** 公司目录和部门层级表取代逐项大卡片。默认展开两级，按部门或负责人搜索会显示完整上级路径；新建、编辑后自动定位对应部门。

- **批量报表：** 在发票列表跨页勾选后生成批量报表，单次最多 200 张；也可从文件任务按发票号／客户添加。模板、带章选项、后台处理和下载复用同一输出链路，文件任务负责进度及失败处理。“Excel 模板与托单”保留导入模板、空白托单和 Excel 转托单，发票托单操作回到发票页面。
- **报表模板：** 管理页分为模板目录、输出默认值和导入导出。文件模板、个人及共享模板进入同一个可搜索目录，标明来源、状态和默认项；所选模板的设计、生命周期和文件操作继续独立授权。设计器保持独立页面。
- **物品领用：** 卡片优先展示登记／申请和补充库存。库存流水、盘点、编辑通过“更多操作”展开，分别保留原权限校验。领用、发放、归还记录继续在页内标签处理。
- **名称与定位：** 菜单名称和普通页面标题共用一份定义。编辑页保留“新建发票”“报表设计”等操作标题，所属业务分组一致；HS 税则目录和知识页面只激活同一导航入口。

## 详情定位与权限方案

客户、供应商、商机和业务资料以受控查询参数标识当前对象，人员使用 `/office/people/:employeeId`。列表的查询、页码和页容量保存在地址中，返回目录时继续使用；非法对象编号不会被当作有效记录。客户、供应商和商机由按编号读取的 API 定位，读取仍执行原有对象数据范围，不依赖预载前 100 条目录。

设置分类、单据字段分组、维护子页、账号／权限方案、报表管理视图均可直接定位。例如 `/settings?section=documentFields&group=payment` 打开付款字段名称，`/system/access-control?view=templates` 打开权限方案。地址只描述当前位置，未保存表单仍在 React 内存中。

账号与权限的功能模块按主导航位置分组并支持按页面或动作查找。一个邮件中心仍包含邮件模板和发送／投递等独立资源；人员档案与通讯录仍按不同动作控制私密信息。资源键、动作键和数据范围不因菜单聚合而合并，技术依赖继续由服务端派生。

切换会卸载的编辑分区、跨模块跳转及浏览器返回／前进均检查草稿。取消离开保持地址、当前对象和输入一致，连续点击返回也执行同一保护；确认放弃后清除对应草稿状态，避免重复提示。邮件和报表中保持挂载的分区可切换查看并保留草稿，更换模板或离开工作区仍检查尚未保存内容。

## 保留的业务边界

以下页面看起来相近，但服务于不同任务，继续分开：

| 页面 | 分工 |
| --- | --- |
| 我的待办 / 文件任务 | 前者处理需要人工办理的业务事项；后者查看后台处理、下载结果、取消和重试 |
| 发票管理 / 统计查询 | 前者创建和维护单据；后者按日期、客户和商品统计、检索、导出明细 |
| 客户跟进 / 基础资料中的客户 | 前者处理销售联系人、跟进和商机；后者维护制单使用的往来资料 |
| 报表模板管理 / 报表设计 | 前者选择默认模板、维护文件及模板包；后者编辑所选模板版式 |

本次重构集中在入口组织、默认信息量和操作方式。复用现有 React 组件、查询、领域服务和授权，不增加 UI 框架、第二份 API 契约、客户端持久化或数据库兼容层。

- `npm --prefix apps/export-doc-web run test:navigation-reorganization-ui`：对象直达、返回定位、连续历史导航、客户草稿、邮件分页及独立权限、统一模板目录和跨页批量报表。
- `npm --prefix apps/export-doc-web run test:office-ui`：行政表单、交接、权限、更多操作和无障碍。
- `npm --prefix apps/export-doc-web run test:document-editor-ui`：单据和设置保存、分类深链、维护定位及窄屏布局。
- `BusinessDirectoryReadScopeTests`、`EmailDeliveryStoreTests` 及 CRM／供应商／商机 API 集成测试：按编号读取、查看范围、匿名拒绝、资源不存在和邮件完整分页。
- `ApiProductEditionIntegrationTests`、`ApiOfficeAccessTests`、`ApiAdministrationEditionTests`、`ApiBusinessFeatureIntegrationTests`：真实 HTTP 和 SQLite 中四产品版的能力、行政业务与待办来源。

既有缩放、视觉、脚本、依赖治理和发布锁图门禁继续执行。浏览器界面夹具不能替代真实 API 验证，跨 RID 构建也不能替代目标设备安装验收。
