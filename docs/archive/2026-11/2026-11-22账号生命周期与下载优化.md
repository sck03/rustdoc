# 2026-11-22—23 账号生命周期与下载优化

## 实施范围

- 修复账号有发票归属时停用被拒绝、删除却成功的问题。账号删除与日常停用共用事务内交接检查，防止形成无法从现有账号目录改派的孤立归属；人员、组织和审批历史引用保护继续生效。
- 认证读取区分账号不存在与数据库错误。账号已删除时撤销对应会话并返回 401，退出和续期沿同一边界处理；普通缺失资源仍为 404，依赖故障不伪装为身份失效。
- 最后一个启用管理员的普通维护与安全停用共用有界编号查询。引用检查改用 Storage 存在查询，部门校验复用公司内自然键定位，HS 清空按每批 200 个编号读取后逐条删除/审计，仍在一个可取消事务内完成。
- 新增业务资料版本下载票据及消费两个端点，由 native_contract 统一生成 OpenAPI、运行元数据、Rust DTO 和 React 客户端。HTTP 现有票据池使用类型化目标统一任务、备份及资料下载，保留容量、期限、Cookie、操作绑定和撤销规则。签发时检查权限及版本存在性，读取时重新验证会话、对象范围与内容完整性。
- React 原件下载不读取完整 Blob，直接交给浏览器处理；离开记录后忽略迟到票据。图片/PDF 预览及桌面受控另存为沿用原入口，更新成功提示和账号删除确认文案，保持共享控件与 680/1180 断点。

没有新增运行依赖、数据库表或 schema 迁移，不增加旧接口或旧数据库兼容实现。

本批重新核定两个 Rust 聚合规模基线：生产目录口径 116,744 行（包含内嵌测试及独立契约比较），测试/示例 36,098 行。增长对应新增的下载票据能力及授权、交接、分块和取消回归；所有单文件上限及原有 75/120 行增长余量保持不变。
