> 本文保留设计、任务与验收边界。数值由[设计系统规范](./前端设计系统规范.md)维护，导航及页面职责由[信息架构方案](./前端信息架构与页面分配方案.md)维护；实施范围和未完成项见本批记录。RR-06 的客户端拆分已落地，前端与[整体重构方案](./程序整体重构与优化方案.md)共用集中门禁。保留专业页签、权限、草稿和实际导入导出/PDF，不新增 UI 库或浏览器持久化事实源。

## 1. 目标、范围与用户诉求

用户诉求归纳为三条：

1. **启动界面**（桌面窗口打开到出现登录）观感不佳；
2. **各业务页面结构不美观、不符合普通人审美、操作不方便**；
3. 重构必须保持**模块化、解耦、可维护、可扩展**，代码高效简洁、资源占用少、程序流畅稳定。

本轮范围是**表现层重构**：启动链路、外壳与导航、页面结构模板、共享控件与样式体系。范围**不含**业务语义、API 契约、权限键、数据库、Rust 服务、专业页签与草稿规则；这些只允许在其现有边界内被新的表现层消费。

明确不做（违反即停）：

- 不引入 UI 组件库（Ant Design／Arco／Radix 等）或第二套 CSS 方案（Tailwind／CSS-in-JS）；
- 不新增 LocalStorage／IndexedDB 事实源（展开态、列偏好等继续按现有受控设置与内存会话处理）；
- 不改 `/openapi/v1.json`、生成客户端、权限资源键与动作键；路由地址只增不删，被拆分页面的旧地址由前端重定向到新地址（映射表见信息架构方案 §7.3）；
- 不删除发票五页签、付款四页签、V3 设计器、HS 七页、单一窗口、OCR、装柜等专业结构；不把专业界面改成通用表单；
- 不改包身份、可执行文件名、应用 identifier、数据目录、更新频道与版本号规则；
- 不为了"看起来统一"放宽既有无障碍、缩放、视觉、规模门禁阈值。

## 3. 目标形态

一句话：**一套令牌、一层样式、一套控件、四种页面模板**；风格定位"商务蓝 · 克制扁平"（规范 §1）。

### 3.1 样式：从四层覆盖到两层，数值以规范为准

```
tokens（唯一数值来源：规范 §3–§5、§8）
  └─ primitives（控件原子规则：规范 §7 状态矩阵）
       └─ patterns（列表/详情/编辑/仪表盘四种模板）
            └─ feature（只写本业务特有、无法用模板表达的规则）
```

- 目录：`styles/tokens/{color,space,type,radius,elevation,zindex,motion,density}.css`、`styles/primitives/*`、`styles/patterns/*`、`styles/features/<domain>.css`，全部 `@layer` 显式归属；同名选择器只保留一处，删除 `base.css`／`tokens-shell.css`／`commercial-workspace.css`／`sales-workspace.css`／`controls-accessibility.css` 的重复定义。
- 取值集合固定：字号 {12,13,14,16,20,26}；字重 {400,600,700}；间距 {4,8,12,16,20,24,32,40,48}；圆角 {4,6,8,10,12,16,999}；阴影 4 级 + 焦点环 + 选中描边；z-index 8 档；渐变 0；`!important` 仅 2 处白名单。
- 只保留一个入口 `styles/index.css`，删除 `styles.css`／`theme.css`／`businessFeatures.css`／`reportWorkspace.css`／`responsiveOverrides.css`／`workspaceFeatures.css` 六个清单文件；`styles/visual-baseline.css` 改为复用同一入口。首屏 CSS ≤4,000 行：审计、文件任务、HS 知识、单一窗口、装柜、V3 设计器、设置中心、runtime 诊断全部路由级懒加载。
- 断点三档 680／1180，容器查询 760 用于表格转卡片；删除 560/600/700/860/1320 等临时断点。

### 3.3 页面模板

四种模板组件（`src/ui/layout/`），页面只提供数据与动作：`ListWorkspace`（12 个列表页）、`RecordWorkspace`（详情类）、`EditorWorkspace`（编辑器类）、`DashboardWorkspace`（概览与审批中心）。结构样张见规范 §9；每条路由归入哪个入口、哪个模板，以信息架构方案 §6 的页面分配表为准。

### 3.3a 导航与页面分配（摘要，详见信息架构方案）

- 主导航从 7 组 39 个一级入口收敛为 **6 组 33 个入口、39 个叶子**：工作台（我的事）/ 客户与供货商 / 单证与申报 / 行政与人事 / 资料与工具 / 系统管理。
- 撤销"申请与资源"组：7 类申请并入"申请与审批"的"发起申请 / 我的申请"视图；会议室与物品并入"行政与人事"。

- 系统设置只保留 6 个配置分类；备份与恢复、系统维护拆为独立操作页；流程管理拆为 6 分区 + 定义编辑屏。

### 3.4 启动与登录体验

目标：**不白屏、不跳变、品牌一致、失败可读**（样张见参考样例"启动骨架 · 登录页"）。

1. `index.html` 内联关键 CSS（画布底 `#f4f6f9` + 居中品牌标 + 4px 细进度条）与中性占位标题；React 挂载后由 `productEdition` 覆盖。
2. 首屏骨架三态：桌面就绪检测中、连接服务中、失败可重试；同一组件，替换"登录页壳 + 转圈"。
3. Tauri 窗口 `visible(false)` + `background_color(#f4f6f9)`，前端 `app-ready` 后 `show()`；默认尺寸 1440×900、最小 1180×720，与桌面阈值 1181 对齐。
4. 启动失败页改为应用内品牌错误页（原因 + 日志路径 + 复制 + 重试）；`rfd` 原生框只保留进程级致命错误兜底；WebView2 首次安装前置说明统一文案与图标。
5. 登录页保留左右分栏；登录卡圆角 16、shadow-4、输入与按钮 44px；底色为画布色，删除渐变。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 扁平化（去渐变、去光晕、实色激活）视觉变化集中释放 | 一次性看起来"全变了" | 参考样例先评审再实施；按 P1→P3 分批，每批与样例并排抽查 ≥6 页并留图 |
| 视觉基线一次性重拍掩盖真实回归 | 退化不可见 | 分两批重拍 + 逐张复核；保留失败截图与差异图；阈值不放宽 |
| 样式层合并改变既有页面观感 | 专业页视觉回归 | 先建令牌与同值别名，再删重复定义；每阶段跑 84+198 |
| 断点收敛与最小窗口 1180 | 紧凑窗口可用性 | FR-24 逐档验收；`compact-tablet` 规则并入而非丢弃；密度两档表固定 |
| 页面模板迁移打乱专业操作 | 工作流中断 | 第 4 节"保留"列逐项对照；OA 台账 F/S 条目作为回归清单 |
| 窗口 `visible(false)` 与尺寸改动影响桌面脚本 | 桌面回归失败 | FR-21 同批更新单测与两个桌面脚本期望，并在三版实跑 |
| 首屏懒加载影响深链 | 直接地址白屏 | 路由级 CSS 与 Suspense 骨架同批落地；`test:navigation-reorganization-ui` 覆盖 |
| 逻辑下沉引入并发/取消回归 | 数据错误 | 复用 `useAbortableOperation`／`useVersionedRecordDraft`／`useScopedSave`，不新造异步模型 |
| 规模上限收紧导致中途失败 | 交付阻塞 | 上限随任务分批收紧，每批只降已实际下降的文件 |
