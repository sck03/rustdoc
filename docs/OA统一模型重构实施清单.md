| 官方依据 | 本项目落地要求 |

| [泛微集团分级分权与多单位任职](https://guoqi.weaver.com.cn/) | 一个自然人、一个账号、多任职；管理授权不等于业务授权 |
| [致远组织主数据、兼职及分层分权](https://www.seeyon.com/NewPro/desc/id/23.html) | 稳定单位、部门、人员、任职 ID；公开组织资料与私密人事档案分开；组织变更与权限联动 |
| [华天动力集团版](https://www.oa8000.com/html/jituanoa/index.html) | 功能操作、管理和查看三类范围分开；统一任务中心；交接后才撤销职责 |
| [蓝凌 EKP 流程仿真、审批要点与效率分析](https://www.landray.com.cn/static-old/solution/ekp/index.html) | 版本化流程发布与模拟；确定的人员/任职路由；明确审批要点；任务计时、异常和历史可追溯 |

以上是公开产品能力证据。本项目的数据结构、算法与技术选型为自主设计，不代表厂商的内部实现。继续采用 Tauri + React + Rust 模块化单体，SQLite 单机与 PostgreSQL 18 团队部署共用业务内核。

## 数据及 API 决策

- 组织单位、部门、人员、任职、汇报关系、组织职责、单位业务角色、管理授权及流程任务具有稳定内部 ID，关系表使用 ID 外键。组织编辑/删除按 ID 定位；部分用例正文及授权上下文仍使用不可变公司代码、单位内部门代码，服务端必须携带完整单位边界解析。代码创建后固定，不提供 code/id 双轨路由或兼容分支。
- 任职是主职与兼任职的统一实体；汇报关系指向任职。一次操作选择一个授权上下文，不跨角色隐式合并权限。
- 组织与身份使用具备外键、唯一性及版本约束的关系模型；申请正文、扩展表单与不可变提交快照可保留 JSON。禁止只增加 JSON 字段便声称新模型完成。
- 私密人事信息独立授权，单位管理员只有公开任职投影；流程管理员只获得任务维护所需摘要。
- OA 接口可重新设计，并统一从一份 OpenAPI 生成 Rust 与 React 客户端；对应旧 OA 接口直接退役，不保留双写、双读或兼容分支。
- 每个业务对象仍归属一个经营单位。集团汇总单独授权，在 SQL 计数/分页前限定单位集合；Group 不是虚构业务公司。
- 原单证、Excel、报表/PDF、邮件及宿主适配模块继续共用既有职责边界，不将 OA 重构变成无关产品升级。

## 账号、权限方案与模块显隐一并重构

2026-10-29 用户补充要求已纳入本轮实施。沿用同一资源／操作目录，统一主身份与单位身份的权限解析，避免出现两套权限计算器。

| 层次 | 责任与约束 |
| --- | --- |
| 产品能力 | Document、Sales、Full 及编译能力定义可用功能上限，任何角色或方案都不能绕过。 |
| 账号 | 登录、停用、平台管理员资格；账号级关闭模块及 OA 可见性限制约束全部业务身份。 |
| 任职／身份 | 稳定任职决定操作单位和组织范围；每次只使用一个身份，不能把总部与子公司权限合并。 |
| 权限方案 | 可复用的资源、操作、数据范围与关闭模块；系统预置仅用于初始化，已保存方案不随升级隐式扩权。 |
| 分级授权 | 组织、任职、流程、转授权分别管理；业务授权不能超过来源管理身份的操作及数据上限。 |
| 实际访问 | 请求按当前身份、方案、模块限制、记录归属、任务分派及有效期校验。菜单、直达路由和搜索使用服务端派生结果。 |
| 变更联动 | 方案修改、模块关闭、任职结束和撤权须核查未结任务；后台任务发布及下载重新检查，保留变更审计。 |

方案的“关闭模块”作用于使用该方案的身份；账号的“关闭模块”作用于该账号的所有业务身份。两者都属于访问限制，不能仅隐藏导航。集团汇总使用独立授权，不能用普通业务方案的“全部”范围替代。

## 配置与使用顺序

1. 平台管理员从“系统管理 → 组织架构”建立经营单位、部门和负责人。只有需要纯管理层时才建立 Group；日常业务归属经营单位。
2. 从人员档案登记主职、兼任职及汇报关系，关联唯一登录账号。调整主任职使用档案中的“调整主任职”，保留原任职及历史。
3. 在“账号与权限”维护主身份方案和账号级限制；在组织架构的“单位身份与授权”中分配正式任职、临时审批协作或单位管理身份。单位管理的组织、任职、流程、业务授权和统计分别勾选。
4. 单位授权管理员先建立“本单位权限方案”，再给本单位业务身份引用。可授操作和数据范围受上级上限约束；账号停用与全局凭据仍由平台管理员维护。
5. 在审批设置中明确节点、条件和找人职责，使用流程模拟核对结果后发布。跨单位审批人须另有目标业务单位的有效授权；组织负责人身份本身不授予审批权限。
6. 多身份账号在页头选择“单位身份”；未保存草稿会先要求处理。点击“我的权限来源”核对方案、账号/身份/上级限制和可操作范围。撤权、结束任职或停用流程前按提示移交未结职责。
