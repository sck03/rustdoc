## 实现与边界

- 装柜的分析、方案保存和柜型保存共用独立请求解析模块。非法行显示行号/字段并保留草稿，不过滤丢行，不将小数整数化或负值改零。柜型尺寸/容量由现行接口初始化，迟到响应不覆盖用户输入。回读保留完整小数和显式零值；既有数值契约无法精确表示的输入在提交前拒绝。
- 四个方案按钮使用整行网格空间；共用工具布局从 jobs-excel 样式抽出，装柜路由独立加载，避免页面访问顺序影响布局。颜色、字号、控件、导航和 680/1180 断点保持现行规范。用户指出的纵向拉长截图来自样式不完整的独立失败夹具，不作为成品验收结果。
- 3D 所有货物面共用带顶点色的几何和材质；边线、层线分别合批，保留六面色阶和层线数量限制。显示模式切换复用 renderer、相机和已构建资源；资源释放幂等。可视化 memo 避免草稿键入重算未变化的 SVG。
- 供应商采购概览在同一授权读取快照中选取每家最新已确认评价，数据库返回全局统计和当前筛选分页，排序增加稳定 ID 兜底。React 使用生成客户端、共享分页和取消信号，明细不再包含未显示的 notes。SQLite/PostgreSQL 共用存储合同。
- 邮件启动恢复按 100 条批读 Attempting，事务化写入 Uncertain 与审计，观察取消并支持重复执行。已发送摘要不变，不重新投递；此改动限制单批物化数据，不宣称数据库扫描成本为常数。
- 退役 `UploadSingleWindowSubmitPackage` 和 `RunShutdownMaintenance`，删除对应路由、处理分支与生成 DTO。测试及桌面脚本使用现行提交包导入，回执上传与真实宿主关闭继续保留。原生定义生成 750 个操作、706 个运行契约模型（OpenAPI 共 713 个 schema），冻结基线仅通过明确差异投影验证。
- 工程套件暴露 Windows 测试夹具删除时短暂的“目录非空”；PostgreSQL macOS 客户端打包脚本的本机模拟测试改用已有目录删除重试函数，保留原先路径/链接检查。随后工程套件完整通过；这不是 macOS 真机验收。
- 续接验收发现 PostgreSQL 恢复后的关闭偶发连接池故障。审查公共事务边界并新增回归，实际复现 SQLite 在提交前已取消仍提交成功；修复为提交前复核取消并回滚，开始提交后使用适配器自身时限完成提交。PostgreSQL 回归用延迟约束触发器使提交跨过调用方期限，检查数据结果与连接池健康；真实网络故障仍保持 fail-closed。

本轮没有确认完整业务模块存在“只有后端、没有前端”的缺失。OA/会议室的动态调用、浏览器下载返回地址和健康探针仍属于有效调用链，不按静态方法名引用数删除。

源码规模门禁通过，保留各文件上限及既有增长预算：Web 生产集合 88,757 行，较其登记基线少 64 行；Rust 原生生产集合 115,190 行，自动化默认集合 31,047 行。后两项登记基线分别由 114,932、30,724 调整为 115,188、31,047；续接修复增加的 2 行生产代码仍在 75 行预算内。新增部分主要为存储分页、显式契约差异和回归验收，自动化增长预算仍为 150 行。此记录不宣称所有语言的总行数都减少。
