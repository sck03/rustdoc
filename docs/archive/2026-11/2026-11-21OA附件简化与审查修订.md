# 2026-11-21 OA 附件简化与项目审查修复

## 业务决定与本次实施

用户确认当前 OA 不需要同一申请内的私密附件分级，随后授权一并修复前次审查问题并推送 GitHub。本批以 `30809811` 为代码基线。前次“后端已有私密附件、前端未适配”的事实不再作为新增前端功能的依据；直接删除未采用能力。

- 删除附件 `Internal/Restricted` 分类的解析、保存、过滤及下载判定，统一复用申请访问授权和节点材料可见性。附件下载不再为分级另查人员详情权限，历史附件重新关联也不重复检查同一节点策略。
- 从唯一原生契约删除九个上传端点的 `classification`、`OaAttachment.classification` 和 `OaMaterialPolicy.allowRestrictedAttachments`，重新生成 OpenAPI、运行契约、Rust DTO 与 React 模型。流程编辑器删除相应选项。上传字段按契约校验，旧 `classification` 参数返回 400，不静默接受。
- 人员隐私资料、私密核验结果、节点正文及附件整体隐藏规则继续有效；不能把删除附件分级误解为开放申请或人员数据。
- 原有材料回归改用节点整体附件授权，覆盖原件下载、当前/未来节点、历史材料和完整归档。另验证普通附件无需人员详情权限、申请权限撤销后下载被拒绝，以及 HTTP 拒绝已删除的上传字段。
- 真实页面与 PDF 联调发现并修复附件空状态误导：后端因节点权限隐藏附件时，OA、资源申请页和审批单 PDF 明确显示材料权限状态，不再把受限结果说成“尚未上传附件”或“无附件”。
- 不升级依赖，不新增数据库迁移或旧字段兼容层。冻结发布契约继续保留，只在测试中明确校验上述字段删除，其余 API、认证、错误和权限元数据保持对照。

| --- | --- | --- |

## 模块与数据边界

- 业务自然日只读取一次，再计算 30 天关注范围。到期筛选仍取公共目录与私密详情权限的交集，保持单位、部门、任职有效期、关键词和稳定分页规则；缺失私密档案或适用的日期损坏不能伪装成零条结果。
- 组织查询复用 `records_by_ids` 的去重和分批能力；没有新增 SQL 到 Engine，也没有读取人员私密档案来显示负责人姓名。
- 请求作用域校验放在 API 生成模板中，App 负责授权生命周期；各业务模块继续复用共享 scoped mutation/save。既阻止尚未发出的旧命令，也阻止已发出命令的旧结果影响当前界面；已经在服务端提交的事务不因此回滚。
- PDF 的 64 MiB 指缓存持有的 PDF 字节总量，不代表整个进程 RSS，也不包括正在使用的响应、字体及图像。条目从生成起有效 300 秒，即使没有后续请求也会移除；不新增外部服务或依赖，关闭操作幂等。
- 当前 schema 18、全新部署和不兼容旧数据的约束不变；不新增迁移链，不删除人员隐私、核验权限、有效冻结契约或当前验收夹具。

## 验证中发现的测试时序问题

- Windows 退出脚本原先只按 PID/父 PID 扫描。一次测试中，应用 PID 复用了几个小时前的父进程编号，导致把已运行很久的 `fastctx.exe` 算为残留。现按进程创建时间、已观察身份和独立 WebView profile 确认归属；重跑 5 个退出场景均为 WebView2 6 → 0，HTTP 端口关闭，没有终止外部进程。
- PostgreSQL 高级流程测试手动生成审批单时，自动系统节点可能仍持有准备锁。真实接口返回约定的 429，原测试的立即 `unwrap` 造成竞态失败。测试现在仅在原有 60 秒期限内重试 429，其他错误立即失败；未取消生产限流或将失败吞成成功。

本次未执行 Linux/macOS/ARM 真机、Docker 容器、OCR 完整资源包或全项目性能基准验收；Windows 本机和隔离 PostgreSQL 的结果不替代这些独立验收。
