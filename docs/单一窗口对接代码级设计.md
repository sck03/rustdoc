# 单一窗口对接代码级设计

> 2026-11-09 按 Rust 源码和联调客户端重整。旧 C# 类、EF 事务、数据库 v3、无绑定的 schema 3.0 包和任意外部目录说明已经过期；旧方案保留在 [Git 历史](https://github.com/sck03/rustdoc/blob/b44fbb6/docs/单一窗口对接代码级设计.md)。匿名报文发送已实测；官方业务回执与签发尚未确认，见本批验收记录。

## 产品与运行职责

办公室使用 Full 网页/PostgreSQL 或获授权的桌面业务端制单、校验、导出提交包和归档回执。持卡机使用独立 Tauri + Rust + SQLite，维护操作档案、向官方客户端交接 XML 和收集回执。PostgreSQL 服务不访问持卡机本地目录，不建立共享工位、抢单租约或远程卡控制。

COO（海关原产地证）与 ACD（报关代理委托）有独立草稿、字段和报文。源发票、商品、出口商和客户负责提供默认值；手工修改保存到单一窗口单据，不覆盖源发票。保存草稿不等于向官方提交，导出或投递文件不等于官方受理成功。

## 独立申报与客户 Excel

无需先创建发票。“申报资料”只需资料编号即可建立手工来源，再分别进入代理委托或原产地证填写。客户 Excel 走现有 `export-doc-excel` 和 `excel-analyzer-rs` 解析器，先显示识别结果，确认创建才保存快照；预览失败时必须重新选择或清除文件转手工输入。无法识别的客户版式可照表手录，不承诺任意版式无配置自动识别，也不把客户 Excel 模板写回成另一套表格。

独立快照使用 `sw-sources`，不写 `invoices`；授权公司、部门和所有者由服务端赋值。新增 GET/POST `/api/single-window/sources`、POST `/api/single-window/sources/excel/preview`。单据、审查、导出使用 `sourceId`，可以指向有权查看的发票或独立快照，旧 `invoiceId`/`sourceInvoiceId` 合同不保留。

原产地证收货人可填目的地客户，发票仍保留交易客户；合同、发票号、英文品名、详细描述以及商品行可独立修改。行增删/顺序锁与字段锁分别保存；重新载入保留人工值，显式解锁才恢复建议值。两种申报之间不互相覆盖。

## 数据与版本

数据库使用全新 Rust schema 17，旧试验库拒绝打开或恢复，重建须显式选择新数据库，详见[架构事实](./当前架构事实.md)。不能按旧文档删除原资料、补列或修改版本标记。

[词典服务](../crates/export-doc-engine/src/engine/single_window/references.rs)从业务库 settings 的 `sw-reference-catalog` 读取完整覆盖；没有覆盖时采用 Domain 内置参考数据。它不再写旧的 JSON override 文件。生产企业、草稿、批次、提交包及回执分别保存在当前业务库，随现有备份恢复。

草稿保存源资料基线、手工锁定与修订；源记录变化后，未锁定字段按当前源资料重新装配，锁定字段保留人工值。修复分组、恢复默认及解锁仍经过业务校验，不能把预览或源资料提示当成正式保存。

## 持卡机档案与路径

[profiles.rs](../crates/export-doc-engine/src/engine/single_window/profiles.rs)当前限制一台数据根最多 **100 个档案**，同时只激活一个。公司或卡标识创建后不能更换；更换应新增档案。卡标识与交接凭证用于包绑定，不保存官方认证卡口令，也不自动控制官方登录。

机器身份保存在 SQLite settings 的 `sw-station`，档案及加密交接密钥保存在 `sw-profiles` 记录；不是旧的 `Security/SingleWindow/station.id` 文件。损坏身份拒绝继续，不能静默生成替代身份接管旧批次。

根据本次用户授权，官方客户端交接是 DataRoot 规则的明确例外：COO 与 ACD 分别保存 OutBox、SentBox、InBox、FailBox 四个现存目录的绝对路径，可以位于不同磁盘；不再从共同根目录拼接，也不在未检测到客户端时生成替代目录。保存和使用时拒绝磁盘根、相对路径、父级穿越、链接及同一档案内不同业务/用途的相同或嵌套目录。不同卡档案可以使用同一官方任务目录，派发和收集仍强制核对当前活动档案与批次绑定。

Windows Tauri 宿主只读当前用户 `LOCALAPPDATA/SIC/UserSetting/DFWJobSettings.xml`，协议模块仅提取 `SubFormSetting FormId="ACD"` 和 `"COOIMP"` 的四个目录属性；排除 PCOOIMP，不返回 PIN、加密配置或通知凭据。新档案自动填入空目录，已有档案可“重新检测目录”，每个目录均可手工输入或选择；检测结果不能覆盖检测期间已编辑的目录。未安装、格式损坏或缺少任务时明确提示，保留手动配置入口。客户端配置不会被本程序改写。

## 提交包与回执包

[packages.rs](../crates/export-doc-engine/src/engine/single_window/packages.rs)生成 **schema 5.0** 的 `.swpkg` 交接包（内容为 ZIP），包括单据/批次/草稿版本、公司、文件摘要、持卡机、档案、卡标识、assignmentNonce 和 HMAC-SHA256 认证。办公室导出时须提供目标持卡机的分配码；SQLite 本机可使用当前活动档案。分配码含交接认证材料，只在授权人员之间交付，不写公共日志或源码。

提交时已经绑定目标机器/档案/卡。导入、派发、收件和回执归档复核相同绑定、公司、业务类型、摘要及认证；不以发票号替代完整性检查。旧版本包不能依据旧说明继续导入，协议版本与数据库 schema 是两个不同合同。

[包模块](../crates/export-doc-single-window/src/package.rs)限制压缩包及展开大小，验证 NFC 路径、重复路径、文件声明和摘要。报文生成、包记录和业务状态通过现有事务及受管文件边界发布；失败不把半成品作为成功输出。

## 实际操作顺序

1. 在持卡机创建并激活公司/操作卡档案，安全取得该档案的分配码。
2. 办公室从发票打开 COO 或 ACD，或在“申报资料”创建手工/Excel 独立资料，核对默认值、填写专用字段、保存并执行导出审查。
3. 使用目标档案的分配码生成提交包；核对公司和业务类型后交给对应持卡机。
4. 持卡机激活匹配档案、导入包并派发至该业务配置的 OutBox；官方客户端负责认证、签名与实际发送。
5. 持卡机收集与批次匹配的官方回执，导出已认证的回执包。
6. 办公室导入回执包，核对绑定及源包摘要，保存回执和更新批次状态。

多个持卡机使用独立数据根与身份；不复制一个正在使用的数据库给不同机器冒充独立工位。备份/恢复须同时保留数据库及主密钥，迁移后重新检测并保存本机目录。外部官方客户端目录不随项目 DataRoot 迁移或备份。

## XML 与字段规则

COO 主根为 Certificate，包含 CertificateHead、CertificateList/Goods 及适用的更改、第三方公司、发票和承诺段；附件为独立 File。ACD 请求根为 ImportAgrRequest，分 OperInfo/ImportInfo；导入响应的 ConsignNo 是根节点直属字段，协议回执包含 ACD002。

COO 和 ACD 的国家、币制与贸易方式码表分别处理，不能互换，例如 COO 一般贸易为 1，ACD 为 0110；COO 使用 USD，ACD 美元为海关代码 502。ACD 货名优先中文再回退英文，海关 10 位代码不能用统一社会信用代码替代。

完整字段、长度、原产标准及回执对照见[字段映射清单](./单一窗口字段映射清单.md)。官方资料与 XSD 是报文对照资料，当前应用行为仍须对照 Rust 源码及实际输出，不以旧 C# 字段清单代替当前 DTO。

常用类型按证书代码处理：C 一般、G 普惠制、A 中澳、E 中国—东盟、RC RCEP（含日本方向）、K 中韩。没有另造“中日自贸证”代码；是否享惠取决于协定成员、产品原产规则及当期政策，G 日本样例只用于历史格式校验，不代表当前日本给予普惠制待遇。

保留的 ACD XSD 在 `TradeMode` 后和 `AgentCode` 后重复定义 `Curr`。现有报文只在后者输出一次；联调客户端接受并发送，但尚无业务回执证明服务端结构受理。`verify-single-window-xml.ps1` 在内存中剔除前一重复项并明确告警，原始资料保持不变；不得将此修正校验写成原始 XSD 通过。COO 六类样例直接通过保留的 `coo.xsd`。`CopCusCode` 按官方字段说明为必填、不超过 10 字符的企业内部编号，不强制 10 位数字；TradeCode/AgentCode 仍校验 10 位海关代码。

## 失败、审计与验收

校验失败先修正字段；目录或档案不匹配拒绝派发；回执损坏不触发自动重发；等待官方处理不标记为技术成功。保持取消、超时、容量、错误分类、版本保护和数据库审计，技术日志使用当前受管日志，不恢复 Serilog。

现有测试包含纯映射/包/回执和应用服务闭环；新增字段需同时验证源资料变化、锁定保留、XML 节点顺序、类型/长度、错误包、错误绑定、重复导入、取消和事务回滚。真实卡、官方客户端文件命名/目录监听、签名、多卡轮换、官方回执变体和目标平台必须现场验收；不执行系统级代码签名或 Apple 公证。
