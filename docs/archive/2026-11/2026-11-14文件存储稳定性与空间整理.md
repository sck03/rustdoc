# 2026-11-14 文件存储稳定性与空间整理

基于 `5613f041` 和前会话审查实施。保持 Tauri 2 + React 19 + Rust、SQLite 桌面及 PostgreSQL 18 团队服务边界，没有依赖升级或新增服务。数据库仍为 schema 18，完整 DDL 指纹已变化；旧指纹测试库和恢复包拒绝打开，须显式使用新数据根或数据库，原件不自动删除。

## 修复与职责

1. 审批 PDF 的不可变对象准备/上传在任务工作阶段完成，完成锁内只复核授权并发布引用。阻塞 S3 上传时其它任务仍能完成。
2. 普通附件上传和二进制下载采用原生契约的 24 小时传输期限；生成 OpenAPI、Rust 元数据和 React 客户端同步，明确差异另有冻结对照清单。
3. 迁移从管理协调器拆出，使用持久待复制队列纳入并发新增对象；写锁外复制核验，最终短锁只检查空队列、权限及配置后切换。
4. S3 凭据采用独立修订和原地替换 API，先校验同一存储身份；远程凭据失效时保留认证管理入口。React 使用共享折叠控件、作用域命令、草稿保护和版本冲突处理，切换会话清空密钥。
5. HTTP 接收、对象写入/下载/迁移、备份压缩/密封/解包共用磁盘预算，保留 256 MiB 余量；已有可定位输入流直接用于摘要和发布，删除重复暂存复制。
6. S3 共用虚拟主机、路径、已含桶名主机三种寻址；小于等于 8 MiB 单次 PUT，更大文件分段。文件服务复用连接，下载同时计算摘要；256 MiB 会话磁盘缓存为重复 Range 提供独立句柄，完整性检查绕过缓存。
7. 成功提交后清理对象写入意图；分段 UploadId 写入受管恢复日志，回收跳过活动上传。取得 UploadId 前的中断窗口仍依靠桶的未完成分段生命周期策略。
8. 对象/引用/组织容量由两库触发器在同一事务维护，状态及配额读取汇总，完整性任务从原始关系复核。前端任务轮询复用临时错误退避。

测试协议服务从备份测试提取为共享夹具；没有复制第二套生产传输、识别器、SQL 或任务系统。源码规模基线仅按相对起点的实测净增量调整，保留单文件上限及原增长余量。

## 空间与交付

清理对象逐项从测试脚本和历史验收记录追溯，计划保存精确绝对路径、文件数及大小，执行前检查运行进程、链接和 Git 边界。第一阶段删除 13 个旧测试目录，共 1,520,297,547 字节（约 1.42 GiB）；另 5 个目录因本轮并发回归套件重新使用而保留。Windows 目录删除失败后重新核对边界，再以同一 PowerShell 内的长路径 API 完成清理。

全部 Cargo 进程退出后，按测试指纹清理 166 个测试可执行文件及相关元数据，共 11,147,527,580 字节。两阶段删除文件的逻辑大小合计 12,667,825,127 字节（约 11.80 GiB）；逻辑长度不等于实际磁盘占用，Cargo 清理阶段实测可用空间增加 5,110,407,168 字节（约 4.76 GiB）。444 个用户备份/私有补丁文件及新程序包的 41 个文件 SHA-256 最终全部一致。可复用下载/编译缓存保留。

本地原始日志、截图、清理计划及回执位于受忽略的 `artifacts/file-stability-final`，不提交数据库、密钥、截图日志和可执行文件。

本批保留的 Full SQLite 测试程序位于 `artifacts/file-stability-desktop/ExportDocManager.Tauri.Full`，含 OCR 和文档资源，共 41 个文件、223,739,542 字节（约 213.4 MiB），主程序 89,828,864 字节；替代旧测试包的 517,843,887 字节。此差异主要来自改用 Release 体积优化构建，不表示仅代码重构即可减少同等比例。

## 尚未验收的边界

S3 协议夹具不代表 AWS、OSS、COS、MinIO 或 Ceph 真服务全部兼容；没有本批真实厂商凭据、慢网长时或百万对象实测。未实现 STS 自动刷新、浏览器断点续传和完整包分卷。Docker、Linux/macOS/ARM64、MSVC、正式安装/升级、系统中文输入法候选窗及实体打印仍需对应环境验收；中文文本和 composition 自动化不能冒充系统 IME 真机验收。
