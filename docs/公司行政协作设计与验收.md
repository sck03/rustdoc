# 人员、组织、账号与 OA 审批

> 2026-10-31 按新源码更新。当前数据库采用全新 schema 11，不兼容 schema 10 及更早数据库/备份。字段与约束见[新基线数据字典](./账号组织OA新基线数据字典.md)，操作见[人员与 OA 操作手册](./人员组织权限与OA操作手册.md)，本轮验证见[验收台账](./OA重构验收与功能保留台账.md)。

## 对象与职责

| 对象 | 含义与维护入口 | 约束 |
| --- | --- | --- |
| 公司、部门 | 组织架构维护真实公司及部门层级 | 拒绝循环、跨公司父节点；启用下级、人员、账号、负责人及业务引用受保护 |
| 人员 | 人事维护稳定人员编号、工号、姓名、状态及私密档案 | 可没有登录账号；工号唯一，姓名可重复；通讯录不授予私密档案权限 |
| 职位目录 | 公司维护最多 200 个常用职位名称，任职可选择或自由填写 | 职位是任职描述，不按“总经理”等名称授予权限；不包含薪酬、编制管理 |
| 任职与汇报 | 一个主职、最多 20 个兼任，具有稳定编号、职位、直属和职能负责人 | 可跨经营单位；各身份独立授权；最多 10 位职能负责人；拒绝自我汇报、重复任职和循环 |
| 登录账号 | 管理员维护登录名、认证、启停及权限来源 | 普通账号与人员最多一对一；管理员是独立管理身份；停用账号与人员离职是不同操作 |
| 权限方案 | 模块、操作及数据范围 | 账号独立配置与明确的共享方案择一；角色只提供初始化起点，空独立配置不回退 |
| 流程定义与发布版本 | 公司按具体业务配置审批节点，保存草稿后独立发布 | 发布内容不可变，停用仅阻止新提交，草稿不会改变已启用版本 |
| 审批实例与任务 | 一次提交冻结实际节点、人员、条件结果、规则版本 | 每个任务独立签署，禁止本人审批；权限和分派必须同时成立 |
| 办理分工 | 具体印章、证明、会议室和物品组的实际交付责任人 | 每项 1–10 人，任一人办理即可；办理权限不授予审批权 |

建议开通顺序：公司与部门 → 职位目录及人员任职 → 账号和权限方案 → 关联人员 → 部门/公司负责人 → 办理分工 → 流程草稿 → 发布 → 提交前预览与实际申请验证。

组织树表达部门隶属；直属与职能汇报独立维护，不为总经理虚构同名部门。公司信息单独指定公司领导审批负责人。负责人账号须启用并具有审批能力；具体业务提交时核对该业务的查看及审批权限，不要求开放所有人事、行政和资源模块。

公司及部门分别设置主负责人和最多十位分管负责人，分管须明确选择九类申请中的业务。公司分管人须具有所选业务的查看/审批权限，部门分管人的实际审批资格在流程发布及提交时核对。组织编辑器默认折叠分管设置，保存回读显示姓名和工号；同一人员不能同时担任该组织主负责人及分管负责人。部门范围权限覆盖已管理的部门及启用子部门，操作授权仍单独配置。

## 员工与账号生命周期

人员主职、兼职及汇报关系共用入职、登记纠错、调岗、返聘及审批表单编辑器。普通档案编辑保留任职信息；真实任职变化通过对应变动办理。管理员可纠正登记错误，但须填写原因，受版本、关系和交接约束。只展开分区或勾选纠错不会丢弃草稿；真正修改后离开需要确认。

账号页显示关联工号、职位及状态，并链接人员档案；人员页显示账号当前状态并链接权限管理。姓名、部门及任职信息以人员档案为准，事务同步关联账号。账号页面维护密码和权限，不维护第二套人员事实。

| 变动 | 生效行为 |
| --- | --- |
| 入职 | 建立试用或正式档案；不自动创建登录账号，同一请求重试不重复建档 |
| 转正 | 试用转正式，记录日期；保留账号及权限 |
| 调岗 | 更新主职、兼职、职位及汇报，同步账号任职部门并撤销旧会话；不自动提权 |
| 离职 | 核对未结申请、审批、会议、借用品、办理分工、主/分管负责人及业务资料归属，交接后停用关联账号 |
| 返聘 | 沿用原人员身份，建立新一轮任职；清除上一轮截止日期，不自动恢复账号启用状态 |
| 解除账号关联 | 复核人员与账号版本、实际关联及未结职责，保留两者身份和历史，撤销旧会话 |

正式入职、转正、调岗、离职、返聘统一通过人员变动申请、已发布流程和真实业务签署生效；删除直接办理接口和可选审批开关。首次建档与未使用误建纠错保留受控入口，技术维护身份不能签署审批。联系信息和私密资料维护独立授权。

单位任职页展示公开任职、有效期、引用与交接影响；获人员变动申请权限的用户从“申请任职变更”进入统一流程。普通任职无须固定任期；兼任结束日期选填，当天仍有效。同岗位重新任职保留旧期间并生成新 ID。日期和汇报设置按需展开，校验错误自动展开。已经被授权（包含停用授权）、汇报、职责或正式申请引用的任职保留；撤任前处理交接，删除仅用于未使用的误建记录。

可选期限自然到期后，未变更的失效汇报关系不会阻塞无关单位的维护；新建或变更的关系、实际受影响任职和流程路由继续严格验证，不能以此绕过循环、职责交接或当前负责人有效性。

人员审批最终通过时，已经到生效日的变动在同一事务内复核目标版本、状态、组织和交接，完成任职、账号、事件和通知，进入 Completed。未来生效的变动保持 Approved 并登记持久执行订单；到期重新核验，失败保留 Blocked 及原因。获准业务人员可重新核验；事实已改变时取消未生效变动后重新申请。取消和重试均使用幂等键，保留原批准内容和历史签署。

日常及资源申请使用登录账号关联人员在当前单位的有效主职或兼任；管理员可显式代选有本单位任职的人员。提交账号与实际申请人员分别保存，二者均不能审批本人申请。SQLite 与 PostgreSQL 使用相同规则。

新员工不复用另一人的编号。账号停用、权限收紧、调岗、离职或解绑不得留下无效审批和办理分工：检查流程草稿、启用版本及在途任务；先交接任务、更新并发布定义或停用新提交，再调整账号。共享方案变更检查所有实际继承者；独立配置不受无关方案变化影响。

发票、付款及其他业务资料的交接数量在人员详情和离职核对中显示，管理员从“维护工具 → 数据归属改派”处理。改派按实际选择分类统计，版本更新与审计同事务，任一失败全部回滚；停用来源账号仍可补交接，目标账号须启用。新建权限方案先在弹窗选择起点或兼任职责，普通审批快捷操作保留原数据范围；普通员工默认不开放付款打印及模板管理。

## 授权边界

单位身份与主身份共用方案及动作目录。可供单位分配的操作单独声明，不能按“是否支持数据范围”筛掉公告和通知；非记录资源的“全部”只代表功能授权，公告仍限当前单位及公告受众，通知仍限实际收件人。系统信息只开放查看，系统维护权限不下放。预置员工方案可以直接分配给单位身份，流程协作方案只包含实际 OA 流程的查看和审批；供应商评价确认属于销售操作。

快捷设置按动作保留已有范围。例如查看公司数据、仅编辑本人数据的方案减少管理动作后，编辑仍限本人；新增动作从明确默认范围开始并受单位上限限制。仅有流程或任职管理权的身份可以打开公开人员选择器，组织修改和私密档案另行授权。审批移交和实际签署使用同一独立复核限制，实际代理签署人也受重复签署检查。

模块决定功能开放，操作权限决定可执行的动作，数据范围决定普通业务读取范围，流程任务决定具体审批责任。职位和负责人身份本身不授予操作权限。

部门范围包括有效任职部门、本人负责的部门及启用子部门；普通成员不因任职上级部门自动获得下级范围。公司隔离始终生效。明确分派的审批任务在同公司内授予该申请的参与访问，仍须有对应查看和审批动作；不再强制给指定审批人公司级数据权限。

“仅查看本人及分派的 OA 申请”限制普通列表为本人、审批任务、有效直接代理和获批后分配的办理事项。公司领导也可启用。私密人员档案、财务接收、资源交付和系统管理分别授权。后台每次请求及写事务重新校验当前账号；角色名称、界面按钮和旧通知不能代替授权。

共享方案和账号可关闭模块；继承者不能重新打开方案关闭的模块。变更权限来源、普通角色时保留额外限制。管理员身份不能作为普通组合职责。公司/部门审批方案只是配置起点，可按实际业务删减；组合方案保存为独立快照，不跟随来源级联变化。

## 流程定义、发布与执行

共 13 个独立定义：请假、加班、报销、出差、采购、通用申请、会议室、物品领用，以及入职、转正、调岗、离职、返聘。默认草稿为“部门负责人 → 公司领导”，初始尚未发布，必须核对职责后显式发布。

每份定义最多 32 个节点，每节点最多 50 位指定审批人，提交实例最多 200 个任务。节点编号稳定，显示名称可编辑；前置节点可以为零个或多个，必须形成无环依赖图。

| 能力 | 执行语义 |
| --- | --- |
| 串行 | 下一节点等待指定前置节点完成 |
| 并行与汇合 | 无前置节点同时开始，多个前置节点全部结束才进入汇合节点 |
| 会签 All | 本节点所有有效责任人同意才通过 |
| 或签 Any | 一位责任人同意即通过，其余任务关闭为未签署，不伪造签名 |
| 比例 Ratio | 按发布的比例、最低人数和否决政策计算；一个自然人不因多身份重复计票 |
| 加减签与指定退回 | 按发布政策开放，只处理当前受控节点；保护必经职责、最低人数、独立复核及材料权限，退回产生新执行代次 |
| 子流程 | 展开固定发布版本，保存输入与父子绑定，父节点等待子流程结果；递归和累计容量受限 |
| 暂停/恢复/终止 | 管理身份记录原因；暂停按节点政策处理时钟，终止不删除真实签署或已发生的办理结果 |
| 条件节点 | 节点条件全部满足才执行；跳过节点仍等待自己的前置依赖，不绕过未完成的祖先 |
| 本人回避 | 节点可配置回避提交人/申请人，或阻止提交；最终无有效任务时拒绝提交 |
| 人员兼任 | 允许兼任时逐节点独立签署；独立复核节点禁止与其它节点共用责任人或实际办理人 |
| 时限 | 节点首次激活时持久化开始及截止时间，工作台显示逾期；不自动替人批准 |
| 代理 | 当前生效的直接代理，不递归；实际办理人、原责任人和代理编号分别留痕 |
| 管理员移交 | 日常及人员申请详情选择具体 Waiting 任务和接任人，填写原因，保留已签意见和事件 |

审批来源支持指定账号、任职部门负责人、直属负责人、职能负责人及公司领导。金额/币种仅用于报销和采购；时长用于请假、出差（天）和加班（小时）；还支持部门、类别及人员变动类型。金额使用精确十进制，条件必须同时限定一种币种，不隐式换汇。不支持任意脚本或表达式执行。

部门/公司来源分为“主负责人”和“主负责人与分管负责人”：多人来源按本次业务选择主负责人加匹配分管人，沿用节点会签/或签决策。直属及职能来源按申请所选任职解析。顶层人员没有上级不妨碍已有汇报关系的流程发布，但其申请若需要该来源仍会明确拒绝缺少负责人；已有任职删去启用流程使用的汇报关系须先交接或停用。停用/撤权和调离公司复核启用版本，不能通过修改草稿绕开原版本职责。

本人范围与审批参与身份分别计算：跨部门明确分派的申请进入常规列表、审批待办及详情，计数与分页在过滤后生成。代理只代表合法原责任人；独立复核检查实际签署账号，已经签署其他独立节点的代理不会再次进入可审批待办。审批中心使用一次聚合请求读取授权队列，数据权限不随技术查询能力扩大。

聚合包含会议室预约和物品领用的待审批、交接与归还队列。资源“待我审批”按当前轮次、任务身份及代理查询，使用本人查看范围也可看到明确分派的他人申请，不追加提交人筛选。列表提供相同筛选，普通资料仍按原范围读取。

保存草稿不发布。点击“保存并发布此流程”先保存设置，再独立生成不可变版本及启用指针；两个请求分别检查版本并提示实际失败。停用不撤销在途申请。代理及办理人员按当前配置核查；提交前预览与正式提交共用同一解析器，正式提交重新核对。

## 申请、审批与业务办理

日常流程状态：

```text
Draft ─提交→ Pending ─全部通过→ Approved ─办理→ Completed / HandedOff
                 ├退回修改→ Returned ─修改重提→ Pending（新提交轮次）
                 ├最终驳回→ Rejected
                 └撤回修改→ Draft
```

草稿/退回修改可编辑。最终驳回是终态，需要重新建立申请。审批任务必须提交服务端返回的 taskKey 和记录版本；同一旧版本只有一个写入成功。退回/驳回关闭余下未签任务，保留已签意见。撤回及取消使待办失效，旧提交档案继续保留。

审批通过表示授权决定；财务接收、采购验收、用印、领钥匙和实物发放是后续办理，不能由“批准”冒充已执行。报销接收为 HandedOff，不生成账务、不支付；原付款/报销打印模块继续独立。

申请页把销假、加班确认、出差归档、采购验收和通用办理并入页签，采用与业务一致的动作名称；空列表隐藏分页。报销页保留财务接收入口，去除与 OA 无关的旧付款打印链接和重复长提示。作废采用独立操作授权。

会议室与物品先保存草稿及附件，核对后显式提交，复用同一审批、提交档案和可编辑审批单。仅原申请身份可以修改草稿，部分上传失败保留成功文件和待重试项，可从申请列表的草稿继续编辑。提交重新检查时段、任职、权限和发布定义，冻结正文及原件；草稿不占用会议室，Pending 即参与冲突检查。物品全部通过才预留库存，发放扣减在库量，借用品支持分次归还；消耗品发放即完成。资源资料折叠区提供附件、正式 PDF/原始材料及未签署任务移交，接任人及身份由单位流程管理复核。取消释放时段或预留；已交接不能直接取消，取消已批准申请后正式 PDF 作废而历史保留。

办理分工采用明确的事项或资源组编号。修改办理人可交接未结事项并发送通知；旧人员不能借旧通知越权，申请中的事项名称快照不改写。引用中的分工不能直接删除或改变类别。

请假/出差/加班的已完成时段仍参与同人重叠检查。当前没有考勤、假期余额、薪酬、采购订单、WMS 或会计结算，不将这些功能描述为已实现。

## 审批单与提交档案

每轮提交冻结完整正文、原附件引用、组织/职位、表单名称、模板及流程发布版本。撤回或退回修改后重提产生新轮次，旧档案和原件保留；最终驳回不可复用原轮次修改。

日常、人员、会议室和物品申请最终通过后通过既有文件任务生成审批单；归档文件和任务成功状态同事务发布，失败可重试且不撤销审批。获准查看本申请的参与人可预览/下载 PDF，或下载含原附件和 JSON 清单的 ZIP；作废版本禁用正式下载，保留历史。不补造不存在的旧审批事实。

审批单使用同一 V3 模板设计器与 Rust 排版，默认 A4 白底黑字，申请人、事项、节点签署及结果分区，长说明/多人意见自动续页。普通流程进度、提交前预览、审批单及模板样例不自动附加“会签/或签”名称，只显示节点名称、审批人、实际结果、意见及时间；未实际签署者明确标为无需处理，不能显示为本人同意。设计端保留“会签：全部同意 / 或签：任一人同意”。用户自定义节点名和意见按原文保留。

表单名称、字体及布局可编辑，必需的审批和结果字段必须在可续页正文。恢复默认/黑白样式先修改设置草稿，保存后仅用于新提交。没有电子签章、认证印章或法律效力声明。

财务以申请编号和提交版本核对冻结档案、当前有效性及接收状态。未批准版本不泄露正文；旧版本、作废、无权限与依赖故障分别处理。纸单编号不等同防伪签章，仍须人工核对原件。

附件复用业务库及受管备份：每文件 10 MiB，每记录 20 个/50 MiB，支持 PDF/PNG/JPEG、DOC/DOCX、XLS/XLSX、OFD/XML。检查实际类型及容量，不执行宏或外部实体。头像/证件单图最多 5 MiB。先保存记录再按返回版本逐项上传，部分失败保留成功项和待重试文件，不宣称多个 HTTP 请求是一个事务。

## 公告、通知与待办

公告具有草稿、发布、撤回、归档、受众、有效期、附件及按发布版本确认阅读。未发布草稿可带原因删除，发布历史和回执保留。阅读不会完成审批。

通知与业务事件在同一事务中按事件/接收人去重。列表、未读数、详情及关联入口复核当前权限。流程抄送人可查看进度，完成时通知；申请人可每份每小时手动催办一次。当前不提供后台自动升级、短信或聊天消息推送。

## 模块职责与数据库

React 页面负责展示，hook 管理草稿、查询、版本和取消，生成客户端调用唯一 OpenAPI。Domain 的 approval_policy/approval_conditions 管理定义和类型化条件，approval 管理图及任务状态；personnel_organization 管理纯任职关系。

Engine 的 oa::definitions 管理发布，approval_routing 解析组织与冻结路线，approval 管理任务授权及决定，approval_handover 管理任务交接，personnel_changes 管理任职生效，resource_requests 协调资源草稿及共用档案。handling 负责实物办理分工，office_workflows 负责库存/交接，communication、worklist、submissions 分别负责通知、待办与档案。Storage 复用关系索引批读人员关联并投影会议室在用状态；身份目录只在本次快照复用组织、人员和方案，不缓存跨请求权限。

Storage 保持 SQLite/PostgreSQL 同一事务契约。发布版本和实例快照存于现有 records；workflow_tasks 是同事务维护的任务查询投影，用于责任人、当前任务、历史参与者与期限查询，不是第二套审批状态源。没有引入 Redis、消息队列、第二数据库或 BPM 运行依赖。

数据库为全新 schema 11：有效索引及查询函数直接进入基线，删除旧版本迁移链。旧库、空文件、损坏库或超前版本明确拒绝，程序不擅自删除或改写。管理员显式选择全新数据目录或空 PostgreSQL 数据库；初始化及恢复由维护账号执行，API 账号没有 DDL 权限。备份恢复仅接受当前基线。

正式多人部署为 Full Web/Docker + PostgreSQL 18；Full SQLite 仅作单机测试，审批权限语义一致。Document/Sales 不开放 OA。各平台、真实 PostgreSQL、Tauri 窗口、PDF 和实体打印分别验收。

## 成熟国内 OA 参考与扩展边界

参考已读取的官方公开资料：[泛微 e-workflow](https://workflow.weaver.com.cn/)的串流、并流、条件流及岗位找人；[致远 BPM](https://www.seeyon.com/NewPro/desc/id/20.html)的流程版本、多级匹配、串并行及回退；[通达流程设计](https://support.tongda2000.com/kb11004001/)的步骤/经办权限与[条件流转](https://support.tongda2000.com/kb11004028/)的按天数/部门路由。

多人共同审批在国内 OA 中是成熟能力。本项目明确区分节点内会签/或签与节点间并行/汇合。本人回避、兼任及独立复核策略属于本项目的明确配置，不声称三家具有相同默认值。

当前是有界审批图，不是完整 BPMN 引擎。跨公司审批使用明确的目标单位授权和冻结任务身份；本轮验收见实施清单。子流程、任意节点退回、运行中加减签、比例会签、图形拖拽编排及自动升级尚未实现。后续应扩展定义/领域命令和同一事务内核，增加对应双数据库回归，不再增加第二套流程模式。
