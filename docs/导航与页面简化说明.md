# 导航与页面简化说明

> 2026-10-02：按当前 React + Rust 源码核对。部署与存储以[当前架构事实](./当前架构事实.md)为准；测试证据见[实施进度](./程序改进重构进度文档.md)。

## 单机与多用户的功能范围

正式单机为 Document 单证版和 Sales 业务员版；Full 网页/Docker 使用 PostgreSQL 18，保留单证、销售、行政人事和多账号协作。本地可显式构建 Full + SQLite 测试便携包，以独立目录验证完整界面和登记流程；不进入正式 All、安装器或更新频道。Administration 不再单独打包。

Document 固定首页为单证概览，Sales 为销售概览。Full 优先进入单证概览，权限不足时进入已授权的申请、销售或单证工作页；普通员工默认进入申请与审批。没有可用页面时显示权限说明。单证概览同时要求概览和发票查看，销售概览同时要求概览、客户及商机查看。

## 按任务查找功能

主导航分七组。概览、邮件和关于支持聚合入口，申报词典纳入单一窗口；具体页面和动作各自授权。各岗位沿用相同分组位置；普通员工的公告、通知、申请中心、付款报销打印和文件任务固定在工作台，私人模板仍在资料与工具。未授权分组自动隐藏，默认仅展开当前分组。

| 分组 | 内容 |
| --- | --- |
| 工作台 | 我的待办、公司公告、站内通知、申请与审批、工作概览、付款报销打印、文件任务 |
| 客户与供应链 | 客户与跟进、商机与报价、供应商管理、邮件中心 |
| 单证与申报 | 发票管理、统计查询、业务资料、单一窗口、HS 编码知识 |
| 人事管理 | 人员档案、公司通讯录、员工请假、加班申请 |
| 行政办公 | 会议室预约、物品领用、费用报销、出差申请、采购申请、通用申请 |
| 资料与工具 | 基础资料、报表模板管理、Excel 模板与托单、文字识别、装柜模拟、今日汇率 |
| 系统管理 | 系统设置、账号与权限、组织架构、审计日志、关于与支持 |

实际菜单只显示当前产品、运行模式、可用模块和账号权限允许的功能。聚合入口打开其第一个获准页面；只有申报词典权限的账号也能通过“单一窗口”直接进入词典。工作概览按权限提供单证、销售视图；关于与支持按权限及运行端提供关于系统、软件更新和授权注册。

顶部“查找功能”支持业务名称和“任务中心”“主数据维护”“智能 OCR”等熟悉名称，也能直达单据字段名称、WebDAV、日志、数据归属、权限方案、写邮件和投递记录。结果显示所在分组和页面，搜索沿用同一权限过滤。

默认只展开当前分组，切换分组收起上一组。精简导航栏只显示已授权分组及文字，点击即可展开；手机使用可关闭的抽屉，支持搜索、Escape、键盘焦点循环和返回页面。

## 页面操作简化

- **客户与供应商：** 页面级只放客户目录／跟进记录、供应商目录／采购概览。打开对象后才显示资料、联系人、跟进或供应产品／评价；新增、导入和导出由工具栏发起。商机目录打开所选记录后提供资料与报价／阶段历史，避免把目录、详情和操作放在同一排页签。
- **邮件中心：** “写邮件、投递记录、邮件模板”集中在同一工作区。写邮件与投递记录切换保留邮件草稿，返回历史保留筛选和页码；跨模块离开仍检查未发送内容。投递历史按收件人／主题和状态查询，使用服务端分页及数据范围校验，不再限制为最近 50 条。SMTP、发件人和外发规则仍由管理员在系统设置中维护；发票继续从本单据发起附件邮件。
- **HS 编码知识：** 税则目录与智能查询、实例、历史学习、联网补充、年度导入和知识库导入导出使用一套导航。基础资料只提供税则目录快捷入口；流程说明按需展开，不把当前页面伪装为业务完成进度。单一窗口内统一使用“申报词典”名称。
- **人员与业务资料：** 人员档案进入独立详情地址，资料、照片与证件、任职历史和交接事项各有分区；编辑和短操作继续使用弹窗。业务资料打开后集中显示该对象的版本与预览，返回列表保留原查询位置。
- **发票编辑：** 基本信息、明细、运输报关、辅助分析和输出各有页签，切换保留草稿。常用字段直接填写，地址／银行／印章等按需展开；保存栏集中显示金额和保存状态。明细的十个备用列默认隐藏，可在系统设置中指定默认显示数量。
- **付款报销打印：** 工作台统一入口；列表显示付款单号及独立业务参考号，行内“打印/PDF”按记录输出权限直达 `?section=report`。四页签保留草稿，模板管理返回和新建保存后保留所在页签。输出只保留一个 PDF 按钮，桌面每次选择保存位置，网页下载；报销审批和财务接收仍在行政的费用报销页。
- **组织架构：** 公司目录和部门层级表取代逐项大卡片。默认展开两级，按部门或负责人搜索会显示完整上级路径；新建、编辑后自动定位对应部门。

- **批量报表：** 在发票列表跨页勾选后生成批量报表，单次最多 200 张；也可从文件任务按发票号／客户添加。模板、带章选项、后台处理和下载复用同一输出链路，文件任务负责进度及失败处理。“Excel 模板与托单”保留导入模板、空白托单和 Excel 转托单，发票托单操作回到发票页面。
- **报表模板：** 管理页分为模板目录、输出默认值和导入导出。普通员工可复制付款报销模板、修改版式并保存为私人模板，直接用于本人单据打印；只有发票查看权限时才提供出口单据数据域。文件模板、个人及共享模板进入同一个可搜索目录，标明来源、状态和默认项；设计、生命周期和文件操作独立授权。公共文件和全局默认限管理员，设计器保持独立页面。
- **物品领用：** 卡片优先展示登记／申请和补充库存。库存流水、盘点、编辑通过“更多操作”展开，分别保留原权限校验。领用、发放、归还记录继续在页内标签处理。
- **名称与定位：** 菜单名称和普通页面标题共用一份定义。编辑页保留“新建发票”“报表设计”等操作标题，所属业务分组一致；HS 税则目录和知识页面只激活同一导航入口。

## 详情定位与权限方案

客户、供应商、商机和业务资料以受控查询参数标识当前对象，人员使用 `/office/people/:employeeId`。列表的查询、页码和页容量保存在地址中，返回目录时继续使用；非法对象编号不会被当作有效记录。客户、供应商和商机由按编号读取的 API 定位，读取仍执行原有对象数据范围，不依赖预载前 100 条目录。

设置分类、单据字段分组、维护子页、账号／权限方案、报表管理视图均可直接定位。例如 `/settings?section=documentFields&group=payment` 打开付款字段名称，`/system/access-control?view=templates` 打开权限方案。地址只描述当前位置，未保存表单仍在 React 内存中。

账号与权限的功能模块按主导航位置分组并支持按页面或动作查找。一个邮件中心仍包含邮件模板和发送／投递等独立资源；人员档案与通讯录仍按不同动作控制私密信息。资源键、动作键和数据范围不因菜单聚合而合并，技术依赖继续由服务端派生。

## 权限闭环核对

来源顺序为账号独立配置、指定共享分组、岗位默认分组，选取一个来源；空独立数组明确拒绝业务。账号额外关闭模块与分组关闭模块共同生效。修改权限、岗位、密码或停用账号后，旧会话须重新登录；停用分组保留配置但有效权限为空。账号、人事关联、交接和最后一位管理员保护见[行政协作文档](./公司行政协作设计与验收.md)。

| 范围 | 入口和操作边界 |
| --- | --- |
| 单证、付款、统计、基础资料、HS、申报、Excel/OCR、装柜、任务、汇率 | 模块开启并具有具体查看动作；新建同时要求查看和操作。管理不自动取得编辑权，缺少查看时在权限编辑器提示 |
| 发票/付款详情与输出 | 查看、编辑、管理、预览、打印、PDF/ZIP/邮件分别校验；记录所属公司、部门和所有者收紧按钮与表单，后台继续复核 |
| 客户、联系人、跟进、商机/报价、供应商及子资料 | 页面按所需资源查看权限开放；各子操作及记录范围分别授权，依赖不授予额外写入权 |
| 报表模板及图片 | 模板查看与设计/复制/发布等独立；私人/共享/公共原稿、受众与所有者约束由服务端决定，公共文件维护和全局默认限管理员 |
| 邮件 | 发送和投递记录分别授权；邮件模板独立，SMTP/发件人策略限管理员 |
| 人事 | 通讯录只需查看；私密档案、附件和任职操作另外授权 |
| 六类 OA、会议室、物品 | 有任一对应查看权限才显示申请中心；办理同时校验动作、范围、状态、当前审批人及版本；OA 固定当前公司边界 |
| 费用报销接收 | 保留本人查看，另授予财务接收及其范围；财务视图只允许已批准/已移交，不扩大他人草稿可见范围 |
| 公告、通知 | Full 专属；公告受众与发布状态、通知本人及关联业务当前权限共同过滤 |
| 账号、组织、审计、审批规则/代理 | Full 管理员；直接地址、搜索和页面入口共用判断 |
| 设置、授权和更新 | 设置/授权限管理员；更新还须桌面模式，安装和信任检查仍由 Tauri 执行 |

菜单、搜索、首页和直接地址共用 `workspaceAccess`，模块访问级别不能取代具体动作；应用壳只保留一次权限跳转。无权限的直接地址回到可用工作页并提示，后端接口独立拒绝越权。已有未知或不完整权限不自动补授，不修改数据库或历史记录来让界面通过。

自定义候选项等技术依赖由统一 OpenAPI 权限目录派生，技术维护动作带入同资源读取，保证独立配置账号能正常加载选项；不扩展普通业务的查看或编辑权。候选项写入在事务内重新校验账号与权限。保存单据的更新标志来自实际写入编号，更新既有单据不会再被提示为新建。

切换会卸载的编辑分区、跨模块跳转及浏览器返回／前进均检查草稿。取消离开保持地址、当前对象和输入一致，连续点击返回也执行同一保护；确认放弃后清除对应草稿状态，避免重复提示。邮件和报表中保持挂载的分区可切换查看并保留草稿，更换模板或离开工作区仍检查尚未保存内容。

## 保留的业务边界

以下页面看起来相近，但服务于不同任务，继续分开：

| 页面 | 分工 |
| --- | --- |
| 我的待办 / 文件任务 | 前者处理需要人工办理的业务事项；后者查看后台处理、下载结果、取消和重试 |
| 发票管理 / 统计查询 | 前者创建和维护单据；后者按日期、客户和商品统计、检索、导出明细 |
| 客户跟进 / 基础资料中的客户 | 前者处理销售联系人、跟进和商机；后者维护制单使用的往来资料 |
| 报表模板管理 / 报表设计 | 前者选择默认模板、维护文件及模板包；后者编辑所选模板版式 |

本次重构集中在入口组织、默认信息量和操作方式。复用现有 React 组件、查询、领域服务和授权，不增加 UI 框架、第二份 API 契约、客户端持久化或数据库兼容层。

## 回归入口

- `npm --prefix apps/export-doc-web run test:workspace-navigation`：导航唯一归属、标题、权限、搜索和默认页。
- `npm --prefix apps/export-doc-web run test:workspace-ui`：真实 React 控件的桌面／手机导航、键盘操作和批量发票选择；使用受控接口夹具。
- `npm --prefix apps/export-doc-web run test:navigation-reorganization-ui`：对象直达、返回定位、连续历史导航、客户草稿、邮件分页及独立权限、统一模板目录和跨页批量报表。
- `npm --prefix apps/export-doc-web run test:office-ui`：行政表单、交接、权限、更多操作和无障碍。
- `npm --prefix apps/export-doc-web run test:document-editor-ui`：单据和设置保存、分类深链、维护定位及窄屏布局。
- `node scripts/test_permission_navigation_ui.mjs`：真实 Rust 登录能力、全部内置岗位导航、直接地址、独立管理/编辑动作与跨账号单据范围；使用隔离数据目录。
- `node scripts/test_account_permissions_ui.mjs`：真实账号创建、共享分组、独立权限、关闭模块、旧版本冲突和草稿保护。
- Rust `product_editions` 回归核对版本资源权限、登录续期和同库数据保留；`test_native_desktop_editions.mjs` 实跑 Document/Sales 两版 Tauri；Full 团队的行政业务和申请审批另由 PostgreSQL 实库回归验证。保留的 Administration 契约测试不代表仍有该版单机包。

既有缩放、视觉、脚本、依赖治理和发布锁图门禁继续执行。浏览器界面夹具不能替代真实 API 验证，跨 RID 构建也不能替代目标设备安装验收。
