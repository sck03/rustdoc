## 实施范围

- 部门负责人本人申请由 Domain 判断是否满足明确的部门本人回避规则，Engine 核对有效任职与真实自然人，并要求后续独立公司领导审批。缺人、缺权限及受保护复核继续阻断，跳过原因进入计划。
- 单位非记录范围授权允许 all，普通记录仍受单位范围约束。平台及本单位有效发布版本由 Storage 合并查询，目录与版本读取共用上限/归属规则，单位管理员不能修改平台方案。两库身份投影将无任职管理身份的 appointmentId 输出为空字符串，符合既有响应契约，修复授权目录加载失败。
- 人员、账号及审批候选使用公共标签批量投影；删除重复的逐人员完整档案读取。材料名称与对应标识字段共同受权限控制，申请保存部门名称快照。
- 七类 OA 草稿可由原申请身份删除，检查当前编辑资格、完整材料权限、版本、从未提交及无审批历史；关联临时附件和事件同事务删除，审计及命令回执保留，成功重试返回相同结果。已提交/退回/取消历史不适用。
- 部门排序使用完整同级 ID 集合与每行版本，原子保存并发冲突时整体回滚。界面支持指定位置、上移/下移、置顶/置底，不改变层级；组织表格在宽窄屏保留操作宽度。
- 权限默认展示全部分类，继承来源始终使用所选发布版本，加载期间禁用转换/保存。保存提示明确草稿、发布和应用的区别。共享按钮空闲无空图标槽，加载使用叠层保持尺寸。
- 申请列表提供编辑/提交、审批、办理和详情入口，仍由详情完成当前权限及版本核对。更新三份 Markdown/PDF 手册和统一操作手册。

仍采用 Tauri 2 + React 19 + Rust 的现有分层，SQL 不进入页面或协调器。两库只维护全新 schema 18，指纹随约束变化；不加入旧库兼容、第二套契约或新运行依赖。新增接口和字段由原生定义生成，独立冻结契约审查保留其它认证、错误、权限和容量元数据。
