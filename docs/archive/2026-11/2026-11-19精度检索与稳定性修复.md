# 精度、检索与稳定性修复

分析基准：`c0481632`。本批按用户要求完成修复、集中验证、无效代码与测试输出清理，并以普通快进方式交付 main。

## 实现边界

- 发票、商品及关联金额 DTO 使用十进制文本；Rust Decimal 的可空字段也按相同声明生成。React 共用数值输入生命周期及展示控件，精确计算、剪贴板、商品库和保存不转为浮点数。自然日、整数编号、金额舍入及权限规则不变。
- DTO 文本解码、输入契约及 Domain 复用一个严格十进制解析器；拒绝科学计数、下划线、超范围和会丢失精度的输入，可空字段仅以 null 表示空值。复现的默认解码器接受 `1e3` 等非契约输入已纳入回归；移走 Domain 原有解析实现后直接复用，未复制第二套规则。
- 最新隔离 HTTP 宿主验证六类非法十进制请求均为 400，按唯一发票号查询确认零写入；同一服务的正常币种、核对和状态历史 React 流程通过。
- 共用算术夹具增加数量 `123456.000049999999`、单价 `100` 的临界案例，精确结果为 `12345600.00`，覆盖负数和相邻舍入边界。真实 React 表格验证输入、请求和回读保持全部小数位。
- 极端数字粘贴可使衍生结果超过文本长度限制，原实现会在 React 状态更新中抛出异常。明细编辑现在先完成计算校验，再同时发布草稿和撤销快照；失败显示错误且保留原值，不污染撤销/重做。15 个真实表格/保存场景通过，包含失败后纠正、撤销、重做及再次保存。
- 会议室和物品申请复用身份分区，第一次保存成功后锁定申请人、任职和项目；附件失败后可修改业务内容并重试同一草稿。
- HS 智能查询分批读取全部实例，按编码只保留必要证据。反馈按规范化查询文本定位，SQLite/PostgreSQL 同事务维护 `hs_search`，新增 `records_hs_feedback_query`。全新 schema 18 指纹更新，不迁移旧实验库。
- HTTP 继续使用原有 128 MiB JSON 响应预算，写请求执行前按声明预留，有界等待释放通知；等待者受现有请求名额限制。固定回执、票据、注销和批量状态回执使用 64 KiB。没有把缓冲计数宣称为进程 RSS 上限。
- `/livez`、`/readyz` 的 GET/HEAD 由唯一原生契约声明探针类别。存活不访问依赖；就绪在独立名额内检查服务健康，成功无正文；`/healthz` 保留详细诊断。
- HS 只读详情使用 FetchRemoteHsCodeDetail，权限为 view，不触发候选采集；采集/解析继续要求 manage。
- 退役 UpdateMeetingBooking、UpdateOfficeSupplyRequest，通用资源目录允许没有更新操作；专用草稿 API 保留。
- 进一步核实并退役 GetCustomsCooProducerProfile、ListAvailableExchangeRateCurrencies、GetReportTemplateV3Contract。前两者分别由现行分页目录和汇率结果覆盖；V3 纸张/限制模型保留在唯一原生定义中，通过共享模型元数据生成，固定描述 JSON 删除，自省测试直接验证 OpenAPI。
- JSON 用例回包在 NativeService 共用同一编码入口；HS 排序阶段只保留候选编号、评分和计数，最多批量回读最终 50 条展示明细，不保留全部匹配实例正文。

## 清理与交付

初始清理器盘点显示 target 为 64,920.4 MiB，是主要空间占用。清理在全部编译、测试及 doc-test 退出后进行；复用下载、浏览器与编译依赖缓存，先确认临时程序和隔离数据用途，再删除精确路径。交付前记录实际释放量与保留文件校验。

开始时本地和远端仅有 main；本批使用临时 codex/precision-query-stability 分支，完成后快进合并并删除临时分支。

Linux/macOS/ARM64、Firefox/WebKit、正式安装升级和现场长时间运行需对应环境独立验收。
