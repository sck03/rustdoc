## 实施范围

| 问题 | 实现与边界 |
| --- | --- |
| 账号迟到响应回填旧会话；密码被操作缓存保留 | 保存、删除、刷新和选择复用 `useScopedMutation`，请求取消及每个等待后的作用域复核先于缓存写入；密码只作短期命令输入 |
| URL 账号参数变化不切换；新建被首条记录覆盖 | 按已提交路由选择账号；首次初始化与新建分开，新建草稿参与未保存保护 |
| 生成二进制响应绕过预算 | `downloads/generated` 统一授权与工作容量准入，HTTP 仅适配 `Download`，发送结束才释放内存结果 |
| CRM 批量更新和办公引用全表读取 | 复用 Storage `records_by_ids` / `record_exists`，授权、冲突及事务约束保持 |
| 审计 Excel 编码长期占用连接并构造整张 XML | `audit/export` 捕获授权快照到匿名文件，释放连接后逐行写 ZIP；共享 Excel 写入器、取消及磁盘预算覆盖最终 flush 和本机复制 |
| 恢复任务失败/取消后仍可在启动时恢复 | 校验阶段只生成 `PreparedRestore`；最终事务重验授权、写审计并发布标记，原任务文件发布日志解决崩溃窗口；提交决定持久化后不依赖可清理的任务历史 |
| 备份数据库与对象清单不一致、额外对象无法回收 | SQLite 使用快照数据库清单；两库安装均只复制恢复数据库登记对象；保留暂存用于重试，启动不重复解包，复制取消/空间失败执行独立补偿 |
| 重试和主动再次发送被内容哈希混为一谈 | 原生契约增加可选发送键，前端复用跨内网 HTTP 可用的 `createRequestKey`；同次失败沿用键，接受/草稿变化后轮换；确认不明禁止自动重投 |
| 自定义邮件正文写入任务 `_retry` | `tasks/sensitive` 只在进程内有界保留正文，序列化描述仅带随机引用；输入失效明确要求重新填写 |
| 自动文件下载因一次临时错误停止 | 复用查询重试策略，连续最多两次退避，成功清零，永久错误/取消/总期限仍结束等待 |

删除重复的 HTTP 文件名/类型适配、整表 XML 累积和第二次恢复解包，复用现有任务、查询、取消、路径和预算模块。保留产品实际使用的 OCR、PDF、Excel、邮件等 feature；没有用删除功能、有效夹具或默认资源换取包体积。源码、冻结契约和参考资源中未发现需保留旧 C# 工程或真实数据库文件的理由，Git 当前追踪清单也无这些退役工程/数据库。

源码体积基线按本批真实物理行差额更新，单文件上限和增长余量不放宽。新增内容主要为提交恢复边界、有界流式写入和故障回归；代码总行数增长不被描述为性能改善。性能改善依据是消除全表读取、整表 XML 副本和长时间占用数据库连接，未宣称未经测量的百分比。
