# 多平台与多架构支持矩阵

> 最近更新: 2026-08-07
>
> 适用主线: `Tauri v2 + React/Vite + ASP.NET Core API sidecar + Domain/Application/Infrastructure`

## 1. 当前结论

项目代码主线按 Windows/Linux 的 x64、ARM64 与 macOS Apple Silicon ARM64 维护，不再把 Windows x64 当成唯一编译事实源。

- React/Web 页面为三平台共享源码，响应式断点覆盖桌面、中等宽度和窄窗口。
- Chromium、Firefox 与 WebKit 已完成桌面 `1440×1000` 和手机 `390×844` 场景验收；严重无障碍问题、页面异常、HTTP 500 和横向溢出均为 0。Safari 由 WebKit 场景覆盖主要兼容契约，正式商业发布仍需 macOS/Safari 真机复核。
- Tauri 主窗口使用平台无关 `Path/PathBuf` 与 `WebviewWindowBuilder::data_directory(...)`，WebView 配置、缓存和浏览器状态固定进入运行数据根 `WebView/`。
- Tauri `runtime-paths.json` 使用同目录原子替换和 `.bak` 恢复，严格校验 schema；损坏配置不会静默切换到默认空数据库，未来 schema 也不会错误回退旧配置。
- 首次安装可显式选择 DataRoot 并执行真实写入探针；不要求第二块磁盘。只有系统盘时可选择该盘上的专用目录，禁止磁盘根、相对路径、链接或不可写目录；非便携安装后续可整体迁移。
- .NET 普通构建根据当前宿主操作系统和进程架构选择 `win/linux/osx × x64/arm64` RID，避免把全部 native runtime 重复复制到每个 `bin`；交叉验证和发布可显式传入 RID 覆盖。
- `prepare-tauri-bundle.mjs` 支持 `win-x64`、`win-arm64`、`linux-x64`、`linux-arm64`、`osx-arm64` sidecar RID；Intel macOS 已随 ONNX Runtime `1.28.0` 升级明确退役。
- Chrome for Testing 供给脚本只接受 Apple Silicon 的 `mac-arm64`，自动检测到非 ARM64 macOS 或显式传入其它 `mac-*` 平台都会终止；跨平台字体/PDF 工作流固定 `macos-15` ARM64 runner，不再通过浮动 runner 间接恢复 Intel macOS。
- GitHub Actions 已建立 Windows/Linux x64 与 ARM64、macOS Apple Silicon ARM64 的 Infrastructure 编译契约和原生 Tauri 检查，以及运行数据根/依赖诊断/系统目录禁用专项测试；另有三个仅手工执行的桌面打包入口，分别输出 Windows NSIS、Linux deb/AppImage、macOS ARM64 dmg。
- Document、Sales、Full 使用独立 Tauri identifier、稳定/预发布通道、`latest-*.json` 和 Release 资产。`publish_release=true` 仍强制每个产品版配置 updater 公钥、带密码私钥和私钥密码；Windows Authenticode、macOS Developer ID 与 Apple 公证当前暂缓到正式商业分发，不属于本阶段门禁。
- 容器按职责选择基线：数据库固定官方 `postgres:18.4-trixie` 多架构镜像，API 运行层为 `debian:trixie-slim`，Node 与 Rust 构建层使用 Trixie 变体；Web 最终层只提供静态文件和反向代理，使用更轻量的 `nginx:1.30.4-alpine3.24`。这些镜像均已确认覆盖 amd64 与 arm64/v8。数据库初始化使用 PostgreSQL 内置 `PG_UNICODE_FAST` Unicode locale，不依赖容器 glibc 默认排序。
- 容器 API 使用 Debian 13 原生 `chromium`，PG 工具使用 `trixie-pgdg` 的 PostgreSQL 18 客户端。Microsoft Container Registry 当前没有稳定版 .NET 10 Trixie SDK/ASP.NET 标签，因此 .NET 构建层保留官方 `10.0.302-noble`，运行层从 Microsoft Debian 13 仓库安装构建时可用的最新稳定 `10.0.x` Runtime，并验证 ASP.NET Core 与 .NET 共享框架补丁版本一致；这不改变最终 API 容器的 Debian 13 运行基线。

## 3. 跨平台边界

### 3.1 字体与报表输出边界

- 正式 PDF 和无头浏览器导出由 `ReportFontPolicy` 注入程序根 Noto CJK 字体；不要求目标系统安装微软雅黑、宋体、Arial、Segoe UI 或 SF Pro。
- 浏览器打印预览复用服务端 HTML，并在打印前等待字体和图片资源；跨平台归档、分页和换行需要使用生成 PDF 作为唯一保真输出。
- Windows 已完成本机真实长文本 PDF 验证；macOS/Linux 已建立原生 runner 的字体、分页和 PDF 指标比较工作流，但在工作流成功前仍标记为 CI 待验证，不冒充生产设备验收。
- 字体 manifest、许可证和哈希由 `scripts/verify-font-license-policy.mjs` 与发布包审计共同校验，字体二进制不进入 Git。

- 业务层不得引用 WinForms、`Microsoft.Web.WebView2`、`System.Drawing.Common`、Registry、WMI 或平台文件对话框。
- 文件与目录使用 `Path`、`PathBuf`、`path.join` 和 Tauri desktop command，不拼接反斜杠作为业务逻辑。
- 稳定资源位于程序根；数据库、缓存、安全文件、WebView 数据和业务可写数据位于运行数据根；用户导入导出使用显式选择路径。
- 运行数据根策略按“可写专用目录”判断，不按盘符判断。Windows 只有 C 盘、Linux/macOS 只有单卷均可运行；推荐非系统盘是容量和故障隔离建议，不是兼容性限制。
- Windows `WebView2Loader.dll` 只在 Windows bundle 中要求；Linux/macOS 不复制该文件。
- OCR、浏览器渲染器、PostgreSQL 工具和安装器属于平台适配资产，按 RID/平台分别打包，不进入 Domain/Application。
- Tauri/Web 客户端不直接加载 PostgreSQL 容器 libc：浏览器/Tauri 访问 ASP.NET Core API，API 通过 Npgsql 网络协议访问 PostgreSQL。数据库镜像 libc 只影响服务器端扩展和 libc locale；当前容器默认使用 Trixie/glibc，并以 PostgreSQL builtin locale 固定文本行为。独立 Linux 浏览器服务器包为扩大宿主兼容范围，仍可携带从 Bookworm 镜像提取的 PostgreSQL 18.4 客户端，这与容器运行基线互不混用。

## 4. 当前验证入口

- Web: `npm --prefix apps/export-doc-web run build`
- Tauri 当前平台: `cargo check --manifest-path apps/export-doc-tauri/src-tauri/Cargo.toml`
- Tauri 路径契约: `cargo test --manifest-path apps/export-doc-tauri/src-tauri/Cargo.toml`
- .NET 路径契约: `dotnet test tests/ExportDocManager.Infrastructure.Tests/ExportDocManager.Infrastructure.Tests.csproj --filter "FullyQualifiedName~RuntimeAppPathProviderTests|FullyQualifiedName~InfrastructurePathPolicyTests|FullyQualifiedName~RuntimeDependencyDiagnosticsServiceTests"`
- 当前宿主 .NET: `dotnet build src/ExportDocManager.Api/ExportDocManager.Api.csproj`
- 显式架构: `dotnet build src/ExportDocManager.Infrastructure/ExportDocManager.Infrastructure.csproj -r <rid>`
- 自动矩阵: `.github/workflows/cross-platform-validation.yml`
- Linux x64 独立服务器 OCR：手工运行 `.github/workflows/linux-browser-server-package.yml`，复用工作流会检查模型/`.so` 并执行 `--verify-ocr-runtime`
- Docker Linux amd64 OCR：手工运行 `.github/workflows/container-images.yml`，API Dockerfile 在 amd64 构建层执行 `--verify-ocr-runtime`
- Firefox/WebKit：`npm --prefix apps/export-doc-web run test:cross-browser-ui`
- 真实 Tauri WebView：`npm --prefix apps/export-doc-tauri run tauri:smoke:single-window:local`；2026-07-30 最近一次隔离闭环为 COO=`Approved`、ACD=`Accepted`、双抬头双卡且仅一个活动档案

## 5. 后续验收

1. 在 Windows ARM64、Linux ARM64 和 macOS ARM64 真实设备上运行 Tauri 主程序与 sidecar。
2. 为 Linux/macOS/ARM64 准备对应 Chrome Headless Shell 或明确采用系统 Chromium 的受控策略。
3. 运行 Linux x64 独立包与 Docker amd64 首次远端构建，记录 `--verify-ocr-runtime` 输出；继续评估 Linux ARM64 与 macOS ARM64，未验证前保持明确“待真机验收”，不静默降级。
4. 分平台完成 Tauri updater endpoint、包签名、安装升级、失败回滚和卸载测试；Authenticode、Developer ID 与公证在正式商业分发前另行启用和验收。
5. PostgreSQL 团队版按平台提供或显式配置 PostgreSQL 18 的 `pg_dump/pg_restore/psql`，客户端工具主版本不得低于服务器主版本，不假设 Windows `.exe` 文件名。
