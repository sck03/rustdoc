# 单据核对与业务资料待办

> 2026-10-08 按 Rust attachments/worklist 与 React 页面整理。部署与存储以[当前架构事实](./当前架构事实.md)为准，逐项完成状态见[迁移核对表](./Rust原生功能迁移核对表.md)。

本文描述单据核对、业务资料归档和待办。财务核算由独立财务软件负责，正式申报使用官方渠道；现有 OA、采购申请和行政物品流程见[行政协作](./公司行政协作设计与验收.md)。

## 单据核对

- 五金等标准商品可复用商品库；服装可直接录入本次 PO、款号、品名、成分和包装，不强制建立商品档案。
- 草稿可以暂存不完整的客户、出口商和独立通知人。非法字段、容量和数值仍在保存时校验，不把真实存储失败当成“尚未填写”。
- “核对检查”检查当前页面内容，列出需要补齐的字段和编辑器中的真实行号；页面修改后旧检查结果失效。正式核对使用已保存的数据和共用 Rust 业务规则。
- 选择性复制会提示重新确认本次客户资料；正式输出仍沿用后端受控报表链路。

## 业务资料归档

从已保存发票的“业务资料”入口上传，或从“单证与申报 → 业务资料”集中检索。资料关联现有发票，PO、款号选填；名称、分类、PO 和款号可以通过“修正资料信息”修改，同一资料的新版本沿用修正后的信息。

| 能力 | 行为 |
| --- | --- |
| 分类 | 管理员在“管理分类”中新增、改名或删除；每家公司独立目录，最多 100 项，初始公司预置原始资料、确认资料、正式输出 |
| 修正信息 | 修改名称、分类、PO 和款号，填写修正说明；保留原始文件、历史版本和已确认的有效版本 |
| 检索 | 客户、发票号、PO、款号、资料名、各版本文件名；按 NFC 和统一搜索键处理 Unicode |
| 文件 | 原文件归档；当前 Rust 上传校验文件名、非空和容量并保存摘要，尚未统一执行 OA 附件的文件头/Office 容器类型校验，不能把旧 C# 类型白名单写成已实现 |
| 预览与下载 | 图片与 PDF 可预览；下载返回该版本原始字节，桌面下载通过原生保存对话框选择目标路径 |
| 版本 | 上传新版本保留旧文件，不自动改变当前有效版本；确认、停用、恢复均需要说明，并记录操作者和时间 |
| 正式输出留存 | 上传实际对外交付的原文件，后续更换模板不改变已归档内容 |
| 权限 | 查看和下载遵循原发票查看范围；上传、信息修正和版本操作还需操作范围；永久删除需管理范围；共享分类由系统管理员维护 |
| 容量 | 单文件 16 MiB、每份资料最多 50 个版本、每张发票最多 100 份资料及 256 MiB；旧版本和停用资料都计入容量 |
| 备份与删除 | 文件字节、版本和确认记录同库存储，随数据库备份恢复；永久删除资料须填写原因并确认，删除全部版本并释放容量，独立审计继续保留；有关联资料的发票不能直接删除或清理 |

列表和版本目录只读元数据。读取文件时验证长度和 SHA-256；发现损坏返回明确故障。上传使用用户级幂等键和乐观并发版本，并通过数据库事务控制单据总容量，重复请求不会新增相同版本。

停用资料保留全部历史，可在“含停用资料”中查询和恢复。确认与停用记录展示最近 100 条及总数，完整记录继续保存在业务库中。归档不新增文件目录、系统临时目录、第二数据库或客户端持久存储。

分类以稳定编号关联，改名同步所有引用资料；被资料使用的分类（包含停用资料）不能删除，须先重新分类。分类和资料的修改、删除都校验版本，过期页面返回冲突；分类删除与上传在同一业务库事务中协调，避免并发留下无效分类。永久删除后文件与资料操作记录一并移除，独立审计中的原因按脱敏策略处理；如需留存，使用停用功能。

## 我的待办

待办从源业务实时查询，不保存第二套完成状态。源业务完成后刷新即可消失；页面在前台每 30 秒刷新，也可手动刷新。查询在同一事务中读取来源，按权限与日期在应用层汇总、稳定排序和分页；不能把它写成全部由 SQL 分页。

| 来源 | 纳入条件 |
| --- | --- |
| 单据待核对 | 本人的草稿，并且具有查看和操作权限；单机模式显示本地可操作草稿 |
| 客户跟进 | 本人未完成的跟进，同时具有客户查看、跟进查看和完成权限 |
| 行政待审批 | 按资源或六类 OA 的当前步骤、有效代理与授权查询；团队禁止本人审批，Full SQLite 测试保留登记语义 |
| 会议室、钥匙、领用与归还 | 按本人/办理分工读取未结事项；已结束、已归还和发放后的消耗品退出待办理 |
| OA 办理与财务接收 | 已获批待完成、移交或接收的申请；查看、审批和办理是不同权限 |
| 人事到期 | 同时具有人员查看与私密资料查看权限，在当前公司及获准数据范围内查询试用期和劳动合同日期 |

支持全部、已到期、未来 30 天、未设截止日期筛选。自然日按公司业务时区计算，时间点转为 UTC 后查询；没有截止日期的事项不标记逾期。每条记录跳回原业务处理。不会根据“已出运”推断欠款，也不会在没有资料清单的情况下推断缺件。

## 模块与产品版

归档由 [engine::attachments](../crates/export-doc-engine/src/engine/attachments.rs)及 attachment_categories 管理，待办由 [engine::worklist](../crates/export-doc-engine/src/engine/worklist.rs)与 worklist_oa 组合；持久化使用共用 Storage。没有单独的 .NET 程序集或 IWorklistSource 注册流程。

| 单机产品版 | 业务资料 | 待办来源 |
| --- | --- | --- |
| Document | 有 | 单据核对 |
| Sales | 不随包携带 | 客户跟进 |
| Full 本地 SQLite 测试 | 有 | 按权限提供完整待办；不替代团队验收 |

Full PostgreSQL 团队版按产品、岗位、动作、分工和数据范围组合来源。Administration 不再单独打包，旧 .NET 构建属性和 disabled-capability-modules 参数不是当前 Rust 入口。可选能力由 Cargo feature/组合根配置，权限由生成目录控制；隐藏入口不删除数据，共享代码也不等于已经从二进制按产品完全剔除。

已归档字节与历史保存在现有数据库并随备份恢复。Rust 从版本 5 起按有序事务迁移保留数据，不能根据旧 v18 文档删除或重建数据库。

系统级 Authenticode、Developer ID 和 Apple 公证不执行；既有 Tauri updater 包签名和产品版公钥信任合同保持。
