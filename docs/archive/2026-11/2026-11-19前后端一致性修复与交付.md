## 行为与模块

- 付款的十个金额字段统一使用十进制字符串，输入、校验、保存、回读及费用合计不经 `Number`。原生契约生成 Rust Decimal 的字符串序列化和 React string DTO；拒绝超出 Decimal 系数/28 位小数范围的输入，空金额按零处理。
- 单一窗口回执收集返回确定顺序的 `receiptBatches`；每包最多 200 文件、50 MiB。页面先导出第一包，并提供按包导出入口；取消保存仍保留当前候选分包，切换批次、身份或权限取消旧命令。正式保存重新验证文件与容量。
- OA 和会议室/物品操作共用命令回执确认。超时、断线和网关故障沿用原 `commandKey` 查询当前操作者的已提交回执，再读取详情，不自动重发写入；无法确认与已提交但详情刷新失败分别提示。取消沿作用域传播。
- 商机详情在可编辑时查询客户，在报价可编辑时查询产品；只读和归档详情使用已保存编号/名称，不发候选查询。
- HS 的规范化搜索文本在 Storage 写入事务中生成，SQLite/PostgreSQL 共用 Domain 规范化和查询构造，关键词筛选、总数与分页留在数据库。schema 18 完整基线增加 `hs_search`，模型指纹更新；旧实验库使用新隔离目录/数据库，不保留迁移兼容链。
- 只有唯一成功状态为 204 的端点省去响应字节预留并输出空正文；普通 JSON 写入仍在业务执行前取得预算。128 MiB 总预算、64 MiB 单响应、429、断线释放与传输期限保持。
- 退役 `BuildCustomsCooExportReview`、`BuildAgentConsignmentExportReview` 两个重复 POST，页面及回归统一走只读预检 GET；原生定义同步生成 757 操作、711 schema。其余认证、权限、错误与容量继续执行冻结对照。

启动公共初始化、Storage 正式文档投影、Excel 工作表解码分别复用已有职责模块，普通记录不再重复克隆正文。词典表头使用字段键/标签和必要别名，统一规范化，不重复登记大小写或空格变体。十二个 React 回归脚本共享受管临时目录、依赖定位和浏览器启动，保留原场景、断言和失败截图。
