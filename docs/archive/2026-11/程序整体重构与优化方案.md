## 0. 当前完成状态与原方案结论

2026-11-05 核对：正式查询计划和两库搜索成本、三条类型化用例、运行时保护、前端共享控件及脚本接线已经实施。隔离四连接容量复测 P95 988.3 ms，低于 2026-11-02 同负载基线 1,486.64 ms；早先受并行检查影响的失败结果仍保留。此次继续修复附件授权/历史、共享保存及控件状态、设计器测试等待和三项 Actions 失败。§9 勾选对应明确实施与实测范围；系统 IME/DPI、其他平台 GUI、实际安装器升级和独立部署不由本机结果代替，详见[二期记录](../../archive/2026-11/二期重构验收与清理记录.md)。

下面 §0 原结论及 §1–8 的问题、规模和候选设计保留 **2026-11-03 实施前评估** 的语境；例如旧契约组合链和候选 schema 13 均已由正式原生契约（数据库后续已到 schema 16） 替代，不是仍存在的当前实现。任务勾选不连带证明尚未完成的验收合同。

**需要继续做有边界的二期重构。** 保留 Tauri + React + 共用 Rust 后端、职责分层及一期 OA／组织／权限内核。一期 schema 12 的 83 组 Rust 测试、双库、容量与三版桌面结果属于 2026-11-02 的[历史验收记录](../../archive/2026-11/OA重构验收与功能保留台账.md)，不是本轮新增通过。二期按以下五类工作推进；已确认缺陷、设计评估和退役候选分别办理：

1. **契约原生化与客户端按域生成。** 当前冻结 OpenAPI 基线加 Rust JSON 扩展的定义方式维护成本较高，生成的单类客户端进入前端入口。逐步改为 Rust 原生单一定义并按域生成客户端，保留当前操作、元数据和业务语义的对照。冻结 JSON 是构建／契约维护负担，不表示当前程序仍依赖 .NET 运行时；文件行数和 DTO 数量本身也不是重写理由。
2. **先优化存储查询，再冻结 DDL。** 通用查询经重组 JSON 的视图读取，部分表达式索引的过滤或排序能力丢失；OA 已有轻量过滤与按 ID 投影路径，不能一律改查 `records`。先验证真实查询和两库搜索语义，再决定全文索引、审计存储、热字段及外键变更。schema 13 是这些 DDL 变更定稿后的候选新基线；仅修查询不必升版。采用新基线时继续全新建库、拒绝旧库，不做迁移链。
3. **引擎层优先修已确认的问题**：重试未消费源任务、许可校验持全局锁且已注册状态重复验签、流程线程缺少异常退出检测、AI 缺少独立并发门、登录预算检查／计数竞态。重复 helper 和公开 API 退役经用途核实后收敛。
4. **宿主层优先修主线程阻塞与 Windows 更新退出路径。** 原 B02 所述普通并发关闭竞态不符合当前锁作用域，改为关闭超时／失败专项验证。包清单已有实际消费者，保留识别、摘要和安全回收职责后再收敛定义。
5. **测试、脚本与 CI 收敛。** 已核实列出的 14 个脚本未被 npm／工作流／PowerShell／CMD 自动入口引用，但其中有手动验收记录；未接线不等于未测试或死代码。先接入关键回归，再核对退役候选的覆盖替代和脚本／CI 重复，保持平台门禁。

前端按既有三份文档执行，并入本文排期（§9）。顺序为：关键回归与真实基线 → 稳定性及宿主修复 → 查询与存储设计 → 契约／客户端及前端迁移 → 工程收敛与集中验收。

明确不做：不改业务边界（销售域与单证域独立、Excel/手工制单）；不引入新运行依赖、UI 库、Redis、消息队列、第二业务库或微服务；不迁移旧库、旧备份；不放宽任何既有门禁阈值；不做 Authenticode/公证。

### 1.2 已核实的源码事实

- `contracts::contract()` 以 `OnceLock` 缓存一次解析（`contracts.rs:5-10`），服务端每请求读契约不重复解析。
- 路由由 `ALL_OPERATIONS` 循环注册，无手写路由表；请求/响应校验、策略、超时都从契约读取。
- 许可检查 `licensing::check_operation`（`licensing.rs:697-724`）对需许可操作持有 `license_gate`，读取并解密锚点、计算机器身份；存在注册码时在 `status()` 内执行签名验证。试用状态也走锚点校验，但不等同于每次都执行 ECDSA。
- `record_rows` 视图（`workflow_runtime_sqlite.sql:164-172`）重组 `body`，并连接提交档案、流程和办理事实；通用 `query_slice/query_page` 经该视图查询（`sqlite.rs:412,443`）。OA 请求分页已通过 `workflow_record_filters` 先筛选，再从 `workflow_list_records` 按 ID 投影（`record_query.rs:333-368`）。
- 审计写入同时插入 `history`（`body` 恒 `'{}'`）与 `audit_logs`（`sqlite.rs:513-516`）。`history` 还承担正式历史删除保护；`delete_audits` 目前只清理 `audit_logs`，两表职责不能忽略。
- 两库搜索规范化不同源：PostgreSQL `exportdoc_record_text` 按键排序 `COLLATE "C"`（`postgres.sql:121-128`），SQLite 用 serde `preserve_order` + NFC + 小写（`sqlite/search.rs:12-22`）。
- 审计查询一次 `json_group_array` 最多 200,000 行（`sqlite.rs:254`）。
- 桌面 `stop()` 的 `host` Mutex guard 在 `DesktopHost::stop()` 返回后释放（`desktop_runtime.rs:106-121`），普通并发停止串行等待；停止超时／失败如何影响完成状态另行验收。
- 有正文契约的认证请求在读正文前执行 `session_actor_for_operation`（`request.rs:200-218`）；备份上传另有授权路径。
- `Publication::rollback` 明确使用独立有界作用域，确保请求取消后仍可补偿（`tasks/output.rs:280-283`）。
- `schedule_data_root_migration` 是同步 `#[tauri::command]`（`desktop_commands.rs:48-72`）。
- 更新器插件在 Windows 上 `on_before_exit` 后 `std::process::exit(0)`（vendored `tauri-plugin-updater-2.14.0/src/updater.rs:403,1017`）。
- Tauri 命令 `select_receipt_file(s)` 在 `desktopBridge.ts` 中零引用。
- `test_oa_advanced_ui`、`test_permission_navigation_ui`、`test_native_desktop_editions`、`smoke-web-runtime-diagnostics` 在 `package.json`、工作流、`.ps1/.cmd` 中零引用。

### 1.4 有限内存验证

本日只读分析将仓库六份 SQLite DDL 按正式初始化顺序载入**内存 SQLite 3.49.1**。对象数为 46 表／9 视图／38 索引／17 触发器；四组代表表达式的 `EXPLAIN QUERY PLAN` 对比如下：

| 查询 | 基表 `records` | 现有 `record_rows` 视图 |
| --- | --- | --- |
| 任务状态筛选 | `records_status_page` 匹配 kind 与状态 | `records_kind_id` 仅匹配 kind |
| 模板版本筛选／排序 | `records_template_version` | `records_kind_id` + 临时排序 |
| HS 编码排序 | `records_hs_code_order` 提供所需顺序 | 仍使用该索引的 kind 前缀，但追加临时排序 |
| 所有人任务时间排序 | `records_job_owner_time` 过滤并排序 | 仍使用 owner 前缀，但追加临时排序 |

因此应修正“全部索引不可达”为“部分索引的过滤／排序能力丢失”。上述是代表表达式的计划验证，不是完整生产 SQL、Rust 随包 SQLite、真实 PostgreSQL 或端到端性能验收；P0 必须补齐这些证据。

同一内存库中，“上海外贸单证管理”用 `instr(text,'外贸')` 命中 1 条，用默认 FTS5 的 `MATCH '外贸'` 命中 0 条。默认全文分词不能直接替代现有中文子串搜索，S2 必须先定义并验证语义。

## 4. 设计原则（二期）

1. 一事一源：契约、DDL、分页规则、搜索规范化、资源布局各只有一个定义点。
2. DDL 先定稿再建库：仅查询修正可保留 schema 12；确定采用新的 DDL 集合时一次冻结 schema 13，以显式新 DataRoot／新 PostgreSQL 数据库初始化，拒绝旧库和旧备份，不写迁移链。契约按同一事实源重生成，不接受未声明的混用。
3. 筛选先于计数／分页，再按 ID 投影：静态字段走基表；OA 当前状态、任职、身份及材料权限走权威关系或轻量过滤源，不能用缺省／过期的 body 字段替代。
4. 修复优先于重写：引擎与宿主只改有证据的缺陷与重复，不重排模块。
5. 每项改动带证据：性能项附完整生产 SQL 的计划与计时，稳定性项附并发／故障回归；退役项附调用、数据用途及覆盖替代核对。代理报告先复现，无法复现的记录保留理由。
6. 业务边界不动：销售域与单证域不联通，Excel/手工制单路径逐项回归。
7. 保留安全和恢复边界：普通操作继承取消，必要补偿使用独立有界作用域；许可缓存不能跳过可信日期／设备绑定／存储故障检查，登录优化保留未知账号哑哈希。
8. 预算按口径定稿：既有门禁阈值不放宽；候选性能指标在 P0／原型阶段确定测量方法和目标，未实测不承诺收益。

### 5.1 搜索选型与两库语义

- 先定义单字／双字中文、连续子串、英文大小写、NFC、数字／代码前缀、标点／转义及结构化多键查询的匹配规则，建立同一输入、同一结果夹具。默认 FTS5 与普通 tsvector 分词不能假定等价于 `contains`。
- 普通记录、身份投影及 OA 冻结材料分别定义检索来源，保留合法检索范围；私密档案不进入公开索引，当前授权过滤先于计数和分页，不能通过检索结果或数量暴露受限字段。
- SQLite 与真实 PostgreSQL 18 同时验证更新、删除、回滚、重建、备份恢复及超过 64 KiB 的正文。替换现有检索列／函数前须证明语义和容量边界完整；不是直接移除上限。
- 用短词、选择性高／低的词和大正文分别测量查询、写入、索引体积与峰值内存。短词无法有效使用索引时明确准确的处理和容量预算，不承诺全部搜索子线性。PostgreSQL 扩展的准备／权限归维护入口，普通 API 不获得 DDL 权限。

## 7. 引擎与宿主修复要点

- **B01 重试**：输入／容量／授权检查后，在同一写事务重新核验源任务、预留消费并建立新任务回执，第二次返回 409；提交后才启动 worker。提交前失败回滚；提交后启动失败持久化可恢复状态，不能抹掉已经发生的任务／外部输出事实。不要向现有只读 `read()` 中直接加入写入。
- **P01 许可**：对已核验签名结果按注册码摘要、设备绑定和验证版本缓存；授权决策仍检查当前锚点、可信业务日、回拨及存储健康。注册、恢复、锚点／设备变化、日期切换均失效或重新判定，存储失败不得返回旧成功；缓存命中不验签，必要状态锁保持短小。
- **B03 调度**：隔离 `tick` panic，暴露最近错误、最近成功和线程存活，原子协调有界重启／退避。恢复前证明事务回滚及状态一致，不可恢复或锁污染时报告 503；保留既有停止、取消和资源释放。两调度器只收敛相同的生命周期逻辑。
- **B21 AI**：实例级独立并发预算，超限返回 429；启动前预留，取消／失败／完成释放，保持现有受控进程树、输入输出和超时限制。B19 继续用于 `--endpoint-file` 清理。
- **B04 登录**：短临界区原子预留用户名／全局预算，哈希在锁外执行；失败、成功及过期按统一规则处理预留。保留未知账号哑哈希和通用错误；来源限流使用实际连接或明确受信任代理信息，不信任任意转发头。
- **B09/B18 取消**：普通子操作观察父取消且截止不晚于父作用域；补偿、提交后清理和必要恢复显式使用独立有界作用域。分别回归普通复制及时停止，以及取消后旧文件恢复、提交后清理、重启恢复完整性。
- **B02 关闭**：保留当前 host 锁串行语义，先做重叠调用、超时、失败和线程异常回归；有具体复现后才调整完成／失败状态，不预先增加另一套关闭句柄。
- **B05 更新**：Windows `install()` 后不安排关键逻辑或承诺 IPC 成功返回；在安装前的确定执行阶段完成管理员复核、进度、后端停止及窗口收尾，退出钩子只做安全幂等收尾。停止失败须阻止安装，安装失败不得记成功并须保留可恢复状态；非 Windows 安装返回／重启单独验收。
- **B20/P12 迁移**：命令异步化并将阻塞工作移入受控工作线程；复用可证明冗余的摘要扫描，保留锁、源变更检测、目标校验及中断恢复。不以“全程只计算一次摘要”作为通过标准（RR-26）。
- **R01–R04**：`store::page`、`contracts::page`、`store::instant`、`paths::hex/is_hex`、`store::int`、`Jobs::start_authorized`。
- **L05**：按用例把 `Value` 边界收到 DTO 转换处，从 OA 命令、权限解析、发票保存开始。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 原生契约重定义引入隐性差异 | 两端客户端行为漂移 | 解析后语义／默认／错误／认证／权限／容量对照，辅助 schema 用途核对，真实 HTTP 回归 |
| 查询优化只按基表状态筛选 | OA 漏数或权限回归 | 派生状态走权威关系，当前授权先于计数／分页，同快照验证多角色／直接地址 |
| 未定稿即新建 schema 13 | 反复重建和恢复合同漂移 | 先做 S1／原型，P2 一次冻结 DDL 和指纹，显式新库初始化并拒绝旧库 |
| FTS 分词替代中文子串 | 短词、标点或大正文找不到记录 | §5.1 两库同一语义夹具和成本原型后选型，不以 FTS 名称当验收 |
| 审计合并或删“只写”事实 | 审计清理解除正式历史保护或损失取证 | 明确保留类别，回归清理后人员／资源删除保护、历史／恢复；不可变事实按用途保留 |
| 许可缓存或登录优化省略安全检查 | 过期／回拨放行或账号可被探测 | 缓存失效、设备／存储失败、哑哈希、统一错误和原子预算回归 |
| 取消统一传给补偿／清理 | 外部旧文件或已提交结果无法恢复 | 普通子作用域和独立清理作用域分开，取消／提交后／重启故障分别验证 |
| 重试消费与启动跨提交边界失配 | 双份任务或消费事实丢失 | 同事务回执与源预留，提交后启动，前后失败分别持久化／恢复 |
| Windows 安装绕过返回／退出事件 | 收尾未执行或安装失败误报成功 | 关键收尾置于可证明阶段，停止失败阻止安装，平台返回与失败恢复单验 |
| 误删包标记／文件清单 | 便携识别或安全资源回收失效 | 消费者与摘要／保护规则回归后才收敛，D04 不作为零读者删除项 |
| 前端导入路径随客户端拆分变动 | 页面迁移返工 | 前端 P3 排在 RR-06 之后 |
| 脚本接线暴露失效场景或选择器 | 原有覆盖不可靠 | P0 先接关键回归，P5 核对完整套件；区分脚本故障与产品回归，失败如实记录 |
