# 2026-11-08 导入与调度边界修复记录

本批从 `4cc85d99` 开始，按用户授权集中修复六项分析结论，并更新文档、清理已核实的测试输出，最终以快进方式交付 main。数据库继续只接受 schema 14，API、依赖版本和产品形态不变。

## 实现

- 客户/供应商导入使用共享 `useFileImportWorkspace`，新文件立即清除旧结果并取消旧请求；预览期间不允许提交，提交期间锁定文件与快照，目录刷新失败明确说明导入已经完成。
- 客户、供应商及联系人状态/删除与普通保存共用 `useScopedSave`；`runRecordAction` 统一确认、请求、成功反馈和刷新。切换记录、页面、客户端或卸载后旧结果不能重选记录、覆盖草稿或显示迟到错误。状态更新使用版本草稿合并，保留请求发出后的续编。
- 预检与提交共用 `accept_row`；无效行不占名称，后续有效同名行可以导入，提交仍复核当前数据并消费一次性快照。查重按 2000 条分批读取名称投影，避免加载全部档案正文。
- 单一窗口操作中心列表/详情退出写事务；列表通过 Storage `record_selection` 共用字段搜索、权限、过滤、计数与分页，仅返回现行列表字段，详情正文不进入列表中间结果。关键词保持 NFC、大小写规范化与字面子串语义。
- 灾备调度登记当前 OperationScope，30 秒轮次预算与停止取消传播到数据库；计划锁等待最多 5 秒。已启动任务的身份发布与启动失败补偿使用独立有界范围，终态仍由原任务系统负责。
- 审批单状态查询在错误后停止周期轮询，手动重试成功后按 Running/Ready 状态恢复或结束轮询，继续使用共享请求重试策略。
