# 2026-11-09 独立申报与联调记录

## 本批实现

单一窗口新增“申报资料”：输入资料编号即可手工建档，也可先预览客户 Excel 再创建。沿用现有 Excel 解析器和字段识别，不生成项目发票；预览不写业务记录，失败必须重选或清除后转手工。任意客户版式仍可能需要配置或手工输入，不承诺无条件自动识别。

独立来源使用受权限控制的 `sw-sources` 快照，与发票共用默认值投影。COO 与 ACD 分别保存；COO 收货人可为目的地客户，合同、品名、英文详细描述和商品增删顺序不再被源发票覆盖。修复人工商品行重复/删除后恢复的问题；行结构锁与字段锁分开，未锁定的关联字段仍能刷新。

API 路径参数和 DTO/交接清单统一为 `sourceId`。新增来源列表、创建、Excel 预览三个原生端点；生成契约 752 操作、688 运行 schema。SQLite/PostgreSQL 基线为 15，ZIP 交接协议为 5.0；不保留旧库、旧接口或旧包兼容。已有库拒绝打开并保留原文件，使用新 DataRoot/数据库建库。

提交批次在生成或导入时立即保存产地证编号，修复第一份 COO 回执没有批次文件名时无法匹配的问题。回执收集检查 InBox/FailBox 的日期子目录，沿用链接拒绝、10000 项扫描及 200 份匹配上限。包清单合同号来自实际申报草稿。修复界面生成 `.swpkg`、后端只允许 `.zip` 的保存阻断；扩展名校验在生成批次前执行，当前统一 `.swpkg`，内部仍使用受限 ZIP。

`CopCusCode` 改为必填、最多 10 字符的企业内部编号；`TradeCode`/`AgentCode` 仍为 10 位海关编码。补齐 ACD 字段长度、4 位贸易方式、严格 yyyyMMdd 日期和 number(19,4)/(19,2) 总精度边界；新增 COO 空商品阻止导出校验。
