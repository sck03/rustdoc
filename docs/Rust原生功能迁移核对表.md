# Tauri + React + Rust 功能迁移核对表

2026-10-08 整理：Document 单机为主力，按资料→制单→校验→模板预览→Excel/PDF 交付→备份恢复逐项验收；Sales 定位个人外贸工作台。组织、人员、行政及审批正式用于 Full 多用户版；显式 Full SQLite 本地包用于完整界面和登记测试。Document/Sales 不开放这些协作入口；下表是持续验收范围，已有批次证据见进度，不将代码存在或历史结果写成全部通过。

> 2026-09-20：原版 C# 备份分支 `origin/tauri-csharp-net10-backup` 为逐页对照来源。React 页面直接复用；每批集中联调，最终统一门禁。旧 Slint 页面记录退役，后端路由覆盖不等于用户操作等价。

当前差距与逐页台账见[后端差距](./Rust与CSharp后端功能差距及修正方案.md)。报表继续使用 **krilla + PDFium**；模板目录、统一 .dtpl 和多项分页/权限问题已有实现与回归，按剩余真实差异推进，不重新执行过期迁移计划。

| 批次／页面 | 原版界面 | 共用 Rust 能力 | 本轮核对要求 |
| --- | --- | --- | --- |
| 桌面启动、登录、退出 | 恢复原版 bridge 与 Tauri 壳 | SQLite、会话、HTTP、关闭任务 | 真实窗口、令牌隔离、空密码单机登录、退出释放 |
| 工作概览、待办、任务中心 | 原版页面保留 | dashboard、worklist、tasks | 真实响应、列表、状态与导航 |
| 发票、商品明细、付款、查询 | 原版五页签及表格保留 | records、workflows、reports | 新增／修改／冲突、草稿、报表与实际 PDF |
| 客户、供应商、商机、跟进 | 原版目录和对象详情保留 | crm、sales、related_records | 保存、并发、范围权限、导入导出 |
| 组织、人员、通讯录、行政 | 原版页面保留 | organization、personnel、office | 组织联动、隐私权限、预约／交接 |
| 行政与人事申请 | 新增独立 OA 页面，分为行政办公/人事管理 | domain::oa、engine::oa、存储层过滤分页 | 请假、加班、报销、出差、采购、通用申请；凭证、审批、移交/完成及交接阻断。报销不连接原付款模板或独立财务软件数据库 |
| 模板与设计器、单据包 | 原版 V3 画布保留 | report_templates、report_assets、document_packages；storage 元数据分页/同名检查/定向版本读取 | 模板资源、发布、预览与输出一致；报表目录及历史避免整类正文加载，完整票面/打印仍按专门方案验收 |
| 邮件、汇率、HS、OCR、Excel | 原版工具页保留 | 独立能力 crate 及 engine 适配 | OCR 已实测 Rust PP-OCRv6 + ONNX；文件选择、预览、识别、结果复制和缺资源提示已接通 |
| 单一窗口、装柜 | 原版页面保留 | single_window、packing | 持卡机／回执样本、生成输出与版本 |
| 权限、日志、设置、备份、恢复 | 原版管理页保留 | accounts、audit、settings、maintenance | 敏感字段、数据库错误、失败恢复、清理 |
| 关于、更新、部署 | 原版入口保留 | Tauri updater、Rust 发布脚本 | notices、签名信任、包内容、跨平台运行 |

六份默认模板共用 `.dtpl` V3 资产，文件/API/Builtin 使用同一文档；字体测量、普通 Flow 分页、明细首/续/末页、图片授权和私人模板已有实现及定向回归。文件模板 API 传递可编辑 JSON，文件导入/导出仍使用带校验的原生容器。复杂用户模板、全部分页组合、多模板输出与目标设备打印继续按[六类 PDF 验收方案](./Rust统一V3模板与原版PDF验收方案.md)逐项记录。

HS 在 2026-09-21 使用公开源页面及实际请求修正有效标准短路、推荐链、字段/顺序/请求头；这些是历史采样证据，源站变化及搜索、审核、发票回填的完整实际操作仍需独立验收。

以上“保留／复用”只描述代码，不表示所有操作已通过真实联调。本批验证结果和明确缺口在《程序改进重构进度文档》记录；Docker、PostgreSQL 现场、其它操作系统和官方单一窗口均须各自环境验收。
