# 2026-11-10 会话、权限与上传资源优化记录

本批从 `efde6826` 开始，处理项目审查确认的六项问题。继续采用 schema 17、单一原生 API 契约与现有 React／Tauri／Rust 分层；不添加旧库、旧客户端兼容链。

## 实现边界

- 待办投影复用授权必需字段集合，保留 `projectId`。会议室预约、物品领用的项目限制与目录读取一致；账号级项目限制按账号的 `companyScope` 定位单位，单位身份仍使用 `companyCode`。
- 设置保存、校验、邮件连接检查、备份／灾备操作和任务中心命令使用现有 `useScopedMutation`。请求及备份轮询接收取消信号，离开页面或切换客户端后禁止迟到结果回写。任务确认阶段也进入作用域锁，卸载后的旧回调不能启动操作。
- 发票保存移除 TanStack mutation 对完整输入／响应的保留及重复保存锁，继续保留保存期间续编、版本推进、HS 反馈和新建跳转。状态类操作保留跨组件忙碌标识，但不再返回完整单据到 mutation 状态；印章和自定义选项也使用无缓存命令。
- HTTP 备份上传由组合根注入缓存卷空间预算。已知长度先预留，未知长度随写入增长；并发请求共享尚未落盘的字节预算，并为运行数据保留 256 MiB。以最多 4 MiB 缓冲批次检查和写入，避免每个网络帧查询磁盘；失败、取消和结束释放预留及匿名暂存文件。该预算不是文件系统硬配额，不能阻止其他进程同时耗尽磁盘。
- 图片注册使用不可变 `ValidatedImage`，在写事务外解码和计算摘要；事务内重新检查权限并持久化。重复图片通过元数据和字节比较验证一致性，不重复解码。单证包导入复用同一注册边界并在事务内刷新身份。
- 图片目录先判断可见性及分页，再按本页资源查询引用；非所有者的可见性检查只查询候选资源。图片目录仍有 1000 项上限；SQL 仍需检查相关引用字段，不宣称已建立反向引用索引。回收继续完整扫描并拒绝损坏的引用，文件模板保持原有锁和权限规则。
- 删除无生产路由的通用 `{code}` 全表查找分支。现行代码路由全部由 HS 模块处理；通用业务记录仅按稳定 ID 寻址。

HTTP 直接声明锁图已有的 `fs2 0.4.3`（MIT／Apache-2.0），版本未升级；Cargo 锁文件仅新增该组合根的依赖边。没有引入缓存服务、新数据库、持久化前端缓存或第二套异步框架。
