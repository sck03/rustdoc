# 自定义 OA 重构与验收

本批按生产部署前授权使用全新 schema 17 和新版 OA 设置请求，不维护旧库迁移链或旧接口兼容。

## 实现边界

- 管理端可创建、复制、设计、保存、仿真、发布和停用自定义事项，员工端自动发现新事项，使用同一表单渲染器申请/查看。
- 领域层管理表单类型、容量、显示条件、精确金额和流程条件。Engine 管理发布快照、单位范围、人员/部门引用、附件和办理；Storage 管理独立设置版本及事项分页索引，UI 无 SQL。
- 13 个内置业务定义保留专业规则，另支持最多 100 个自定义事项。新增事项复用 `general:<key>`，不创建第二套请求执行器、数据库表或专用路由。
- `PUT /api/office/approval-settings` 只接受 `OaSettingsPatch`，每次保存一个流程或设置分区。发布同时校验发布目录版本和当前流程草稿版本；重复发布指令保留幂等回执。未发布草稿删除保留版本墓碑。
- `GET /api/office/applications` 提供当前身份可用事项；人员/部门选项独立分页，仅返回当前单位的编号和名称。申请保存服务端冻结显示名称，材料过滤同时保护原始值和显示值。
- 修正嵌套 AND/OR 部门条件的职责完整性检查、条件编辑器字段/运算符范围、材料字段选择、事项筛选切换及设置草稿保留。列表复用授权上下文，错误和终态停止详情轮询。
- 前端保存结果按实际提交范围合并，未提交流程继续保留原版本基线；保存或删除另一个流程不会借响应中的新版本号绕过冲突检查。
- CI 的 OA 集成任务包含自定义事项回归；仅修改 OA 前端或 OA 测试脚本也触发，避免被 Rust 文件变更条件跳过。
- 办理权限查询与分区存储保持一致，SQLite/PostgreSQL 均从独立办理分工记录重验当前成员，避免详情可办理但列表漏项；人员交接后历史成员不再借旧节点取得权限。
- 自定义内容进入现有审批单投影和分页排版；所有正式业务动作仍经过原事务内核。完整 BPMN 任意脚本、外部可执行表达式和独立分布式引擎不在本批实现范围。

## 统一页面设计核查

遵循《前端设计系统规范》和《前端视觉与产品命名规范》。流程管理沿用 `EditorWorkspace`，事项目录沿用 `PageHeader` / `FilterBar`，申请沿用共享 `Dialog` / `Field`，没有增加第二套 UI 库、配色或专用视觉令牌。

- 设计器、设置操作与引用选择器统一使用 `Button`，并统一条件、子流程、材料核验、流程图和历史操作等 19 个已有组件的普通按钮，保留原主次语义；新表单移除/删除使用危险语义。高级显示条件使用 `CollapsibleSection`，保留草稿并在原生校验失败时展开。
- 引用选择器复用 `Pagination` / `useServerPageNumber`、筛选条与 `PageState`，仅展开时按页请求；移除嵌套 label 和手写分页边界。
- 详情使用合法的 `dl/dt/dd` 与已有 `oa-facts` 布局，多行文本由共享样式保留换行；删除一次性行内样式与事项目录空说明。
- 自定义事项实测覆盖设计器、已填写申请及展开的部门选项、完成详情，每个页面分别在 1440/1024/390 宽度检查页面溢出和 WCAG A/AA axe 规则，9 个组合通过；截图位于本批精简证据目录。
