# 文件存储与容量管理

核对日期：2026-11-14。使用全新 schema 18 及当前模型指纹。旧实验数据库和旧恢复包不自动升级，不能覆盖原数据；更换 DataRoot 或 PostgreSQL 数据库建立新基线。

## 模块与数据

- Storage 的 `file_objects` 保存物理对象摘要、长度和引用计数，`file_versions` 保存业务文件名、类型及记录引用，`file_locations` 保存已经核验的迁移位置。SQL 不读取磁盘或访问 S3。
- `file_storage_totals` 和按组织的 `file_usage_totals` 由两库触发器随对象、引用、组织归属变化在同一事务内维护。配额及状态读取汇总；完整性检查另行从原始引用核对汇总，发现不一致报错。
- Engine 的 `file_store` 按职责拆分对象读写、缓存、凭据、迁移、归档和回收。业务先授权并准备不可变对象，再在写事务中重新授权、检查版本、存储身份及组织配额并发布引用。
- 发票资料、OA/公告附件、人事文件和照片、报表图片、审批 PDF、单一窗口提交包和回执使用永久对象。任务重试输入、短期预览及临时输出有独立生命周期，不能与业务原件一起清理。
- 发票资料版本和操作记录在 `attachment_history` 按序号游标分页，不将全部历史写回主记录。摘要去重只合并物理字节，不合并业务引用或权限；组织配额按业务引用计费。

## 容量与传输

默认单文件 100 MiB、每份 OA/公告记录最多 100 个附件、合计 500 MiB，组织配额 0 表示不限制。人事档案不设终身附件数量上限，详情仅返回首 50 条，附件目录按游标独立分页。管理员可降低单文件及数量限制，每份申请总量最多可调到 1 GiB。报表印章和图片仍执行专用格式、像素和解码预算。

历史文件继续占用配额；停用不等于删除。读取已有历史不因管理员降低新上传限制而丢失。发票资料不设终身 100 份、50 个版本或累计 256 MiB 的旧限制。

普通附件上传和二进制下载采用契约声明的 24 小时总期限，网络阻塞读写仍有超时和取消边界。HTTP 接收、对象写入/下载/迁移以及备份压缩、密封和解包共用磁盘预算，写入前检查可用空间并保留 256 MiB 余量；预算不替代实际 I/O 错误处理。HTTP 已暂存的可定位流直接参与摘要及发布，避免再次复制整份输入。

设置页沿用共享表单、折叠分区、作用域取消和草稿保护。任务正常每 2 秒刷新，临时错误复用共享退避策略；密钥不进入状态响应或 Mutation 历史。

## 本地磁盘与迁移

默认位置为 `DataRoot/Files`。`Configuration/file-storage.json` 保存身份、位置修订号、独立凭据修订号及策略，S3 密钥使用主密钥加密。每个存储身份使用独立对象前缀。

服务器通过重复的 `--file-store-root archive=E:\AttachmentArchive` 登记现有目录，或通过 `EXPORTDOCMANAGER_FILE_STORE_ROOTS` 注入 JSON 名称映射，例如 `{"archive":"/srv/exportdoc-files"}`。目录须在 AppRoot/DataRoot 之外，禁止盘根、穿越、符号链接和联接点；网页以 `@archive` 选择登记位置或受管子目录，不接受任意服务器绝对路径。

已有本地存储必须匹配 `.store-id`。挂载消失、身份不符、文件缺失或摘要损坏均报错，不创建空目录冒充已有存储。迁移由 `file_migrations` 和 `file_migration_queue` 记录待复制对象，新提交对象自动入队。传输和校验在写锁外执行；最终短锁只复核权限、配置和空队列后切换，不在锁内重新下载全库。中断后可继续并重新核验目标，源文件保留；未经核对不得直接删除源目录。

Docker 使用 `deploy/rust-native/file-storage.override.example.yml`，管理员先挂载并建立目录，授予 UID/GID 10001 访问权限。应用与恢复服务使用相同挂载和位置映射；示例禁止自动创建不存在的宿主目录。

## S3 配置与凭据恢复

文件与备份共用 SigV4 传输和以下显式寻址设置；API 端点不能带对象路径。

| 寻址方式 | 端点与用途 |
| --- | --- |
| 虚拟主机 `virtualHost`（默认） | 区域服务端点，程序添加桶名前缀；适用于按该规则配置的 AWS、OSS、COS 等服务 |
| 路径 `path` | 服务端点后添加桶名；用于支持路径寻址的 MinIO、Ceph 或其它兼容服务，IP 端点只允许此模式 |
| 已含桶名的主机 `bucketHost` | 直接使用已包含桶名的端点或桶绑定域名，不再添加桶名 |

已知 OSS/COS 官方域名拒绝路径寻址。区域、证书、桶名及服务端策略须按实际服务配置。只使用显式 Access Key、Secret 和可选 Session Token，不读取机器凭据或实例元数据，**不自动刷新 STS**。

管理员在“更新存储凭据”调用 `PUT /api/file-storage/credentials`：新凭据先核验同一存储身份，再原子替换；不迁移对象或改变位置修订号。过期凭据和远程暂时故障不阻断认证管理入口启动，文件访问仍按实际结果报错。配置损坏、不能解密或本地身份失配仍拒绝启动。

不超过 8 MiB 的对象单次 PUT，更大对象分段上传；文件服务复用连接池，取消检查绑定当前操作。下载流式计算摘要，验证后进入 256 MiB 会话磁盘缓存，重复 Range 使用独立句柄；超限对象只作临时下载。完整性检查绕过缓存直接检查远端。缓存命中可继续提供已验证原字节，不表示远端当前仍健康。

分段 UploadId 保存在 `Configuration/S3Uploads`，异常中止和后续回收可清理崩溃遗留，活动上传不会被回收。服务端创建分段成功而客户端尚未取得 UploadId 的中断窗口无法仅靠本地日志恢复，桶必须配套未完成分段生命周期策略；桶版本及保留锁也由存储端管理。

## 备份与回收

完整加密恢复/迁移包用 `FileObjects.pack` 按摘要排序流式保存对象。恢复须逐一验证数据库清单对应的长度和摘要，缺件、损坏不能报告成功。

普通 SQLite/PostgreSQL 快照配套 `<快照名>.objects.jsonl` 和同目录 `Objects/` 库，相同对象仅复制一次，最后发布快照。迁移这种备份必须同时保存数据库、清单及对象库；单独数据库文件不能完成附件灾备。

写入意图在业务事务明确提交后移除；失败或提交结果不明时保留，供回收重新核对。回收与备份/迁移持排他维护锁，在暂停写入期间复核引用；历史引用不回收。备份对象库按保留恢复点清单回收，清单缺失或损坏即停止。

审批 PDF 在任务工作阶段完成对象准备和上传；收尾阶段只授权并事务化发布引用、状态，避免慢速存储占用任务完成锁。
