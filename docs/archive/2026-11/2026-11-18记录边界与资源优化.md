# 2026-11-18 记录边界与资源优化

## 实施范围

基线提交为 `3a2cc0a1`。沿用 Tauri 2 + React 19 + Rust 的模块化单体、schema 18 和现有设计令牌，不增加运行依赖、旧数据库迁移或旧软件兼容分支。

- 发票及六类主数据按路由记录建立独立编辑生命周期。新记录加载失败不显示旧草稿；旧确认不能操作新记录。通用记录解析契约允许的数字/十进制字符串编号，拒绝无效、负值及非零正文编号与路径编号不一致，并在类型化业务校验前统一编号表示。
- Domain 统一发票利润计算、核对条件和参考资料名称校验。金额使用精确十进制的四舍五入，中点远离零，通常金额两位、单价最多五位；退税先汇总再舍入，利润使用舍入后的采购/退税合计。CNY/RMB 未设置有效汇率时按 1，其余币种缺汇率继续显示未设置。税率与计税公式保留现行业务规则。
- 空明细可以保存为草稿，但核对和状态流转必须拒绝；表头及明细缺项沿用原字段定位和提示。
- 既有 `ApiErrorResponse.code` 用于 `ConcurrencyConflict`。Rust 以独立错误类别标记版本冲突，HTTP 传递稳定代码，React 不再匹配提示文字。普通 409 业务冲突、权限错误和内部日志诊断保持独立。
- 自定义候选项的列表使用读事务，Storage 按类型只投影最近 500 条值并恢复原显示顺序；保存通过唯一键检查重复，包括不在当前返回窗口中的旧值。去重使用集合，取消逐项重复规范化扫描。
- 普通认证请求在读取正文前复用端点元数据做操作授权；请求名额和关闭登记仍跟随阻塞阶段，正式业务发布继续重验当前权限、版本和记录范围。
- 资源目录移除无生产用途的标题、列标签和操作查找包装；名称校验不再依赖前两列的展示顺序。内存下载便利接口移入测试辅助层，生产继续使用有预算的准备/传输入口。
