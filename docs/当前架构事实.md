# 当前架构事实

> 核对日期：2026-09-30。本文只描述当前 Rust 分支；历史 C# 验收不证明 Rust 功能等价。实施证据见[进度](./程序改进重构进度文档.md)，功能验收范围见[迁移核对表](./Rust原生功能迁移核对表.md)。

## 运行形态与职责

| 产品 | 界面与宿主 | 业务服务 | 数据库 |
| --- | --- | --- | --- |
| 桌面 | Tauri 2 + React 19 | 进程内共用 Rust HTTP 服务 | SQLite |
| 网页 | 同一 React 前端 | Rust HTTP 服务 | PostgreSQL 18 |
| Docker | React 静态资源与反向代理 | Rust HTTP 容器 | 独立 PostgreSQL 18 容器 |

正式桌面为 `apps/export-doc-tauri`，网页为 `apps/export-doc-web`，HTTP 组合根为 `apps/export-doc-server`。Node 用于前端构建和开发验证，API 契约及客户端由 Rust 生成。Slint、egui、C# 服务/测试/工程以及旧 .NET 容器部署已从本分支移除；相邻 `ExportDocManager_CS` 和 Git 历史保留行为对照，删除重复源码不代表全部业务差距已验收。仍使用的 OpenAPI、单一窗口参考数据及报表夹具保留，不能将 EF、Scriban、Chromium 或数据库 v19 描述成 Rust 实现。

2026-09-29 产品定位收敛：单机只交付 **Document 单证版**和 **Sales 业务员版**。单证版是主力，优先完成资料、制单、校验、模板、Excel/PDF 输出与备份恢复；业务员版定位个人外贸工作台，保留客户、联系人、跟进、商机、报价、供应商和邮件。账号/组织/权限管理、行政人事及 OA 申请审批集中于 **Full 多用户版**，由同一 React + Rust HTTP + PostgreSQL 18 提供完整模块，再按岗位授权；不再单独打包 Full 或 Administration 桌面。此调整不表示未验收业务已经完整，也不删除现有 OA 实现或历史业务数据。

`export-doc-contracts` 保存从官方 OpenAPI 生成的 DTO、路由和权限契约；`export-doc-domain` 处理纯业务规则；`export-doc-engine` 组织用例、认证、任务和能力；`export-doc-storage` 负责 SQL、事务与 SQLite/PostgreSQL 适配。Excel、报表、HS、邮件、汇率等按 crate/feature 分工。页面只组合展示，查询、草稿和平台操作分别位于 hook/model/service 与 Tauri 平台适配器。

## 数据、路径和并发

当前 Rust 数据库版本为 `export_doc_storage::SCHEMA_VERSION = 6`，最低可升级版本为 5。版本 5 建库 SQL 保持不变，新库和已有库共用有序事务迁移；5→6 解除版本表固定为 5 的约束，不改变业务数据。后续升级追加迁移，失败回滚；已有空文件、损坏库、版本 4 及更早试验库、C# 库或超前版本明确拒绝，不覆盖重建。PostgreSQL 通过独立维护账号执行初始化/升级，普通 API 只接受当前版本。

SQLite 位于 `DataRoot/Database/exportdoc-native.db`，WAL/SHM 等伴随文件同目录，实例锁位于 `DataRoot/Locks/native-instance.lock`。记录、图片二进制、用户模板、模板版本、设置和审计均保存在业务库。根目录已有受支持数据库时，在新旧实例锁内通过 SQLite 快照完整搬入 Database；只升级快照，原库及伴随文件归档到 `Backups/DatabaseLayout/<唯一目录>`；两处同时有数据库或只有伴随文件时拒绝猜测。PostgreSQL 使用同一语义存储接口。

`RuntimePaths` 由组合根注入 AppRoot/DataRoot。受管日志为 `DataRoot/Logs`，运行缓存为 `DataRoot/Cache/Native`，WebView profile 为 `DataRoot/WebView`。内置模板与字体来自只读 AppRoot；用户文件模板位于 DataRoot/Templates。完整边界见[路径清单](./运行目录与路径存储审查清单.md)。

正式团队拓扑为一个 Rust API、一个 PostgreSQL 18 业务库、多个浏览器用户。存储层用事务和版本控制保护更新；当前单连接互斥模型和部分应用层分页限制了大规模吞吐，不能据此宣称多 API 高可用或实时协同。可用性与规模待办见[后端差距](./Rust与CSharp后端功能差距及修正方案.md)。

权限按 resource/action/dataScope 解析，模板发布状态与共享受众另行限制。认证、桌面令牌与许可证依赖生成的 endpoint metadata；缺少授权或未知能力拒绝执行。数据库和文件故障保持 503，明确不存在为 404，版本冲突为 409，校验为 400，权限为 403，繁忙为 429，超时为 504。

桌面随机回环端口与访问令牌由 Rust 宿主管理；令牌通过受限 IPC 获取，不写入 URL。浏览器不获得数据库凭据或任意本机文件操作。任务使用当前权限、取消和超时边界，正式输出路径来自用户选择。

桌面确认退出后，由后台线程停止共用 Rust HTTP 服务及任务，再销毁 Tauri WebView 窗口并退出；重复退出请求等待同一次清理，不能提前放行。Windows 的 wry 控制器销毁会调用 WebView2 Close；程序不按进程名批量结束系统中的 WebView2。实际平台证据见[桌面验收](./Rust桌面平台适配与验收.md)。

## 模板、设计器与 PDF

商品字段可直接拖到 A4 画布，保留独立 X/Y、大小、文字和边框；`item.*` 只在主体区域逐件输出，共用最小行距，长内容撑高整行、顺延同列下方字段并由 Rust 分页。设计画布只编辑一行，普通字段与商品字段分别选择，高级组件入口默认收起。默认发票采用独立商品字段及单独的表头/线条，TOTAL 与分列合计同一行并在末页跟随正文；金额与单价沿用统一精确数值格式。发票号、唛头等单据信息独立于商品循环，按所属图层的首页/重复规则输出。普通表格、合并表头和高级组合明细保留；自由商品字段与高级明细表不可混用，已有用户复杂模板不自动改写。

只接受 `.dtpl` 文件，容器包含格式标记、长度及 SHA-256；内部文档为 V3 JSON。API 为保留 OpenAPI 兼容字段名仍使用 `contentHtml` 等字段，但内容是结构化 JSON，不是任意 HTML。旧 HTML、V2、裸 JSON 文件和损坏容器均拒绝导入。

六份内置模板由 `scripts/lib/default-report-designs.mjs` 生成，`Builtin` 读取同一份 `.dtpl`；没有第二套硬编码票面。React 自由画布修改同一文档，Rust 统一测量、分页并生成 SVG，krilla 编码正式 PDF。PDFium worker 负责已有 PDF 的预览、提取、OCR 页图和合并。

样例与当前单据预览都经过 Rust 排版；有设计权限时两者使用当前画布草稿，预览不保存模板或单据。预览按随包字体将字形转为矢量轮廓，并保留页面文本描述及等比例 viewBox，不依赖浏览器安装字体。数值与单位、币种与金额按直接连写输出（例如 `1110CTNS`、`USD11.00`）；独立金额字段和高级明细合计支持可选币种格式，普通网格支持标签直接前缀。

设计器支持 A4 横竖版、四类图层、普通网格合并/斜线/竖排/勾选、循环明细、组合字段分栏、显隐、首页/续页行数、首页唛头、末页合计及页脚跟随。发票与装箱单可隐藏 PO/款号，商品间横线默认关闭；金额与单价、装箱单的数量/重量/体积均按明细底部基线对齐，长款号与空 PO 不破坏对齐。付款报销只使用 Payment/Payee 数据。具体编辑说明见[设计器](./新版报表设计器进度参考文档.md)，版式和分页验收见[PDF 方案](./Rust统一V3模板与原版PDF验收方案.md)。

数据库模板使用草稿、已发布、停用、归档状态和 ExpectedVersion。文件模板使用内容及显示名称生成的 revision；保存、改名和删除校验旧版本。编辑内置模板创建用户副本。文件变更与回滚共用 DataRoot/Locks 下的模板存储锁，失败只恢复本次捕获的文件及目录清单；回滚失败保留恢复快照并明确报错。

受控图片使用 PNG/JPEG，按 SHA-256 去重，内容和上传归属在业务库中。读取校验所有者或可见引用，模板图片还校验对应出口/付款数据域。引用只来自正式唛头/印章字段与模板资源清单，普通备注或备用字段中的资源编号不构成授权。文件模板、数据库模板及历史引用都阻止回收；回收与文件变更使用同一存储锁。资源清单、图片摘要和大小在保存及输出时再次校验。当前图片支持范围以 Rust 校验为准，不能沿用旧 C# 支持 GIF/WebP 的说明。

发票可以独立上传单证章和报关章，无需先关联出口商档案；上传写入受控图片库，点击保存发票后持久化引用。选择出口商档案会带入其印章，随后修改只属于当前发票。发票印章的 null/缺省值继承关联档案，空字符串明确不盖章；单据包分别携带发票及档案图片，权限、回收和恢复沿用同一受管存储边界。

报表字体由各服务实例显式持有并按需加载，预览、PDF 及后台任务共享同一字形库和有界测量缓存。同步排版结束或异常时恢复调用方字体绑定；不全局缓存宿主字体路径，不允许其它实例初始化覆盖当前报告的字体。缺失随包字体保持 503，连续导出不重复加载字体文件。

## API、依赖与交付

业务授权统一执行生成契约的 `requiresLicense`，无效/过期注册码保持拒绝状态，七天试用到期后不能绕过 React 调用业务 API。账号/权限版本变化撤销旧会话；桌面更新 IPC 验证管理员会话并在安装前复核。团队授权使用持久安装身份，不因容器 HOSTNAME 重建而变化；桌面灾备迁往另一设备仍须按机器绑定重新注册。

SQLite 灾备恢复在 DataRoot 实例锁内、数据库打开前执行。独立加密包包含数据库、主密钥和用户模板，统一进行类型/版本/摘要/大小与路径校验；替换前保存原文件并记录恢复日志。版本 5 起的备份可恢复后升级；SQLite 普通恢复先升级快照，灾备升级纳入文件恢复回滚范围，成功后才移除待恢复标记。PostgreSQL 普通备份使用 custom-format dump；完整服务器迁移包另包含主密钥和用户模板。恢复须先停止 API，由独立 `--restore-pending` 维护命令持同一数据库实例锁执行并升级 schema；业务账号不获得建表、属主或集群管理权限。失败保留安全备份与待恢复标记并拒绝正常启动。命令和边界见[脚本说明](../scripts/README.md)。

`/openapi/v1.json` 是唯一业务契约事实源。`export-doc-contracts::openapi` 保留冻结的官方 .NET 导出 `reference_openapi.json`，由 Rust 组合新增能力；回归逐项比较原端点、schema、认证及错误元数据。`generate-api-client.ps1` 从同一文档生成 React/Rust 客户端和策略；生成器位于 `export-doc-contracts/examples/generate_clients.rs`，直接调用 Rust OpenAPI 组合器，不依赖 Node 或 .NET SDK。禁止手改生成结果。

行政 OA 独立于原付款数据和报表：人事管理包含档案、通讯录、请假与加班；行政办公包含会议室、物品、费用报销、出差、采购与通用申请，工作台提供申请与审批中心。请求、附件、历史和权限按同一公司边界处理；报销仅移交独立财务软件，不记账或付款。新 OA 列表/历史使用存储层过滤与分页，员工调岗/离职检查未结申请。详见[行政与人事](./公司行政协作设计与验收.md)。

员工档案与六类 OA 申请在填写时选择图片/PDF，一次点击保存资料及附件；后台依次使用版本控制的写入和上传接口，部分失败保留已保存记录和待上传文件，不把分步请求宣称为一个数据库事务。人员档案新增私密文档附件，复用业务库、备份与档案详情权限。普通通讯录权限不能下载证件或文档。人员改名、调岗同步关联账号，离职停用账号并使旧会话失效；返聘不自动恢复登录权限。

通用记录保存只接收生成的请求 DTO 字段，防止通过额外 JSON 字段注入人员账号关联、附件引用等服务端状态。账号、人事、OA、单据、客户跟进、供应商关联、商机及业务附件的相关写入在事务获取后复查当前账号和权限；登录校验期间账号变化拒绝签发会话，续期保留原会话的权限版本。

Cargo/npm 清单和锁文件以及 `eng/native-runtime-packages.json` 决定 Rust 交付依赖。Tauri/WebView、SQLite 属于桌面依赖；桌面不携带 PostgreSQL 服务端适配器、Node 或 .NET。PDFium/ONNX 原生归档与许可按固定清单准备，NuGet 仅作为归档来源。

正式入口和工作流见[脚本说明](../scripts/README.md)。Windows 批量入口及三端桌面 Actions 的 All 只生成 Document、Sales 两版；单版构建、安装器和默认启动指向 Document。桌面版本清单只包含这两版，旧 Full/Administration 参数在构建前拒绝。两版沿用各自 `.Document`/`.Sales` 目录、包身份及更新频道，不接管旧 Full 目录或数据库。Document 提供 OCR 和单证模板，Sales 保留字体/PDFium 而不附上述资源；多用户 Web/Docker 保持 Full 完整模块与资源。后端按同一权限契约限制管理员和普通账号，单机不能通过直接请求使用 OA 或账号权限管理。共享 Rust 代码未全部按版本从二进制剔除。系统级 Windows Authenticode、macOS Developer ID 和 Apple 公证不执行；Tauri updater 的签名与公钥信任合同保留，实际签名升级另行验收。

本机测试、真实 PostgreSQL、桌面窗口、其它 OS/架构、Docker、浏览器兼容和实体打印分别记录。通过编译、路由或旧版测试，不等于所有功能及所有平台已验收。
