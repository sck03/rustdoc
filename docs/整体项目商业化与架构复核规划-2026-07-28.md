# 整体项目商业化与架构复核规划、实施与验收记录（2026-07-28）

> 文档性质：当前源码事实、一次性重构实施结果、完成度口径和生产前剩余验收。
>
> 实施边界：项目尚未投产，不兼容开发期旧数据库、旧程序根配置或旧模板路径；以精简、清晰、可扩展的正式 v1 为目标。
>
> 主要依据：三份核心文档、当前源码、OpenAPI、发布脚本、视觉基线和 2026-07-28 最终自动化验证结果。

## 1. 最终结论

项目不需要推倒重写，现有 `Domain + Application + Infrastructure + ASP.NET Core API + React/Vite + Tauri` 主架构继续成立。本轮已经把原规划中的发布前 P0 项完整落地：程序根只读化、运行配置归入数据根、内置/用户模板分层、正式数据库 v1 基线、普通用户界面降噪、受管模板入口、OCR 能力诚实化，以及出口单证与付款/报销模板和数据的硬隔离。

当前应区分两个结论：

- 本轮计划内可代码化重构项已完成，完成度 `100%`。
- 项目仍未经过全部目标平台和真实生产拓扑验收，因此不能宣称“已生产发布完成”。整体生产发布就绪度约 `86%`，剩余工作主要依赖 Docker/PostgreSQL 服务器、Windows/macOS/Linux/ARM64 真机、正式签名密钥和真实升级回滚环境。

本轮没有引入微服务、Redis、消息队列、第二 ORM、大型 UI 框架或商业闭源运行库。现阶段继续使用 PostgreSQL/SQLite、React、TanStack Query、Lucide、Tauri、Scriban、Chromium、ONNX Runtime、Noto CJK 等现有免费开源技术栈，避免为了“现代化”增加无必要依赖。

## 2. 当前目标架构

```text
React/Vite shared UI
├─ Browser/Web: upload + download semantics
└─ Tauri: native dialog/update/path bridge
            │
            ▼
ASP.NET Core API / Application use cases
            │
            ▼
Infrastructure adapters
├─ SQLite: local, single machine, single process
├─ PostgreSQL: network/team mode
├─ Reporting: managed templates + Scriban + Chromium/PDF
├─ OCR / Excel / Single Window / Mail / Backup
└─ Runtime paths: read-only AppRoot + writable DataRoot
```

核心原则：

- Domain/Application 不依赖具体数据库、文件系统或桌面 UI。
- Web/Tauri 共用业务页面，平台能力通过桥接和 capability 判断提供。
- `AppRoot` 只保存可随版本整体替换的稳定资源。
- `DataRoot` 保存所有应用运行写入和用户可编辑内容。
- SQLite 不通过共享文件模拟多人；多人/浏览器/容器使用 PostgreSQL。
- 业务域可以复用渲染引擎和基础设施，但不能复用不相容的数据合同。

## 3. 本轮已完成实施

### 3.1 AppRoot 只读与 DataRoot 可写

- `appsettings.json` 改为 `DataRoot/Config/appsettings.json`。
- `local-preferences.json` 改为 `DataRoot/Config/local-preferences.json`。
- 数据库连接读取、设置 API、数据库维护、支持包和相关测试同步使用新事实源。
- `RuntimeAppPathProvider` 明确提供 `AppRoot`、`DataRoot`、`ConfigRoot` 和 `UserTemplateRoot`。
- Tauri `runtime-paths.json`、备份和临时文件改存平台应用配置目录；`EXPORTDOCMANAGER_RUNTIME_CONFIG_ROOT` 可将该小型定位指针定向到运行包或数据盘。
- NSIS 不再在 `$INSTDIR` 写 `runtime-paths.json`。
- 发布资源包不包含数据库、运行设置、本机偏好或运行路径指针。

当前目录合同：

| 根 | 内容 | 写入规则 |
| --- | --- | --- |
| `AppRoot` | 主程序、sidecar、Web、内置模板、字体、OCR 模型、浏览器、Excel/单一窗口资源、原生工具 | 只读 |
| `DataRoot/Config` | 程序设置、本机偏好 | 可写、原子保存 |
| `DataRoot/Database` | SQLite 单机数据库 | 可写，仅单机单进程 |
| `DataRoot/Templates` | 文件型用户模板 | 可写、按业务域分目录 |
| `DataRoot/Logs/Cache/Backups/Security/WebView/SingleWindow` | 日志、临时数据、备份、安全材料和平台运行数据 | 可写、受控清理/备份 |

### 3.2 内置模板与用户模板分层

- `AppRoot/Templates` 作为只读内置模板源。
- `DataRoot/Templates` 作为可写用户模板源。
- 编辑内置模板时创建用户副本；同路径用户模板覆盖内置模板。
- 新建、重命名、删除和模板包导入只修改用户模板。
- 模板包导入导出会规范化相对路径和报表类型，不接受目录逃逸或跨域引用。
- 前端删除模板路径手工输入，桌面端删除任意模板文件选择命令、桥接方法和权限。
- API 只返回受管模板目录或数据库用户模板；外部任意路径不能直接进入渲染链。

### 3.3 出口单证与付款/报销业务域硬隔离

用户补充的“报关单证类和付款报销类模板数据不通用”已作为硬约束落地，而不是文档提醒。

| 项目 | 出口/报关单证 | 付款/报销 |
| --- | --- | --- |
| 报表类型 | `ExportDocument` | `PaymentVoucher` |
| 文件目录 | `Templates/Export` | `Templates/Internal` |
| 配置集合 | `BatchExport.Items` | `PaymentTemplates` |
| 业务主数据 | Invoice、Customer、Exporter、Items、报关/装箱/合同相关字段 | Payment、Payee、金额换算、付款/报销字段 |
| 预览 | 出口单证样例模型 | 付款/报销样例模型 |
| 真实加载 | 发票/客户/出口商/商品明细链路 | 付款/收款方/单位信息链路 |
| PDF 入口 | 只接受 `ExportDocument` | 只接受 `PaymentVoucher` |

隔离规则：

- 目录决定业务域，配置中的 `Type` 不能把 `Export` 文件伪装为 `Internal`，反之亦然。
- 保存、重命名、删除时只更新所属业务域配置。
- 模板包清单中的 `ReportType` 会被目录规则重新规范化。
- 预览和真实 HTML/PDF 渲染都会核对请求类型、模板目录和用户模板类型。
- 出口模板请求付款模板、付款模板请求出口模板均直接拒绝。
- 共用 Scriban、字体、Chromium 和 PDF 服务只是基础设施复用，不表示字段目录或业务数据可以互换。

### 3.4 正式数据库 v1 基线

- 新增 `DatabaseSchemaBaseline`，正式版本为 `1`。
- 空 SQLite/PostgreSQL 按当前 EF 模型创建，建立必要性能索引并写入 `__ExportDocManagerSchema`。
- 已有数据库只有版本为 `1` 才继续启动；无版本标记或其它版本明确拒绝。
- 删除约 900 行开发期旧字段探测、逐列补齐、旧索引识别和历史回填兼容代码。
- PostgreSQL 前缀索引和可选 `pg_trgm` GIN 索引保留；缺少扩展权限时稳定降级。
- `DatabaseInitializationService` 只保留锁、基线、种子和首次管理员等薄编排职责。

该策略符合“尚未投产、不为旧数据增加复杂度”的决定。开发样例如需保留，应人工导出后在空 v1 数据库重建。

### 3.5 普通前端商业化降噪

- 关于页不再展示 API 版本、数据库模式、User-Agent、内部字体路径和运行路径政策。
- 顶部服务状态只显示可用性，不泄露 API URL。
- 登录页使用“高级连接选项”“服务器地址”“首次启用口令”等用户文案；桌面单机版隐藏网络部署输入。
- 发票与付款预览不再展示 `storagePolicy`。
- 发票原始扩展字段 JSON 编辑框删除；“备用字段”改为“自定义备注”。
- 多处“运行数据根”“内部存储政策”等审查语言改为任务结果、临时区、保存位置或下一步操作。
- 开发者说明保留在 OpenAPI、管理员诊断、支持包和专项文档，不常驻普通业务页面。
- 第三方许可和法律信息入口保留，避免把“降噪”误解为删除许可证义务。

现有 React、TanStack Query、Lucide、Three.js 和 CSS token 已足够形成统一商业后台体验，不需要整体迁移到 Ant Design、MUI 或其它大型框架。手机继续承担查询、提醒、轻量审核和快速回填；复杂明细、批量操作和报表设计以桌面为完整工作台。

### 3.6 平台能力与外部路径收口

- OCR 页面读取健康检查中的 `ocr-runtime` capability。
- OCR 组件关闭、缺失或不完整时禁用文件载入和识别，不保留必然失败按钮。
- Web 端使用浏览器上传/下载；Tauri 端通过受控桥接提供原生路径操作。
- 删除 Web `selectReportTemplateFile`、Tauri `select_report_template_file` 和对应 ACL 权限。
- API/OpenAPI 明确模板只来自受管目录，并描述模板类别隔离规则。

### 3.7 容器运行配置修复

旧 Compose 同时挂载 `runtime/api-data:/runtime-data`，又把单个配置文件只读挂载到 `/runtime-data/Config/appsettings.json`。这会破坏 `SettingsService` 的同目录临时文件和原子替换，导致管理员无法保存设置。

现已统一为：

```text
宿主 runtime/api-data  ->  容器 /runtime-data
配置 runtime/api-data/Config/appsettings.json
```

- `initialize-container-runtime.ps1` 在 `api-data/Config` 生成配置。
- 两份 Compose 删除嵌套只读配置挂载。
- 容器 README 同步新路径和“高级连接选项/首次启用口令”文案。
- 生命周期工作流新增配置目录/文件可写、临时文件写入、同目录原子改名和清理探针。

## 4. 依赖与可扩展性决策

- 保留单体模块化架构，不提前拆微服务。
- 保留 SQLite 单机与 PostgreSQL 团队双 provider，不新增第二业务数据库。
- 不引入 Redis，除非未来多 API 节点出现可测量热点和跨节点失效一致性需求。
- 不引入消息队列，除非后台任务需要跨节点租约、可靠投递和失败重放。
- 免费开源优先，但新库必须解决可测量问题并通过许可证、漏洞、体积和跨平台审查。
- 继续使用集中 NuGet 版本、npm/Cargo lock、SBOM、字体许可和发布载荷门禁。

后续维护性优先级仍包括：拆分 HS 知识和共享数据库维护大型服务、逐业务域启用 Nullable、统一 Application 端口命名、继续收敛 CSS 全局债务。这些是长期 P1，不影响本轮 P0 已完成结论。

## 7. 剩余外部验收与风险

### 发布前必须在目标环境完成

- Docker Compose HTTP/HTTPS 真实启动、配置保存、volume 重建和 `pg_dump/pg_restore`。
- PostgreSQL 18 真实多岗位权限、容量、断网、并发冲突、备份恢复和长时间运行。
- Windows x64 干净客户机安装、数据根选择、升级、失败回滚和卸载数据保留。
- macOS x64/ARM64 签名、公证、Keychain、文件对话框、PDF、更新和卸载。
- Linux x64/ARM64 安装权限、Secret Service、Chromium/PDF、字体和更新。
- 正式 Tauri updater 密钥生成、至少两份加密离线备份、GitHub Secret 发布副本和恢复演练。
- 真实触控、软键盘、系统返回、读屏、125%/150%/200% 缩放和 Retina/高 DPI。

### 当前已知限制

- 本机没有 Docker CLI，无法把 Compose 写成“本机已运行通过”；当前只完成 YAML、初始化脚本、挂载契约和 CI 工作流验证。
- macOS/Linux/ARM64 的 native 资源和安装事务不能由 Windows 本机结果替代。
- Docker Engine 自身镜像/缓存位置由宿主配置；要求系统 C 盘零占用时必须迁移 Engine data-root。
- React Router 上游公告仅影响未使用的 RSC/server API，已由版本与源码契约限制；兼容修复版本发布后继续升级复核。

## 8. 审查决策摘要

- 保留当前分层架构，不推倒重写。
- AppRoot 永久视为只读资源根，DataRoot 是唯一应用运行写入根。
- 不为开发期旧数据、旧配置和旧模板路径编写兼容迁移。
- 出口/报关单证与付款/报销是两个独立业务数据域，不能因共用模板引擎而互换数据。
- 普通用户页面只显示业务结果、状态和下一步；部署/开发说明进入管理员诊断、支持包和文档。
- 手机提供合适任务范围，不机械复制桌面复杂工作台。
- 优先免费开源依赖，但不以增加库数量代替产品设计。
- 生产发布状态只由真实目标环境、签名和恢复证据确认。
