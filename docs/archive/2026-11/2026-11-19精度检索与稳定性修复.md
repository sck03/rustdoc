# 精度、检索与稳定性修复

分析基准：`c0481632`。实施与验证跨 2026-11-19 至 2026-11-20。本批按用户要求完成修复、集中验证、无效代码与测试输出清理，并以普通快进方式交付 main。

## 实现边界

- 发票、商品及关联金额 DTO 使用十进制文本；Rust Decimal 的可空字段也按相同声明生成。React 共用数值输入生命周期及展示控件，精确计算、剪贴板、商品库和保存不转为浮点数。自然日、整数编号、金额舍入及权限规则不变。
- DTO 文本解码、输入契约及 Domain 复用一个严格十进制解析器；拒绝科学计数、下划线、超范围和会丢失精度的输入，可空字段仅以 null 表示空值。复现的默认解码器接受 `1e3` 等非契约输入已纳入回归；移走 Domain 原有解析实现后直接复用，未复制第二套规则。
- 最新隔离 HTTP 宿主验证六类非法十进制请求均为 400，按唯一发票号查询确认零写入；同一服务的正常币种、核对和状态历史 React 流程通过。
- 共用算术夹具增加数量 `123456.000049999999`、单价 `100` 的临界案例，精确结果为 `12345600.00`，覆盖负数和相邻舍入边界。真实 React 表格验证输入、请求和回读保持全部小数位。
- 极端数字粘贴可使衍生结果超过文本长度限制，原实现会在 React 状态更新中抛出异常。明细编辑现在先完成计算校验，再同时发布草稿和撤销快照；失败显示错误且保留原值，不污染撤销/重做。15 个真实表格/保存场景通过，包含失败后纠正、撤销、重做及再次保存。
- 会议室和物品申请复用身份分区，第一次保存成功后锁定申请人、任职和项目；附件失败后可修改业务内容并重试同一草稿。
- HS 智能查询分批读取全部实例，按编码只保留必要证据。反馈按规范化查询文本定位，SQLite/PostgreSQL 同事务维护 `hs_search`，新增 `records_hs_feedback_query`。全新 schema 18 指纹更新，不迁移旧实验库。
- HTTP 继续使用原有 128 MiB JSON 响应预算，写请求执行前按声明预留，有界等待释放通知；等待者受现有请求名额限制。固定回执、票据、注销和批量状态回执使用 64 KiB。没有把缓冲计数宣称为进程 RSS 上限。
- `/livez`、`/readyz` 的 GET/HEAD 由唯一原生契约声明探针类别。存活不访问依赖；就绪在独立名额内检查服务健康，成功无正文；`/healthz` 保留详细诊断。
- HS 只读详情使用 FetchRemoteHsCodeDetail，权限为 view，不触发候选采集；采集/解析继续要求 manage。
- 退役 UpdateMeetingBooking、UpdateOfficeSupplyRequest，通用资源目录允许没有更新操作；专用草稿 API 保留。
- 进一步核实并退役 GetCustomsCooProducerProfile、ListAvailableExchangeRateCurrencies、GetReportTemplateV3Contract。前两者分别由现行分页目录和汇率结果覆盖；V3 纸张/限制模型保留在唯一原生定义中，通过共享模型元数据生成，固定描述 JSON 删除，自省测试直接验证 OpenAPI。
- JSON 用例回包在 NativeService 共用同一编码入口；HS 排序阶段只保留候选编号、评分和计数，最多批量回读最终 50 条展示明细，不保留全部匹配实例正文。
- 首轮真实并发测量复现响应预算竞争：两个 64 MiB 执行前预留会挤占全部 128 MiB，四连接组读取在持续 429 后失败。已为读取编码保留 8 MiB 执行前余量，继续共用原总上限；追加两个大响应请求与 32 个小读取共存的回归。首轮失败数据只作为问题证据，不算性能验收通过，最终样本在修复后重跑。
- 复测进一步暴露请求接收预算问题：小 JSON 也按 16 MiB 上限计费且延续到工作结束，使 64 MiB 输入预算过早耗尽。接收改为增长前按实际缓冲计费，输入/输出复用有界字节缓冲；解析名额有界公平等待。27 项 HTTP 测试通过，新增 20 个并行小请求、真实预算耗尽和部分接收取消回归。聚合体量基线按该共享模块与源码内回归重新测量，单文件和增长限制不放宽。

## 最终运行样本

PostgreSQL 18.6 / Windows x86_64 GNU Release，每组 10,000 条历史发票加 20 个会话自有发票，20 个 Admin 会话各 200 轮。两组均完成 4,007 次逻辑操作、5 次审批和 2 个 PDF 任务，最终版本/数据与任务回收断言通过。

| 连接池 | 操作/秒 | P50 | P95 | P99 | 429 重试 | API 进程工作集峰值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 14.7 | 801 ms | 4,926 ms | 9,462 ms | 60 | 107.7 MiB |
| 4 | 33.8 | 385 ms | 2,012 ms | 3,103 ms | 10 | 112.5 MiB |

高频连续请求下仍可触发有界限流，以上不是生产 SLO 或普通用户点击延迟承诺。P50/P95/P99 包含重试等待；进程工作集峰值包含初始化，未包含 PostgreSQL 服务端。相同单连接首轮问题样本为 7.4 操作/秒、P95 6,580 ms、2,135 次 429，最终样本已明显减少竞争；不把这一对照外推为全部功能性能提升比例。

独立 SQLite 原生负载使用同一 Release 代码和完整受管资源，数据均为本次匿名生成。各阶段在其它重型构建/测试退出后执行。

| 负载 | 实测耗时 | 进程树 RSS 采样峰值 |
| --- | ---: | ---: |
| 清理 100,000 条审计记录 | 1.93 s | 66.8 MiB |
| 导出 20,000 条审计记录为 Excel | 2.08 s | 77.0 MiB |
| 20 份 PDF、每张发票 40 行 | 2.21 s | 128.8 MiB |
| 8 张 OCR 图片，每张 16 行，串行 | 14.84 s | 335.9 MiB |
| 5,000 条 HS 实例 + 1,000 条无关反馈，12 次检索 | 中位 368 ms / P95 402 ms | 131.0 MiB |

HS 样本包含 0 条正式年度税则，验证的是实例完整扫描和反馈过滤，不代表完整年度税则/全部商品分布。50,000 条审计 Excel 扩展内容触发原有 120 MiB 容量拒绝；取消审计、Excel、PDF、OCR 后，资源回到空闲约分别用时 10、13、66、55 ms。RSS 按约 50 ms 采样进程树，可能漏掉瞬时峰值，共享页可能重复计数，不能当作硬性内存上限。OCR 批次后进程树工作集回落至约 130.3 MiB。

原始成功结果保存在 `artifacts/precision-query-stability/performance/postgres-capacity.json` 与 `native-workloads.json`；失败样本与诊断分开保留，不算通过。
