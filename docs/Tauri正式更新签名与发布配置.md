# Tauri 更新签名与发布配置

> 2026-09-25 核对。系统级 Windows Authenticode、macOS Developer ID 和 Apple 公证不执行；以下仅说明 Tauri updater 的独立信任合同。

## 当前状态

当前 Rust 桌面配置默认没有更新端点或正式公钥。三个操作系统的手工工作流生成 Full 构建 Artifact，`publish_release` 可上传归档到对应版本的 GitHub Release，供人工下载安装。此开关不启用 Tauri 自动更新，也不发布旧 C# 四产品通道或 latest-*.json。正式更新须在配置受信公钥、保管私钥及完成真实升级验收后启用；不宣称旧 .NET 安装包可直接升级为 Rust。

## 信任边界

检查、下载、取消和安装更新的 Tauri IPC 均接收当前会话，并由共用 Rust 应用服务验证管理员身份；安装前再次核验会话和账号/权限版本。React 隐藏按钮不是授权边界。会话只通过 IPC 参数传递，不放到 URL 或日志中。

- 公钥在构建时固化到客户端，不能通过 React、HTTP 设置、数据库或 IPC 替换。
- 私钥与私钥密码仅保存在受控发布端，不能进入源码、客户端、容器、日志或业务数据库。
- 管理员更新地址只决定清单来源；改变地址不能绕过包签名验证。
- 更新清单与产物必须属于同一产品、平台、架构和版本。未来多产品通道应各自配置密钥，不回退使用另一产品的信任材料。
- 便携包保留人工替换程序、保留 App_Data 的流程；浏览器/容器不执行 Tauri 安装器更新。

## 地址与密钥

管理员在系统设置中维护 system.updaterEndpoint。Rust 设置由当前业务库保存，不再写 C# 的 Config/appsettings.json。支持受校验的 HTTPS 地址及明确受信内网 HTTP；禁止用户名/密码、控制字符、反斜杠及 fragment。修改地址后重新检查更新。

正式密钥由项目所有者在可信发布环境使用项目锁定的 Tauri CLI 生成并离线备份，不在每次 CI 临时生成。公钥可公开；私钥和密码分开保管。密钥丢失或轮换必须设计旧客户端可验证的过渡发布，不能通过关闭验签解决。

## 启用前验收

1. 用受信公钥构建目标产品，签署对应更新产物并保存摘要和版本清单。
2. 分别验证合法包、错误公钥、被篡改包、错误平台/版本、不可用地址及取消。
3. 验证安装前退出、升级失败恢复、重启及 DataRoot 数据保留。
4. 在 Windows/Linux/macOS 对应设备验证；本机测试不能代替其他平台。
5. 执行 `node scripts/test_tauri_updater_release_contract.mjs`，并检查实际构建图和发布资产。

以上保留 updater 验签，不要求执行系统签名、公证或本轮创建任何私钥。入口见[脚本说明](../scripts/README.md)与[工作流手册](./GitHub%20Actions工作流用途与运行手册.md)。
