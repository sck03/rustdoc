# 当前架构事实

核对日期：2026-11-14。本文件只维护现行契约；实施数量、性能样本、截图和清理结果见[实施进度](./程序改进重构进度文档.md)。旧软件版本的兼容链已退役，历史流程版本和审计事实仍属于业务数据。

## 产品与模块边界

| 产品 | 宿主与界面 | 服务和数据库 |
| --- | --- | --- |
| Document：外贸单证管理 | Tauri 2 + React 19 | 进程内共用 Rust HTTP + SQLite |
| Sales：外贸业务工作台 | 同一 Tauri/React 源码 | 个人外贸工作台，SQLite |
| Full：业务协同平台 | 网页或 Docker，同一 React 前端 | Rust HTTP + PostgreSQL 18，多用户 |
| Full 单机测试版 | 显式构建的独立 Tauri 便携包 | SQLite，仅用于完整界面和业务测试 |

正式桌面默认 Document，批量及安装器只交付 Document/Sales。Full SQLite 测试不能代替 PostgreSQL 多用户验收。Administration、C#/.NET、Slint、egui 工程和部署链已退役；仍在使用的冻结契约、匿名夹具、官方参考数据和原生资源保留。

| 目录 | 职责 |
| --- | --- |
| apps/export-doc-web | 唯一 React 前端；页面组合，hook 管状态/查询/命令，model 放纯计算 |
| apps/export-doc-tauri | 桌面组合根及窗口、对话框、更新、剪贴板等平台适配 |
| apps/export-doc-server | HTTP 和 PostgreSQL 服务组合根，不向浏览器暴露数据库凭据 |
| crates/export-doc-contracts | native_contract 生成 OpenAPI、DTO、客户端、权限和容量元数据 |
| crates/export-doc-domain | 纯业务规则，不依赖 HTTP、GUI、数据库或宿主文件系统 |
| crates/export-doc-engine | 授权、业务用例、任务和可选能力编排 |
| crates/export-doc-storage | SQL、查询投影、事务、SQLite/PostgreSQL 适配 |
| export-doc-excel/report 等能力 crate | Excel、报表/PDF、HS、邮件、OCR 等独立能力 |

维持模块化单体、单 API 实例与有界连接池。没有 Redis、消息队列、第二业务库或多实例高可用承诺。可选能力由组合根通过 Cargo feature 启用；缺能力明确返回不支持，不复制降级业务实现。详细选型见[Rust 架构与选型](./Rust原生架构与选型.md)。

## 数据、权限与事务

- 当前只接受全新 **schema 18** 及对应模型指纹；SQLite/PostgreSQL 使用 Storage 中的完整基线。仅确认数据库不存在时初始化。旧库、空文件、损坏、版本未知、超前或缺表均拒绝打开/恢复，原文件保留。新变更直接更新正式基线，不续接旧实验库迁移链。
- SQLite 仅用于桌面单机，业务库位于 DataRoot/Database；网页和 Docker 使用 PostgreSQL 18。普通 API 只持业务账号，初始化/恢复使用独立维护账号及 NOLOGIN 所有者。数据库原始卷只挂给 PostgreSQL。
- 写入在统一协调器中取得同连接事务，最终提交前重新核对账号、身份、权限、版本和业务引用；用例异常请求回滚。数据库/文件故障不能伪装为空列表或普通冲突。实例锁失效保持停止办理。
- 写入协调与任务发布共用可取消的通知等待锁；释放时唤醒等待者，等待中的写者优先于新读者，取消最多按 100 毫秒间隔复核。数据锁保留标准库 poison 行为；任务发布失败只有完整恢复核对后解除。
- 人员稳定身份、登录账号、任职、单位授权和权限方案分别维护。岗位名称不自动授权；独立权限为空就无业务权限。账号可显式选择已发布方案，模块关闭及单位/部门/项目限制继续收紧最终权限。
- 多身份人员每次只使用顶部选定身份。代理、分派、抄送及办理分工不能绕过显式范围限制。权限变化撤销旧会话；离职/任职结束前处理未结审批和资源交接，不改写历史签署。
- 私密档案独立存储、单独授权；公开人员检索不索引私密值。审批和下载按当前节点与身份裁剪材料，通知、历史和 ZIP 不能补回隐藏内容。
- 自然日为严格 YYYY-MM-DD；时间点保留偏移并规范化 RFC 3339。金额/数量采用精确十进制。发票单价五位、金额两位，中点远离零；不能用字符串截断时间或浮点乘积决定业务舍入。

DDL、权威关系与索引见[账号组织 OA 数据字典](./账号组织OA新基线数据字典.md)，岗位/授权规则见[行政与人员设计](./公司行政协作设计与验收.md)。

## 路径、资源与异步操作

AppRoot/DataRoot 由组合根注入 RuntimePaths。数据库、日志、缓存、模板、备份和原生工具使用受管路径，校验穿越、符号链接/联接点、盘根及可写性。Windows 路径比较不区分大小写，其他平台遵守目标文件系统语义；文件名 NFC 规范化并满足跨平台规则。

单一窗口 COO/ACD 的四种官方交接目录是已授权的例外：保存检测或手选的现存绝对目录，仅只读官方配置，不取得 PIN；这些目录不随本应用迁移、备份或清理。详见[路径审查清单](./运行目录与路径存储审查清单.md)。

HTTP 有 16 个执行名额和 16 个公平等待名额，普通排队最多 5 秒。失败分类为校验 400、权限 403、不存在 404、冲突 409、繁忙 429、依赖故障 503、超时 504。公开操作传播取消、超时和清理；后台终态持久化采用独立的有界收尾作用域。

前端共享保存边界处理重复提交、页面卸载、身份/客户端变化和迟到响应。保存成功后合并基线并保留续编，目录刷新在后台执行。装柜、维护、备份和任务命令不在 Mutation 缓存中保留历史 File、密码或大结果。OA、公告、通知和办公列表共用轮询策略：正常 30 秒、后台页不轮询、永久错误停止、临时错误有界退避；终态 OA 详情停止轮询，批准后尚待办理的申请继续更新。

文件任务发布状态与结果事务化；预览不隐式登记业务数据。任务历史默认保留 30 天、全局 2000/每人 200 条；输出和可重试输入各自使用全局 512 MiB/每人 128 MiB 默认预算，活动输入不回收。普通 BLOB 下载共用 128 MiB 内存预算；完整备份和业务附件不按普通任务输出预算删除。外部用户文件不随任务历史清理。

永久业务文件使用 `file_objects`、`file_versions` 和 `file_locations` 保存元数据、引用及迁移位置，字节由 Engine 的本地/S3 文件存储管理；默认位置为 DataRoot/Files。组合根可登记独立挂载目录。普通附件接收使用受管匿名暂存文件，下载支持单段 Range。存储身份失配或挂载消失报错，不接管空目录。容量策略、历史分页、备份对象清单、迁移和回收见[文件存储与容量管理](./文件存储与容量管理.md)。

文件容量与组织配额由同事务汇总维护，完整性任务独立复核。迁移通过持久待复制队列处理并发新增，字节传输在写锁外完成；审批 PDF 同样在任务工作阶段准备，收尾只发布引用。HTTP、对象和备份流水线共用磁盘预算并保留 256 MiB 余量；附件上传和二进制下载期限为 24 小时。S3 使用独立凭据修订、显式寻址、复用连接、256 MiB 已验证下载缓存及分段日志；远端凭据失效时保留认证管理入口，文件操作仍报错，未实现 STS 自动刷新。

请求日志保留关联号、操作名、状态和耗时，不保存请求正文、凭据或 SQL；有界队列及约 8 MiB 轮转限制体积。管理员指标记录队列、连接、写入、错误及任务容量。实际生产容量与设备故障恢复须独立测量，参数和验证入口见[脚本说明](../scripts/README.md)。

## OA 当前模型

内置 13 种定义保留专业业务约束；自定义事项和代理配置取消累计 100/50 条封顶，每份表单仍最多 40 个字段、明细表 10 列/100 行。表单支持文字、数字、金额、日期、单选、人员、部门、明细及显示条件。适用部门从名称选项多选，提交保存稳定编号；重新编辑草稿时引用名称来自与编号配对的快照，移动明细行不会错配名称。

流程草稿保存、仿真、发布、停用分别执行，按分区/定义维护修订号。发布前使用 1–20 个有效任职样例仿真，立即或定时启用；未发布不能发起正式申请。定时任务到期后复核发布身份、版本及启用状态，受阻进入待处理。流程管理的定义目录、表单模型、编辑、发布和运行队列分别维护。

审批决定与实际办理分阶段执行，支持会签/或签、条件、独立复核、有效直接代理、受控移交、加减签、指定节点退回、暂停/恢复/终止、固定版本子流程和有界升级。系统不代替人员签署审批；减签不能抹去已有签署或绕过必经职责。发布后的在途申请保留冻结流程/材料版本，不是旧软件兼容分支。

申请保存草稿后可上传附件、查看路径并提交；退回修改后重提形成新的提交轮次，历史原件和意见保留。人员未来生效、采购验收、会议室交接/归还、库存预留/发放/分次归还分别有专用节点。报销财务接收终态为 HandedOff，表示已交接财务，**不表示实际付款**，也不自动写入独立付款打印单。

详见[OA 手册入口](./人员组织权限与OA操作手册.md)。真实组织规则、任职期限、权限范围与材料可见性必须一起验收；薪酬、总账和 WMS 不属于当前系统。

## 模板、Excel、OCR 与单一窗口

- 六份业务报表和 OA 审批单共用 .dtpl V3、Rust 排版与 krilla PDF；PDFium 提供实际 PDF 页图及受控处理。空白设计与内置模板使用同一组件和属性，不恢复 Chromium/HTML/Scriban 报表生成链。
- 模板按个人/共享权限、版本及图片引用管理，预览绑定草稿/数据修订；模板预览显示不代表真实 PDF 已通过。复杂组合、长内容、实体打印及各平台继续按[PDF 验收方案](./Rust统一V3模板与原版PDF验收方案.md)记录。
- Noto Sans 400/500/700 与 Noto Serif 400 统一由字体准备脚本验证；UI 使用 WOFF2，PDF 使用 OTF。设计令牌、680/1180 断点和共享控件统一生效。候选确认和中文 composition 不触发跳格/保存，详情见[设计系统](./前端设计系统规范.md)。
- Excel 由 export-doc-excel 复用 excel-analyzer-rs 库，工作表解码、表头识别和字段校验不重复实现。模板紧凑行高与固定坐标同步解析规则；单一窗口模板说明见[填写指南](./单一窗口Excel导入说明.md)。
- OCR 使用受管原生库和模型；PDFium/ONNX 从已核验 NuGet 归档抽取，不需要 .NET。默认正式包携带对应 OCR 资源，WithoutOcr 只用于明确的轻量测试。
- 单一窗口保留发票来源及独立申报草稿、官方 XML、认证交接包、目录检测和回执收集。真实卡、签名与正式发送必须在官方客户端和企业现场验收，不能把离线生成当成发送成功。

## 契约、交付与验收

唯一 API 事实源是 native_contract 投影的 /openapi/v1.json。生成器统一生成 DTO、按域客户端、认证/权限和容量元数据；不手改生成文件，不建立第二套路由/schema。内部用例逐步收紧类型；内置办理节点直接构造类型化规则，流程修订不经过 JSON 字符串往返。

Cargo/npm/受管原生资源的清单和锁文件集中固定依赖；notices/SBOM 只包含当前交付。普通 Dependabot 版本检查每月，完整依赖治理每周及依赖改动时执行，每日保留漏洞审计。GLib 0.18.5 仍受 Tauri GTK3 上游约束，安全例外不等于漏洞已修复；详见[依赖安全](./依赖更新与安全检查.md)。

Tauri Release 内嵌前端，界面变化须重建宿主；SkipBuild 只组装资源。桌面排除 PostgreSQL 服务适配和构建工具运行依赖，网页不包含 Tauri。保留 updater 签名/公钥，不执行 Authenticode、Developer ID 或 Apple 公证。

每批集中执行受影响的 Rust、React、脚本、依赖、真实 PostgreSQL、桌面和 PDF 验收。编译、接口存在、旧测试结果都不能代替功能通过。Firefox/WebKit 重型验收只手动触发；Linux/macOS/ARM64、正式安装与升级及现场长时负载按[平台矩阵](./多平台与多架构支持矩阵.md)独立记账。最新实测见[实施进度](./程序改进重构进度文档.md)。
