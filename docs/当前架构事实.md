# 当前架构事实

核对日期：2026-11-26。本文件只维护现行契约；实施数量、性能样本、截图和清理结果见[实施进度](./程序改进重构进度文档.md)。旧软件版本的兼容链已退役，历史流程版本和审计事实仍属于业务数据。

授权状态由 Engine 按业务时区及防时钟回拨锚点计算；原生契约 `ApiLicenseStatusResponse.licenseState` 明确区分 Trial、TrialExpired、Lifetime、FixedTerm、Expired、Invalid。终身授权的 `daysRemaining/expireDate` 为 null，界面显示“永久有效／永不过期”；定期与试用返回实际 `YYYY-MM-DD` 截止日及包含当天的非负剩余天数，正式授权过期不退回试用。React 的独立展示模型只映射文案，不解析提示文字或猜测最大年份。签名格式、端点权限、授权锚点和 schema 18 不变；验收见[授权有效期显示修复](./archive/2026-11/2026-11-26授权有效期显示与清理.md)。

OA 七类申请共用 `/api/organization/unit-tasks/reassign`，按任务编号、单位身份及申请版本移交；各流程定义、发布版本和审批计划保持独立。审批及移交弹窗固定打开时的版本，临时详情刷新失败保留草稿；历史快照统一查询并在关闭后释放。普通流程节点移除后，后续节点承接其前置关系并去重，支持撤销／重做；分支目标、配对和最后审批节点的限制显示具体原因。兼任负责人仍逐节点签署，本人回避与独立复核继续由领域规则校验；操作见[负责人兼任与节点配置](./OA负责人兼任与节点配置.md)。

设置校验级别统一为 `error/warning/info`，移除未实现的自动修复字段和入口。基础档案删除、许可证注册和模板目录诊断复用作用域命令，离页取消且不持有全局变更缓存。HS 数字编码搜索由 Storage 按年度及前缀收窄后加载；名称搜索语义保持不变。TIFF 预览复用隔离 OCR 工具的 JPEG 转换，上传上限 25 MiB，保留超时、处理许可和输出预算；识别仍接收原文件，预览不加载模型或写业务数据。无依赖、SQL 或 schema 18 变化；定向证据见[本批记录](./archive/2026-11/2026-11-26审批一致性与资源优化.md)。

2026-11-26 维护契约：文本日志清理与审计删除分离，支持包仅导出五份脱敏摘要；审计统计由 Storage 只读快照返回精确总数和最早时间。删除旧 PostgreSQL 连接／自动备份等 14 个失效设置，数据库身份只读，默认导出目录按 DataRoot 保存和解析相对路径。桌面日志轮换固定 20 MiB／三个历史文件，失败明确报错；附件在线预览设 16 MiB 上限。实现、CI 修复与定向验收见[本批记录](./archive/2026-11/2026-11-26维护契约修复与清理.md)。

下载票据的首次并发签发在有界票据锁内复用同一认证会话的浏览器绑定，退出继续撤销全部票据。React 与 Rust 对新输入的夏令时重复／跳过时段均拒绝；未改动的公告、加班、跟进及代理时间保留原始时间点和精度。自然日边界采用该日期首个有效时间点，整日跳过时为空范围；会议室日期查询与登录业务日刷新共用此语义。

PDF 合并在请求预算仍有效时将输入转存受管匿名文件，接入现有磁盘空间预算；后台仅持有文件句柄，通过受控管道分块传输并获取共享重型渲染许可。成功、拒绝、取消和进程退出均随所有权释放暂存；仍执行 1–100 个文件、128 MiB 总输入和 64 MiB 输出上限。OA 六类申请仅保留 `/fulfillment` 办理入口，删除重复 `/complete` 路由及不可达前端动作，原动作权限、办理节点和业务历史保留。确认弹窗上下文与渲染 Provider 独立，卸载时结束未决确认。实现和验证边界见[本批记录](./archive/2026-11/2026-11-25稳定性资源优化与清理.md)。

客户／供应商文件导入与手工新建共用初始状态：客户为“潜在客户”，供应商为“考察中”；文件指定其他状态列为错误行，准入及停用仍通过独立业务动作办理。导入联系人同时要求创建和设为主要联系人权限，预检与提交均重核当前授权。Storage 仅按导入候选名称、当前可见范围做规范化重名查询，预检序列化和摘要在写事务外准备；提交时在事务内复核重名和权限。两类目录共用预览表格，支持全部／错误／重复／可导入筛选与分页，每次仅挂载当前页；现有 5000 行有界响应仍由当前预检会话持有，没有新增第二套接口。

商品明细表按行高及每页行数自动续页；独立分页符只用于普通正文。React 插入／粘贴／保存校验与 Rust 领域规则禁止明细表和独立分页符同时输出，保存与排版入口复用同一规则，关闭输出的组件不参与排版。付款货物仅使用 goodsItems 输入，删除旧单行 goodsName／quantity／quantityUnit DTO 字段及回填分支；报表继续从数组派生同名模板字段，付款列表直接展示明细品名。组织负责人草稿比较同时包含人员编号和任职编号。

OA 付款报销明细支持差旅、交通、餐饮、办公、运费、工厂付款和其他七种类别；运费与工厂付款的稳定代码为 Freight、FactoryPayment，保存及提交材料使用相同原生契约，沿用付款报销审批与财务接收流程。

OA 默认请假、加班和出差办理节点分别显示“销假登记”“加班完成确认”“出差归档”，保留原稳定节点编号和 Complete 动作；已保存或发布的节点名称不自动重写。责任解析的业务错误显示具体节点及其查看／实际动作权限，权限名称来自现有目录；依赖错误、超时和取消保持原分类。办理权限不能由任务审批代替，责任账号还须关联有效人员任职；销假和加班确认可由人事管理员方案或对应资源的独立授权提供，不要求私密人事档案权限。

2026-11-24 独立依赖安全补丁：url 固定 2.5.9，传递 cookie 为 0.18.3、form_urlencoded 为 1.2.3，修复新公布的 URL／Cookie 公告；保持 MIT OR Apache-2.0，notices 和 SBOM 与锁文件同步。架构与业务模型不变，审计边界见[依赖安全记录](./依赖更新与安全检查.md)。

右上角账号区域统一为共享下拉菜单，提供个人修改密码、权限来源和退出登录；单位身份切换、服务状态及界面密度保持直接可见。`POST /api/auth/password` 使用已认证的登录账号，独立于单位业务权限及账号管理权限；原密码验证和新密码哈希复用认证模块，凭据与账号版本／审计在同一事务中更新，随后撤销该账号全部会话。React 复用未保存内容确认及会话清理，不持久化密码，无新增依赖或数据库模型变化。

内置财务方案的费用报销查看、财务接收均为本公司范围，自助创建／编辑／撤销仍限本人，不默认授予审批决定。默认办理节点关闭维护身份接管；自动寻找办理人员始终排除系统管理员，维护接管必须明确分派并启用对应选项。已保存方案、绑定版本及历史流程不会因升级自动重写；现有财务组合须核对查看范围，保存、发布并应用新版本。发布失败显示具体节点和部门，避免将财务接收误当作部门审批缺权。

站内通知按当前申请、审批任务和处理身份投影是否仍需审批，保留原事件和已读状态。Storage 的通知列表、未读数量和全部已读共用可见性筛选，计数与分页仅展开一次权限查询；当前任职来源校验从各审批身份分支提到共同条件，避免组合部门审批与财务职责时触发 SQLite 查询复杂度限制。历史签署、委托身份、办理权限及单位隔离继续独立校验，数据库失败仍返回依赖错误。

权限来源弹窗直接复用共享 Dialog／折叠分区，摘要样式由账号模块独立加载，不依赖行政页面样式。隐藏解释段落和空的关闭项，仅显示实际受限功能；授权操作默认折叠。所有站内通知共用同一卡片和现有 300px 最小列宽，保留空列以避免少量卡片撑满整行；长标题完整换行，右侧标签不压缩。报销通知仅在当前状态为 Approved／HandedOff 时分别显示“待财务接收”／“已财务接收”，保留原审批事件、申请标题和已读事实；复用已有只读申请状态，无新 API、数据库模型或权限变化。

桌面审批材料沿用 Rust PDF 输出，WebView 允许应用自身 origin 的 Blob 预览，CSP 只为嵌入预览开放相同来源和 Blob；下载由宿主提供保存对话框，用户明确选择文件路径。平台下载适配与业务报表分离，不增加另一套 PDF 生成链。

部门负责人本人申请仅在有效部门负责人节点明确允许本人回避、无必经独立复核约束且实际责任人全部为申请自然人时跳过该节点，并要求后续命中独立公司领导审批；缺负责人、失效任职和无权限仍阻断。分流原因随审批计划保存，普通员工路径保持部门与公司两级审批。

单位权限目录由 Storage 批量读取平台或本单位的最新有效发布版本，Engine 共用归属与可下放上限校验。管理身份的可下放上限必须独立配置，目录、版本读取和转授权共用该来源；缺失上限按异常阻断。单位管理员可读取符合边界的发布版本，不能编辑或发布平台方案。非记录范围资源的 all 授权进入两库约束，普通业务记录仍拒绝跨单位 all；继承显示和转为独立配置均使用选定版本，版本未读完禁止复制和保存。全新 schema 18 指纹随正式 SQL 更新，不提供旧库迁移。

人员主职、兼职、汇报负责人及单位名称由共用公开投影批读，账号列表不加载完整私人档案或任职删除检查。申请保存部门名称快照，材料中的显示名称遵守对应标识字段的可见性。部门显示顺序通过稳定 ID、完整同级集合和逐行版本在单事务中保存，不改变组织层级；行末上移、下移直接保存，表格占满可用宽度，窄屏保留受控横向滚动。

原有八种权限职责保留，增加部门审批人员、公司审批人员两种内置初始方案，分别提供部门/公司范围的 OA 查看、审批及本人自助申请，不授予私密人事档案、实物办理或系统管理。缺失的内置方案在系统管理员成功登录的同一事务中补齐，已有草稿、发布版本及账号绑定不改写。新建方案直接复制服务端内置配置，不再由前端另行拼装审批预置。兼任职责通过组合多个方案形成独立方案，同一资源/动作取较大范围，须明确核对后发布和分配；角色及职位不自动追加权限。

节点生效条件和流程图共用本人回避设置的展示模型，显示负责人本人跳过或独立/必经复核阻断；实际有效人员及后续独立领导资格仍由 Domain/Engine 判定。发布解析失败保留权限/任职的具体原因，或提示责任人、单位、业务资源及所需动作。

七类 OA 申请允许原申请身份删除从未提交且无审批计划或正式历史的草稿。删除须通过当前编辑权限、版本和材料权限校验，关联临时附件与事件同事务移除，审计和幂等命令回执保留。回执目标保存正整数身份而不再阻止合法草稿删除；原调用人外键、命令正文摘要和身份绑定继续生效。已提交、退回和取消的历史申请不能按草稿删除。

账号删除与日常停用共用事务内交接检查：发票、付款及已纳入归属管理的其它业务资料和未结职责必须先交接，历史引用保护继续生效。账号已删除时认证撤销对应会话并返回 401，普通资源不存在仍为 404，数据库故障继续保留依赖错误。最后一个启用管理员的日常维护和安全停用共用 Storage 的有界编号查询；引用存在性检查及部门身份校验不再加载完整目录或统计全部匹配记录。

业务资料原件的浏览器下载复用现有短期票据和 HttpOnly Cookie 绑定，签发及每次下载均复核当前身份与资料权限；链接单独转发不可使用。下载按块传输并保留单段 Range，React 不为原件下载读取完整 Blob，离开记录后迟到的票据不会触发下载。预览继续读取受限 Blob，桌面另存为继续使用受控流式文件输出。HS 清空仅按编号游标分批扫描，逐条审计和全事务取消/回滚保持不变；无数据库 schema、依赖版本或设计令牌变更。

HS 增量导入保留文件未提供的列，明确提供的空单元格表示清空；完整年度模式继续按完整行覆盖并核对缺失编码。预检返回摘要和 token，明细由 Storage 按变更类别筛选后分页，每页最多 200 条；React 只保留当前页，展开查看字段修改前后的值。临时导入共用 `import_preview_rows` 保存唯一一份行内容，提交仍核对账号、单位、期限、完整性及业务版本，并在同一事务内消费。新增表及索引进入全新 schema 18 模型指纹，不保留旧 BLOB 预检或旧数据库接受链。

报表图片目录的 `canRecycle` 同时检查回收动作权限、归属和引用；S3 缓存的摘要读取被取消或超时不淘汰已有字节，后续读取仍重新验证摘要。业务资料分类筛选从原生契约贯通前端，删除不存在的 `status` 过滤和恒为空的 `invoiceBytesLimit` 字段；单文件及组织配额继续由文件策略控制。共享库归属汇总在同一读取快照内复核权限、批读账号显示字段并聚合，按编号索引各用户的统计。

申请可编辑状态由 Domain 按业务种类判定：普通 OA 的退回修改仍可续编，会议室和物品只允许草稿编辑；物品的已归还是办结状态，正文和附件入口共同拒绝再次修改。会议室冲突校验在写事务内使用 Storage 的状态、单位、资源筛选和精确时刻存在查询，最多读取一个编号；保持相邻时段允许、偏移和纳秒语义，实际交接超时另行核对，不将历史预约集合加载到 Engine。

HS 写入明确区分新建、编辑和受控导入；重复编码的新建返回冲突，编辑统一解析数字/字符串编号并检查调用方版本。联网参考保存由独立前端命令 hook 查询本地记录；已有参考资料需确认后按读取版本更新，只接受远程提供的参考字段，保留本地备注、来源、年度与替代关系，空字段不清空原值。年度有效税则继续通过原有专用流程维护。

业务日刷新复用查询临时错误退避，成功后按新的业务日截止时间调度；隐藏页面停止轮询，恢复可见或联网时重新核对。请求和计时器随客户端、令牌和页面生命周期取消，过期响应不能回填；认证及永久错误不自动重试，过时的服务端截止时间不会触发零间隔循环。

信用证导入由一个受控任务打开 PDF 一次，逐页提取文字；无文字的可绘制页、含图片或 Form 对象的页进入 OCR，原生文字补回 OCR 未识别的行。OCR 按任务复用一个模型进程，每次只传一页，保留 50 页、2 亿总渲染像素、50 万字符、单帧容量和任务期限。超时/取消终止进程树；输入错误、缺依赖、超时分别保留 400/503/504，不返回部分成功。导入仍是预览，只有发票保存才持久化。支持 PNG/JPEG/BMP/WebP/TIFF，不声明 GIF；信用证导入及审核使用 `document.invoices/operate`，与界面一致。

岗位部门、职责限定项目和权限项目集合共用 `/api/organization/assignment-options`：Storage 按当前单位、名称/代码筛选后分页，每页最多 100 条，另外回传最多 200 个已选 ID 的标签。停用项目可回显保留的关系，新分配只能选择有效项目。人员候选不再附带截断的部门目录；检索使用防抖和取消，翻页/搜索保留已选限制。已有关系继续通过结束有效期维护历史。项目限定职责负责路由分工，不授予账号动作权限，也不替代明确数据范围限制。项目负责人及有效成员资格共用 Storage 判定；流程先验证来源，再以真实项目/任职样例仿真发布，提交与签署复核有效职责、账号授权和当前任务资格。

模板 JSON 的数值必须为有限数字，整数不能由字符串解析或四舍五入获得；非法数值产生阻断错误，安全草稿与正式校验分离。HTTP 写命令仍先预留响应容量再执行，容量分组内顺序等待，小响应可独立获得预算，继续为读请求保留 8 MiB。信用证提取上限 4 MiB，OCR/登录响应上限 8 MiB；其它未证明可缩小的容量继续保持原契约。该预算不是进程 RSS 上限。启动账号存在性复用有界存在查询，Excel 默认出口商只批读获授权的名称并在发现第二个不同名称时停止。

装柜项目保存、分析及柜型保存共用输入校验；无效货物行保留并阻止提交，不截断整数或默默丢行。柜型默认尺寸和容量来自当前接口，迟到的默认值不覆盖用户草稿；数值回读不作三位小数舍入。装柜页显式加载共用工具布局，四个方案操作占据完整网格行，保留原设计令牌、680/1180 断点与宽屏分栏。3D 货物面、轮廓和层线分别合批，切换轮廓/完整分格复用渲染器，关闭时统一释放资源。

供应商采购概览按授权范围由 Storage 计算最新已确认评价的全局统计，并按 `filter`、`pageNumber`、`pageSize` 返回当前页。明细最多 200 条且不携带未展示的评价备注；React 提供分页、筛选和请求取消，换页不改变总览统计。邮件启动恢复按每批 100 条读取 Attempting 摘要并事务化改为 Uncertain，不加载全部历史，也不自动重发。

无消费者的 HTTP 关闭维护入口和重复提交包上传入口已退役；桌面关闭继续走宿主生命周期，单一窗口保留现行提交包导入与回执上传。契约变化由原生定义统一生成并与冻结基线的明确差异验证，不新增旧接口兼容链。

公司内自然键与访问授权分开：客户、出口商、商品、单位、港口、会议室和物品目录以规范化 `[company,key]` 定位，同一公司仍拒绝重复。商品按编码查询沿用授权数据范围，计数和分页前筛选；发票明细回存商品库遇到多个同编码候选时停止自动更新，要求明确选择档案；全局 `all` 单证授权可读取获准的不同公司记录。发票/付款编辑保留原公司、归属人与部门。OA 报销、资源办理和审批继续绑定一个明确单位身份，跨单位协作通过已授权身份及具体任务完成，集团汇总使用独立单位集合授权，不能将单证 `all` 规则套到 OA。

单据包往来单位匹配在 Storage 按目标公司及规范化名称/税号/信用代码查询至多两个候选。多候选或强标识冲突返回 409，预览与导入共用判定，避免按插入顺序误关联；该规则不限制已有记录的跨公司授权读取。

发票/付款的 `all` 是同一系统内的全公司范围，不自动按集团或已任职单位缩小。非管理员账号可以在“明确的数据范围与限制”中为每个资源/动作配置“指定单位集合”，实际范围与原授权取交集；例如全范围查看再限制为 A、B 公司，只开放这两家公司，限制本身不会增加编辑权。登录能力返回后端已解析的 `scopeRestrictions`，前端记录按钮与后端使用相同成员集合；查看 A/B、操作仅 A 时，B 可打开但保存/编辑不可用。权限编辑器回显已保存的集合，修改授权会撤销原会话，重新登录后按新范围加载。单证操作按查看、日常操作（新增/编辑）、管理（删除等）分开，打印/导出另有输出权限。内置单证人员方案使用本人范围，财务方案查看本公司付款、操作本人付款；实际权限来自账号所选已发布方案或独立配置。本批保留授权能力并验证隔离，没有为现有账号增加跨公司授权。普通人员使用本人/部门/公司范围；集中财务按负责的明确单位集合配置，不以不受限 `all` 作为日常默认。

工作台在 Storage 内按可见范围选取同公司/发票号的优先版本，再按 ID 游标分批投影；Engine 只保留最近十条和有界待办，使用 Decimal 汇总各币种。统计仍扫描全部可见有效发票，不宣称常数时间或进程内存上限。两库新增发票版本及规范化商品编码索引，schema 18 指纹随新基线更新，不提供旧实验库迁移。

公告编辑详情与 HS 反馈/学习复用作用域取消；客户端、身份、权限或查询变化后，迟到结果不能覆盖当前草稿或提示。资源申请详情的“提交版本”默认收起，展开后分页读取历史，选中后展示提交快照、原附件和对应审批单；复用现行控件、打印与材料权限。

单一窗口无消费者的回执下载端点及失效工作目录参数已退役，保留受管临时空间与现行另存为流程；工作台删除不按币种区分的旧出口总额字段。OpenAPI、运行元数据、Rust DTO 和 React 客户端从原生定义同步生成。

文件读取每次校验内容摘要，文件时间戳和长度不能代替完整性证明。本地对象及 S3 下载缓存共用校验与游标复位；已下载文件仍受容量/条目上限控制并复用，损坏缓存移除并返回依赖错误。此规则取代此前的文件变更戳校验缓存。

发票、商品资料以及发票目录、查询、利润和工作台金额使用十进制文本契约。React 输入、草稿、剪贴板、商品库转换、计算和保存不经二进制浮点中转；整数编号和视觉坐标仍使用对应类型。Rust DTO 按字符串序列化 Decimal，显式输入字段在原生契约边界验证类型，内部精确 JSON 数值按响应声明投影为文本。现有金额舍入和数量范围保持。

发票明细先计算校验，再发布草稿与撤销快照；超长输入或计算失败显示错误，保留原值及历史，避免异常进入 React 状态更新。

契约层提供共用严格十进制文本解析，生成 DTO、字段校验和 Domain 使用同一实现；非普通十进制写法、数值超范围和隐式精度舍入均拒绝，可空数字使用 null，不接受空字符串代替。

HTTP JSON 输入继续共用 64 MiB 接收预算，按实际缓冲容量增长在分配前计费，读取完成后额度随解析值保留到工作结束；不按每次请求的 16 MiB 上限固定占用。4 个解析名额使用最多 5 秒的有界公平等待。输入与输出复用有界字节缓冲，单请求上限、空闲期限、取消和错误释放保持生效。

HS 智能查询按游标分批遍历全部候选实例，按编码聚合必要证据，匹配后才限制结果数。反馈的规范化查询文本由 Storage 在记录写事务内生成，复用 `hs_search` 及两库的 `records_hs_feedback_query` 部分索引。该索引进入 schema 18 全新基线并更新模型指纹；旧实验库使用新 DataRoot/数据库重建。联网详情的只读查询使用 view 权限和无采集接口，候选采集继续要求 manage 权限。

办公资源申请在首次保存草稿后锁定申请人、任职和项目，附件失败重试继续使用同一身份及版本；数量、时间、主题等草稿内容仍可续编。会议室和领用申请只保留专用草稿更新接口，两个始终拒绝更新的通用 PUT 入口已退役。

生产企业详情已由分页目录的完整记录提供，可用币种随汇率查询返回；对应的两个重复 GET 已退役。V3 的纸张和限制模型通过 OpenAPI `x-exportdoc-shared-schemas` 显式生成，前端与 Domain 共用；删除独立 V3 描述接口及重复固定 JSON。契约自省统一读取 `/openapi/v1.json`。

HTTP JSON 写入在执行前按契约预留响应容量，并在共用 128 MiB 预算中给读取编码保留 8 MiB 余量，避免两个 64 MiB 预留挤占全部读取空间。短时冲突按到达顺序等待释放通知，最多五秒，等待仍占原请求名额并可取消。固定回执、下载票据、注销和批量状态回执使用 64 KiB 上限。存活、就绪由原生探针元数据区分：存活不访问数据库或磁盘，就绪使用两个独立名额及一秒期限；两者成功正文为空，不进入业务队列或详细诊断。详细运行信息继续由 `/healthz` 提供。

商机工作区分离页面、草稿模型、作用域命令和历史展示；保存保留无权编辑的报价字段及请求期间续编，确认、流转、归档和导航共用串行边界。归档记录通过 `includeArchived` 查询并只读查看；详情与历史共用商机、关联客户和产品权限检查。历史使用 `beforeId/limit` 游标，仅在展开时读取，Storage 两库的 `records_opportunity_history_page` 索引覆盖关联编号和倒序记录号。该索引进入 schema 18 完整基线并更新模型指纹，旧实验库使用新数据根重建。

发票 `pendingHsFeedback` 在发票写事务内去重、验证并消费，反馈与发票一起提交或回滚，成功响应不再携带待提交反馈。客户端不另发即时反馈请求。客户、出口商、收款对象和港口只保留分页目录；HS 导入只保留预检/提交，七个重复接口及两个失去引用的导入类型已退役。

普通 JSON 与报表预览共用 HTTP 实例的 128 MiB 响应预算。端点容量由原生契约生成：命令回执、供货关系和评价单记录为 64 KiB，评价统计为 1 MiB，其余最多 64 MiB。JSON 写入在业务执行前预留容量，编码后缩减到实际缓冲容量；共用编码器在缓冲增长前准入，读取操作按增长计费。无正文成功响应和文件输出沿各自边界执行。该计数覆盖受管编码缓冲及发送保留，不覆盖 JSON Value、数据库驱动或进程 RSS；个别独立能力的已编码返回值仍在发送前准入。预览另有两个传输名额；普通 JSON 不占文件下载名额，也不计入文件下载统计。JSON 使用端点执行时限，文件使用传输时限。设置页按需加载队列、连接池、写等待、任务和缓冲预算。运行诊断使用 `application/data`、`read/read-write` 与 `required/optional` 元数据；数据库必需，未知或矛盾状态显示异常。

供应商供货关系与评价分离展示、草稿模型和作用域命令，复用分页/版本草稿基础模块。参考价采用可带正负号和前导零的普通十进制字符串，保存时精确规范化，编号、交期和评分采用整数；不接受下划线、科学计数、旧字符串编号或浮点价格兼容链。发票销售单价、行金额和采购金额允许负数，数量、包装、尺寸、重量和体积非负，退税率为 0–100。供货/评价写入按生成契约检查结构，关联记录复用编号解析并拒绝正文与路径的非零编号冲突。评价目录直接分页，分析由 Storage 在同一读事务内聚合全部当前可见记录并返回最近 12 条；普通用户仅见自己的草稿及已确认记录，审批权限继续受所属供应商范围限制。React 分页及分析采用同一生成契约，分析按需请求；客户端/权限切换隔离查询和反馈，保存保留续编并衔接新编号/版本，停用、恢复、删除和确认复用串行确认边界。

商机目录、详情和历史要求商机及产品查看权限；关联客户范围仍单独校验。预计金额输入支持十进制字符串，商机、历史和看板的金额输出使用十进制字符串，React 不经浮点转换。看板“未来 30 天预计成交”使用业务自然日半开区间 `[今天, 今天+30天)`，两库均先筛选再取前八条。HS 联网查询按权限区分只读查询和候选采集；候选审核统一使用批量契约，最多 200 条，忽略操作不读取年度税则。GET/HEAD 存活和就绪探针各有独立操作名。

全部成功响应均无正文的操作免除响应字节预留，成功正文为空；其它 JSON 写入的执行前预算规则保持。商机只读/归档详情不查询候选客户或产品，可编辑字段才查询对应候选项。HS 搜索文本由 Storage 在记录写事务中共用 Domain 规则生成，关键词筛选与分页由两库完成；`hs_search` 纳入全新 schema 18 指纹，不兼容旧实验库。

发票和通用主数据的编辑器按记录身份建立独立生命周期；新记录加载失败时不沿用旧草稿或确认。通用记录在用例边界统一解析契约允许的数字/十进制字符串编号，拒绝无效、负值及正文与路径编号不一致。版本冲突通过既有 `ApiErrorResponse.code=ConcurrencyConflict` 传递，前端不再根据提示文字猜测；普通业务冲突继续独立处理，内部诊断不进入响应。

发票核对和利润规则归 Domain：空明细草稿可以保存，不能核对；金额以十进制四舍五入到两位，中点远离零，单价最多五位。退税先汇总再舍入，利润使用已舍入的采购和退税合计；编辑、保存与分析使用同一口径，CNY/RMB 未设置有效汇率时按 1 计算。自定义候选项使用读事务和按类型的有界投影，保存按唯一键检查已有值；普通认证请求在接收正文前按端点元数据授权，正式业务提交仍重验权限与记录范围。

付款编辑按路由记录隔离草稿，工作区 hook 统一查询、确认、保存、删除和版本重载；命令绑定客户端与当前权限，记录加载失败不会沿用另一笔记录的草稿。查询导出绑定已提交筛选，付款 PDF 绑定来源、模板与输出权限，统一复用作用域命令，不保留 mutation 输入/结果缓存。权限方案引用数及最新发布版本由 Storage 按批聚合现有权限绑定/发布表；Engine 仅投影。非分页目录复用游标读取，仍完整返回现行数组契约。

付款金额采用非负十进制字符串契约，输入、保存、回读与费用合计不做浮点转换，Rust DTO 按字符串序列化 Decimal；沿用 Decimal 系数和最多 28 位小数限制。

## 产品与模块边界

客户跟进由独立草稿/命令 hook 管理；保存成功合并返回版本，保留提交期间的续编。联系人使用现行分页契约和共享分页控件，历史跟进的已选联系人即使不在当前页仍保留编号/名称。发票 PDF、托单及单据包的路径选择、提交和下载使用同一作用域命令，绑定来源、客户端、模板及当前输出权限。

装柜分析保留完整输入与结果快照，输入修订后旧图仅作参考，重新分析前禁止 PDF 导出；柜型保存/删除与 PDF 输出复用作用域命令。方案目录使用 `keyword/pageNumber/pageSize` 分页，列表只传摘要，详情按需读取。权限方案拆分展示、工作区和草稿模型，删除先移除缓存条目，确认与命令绑定当前身份和草稿。

发票维护通过 Storage 的关联键索引及编号/版本投影按游标分批清理，所有删除仍在同一事务中。审批可见性与待办状态按记录复用一次审批快照；没有引入跨请求权限缓存。通用保存的业务身份/范围准备集中在 `store::record_policy`，事务、审计和文件发布仍由 Store 统一管理。新增 `records_source_page` 索引已进入 schema 18 完整基线，模型指纹随之变化，旧实验库须使用新 DataRoot/数据库重建。

| crates/export-doc-engine | 授权、业务用例、任务和可选能力编排 |

维持模块化单体、单 API 实例与有界连接池。没有 Redis、消息队列、第二业务库或多实例高可用承诺。可选能力由组合根通过 Cargo feature 启用；缺能力明确返回不支持，不复制降级业务实现。详细选型见[Rust 架构与选型](./Rust原生架构与选型.md)。

## 数据、权限与事务

- 当前只接受全新 **schema 18** 及对应模型指纹；SQLite/PostgreSQL 使用 Storage 中的完整基线。仅确认数据库不存在时初始化。旧库、空文件、损坏、版本未知、超前或缺表均拒绝打开/恢复，原文件保留。新变更直接更新正式基线，不续接旧实验库迁移链。
- SQLite 仅用于桌面单机，业务库位于 DataRoot/Database；网页和 Docker 使用 PostgreSQL 18。普通 API 只持业务账号，初始化/恢复使用独立维护账号及 NOLOGIN 所有者。数据库原始卷只挂给 PostgreSQL。
- 写入在统一协调器中取得同连接事务，最终提交前重新核对账号、身份、权限、版本和业务引用；用例异常请求回滚。数据库/文件故障不能伪装为空列表或普通冲突。实例锁失效保持停止办理。
- SQLite/PostgreSQL 共用提交取消边界：提交前再次检查取消并回滚；提交开始后由适配器自身的有界时限取得明确结果，调用方取消不再中断提交。真实连接/协议故障或不确定提交仍使连接池停止服务。
- 写入协调与任务发布共用可取消的通知等待锁；释放时唤醒等待者，等待中的写者优先于新读者，取消最多按 100 毫秒间隔复核。数据锁保留标准库 poison 行为；任务发布失败只有完整恢复核对后解除。
- 人员稳定身份、登录账号、任职、单位授权和权限方案分别维护。岗位名称不自动授权；独立权限为空就无业务权限。账号可显式选择已发布方案，模块关闭及单位/部门/项目限制继续收紧最终权限。
- 多身份人员每次只使用顶部选定身份。代理、分派、抄送及办理分工不能绕过显式范围限制。权限变化撤销旧会话；离职/任职结束前处理未结审批和资源交接，不改写历史签署。
- 私密档案独立存储、单独授权；公开人员检索不索引私密值。审批和下载按当前节点与身份裁剪材料，通知、历史和 ZIP 不能补回隐藏内容。
- 自然日为严格 YYYY-MM-DD；时间点保留偏移并规范化 RFC 3339。金额/数量采用精确十进制。发票单价五位、金额两位，中点远离零；不能用字符串截断时间或浮点乘积决定业务舍入。
- 发票状态变化与 `invoice_status_history` 同事务保存，记录前后状态、原因、操作账号 ID 与登录名快照和时间；与通用审计一样，显式清除发票不会改写历史事实。状态历史按版本游标分页，界面展开后按需加载。邮件服务状态允许发送或查看投递记录的用户读取，投递记录仍独立授权。
- 审计的“现存发票号”筛选关联当前发票号码，按当前号码查出该发票的审计记录；改号后使用新号码，已删除发票的日志使用实体、操作人、时间等其它条件查询。审计正文继续脱敏，不额外复制明文业务数据。清理与列表复用 Storage 筛选规则，清理只读编号、按游标分批删除，授权、数量上限和维护日志仍在同一事务内。

DDL、权威关系与索引见[账号组织 OA 数据字典](./账号组织OA新基线数据字典.md)，岗位/授权规则见[行政与人员设计](./公司行政协作设计与验收.md)。

## 路径、资源与异步操作

业务附件另存为使用已验证对象句柄和 64 KiB 分块复制，校验最终长度/摘要，在 flush 后、原子替换前重新核对当前权限、版本及取消状态；失败保留原目标文件并清理临时输出。独立文件挂载目录先规范化真实路径，Windows 按组件不区分大小写比较，拒绝 AppRoot/DataRoot 的重叠目录。

AppRoot/DataRoot 由组合根注入 RuntimePaths。数据库、日志、缓存、模板、备份和原生工具使用受管路径，校验穿越、符号链接/联接点、盘根及可写性。Windows 路径比较不区分大小写，其他平台遵守目标文件系统语义；文件名 NFC 规范化并满足跨平台规则。

单一窗口 COO/ACD 的四种官方交接目录是已授权的例外：保存检测或手选的现存绝对目录，仅只读官方配置，不取得 PIN；这些目录不随本应用迁移、备份或清理。详见[路径审查清单](./运行目录与路径存储审查清单.md)。

HTTP 有 16 个执行名额和 16 个公平等待名额，普通排队最多 5 秒。执行期限读取最终生成契约，包含附件和二进制响应的期限覆盖；不直接使用契约构造时的默认值。失败分类为校验 400、权限 403、不存在 404、冲突 409、繁忙 429、依赖故障 503、超时 504。公开操作传播取消、超时和清理；后台终态持久化采用独立的有界收尾作用域。

前端共享保存边界处理重复提交、页面卸载、身份/客户端变化和迟到响应。保存成功后合并基线并保留续编，目录刷新在后台执行。装柜、维护、备份和任务命令不在 Mutation 缓存中保留历史 File、密码或大结果。OA、公告、通知、办公、任务、维护和汇率共用轮询策略：正常间隔按业务设置、后台页不轮询、永久错误停止、临时错误有界退避；首次失败也能恢复。终态 OA/任务详情停止轮询，批准后尚待办理的申请继续更新。

资源申请详情在列表版本推进后重取，后台刷新失败保留原详情和打开的编辑器；草稿使用打开时的版本快照保存，由后端明确拒绝并发覆盖。办公命令与发票存入商品库复用作用域取消，客户端、记录或编辑资格变化后旧确认不能写入。资源状态筛选覆盖暂停和终止；在途职责任务仅在展开后查询，审批单设计器按需加载。

模板真实单据来源复用发票/付款分页接口，每页 50 条，检索防抖并取消过期请求；翻页和搜索保留已选来源，不因演示或设计模式读取真实单据。销售概览的客户/联系人使用授权计数查询，未完成跟进使用同一筛选下的类型化数据库聚合及八条提醒投影，保留偏移与纳秒边界。发票工作台的历史状态数量由数据库统计，最近记录／各状态待办有界读取，金额仅扫描本月和上月投影；各查询共用同一授权与发票优先版本筛选，并在同一读取快照内执行。商机和发票金额继续在 Rust 中按精确十进制累加，不使用 SQLite 浮点 SUM 代替。

供应商与联系人保存允许续编，生命周期操作单独锁定编辑。发票永久清理及归属改派由专用 hook 编排，确认包含在串行作用域内，提交使用确认时快照；页面、客户端、权限或目标变化取消旧操作，维护查询不接受过期响应。待办首屏列表与来源汇总共用一次读取，后续页仅取游标页；精确汇总仍按实时权限扫描活动候选。

文件任务发布状态与结果事务化；预览不隐式登记业务数据。任务历史默认保留 30 天、全局 2000/每人 200 条；输出和可重试输入各自使用全局 512 MiB/每人 128 MiB 默认预算，活动输入不回收。普通 BLOB 下载共用 128 MiB 内存预算；完整备份和业务附件不按普通任务输出预算删除。外部用户文件不随任务历史清理。

永久业务文件使用 `file_objects`、`file_versions` 和 `file_locations` 保存元数据、引用及迁移位置，字节由 Engine 的本地/S3 文件存储管理；默认位置为 DataRoot/Files。组合根可登记独立挂载目录。普通附件接收使用受管匿名暂存文件，下载支持单段 Range。存储身份失配或挂载消失报错，不接管空目录。容量策略、历史分页、备份对象清单、迁移和回收见[文件存储与容量管理](./文件存储与容量管理.md)。

文件容量与组织配额由同事务汇总维护，完整性任务独立复核。迁移通过持久待复制队列处理并发新增，字节传输在写锁外完成；审批 PDF 同样在任务工作阶段准备，收尾只发布引用。HTTP、对象和备份流水线共用磁盘预算并保留 256 MiB 余量；附件上传和二进制下载期限为 24 小时。S3 使用独立凭据修订、显式寻址、复用连接、256 MiB 已验证下载缓存及分段日志；远端凭据失效时保留认证管理入口，文件操作仍报错，未实现 STS 自动刷新。

请求日志保留关联号、操作名、状态和耗时，不保存请求正文、凭据或 SQL；有界队列及约 8 MiB 轮转限制体积。管理员指标记录队列、连接、写入、错误及任务容量。实际生产容量与设备故障恢复须独立测量，参数和验证入口见[脚本说明](../scripts/README.md)。

HTTP 请求名额与关闭登记跟随全部阻塞阶段，包括正文读取前的认证和备份授权；调用方断开后，已排队或尚未退出的后台工作继续占用名额，直至真实退出。

对象回收在短写锁内复核引用并认领对象，物理删除在锁外进行；同对象上传与回收互斥，未完成意图和无引用元数据支持重试。本地文件每次打开均校验内容摘要；S3 同对象缓存填充共享有界、可取消的等待，缓存命中也重新校验摘要。审批 ZIP 全部字节接入磁盘预算；模板、支持包和图片下载在分配前预留工作内存，发送期间持有结果实际容量预算。

S3 已验证缓存同时限制 256 MiB 和 1024 条，按使用顺序索引淘汰，打开/核验/删除文件在缓存状态锁外执行。HS 知识包同样在 HTTP 发送期间持有结果容量预算；磁盘写入分块预留，ZIP 和归档头使用有界缓冲并显式检查最终 flush。利润分析随草稿或客户端变化取消并清空；邮件发送与完整备份恢复复用无缓存作用域命令。

审计导出、下载、清理和路径选择共用作用域命令，下载 Blob 不进入 MutationCache；页面、客户端或已提交筛选变化时忽略迟到结果。生产企业弹窗分离展示、草稿模型和工作区命令，确认、切换、保存、删除共用串行边界。供应商只保留当前详情和当前分页查询，未被观察的目录/详情缓存即回收；联系人工作区独立管理查询、版本草稿和命令，只在打开时加载。报表模板的管理输入、写入及回读后的文档状态更新由独立命令 hook 编排。路由参数跟随实际提交的位置，哈希导航保留旧 history key 时也能正确切换记录。

账号保存、删除、刷新、切换和新建复用作用域命令；迟到响应不得回填另一会话的查询缓存，重置密码不进入 MutationCache，已提交的 `userId` 导航同步账号选择。自动文件下载对临时网络/HTTP 故障最多连续重试两次，成功查询重置失败计数，所有等待共用原总期限。

生成型 PDF、Excel、提交包、回执和 OCR 图片共用下载预算，响应释放前持有结果实际容量。审计先在授权快照内分批写入受管匿名暂存，再释放连接并逐行压缩 Excel；导出及本机保存均接入磁盘预算。CRM 批量状态只读取选定编号，物品已领用判断使用存在查询。

完整恢复先校验并暂存，在任务最终授权和提交中发布恢复标记，取消或失败不安排下次启动恢复。标记与现有任务发布日志共同恢复，成功决定在数据库提交后落盘，任务历史清理不撤销已安排的恢复。SQLite 完整备份以数据库快照的对象清单为准；安装只复制恢复数据库登记的对象，按块核查取消和空间，失败在独立补偿作用域回滚。启动验证已解包内容，不重复提取对象。

2026-11-25 备份恢复收口：SQLite 普通备份改为真实后台任务，普通恢复同完整恢复一样先暂存、重启后持实例锁替换，任务提交不再依赖被恢复掉的账号。PostgreSQL 单独 dump 和完整迁移包都返回后台校验任务，使用受控 `pg_restore` 完整读取并丢弃输出，校验失败不发布恢复标记；恢复标记、审计与任务沿用同一提交确认机制。`pg_dump` 流式写入共享磁盘预算，SQLite 快照通过 Storage 容量回调预留空间。归档列表独立分页，单份异常可见且不能用于恢复，计划轮询不扫描全部归档。桌面提供显式 `--import-recovery` / `--restore-sqlite-pending` 离线入口，复用恢复模块且保留损坏数据库现场。

单据邮件使用原生契约声明的可选 `Idempotency-Key`；同次请求重试沿用键，主动再次发送使用新键。自定义正文只进入进程内有界重试输入（最多 128 份，每份序列化不超过 64 KiB），不写入任务 `_retry`；成功或替换任务后释放。进程重启或输入被回收后，重试明确要求重新填写。SMTP 确认不明继续禁止自动重投。

## OA 当前模型

2026-11-21 审查修复：同名同摘要 OA 附件的相同用途重试幂等返回，不同用途返回 409。人员到期关注项由 Storage 在同一查询中完成权限交集、日期判断、计数与分页，不再由 Engine 逐批扫描私密字段；人事部门选项按单位过滤，组织负责人姓名和工号按去重 ID 有界批读。详情和原件仍重新检查当前访问权限。

前端会话按身份、单位、部门及权限建立授权作用域；授权变化统一取消查询并清空缓存，客户端在发出请求和读取响应后检查当前作用域，防止旧成功结果回填。正常令牌续期和授权未变化的业务日期刷新保留客户端。PDF 页预览入口继续持有全局渲染许可；PDF 缓存最多 4 项、合计 64 MiB，单个超限 PDF 不进入缓存，闲置条目 300 秒后主动移除，清理线程随服务关闭。

OA、会议室预约和物品申请的附件不设私密级别，上传及返回契约不含 `classification`，流程节点不含 `allowRestrictedAttachments`。附件统一受申请访问范围和节点材料规则控制；节点隐藏附件时，列表、原件下载和完整归档保持相同限制。人员私密档案、核验字段及其它正文材料的独立授权继续有效。2026-11-21 用户确认删除该未采用能力，不维护旧字段或旧流程配置兼容链，详见[清理及审查修订](./archive/2026-11/2026-11-21OA附件简化与审查修订.md)。

待办扫描中的人员资格、有效代理、业务身份和办理分工只在当前数据库读取中复用；各记录仍分别检查单位、数据范围、申请人隔离及任务来源。`ReadContext` 随读取结束释放，不跨请求或写入复用权限结果。

OA、会议室和物品命令在超时/断线或网关故障后共用 `commandKey` 回执确认，再读取详情；不自动重发写入。未确认与已提交但详情刷新失败分别提示，取消仍绑定原客户端、记录及权限作用域。

内置 13 种定义保留专业业务约束；自定义事项和代理配置取消累计 100/50 条封顶，每份表单仍最多 40 个字段、明细表 10 列/100 行。表单支持文字、数字、金额、日期、单选、人员、部门、明细及显示条件。适用部门从名称选项多选，提交保存稳定编号；重新编辑草稿时引用名称来自与编号配对的快照，移动明细行不会错配名称。

流程草稿保存、仿真、发布、停用分别执行，按分区/定义维护修订号。发布前使用 1–20 个有效任职样例仿真，立即或定时启用；未发布不能发起正式申请。定时任务到期后复核发布身份、版本及启用状态，受阻进入待处理。流程管理的定义目录、表单模型、编辑、发布和运行队列分别维护。

审批决定与实际办理分阶段执行，支持会签/或签、条件、独立复核、有效直接代理、受控移交、加减签、指定节点退回、暂停/恢复/终止、固定版本子流程和有界升级。系统不代替人员签署审批；减签不能抹去已有签署或绕过必经职责。发布后的在途申请保留冻结流程/材料版本，不是旧软件兼容分支。

申请保存草稿后可上传附件、查看路径并提交；退回修改后重提形成新的提交轮次，历史原件和意见保留。人员未来生效、采购验收、会议室交接/归还、库存预留/发放/分次归还分别有专用节点。报销财务接收终态为 HandedOff，表示已交接财务，**不表示实际付款**，也不自动写入独立付款打印单。

详见[OA 手册入口](./人员组织权限与OA操作手册.md)。真实组织规则、任职期限、权限范围与材料可见性必须一起验收；薪酬、总账和 WMS 不属于当前系统。

## 模板、Excel、OCR 与单一窗口

- 七份业务报表和 OA 审批单共用 .dtpl V3、Rust 排版与 krilla PDF；PDFium 提供实际 PDF 页图及受控处理。付款增加默认工厂付款单，竖向 A4 白底双联（财务付款／核算），最多四项独立货物明细。空白设计与内置模板使用同一组件和属性，不恢复 Chromium/HTML/Scriban 报表生成链。
- V3 Flow 的结构化组件直接复用字段域校验，传入组件、报告类型、版区和原始错误路径；不再临时拼装 V2 页/版区。行、网格、条件、明细表 AST 仍是现行共用模型。
- 模板按个人/共享权限、版本及图片引用管理，预览绑定草稿/数据修订；模板预览显示不代表真实 PDF 已通过。复杂组合、长内容、实体打印及各平台继续按[PDF 验收方案](./Rust统一V3模板与原版PDF验收方案.md)记录。
- 报表任务及预览在加载图片前取得共用重型处理名额，名额覆盖准备、排版和编码；等待不持数据库连接，批次快照与锁外图片读取规则保持。
- Noto Sans 400/500/700 与 Noto Serif 400 统一由字体准备脚本验证；UI 使用 WOFF2，PDF 使用 OTF。设计令牌、680/1180 断点和共享控件统一生效。候选确认和中文 composition 不触发跳格/保存，详情见[设计系统](./前端设计系统规范.md)。
- Excel 由 export-doc-excel 复用 excel-analyzer-rs 库，工作表解码、表头识别和字段校验不重复实现。模板紧凑行高与固定坐标同步解析规则；单一窗口模板说明见[填写指南](./单一窗口Excel导入说明.md)。
- OCR 使用受管原生库和模型；PDFium/ONNX 从已核验 NuGet 归档抽取，不需要 .NET。默认正式包携带对应 OCR 资源，WithoutOcr 只用于明确的轻量测试。
- 单一窗口保留发票来源及独立申报草稿、官方 XML、认证交接包、目录检测和回执收集。真实卡、签名与正式发送必须在官方客户端和企业现场验收，不能把离线生成当成发送成功。
- 回执收集按每包 200 文件/50 MiB 返回分包，页面支持逐包导出；两个重复的 COO/ACD 预检 POST 退役，统一使用只读预检 GET。

## 契约、交付与验收

唯一 API 事实源是 native_contract 投影的 /openapi/v1.json。生成器统一生成 DTO、按域客户端、认证/权限和容量元数据；不手改生成文件，不建立第二套路由/schema。内部用例逐步收紧类型；内置办理节点直接构造类型化规则，流程修订不经过 JSON 字符串往返。

端点权限只声明 `access`，运行时不再接受 `permissions`、`requirements`、`permissionBypass` 三套旧注解。记录操作从同一访问规则取得数据范围动作。冻结注解仅用于独立权限矩阵回归，不参与正式授权。普通 Chromium 回归按编辑、维护、业务、会话四组登记，同组单项失败仍执行剩余测试，失败日志及可用截图/trace 供 CI 上传。

Cargo/npm/受管原生资源的清单和锁文件集中固定依赖；notices/SBOM 只包含当前交付。普通 Dependabot 版本检查每月，完整依赖治理每周及依赖改动时执行，每日保留漏洞审计。GLib 0.18.5 仍受 Tauri GTK3 上游约束，安全例外不等于漏洞已修复；详见[依赖安全](./依赖更新与安全检查.md)。

Tauri Release 内嵌前端，界面变化须重建宿主；SkipBuild 只组装资源。桌面排除 PostgreSQL 服务适配和构建工具运行依赖，网页不包含 Tauri。保留 updater 签名/公钥，不执行 Authenticode、Developer ID 或 Apple 公证。

已有程序资源必须有当前包文件清单及匹配摘要；无清单旧包或未登记资源拒绝接管，使用新输出目录。数据迁移仅使用当前 `Locks/native-instance.lock`，移除旧根目录锁兼容；旧数据库继续拒绝打开，清理只针对已核实的一次性测试数据。

每批集中执行受影响的 Rust、React、脚本、依赖、真实 PostgreSQL、桌面和 PDF 验收。编译、接口存在、旧测试结果都不能代替功能通过。Firefox/WebKit 重型验收只手动触发；Linux/macOS/ARM64、正式安装与升级及现场长时负载按[平台矩阵](./多平台与多架构支持矩阵.md)独立记账。最新实测见[实施进度](./程序改进重构进度文档.md)。
