# 单据核对与业务资料待办

本轮范围为现有单据流程、业务资料归档和个人待办。财务核算继续由财务软件负责，正式申报继续使用官方单一窗口渠道；本功能不新增订单、采购、库存或通用审批系统。

## 单据核对

- 五金等标准商品可复用商品库；服装可直接录入本次 PO、款号、品名、成分和包装，不强制建立商品档案。
- 草稿可以暂存不完整的客户、出口商和独立通知人。非法字段、容量和数值仍在保存时校验，不把真实存储失败当成“尚未填写”。
- “核对检查”检查当前页面内容，列出需要补齐的字段和编辑器中的真实行号；页面修改后旧检查结果失效。正式核对使用已保存的数据，并复用同一个 `InvoiceReviewPolicy`。
- 选择性复制会提示重新确认本次客户资料；正式输出仍沿用后端受控报表链路。

## 业务资料归档

从已保存发票的“业务资料”入口上传，或从工作台“业务资料”集中检索。资料关联现有发票，PO、款号选填；资料名称、分类、PO 和款号在首次上传时确定，同一资料的新版本沿用这些信息。

| 能力 | 行为 |
| --- | --- |
| 分类 | 原始资料、确认资料、正式输出 |
| 检索 | 客户、发票号、PO、款号、资料名、各版本文件名；按 NFC 和统一搜索键处理 Unicode |
| 文件 | PDF、PNG/JPEG/GIF/WebP、Word、Excel、PowerPoint、UTF-8 TXT/CSV；校验文件名、扩展名和文件头或文档包结构 |
| 预览与下载 | 图片与 PDF 可预览；下载返回该版本原始字节，桌面下载通过原生保存对话框选择目标路径 |
| 版本 | 上传新版本保留旧文件，不自动改变当前有效版本；确认、停用、恢复均需要说明，并记录操作者和时间 |
| 正式输出留存 | 上传实际对外交付的原文件，后续更换模板不改变已归档内容 |
| 权限 | 查看、下载和历史版本遵循原发票查看范围；上传和版本操作还需原发票操作范围 |
| 容量 | 单文件 16 MiB、每份资料最多 50 个版本、每张发票最多 100 份资料及 256 MiB；旧版本和停用资料都计入容量 |
| 备份与删除 | 文件字节、版本和确认记录同库存储，随现有数据库备份恢复；有关联资料的发票可作废，不能直接删除或由管理员清理 |

列表和版本目录只读元数据。读取文件时验证长度和 SHA-256；发现损坏返回明确故障。上传使用用户级幂等键和乐观并发版本，并通过数据库事务控制单据总容量，重复请求不会新增相同版本。

停用资料保留全部历史，可在“含停用资料”中查询和恢复。确认与停用记录展示最近 100 条及总数，完整记录继续保存在业务库中。归档不新增文件目录、系统临时目录、第二数据库或客户端持久存储。

## 我的待办

待办从源业务实时查询，不保存第二套完成状态。源业务完成后刷新即可消失；页面在前台每 30 秒刷新，也可手动刷新。列表按来源分组、组内按截止时间和编号稳定分页，数量和当前页来自同一数据库快照。

| 来源 | 纳入条件 |
| --- | --- |
| 单据待核对 | 本人的草稿，并且具有查看和操作权限；单机模式显示本地可操作草稿 |
| 客户跟进 | 本人未完成的跟进，同时具有客户查看、跟进查看和完成权限 |
| 行政待审批 | 有权审批的待处理申请，排除自己的申请；单机行政版不生成双人审批事项 |
| 会议室、钥匙、领用与归还 | 本人待使用、待领取或待归还事项；单机行政版显示操作员管理的交接记录 |
| 人事到期 | 同时具有人员查看与私密资料查看权限，在当前公司及获准数据范围内查询试用期和劳动合同日期 |

支持全部、已到期、未来 30 天、未设截止日期筛选。自然日按公司业务时区计算，时间点转为 UTC 后查询；没有截止日期的事项不标记逾期。每条记录跳回原业务处理。不会根据“已出运”推断欠款，也不会在没有资料清单的情况下推断缺件。

## 模块与产品版

归档和待办分别由 `ExportDocManager.Infrastructure.Attachments`、`ExportDocManager.Infrastructure.Worklist` 实现，仅依赖核心 Infrastructure。API 负责发现和注册，核心单据保存、报表和登录不依赖这两个程序集。待办来源按独立 `IWorklistSource` 组合，移除一个来源不影响其余来源。

| 单机产品版 | 业务资料 | 待办来源 |
| --- | --- | --- |
| Document | 有 | 单据核对 |
| Sales | 不随包携带 | 客户跟进 |
| Full | 有 | 单据核对、客户跟进、人员到期、会议室及物品交接 |
| Administration | 不随包携带 | 人员到期、会议室及物品交接 |

PostgreSQL 团队版按现有产品、岗位、动作和数据范围组合来源。Sales 与 Administration 继续共用 `core` 依赖档位，归档不进入该档位；待办进入两个档位。缺少 Excel、Browser 或 PDF/OCR 能力时，对应操作入口按实际可用能力关闭。

可通过 `--disabled-capability-modules` 或 `EXPORTDOCMANAGER_DISABLED_CAPABILITY_MODULES` 配置逗号分隔的模块键：`excel`、`browser`、`pdf-ocr`、`business-attachments`、`worklist`。未知键拒绝启动，避免配置拼写错误被忽略。归档或待办缺失、关闭时不显示入口，直接请求返回明确的 503；其余模块继续运行。

构建时可通过 `ExportDocIncludeAttachmentsModule`、`ExportDocIncludeWorklistModule` 排除程序集。已归档数据的模型和留存约束仍属于共同业务库，不随功能开关删除。正式空库基线为 v17（含人员证件图片与组织层级）；项目尚未投产，不增加旧开发库迁移或双读分支。

系统级 Authenticode、Developer ID 和 Apple 公证不执行；既有 Tauri updater 包签名和产品版公钥信任合同保持。
