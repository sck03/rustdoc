## 实现与职责

原先 Tauri 在窗口创建前同步复制数据，用户无法知道正在复制、校验还是已失败。现在 `desktop_startup` 先打开独立迁移窗口，再由工作线程执行迁移；`migration_progress` 保存只读快照、原子取消及一小时执行预算；路径迁移和树清单模块继续负责锁、摘要、提交与恢复。业务服务和主窗口只在迁移完成后启动。

复制按 1 MiB 块报告已写字节，恢复时先校验已有副本再计入进度；准备、校验、切换与清理分别显示阶段。关闭窗口请求取消，在文件 I/O 安全边界退出，保留原恢复机制。总预算不抢占尚未返回的单次操作系统 I/O，不宣称解决断开映射盘等平台专项。

启动窗口使用 `RuntimeConfigRoot/StartupWebView`，源/目标数据树与该 profile 必须互不包含，避免复制时浏览器占用业务 profile。独立 capability 仅允许查询迁移进度，Rust 同时核验窗口标识；普通业务和文件命令均不授权。权限门禁统一读取 permissions 目录，34 个注册命令与授权声明一致。

React 专用屏只管理串行轮询和卸载取消，复用 `StartupScreen`、Button、原生 progress 和既有令牌。未重复建立业务路由、迁移服务、持久化状态或前端文件复制逻辑。没有 SQL、HTTP 契约及依赖版本变更。
