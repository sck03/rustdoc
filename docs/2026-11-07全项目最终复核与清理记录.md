## 本轮补修与精简

- 公告有效期原先按毫秒保存，当前时间却带纳秒；列表和发布检查按字符串比较。在相同毫秒内，`...00.000Z` 会排在 `...00.000000000Z` 后面，到期公告可能继续出现在列表，刚生效公告也可能漏出。小于一毫秒的合法区间还会被保存成相同起止时间，导致再次发布时被拒绝。
- Domain 保留输入时间点并规范化为 UTC 纳秒文本；Storage 复用既有秒/纳秒表达式，按 `startsAt <= now < expiresAt` 比较；Engine 发布检查复用类型化时间解析。没有增加第二套日期解析器、数据库迁移或 API 接受分支。
- 通知查询复用 Storage 参数绑定器，状态筛选只构造/绑定一次，删除重复的空办理对象检查。“仅参与的记录”查询不再绑定最终丢弃的部门条件，参与权限、状态范围及最终限制保持各自职责。
- 两库共用通信夹具复用查询与权限范围构造，保留原有权限、回执版本、排序、分页和事务回滚断言，增加到期/生效、不同偏移、小数位数及参与范围回归。新增覆盖后未放宽源码规模阈值。
- 检查方案新增当前逐项状态表，区分已完成实现、经审查保留的候选和独立平台验收，避免多批记录使初审结论成为错误的当前清单。
