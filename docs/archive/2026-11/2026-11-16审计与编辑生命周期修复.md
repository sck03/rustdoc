基线提交：`6d7161f6`。范围为前轮已复现的生产企业编辑覆盖、审计下载保留/迟到执行，以及审计筛选、清理投影、HTTP 阻塞认证和供应商详情累计状态。未升级依赖，未修改 schema 18 或模型指纹，也未增加旧版兼容链。

## 实现与边界

- 生产企业弹窗拆为展示、纯草稿模型和工作区 hook。确认、行选择、新建、套用、保存和删除统一进入既有 `useScopedMutation`；同一时刻只执行一个命令，确认期间同样受保护。请求携带 AbortSignal，卸载或货项/客户端变化后忽略迟到响应。刷新在提交之后独立执行。
- 审计的视图状态与命令分离。下载 Blob 在当前作用域内消费，不作为 mutation 结果保留；导出、清理、删除和路径选择复用同一串行边界。客户端、筛选或页面变化会取消旧操作，防止离开后触发下载。
- 发票号筛选通过 Storage 关联现存发票的当前业务号码，使用两库共同的 Unicode 规范化匹配。改号后按新号码查询；已删除发票不再能通过该号码筛选，但审计事实仍可按其它条件查询。界面明确标为“现存发票号”，原值/新值继续脱敏。现行 25 项实体标签与后端目录逐项核对，删除不存在的独立 Item 选项。
- 清理使用 `query_audit_ids`，只读取整数编号；与列表共用过滤规则及游标，单批最多 2000 条。Engine 保持操作上限、同事务最终授权和维护记录，不在协调器编写 SQL，不读取并序列化待删除正文。
- HTTP 请求许可与关闭登记跟随正文前认证、备份授权和正式执行阶段；断开请求后排队的阻塞工作真实结束才释放名额。
- 供应商档案命令进入 `useSupplierProfile`，联系人查询、版本草稿和命令由 `useSupplierContacts` 与独立工作区组合。进入联系人页签才查询，未观察的详情和分页快照即回收，不累计访问历史。保存/状态/删除共用串行命令，刷新不延长写入锁；导出携带取消信号且不缓存 Blob。
- 报表管理输入、保存/创建/归档/恢复和回读后的文档更新集中到 `useReportTemplateCommands`。同一接受入口更新选择与文档，删除重复的清空名称/文件名状态；报告类型改变时重置管理输入，保留现行版本校验、草稿和历史恢复。
- 真实 React 回归另复现哈希地址手动改变仍沿用 history key 时，后续页签更新可能丢失记录 ID。`useRouteQuery` 改为识别已提交的位置对象；本地草稿渲染仍保留尚未提交的连续参数更新。

界面继续沿用原有控件、折叠分区和设计令牌，没有新增断点或独立样式系统。历史审批版本、冻结合同、匿名夹具和有效 PDFium/ONNX 等资源不属于废弃代码。

## 工作负载测量

Windows x86_64，`office_review` Release，SQLite schema 18，沿用当前 OCR/报表资源与编译选项。测量时其它编译和重型验收已退出。进程树 RSS/Private Bytes 每约 50 ms 采样，峰值为采样下界，RSS 相加可能重复计算共享页；不是机器总内存或分配器精确峰值。取消回收要求数据库租约与活动任务归零、HTTP 普通/批量名额全部恢复，审计还验证原 10 万条全部回滚保留。保留已完成任务结果属于正常下载保留策略；已结束的线程句柄可在下一次任务登记时收割。

| 工作负载 | 完成耗时 | 峰值 RSS / Private Bytes | 取消后资源恢复 |
| --- | ---: | ---: | ---: |
| 10 万条审计清理，每条约 2 KiB 正文 | 2.921 s | 69.1 / 53.9 MiB | 7.8 ms（50 ms 后取消） |
| 2 万条审计导出 XLSX | 1.235 s | 147.1 / 186.0 MiB | 16.9 ms（5 万条负载，50 ms 后取消） |
| 10 张发票 × 2 种模板，每张 40 个商品，20 份 PDF ZIP | 2.144 s | 129.8 / 113.0 MiB | 78.5 ms（100 ms 后取消） |

5 万条大正文 Excel 样本在 2.532 s 触发既有 **120 MiB 解压容量**校验并返回 400，峰值 RSS 192.4 MiB、Private Bytes 315.1 MiB。容量内 2 万条输出为完整 XLSX；PDF ZIP 精确包含 20 份文档；OCR 每张均核对 16 行及末行内容。OCR 批次结束后进程树 RSS 回到约 130.0 MiB，全部 HTTP 名额可用，未留下活动任务或任务输入缓冲。正式原生证据：`artifacts/lifecycle-final-evidence/native-result.json`。

复杂模板使用生产 React 构建和模拟 API，500 个合法尺寸的画布文本元素、30 次实际文本编辑提交：加载 611.7 ms，交互 P50 64.8 ms、P95 66.0 ms、最大 91.2 ms。交互时长包含打开编辑、两次输入/提交帧及双帧完成等待；不是纯 JavaScript 执行时间。浏览器进程树峰值 RSS 375.5 MiB，采样 JS 堆峰值 24.5 MiB；卸载及详情缓存回收 8.8 ms，强制 GC 后 JS 堆约 5.9 MiB（加载前约 4.2 MiB，仍保留框架和模块缓存）。正式证据：`artifacts/lifecycle-final-evidence/designer-result.json`；最终截图无尺寸规范化提示。

结论：保留审计每批 2000、Excel 容量上限、OCR 串行及当前编译配置。当前证据支持先移除多余正文读取和跨页缓存；没有依据扩大并发、缓存或放宽容量限制。数据是本机单次受控样本，未做旧版本同条件对照，不能声称整体性能提高了某个百分比，也不替代长期负载、PostgreSQL 多用户或其它平台容量验收。
