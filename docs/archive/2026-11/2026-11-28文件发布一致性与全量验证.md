# 2026-11-28 文件发布一致性与全量验证

## 范围与实现

承接项目审查，先修复确认的缺陷，再统一验证。用户随后将“必要测试”改为全量测试；本记录只列本次真实执行结果。

- 相同摘要重新上传时，新对象已在当前在线库核验，文件发布事务清除旧归档路由。旧副本日志在事务前落盘，租约保留到事务结束；回滚继续保留原正式位置。
- 归档复制前登记源与目标清理日志。未提交、冲突或取消后目标副本可由原回收入口发现；成功后按正式位置重新核验再清理旧源。未知提交结果仍保留记录。
- 合并原三处重复日志读取：每轮推进最多 1000 条目录项，正常并发移除忽略 NotFound，损坏或权限错误继续明确失败。Storage 每批最多 500 个摘要读取引用与位置，预检不再每条日志租用数据库连接。候选对象总数最多 1000，目录扫描最多 500；24 小时隔离、预检有效期、管理员复核和删除前引用复核保留。
- 文件容量策略与 S3 凭据保存只返回提交版本和已保存字段，运行状态/健康检查通过后续 GET 刷新。前端保留成功结果并单独提示刷新失败。
- 原生契约投影 canArchive/archiveBlocker、canApprove/approvalBlocker，界面禁止必然失败的归档或申请人自行批准；后端提交时继续校验。
- Storage 聚合单据待办总数，Engine 只读取当前页的有序明细。动态 OA、办理权限和带日期的其它来源仍按现行规则实时校验，未引入权限缓存，未声称全部待办均已聚合。
- 容量展示拆为 StorageCapacityPanel，档案管理继续复用设计令牌、共享表格、折叠区和作用域命令。删除被替代的重复扫描逻辑，不按静态名字未引用判定动态 API 为死代码。

全量回归补充修复：

- 新建报表线条高度原为 3 mm，低于共享契约要求的 4 mm；改为与 ProductSpacer 一起引用共享最小尺寸，避免新建元素使整个模板校验失败。
- 会议室/物品申请列表过去只判断普通权限或保管分工，未核对已发布流程的实际办理节点。列表现投影既有 workflowTasks，前端按 canExecute 显示交接/归还并选择可执行节点，仍由后端提交时复核。
- 审批移交按返回的身份选项验证选择；主身份的有效编号为空字符串，不能被非空判断及 HTML required 拒绝。申报实例的保存按钮显式使用共享 primary 样式。
- OA 正向验收补齐普通账号与有效人员任职、办理事项和财务接收人；保留办理阶段的依赖关系。负向验收继续检查责任缺失和越权，不放宽产品授权。
- 修复任务列表的关键字查询遗漏 jobId/outputPath：前端“查看任务”使用任务号定位，Storage 现在同时查询任务号、输出路径及原有文字字段，保留身份和归属过滤；SQLite/PostgreSQL 共用查询回归，桌面要求对应任务行显示已完成。
- 备份验收按当前异步发布与重启恢复执行，核对输出路径、恢复库对象目录、完整文件内容、旧会话撤销以及恢复后的报表附件；独立发布样本覆盖金额条件，撤权前正式完成办理并将事项交接给有效接任人员，已引用的事项继续保留。
- PostgreSQL 维护页并发加载恢复点列表时，短暂的读取锁曾使新备份直接失败；备份公共锁现在在写入开始前最多等待 5 秒，每 10 ms 检查取消/超时，持续占用继续返回 429。定时调度持有自身闸门时仍立即尝试并延后繁忙任务，避免阻塞其它 tick；未增加写操作重试或放松互斥保护。
- Firefox 移动视口发现卡片布局表格仍位于可滚动容器内，但共享组件移除了键盘焦点。统一保留带名称的 region 和 tabIndex=0，不新增样式或每表 ResizeObserver；真实 axe 无障碍验收保留。
- macOS 网页包原先安装浮动 Homebrew PostgreSQL 18，出现清单固定 18.6、实际安装 18.7 的失败。这是打包版本不一致，不是业务不兼容的证据。依赖升级独立将客户端和容器固定到 18.7；Windows 官方归档、macOS 官方配方分别核验 SHA-256，Homebrew 复用官方瓶装归档和既有动态库/许可闭包采集。保留精确版本检查，不使用浮动 latest。
- 远端全平台测试发现 Linux/macOS 打开路径测试仍按旧返回类型使用命令规格；已按现行 Result/PathBuf 接口修正断言，不改平台执行逻辑。
- 更新已过期的控件名称、组织名称显示、空任务编号、恢复分页控制器和折叠区可见性断言。独立权限回归补录逐项审查的存储、OA 和维护上下文端点，未从运行时规则直接生成预期。
- 冷恢复审查发现后端返回了 repositoryId，独立维护页也要求填写，但日常备份页没有展示。补上带明确标签的只读可复制编号，以及与恢复凭证、备份位置一起异机保管的提示；复用现有契约、控件和样式，不回显密码，也不增加厂商专用生产分支。新增真实 React 冷恢复用例验证保存身份、S3 解锁、预检与执行。
- Windows x64 全量工作流的 workspace、feature、React、OCR worker 和构建步骤通过，但发布包阶段触发原 90 分钟总超时。全量桌面任务改为 150 分钟有界时限，保留各阶段真实失败传播；被中断的包验收另行执行，不能将超时任务整体记为通过。

数据库保持 schema 19，不增加运行时旧库兼容。PostgreSQL 18.6 → 18.7 是独立依赖变更，继续使用 PostgreSQL 开源许可证；notices 与治理清单同步，840 个组件，unresolved=0、disallowed=0。18.6 的已完成测试不改写为 18.7 通过，升级后另行验收。OpenAPI/运行契约/Rust/React 由原生定义统一生成，审查夹具逐项记录变更。
