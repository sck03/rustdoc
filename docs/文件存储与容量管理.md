# 文件存储与容量管理

本批实现使用全新 schema 18。旧实验数据库和旧恢复包不自动升级，不能覆盖原数据；更换 DataRoot 或 PostgreSQL 数据库建立新基线。

## 模块与数据

- Storage 的 `file_objects` 保存物理对象摘要和长度，`file_versions` 保存业务文件名、类型及记录引用，`file_locations` 保存迁移中已经核验的目标副本。SQL 不读取磁盘或访问 S3。
- Engine 的 `file_store` 管理本地/S3 对象、身份标记、写入意图、校验、迁移和回收。业务模块先授权并准备不可变对象，再在写事务中重新授权、检查版本、发布引用和核算组织配额。
- 发票资料、OA/公告附件、人事文件和照片、报表图片、审批 PDF、单一窗口提交包和回执使用永久对象。任务重试输入、短期预览及临时输出保留独立生命周期，不能与业务原件一起清理。
- 发票资料版本和操作记录保存在 `attachment_history`，使用序号游标分页；不再把全部历史写回资料主记录。报表图片的上传者和业务引用使用关系索引，列表只返回当前授权范围的元数据。
- 摘要去重只合并物理字节，不合并业务引用或读取权限。组织配额按业务引用计费，物理容量和引用容量分开显示。

## 容量策略

默认单文件 100 MiB、每份 OA/公告记录最多 100 个附件、合计 500 MiB，组织配额 0 表示不限制。人事档案不设终身附件数量上限，详情仅返回首 50 条，附件目录按摘要游标独立分页。管理员可降低单文件和数量限制，每份申请的总量最多可调到 1 GiB。报表印章和图片仍执行专用格式、像素和解码预算。

发票资料不再限制每张单据终身累计 100 份、每份终身累计 50 个版本或累计 256 MiB。历史文件继续占用组织配额；停用不等于删除。读取已有历史不因管理员降低新上传限制而丢失。

前端设置的“文件与存储”提供状态、容量策略、完整性检查、无引用文件回收和迁移任务。页面沿用共享表单、折叠分区、作用域取消、任务中心和未保存草稿保护；凭据不随状态接口返回。

## 本地磁盘和 S3

默认存储为 `DataRoot/Files`。`Configuration/file-storage.json` 保存存储身份、配置修订号、相对位置和容量策略。S3 密钥使用主密钥加密；每个存储身份使用独立对象前缀。

服务器组合根通过重复的 `--file-store-root archive=E:\AttachmentArchive` 登记现有目录，或通过 `EXPORTDOCMANAGER_FILE_STORE_ROOTS` 注入 JSON 名称映射，例如 `{"archive":"/srv/exportdoc-files"}`。该目录必须位于 AppRoot/DataRoot 之外，禁止磁盘根、路径跳转、符号链接和联接点。网页以 `@archive` 选择登记位置，也可使用其受管子目录；不能通过浏览器传入任意服务器绝对路径。

已有存储必须匹配 `.store-id`。目录消失、挂载丢失、身份不符、文件缺失和摘要损坏均报错，不创建空目录冒充已有存储。目标迁移先复制核验并记录进度，最终短暂暂停业务写入、补齐最后一批对象再切换配置。中断后可继续，源位置保留；未经核对不得直接删除源目录。

Docker 可参考 `deploy/rust-native/file-storage.override.example.yml`，管理员预先挂载磁盘、建立目录并授予容器 UID/GID 10001 访问权限。应用与恢复服务使用同一挂载、位置映射；S3 恢复需要恢复容器能够访问对象服务。示例禁止自动创建不存在的宿主目录。

## 备份和回收

完整加密恢复/迁移包增加 `FileObjects.pack`，按摘要排序流式保存对象，文件数不消耗 ZIP 条目数量。恢复必须验证数据库清单对应的每个文件长度和摘要；缺件、损坏不报告成功。

普通 SQLite/PostgreSQL 本地快照配套保存 `<快照名>.objects.jsonl` 和同目录 `Objects/` 对象库；相同对象仅复制一次，数据库快照在对象和清单保存后发布。迁移这种本地备份时必须一起保存快照、清单和对象库。单独下载的数据库文件不构成独立附件灾备，请使用完整加密恢复/迁移包完成异机恢复。

写入未提交的对象由上传意图日志保留，回收只处理已结束且没有业务引用的对象。回收与备份、迁移使用排他维护锁，并在应用写入暂停期间再次查询引用；保留的历史引用不回收。备份对象库不随业务对象回收清理。SQLite 旧快照清理同步移除对应清单，以保留恢复点的清单在磁盘上归并索引，只回收不再被任何保留恢复点引用的对象；清单缺失或损坏时停止回收。
