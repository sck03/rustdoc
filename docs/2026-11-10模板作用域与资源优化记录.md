# 模板作用域与资源优化记录

## 实施范围

本批承接此前七项审查问题，按用户授权完成修复、文档更新、已核实测试产物清理及 main 交付。数据库继续只接受全新 schema 16；没有依赖升级、旧库迁移链或旧接口兼容分支。

| 问题 | 修复与职责 |
| --- | --- |
| 报表模板迟到成功/失败污染新工作区 | `useScopedMutation` 复用作用域保存边界；客户端、模板变化及卸载取消旧操作，响应及文件对话框结束后重验。只有当前命令能更新缓存、反馈或下载 |
| 邮件读取使用快照外旧身份 | 目录、历史、版本详情及 CRM 草稿统一进入 `read_for`；写入使用 `transaction_for`，在快照/事务内重验账号、身份及生成操作权限 |
| HS 知识包全量物化与复制 | 导出逐条序列化到有界 ZIP；导入每次保留一个展开文件并逐条处理，在同一事务原子提交；I/O 校验独立为模块 |
| HS 普通列表全扫及 OFFSET 重读 | 无关键词由 Storage 计数分页；批量读取共用排序游标与索引表达式；语义搜索只扫描必要字段，读取完整记录限于当前页 |
| 邮件目录/历史/重名/CRM 全量加载 | Storage 负责目录筛选分页、定向重名检查及主要联系人；历史复用版本摘要查询，正文通过新增版本详情端点按需读取 |
| 报表变更缓存留存大型参数/结果 | 报表五类命令模块不再进入 MutationCache，不额外留存 File、Blob 和正文 |
| 保存状态等待后台刷新 | 有效响应同步提交编辑器状态，立即结束保存状态；刷新独立执行，较旧轮次或旧作用域的失败不能覆盖当前反馈 |

共享查询、权限与文件规则仍分别归 Storage、Domain/Engine 和受管 I/O。没有将 SQL 移入 UI/用例，也没有增加第二套表头解析器、数据库或任务队列。移除重复报表刷新、旧邮件完整历史查询和重复 HS 排序定义。

邮件目录及历史默认每页 30 条；历史列表不返回 subject/bodyHtml，选择版本后才获取正文。恢复旧版本仍追加新历史，目录刷新与历史翻页不覆盖编辑草稿。API 原生定义及全部生成物同步更新：OpenAPI 为 628 路径、753 唯一操作、755 方法声明、698 schemas；运行契约为 753 操作、692 schemas。冻结合同通过明确的分页及详情变更投影验证，其余权限、认证、错误和容量元数据继续比较。

知识包压缩体与单个展开数据文件各最多 100 MiB，展开总量 300 MiB（含清单），编码 50 万条、其它各类 100 万条。导出在写入前检查容量，预留清单空间，增量时间保留偏移及纳秒。导入若后续文件摘要失败，前面已处理记录全部回滚。每次操作从既有共享工作预算预留 100 MiB，用于限制并发；压缩输入/输出、当前展开文件、单条解析对象与去重键仍会占用内存，不能把该预算解释成进程 RSS 硬上限。语义关键词计数仍需有界扫描，不宣称已完全 SQL 化。
