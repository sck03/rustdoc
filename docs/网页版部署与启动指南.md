# 网页版部署与启动指南

> 2026-10-14。适用于不使用容器的 Full 多用户部署。浏览器使用同一 React 界面，服务端为 Rust + PostgreSQL 18。运行机器不需要 Node、Rust、.NET 或 Tauri 桌面壳。更省事的容器入口见 [Docker 指南](./Docker容器部署与启动指南.md)。

## 1. 准备程序与数据库

取得与服务器 OS／CPU 架构一致的 **Web 服务发布包**并解压。保留包内全部文件，包括 `Web`、`Resources`、`Templates` 和 `Tools/PostgreSQL`；不要只复制主程序。自行构建时使用 `scripts/package-native-web-server.ps1`，这是开发者操作，不是安装发布包的必要步骤。

另外安装并运行 PostgreSQL 18，或使用已有受管 PostgreSQL 18 实例。包内 PostgreSQL 客户端用于备份与恢复，不是数据库服务端。安装同一主版本的稳定维护版本，定期安排安全更新；大版本升级另行验证。

建议固定程序、业务数据及数据库服务各自的目录。Windows 例如 `E:\ExportDoc\Web`；Linux 例如 `/srv/exportdoc/app`。应用的数据默认位于程序目录下 `App_Data`，也可通过 `--data-root` 指定独立的绝对路径，后续启停和维护始终使用相同值。

## 2. 一次生成部署配置

Windows 在解压目录打开 PowerShell 7：

```powershell
.\ExportDocManager.Server.exe --setup-web
```

Linux 在程序目录运行：

```sh
./ExportDocManager.Server --setup-web
```

该命令在程序目录的 `RuntimeConfig` 中生成随机凭据、连接文件、初始化口令和 `initialize.sql`，并设置私有访问权限。也可显式指定绝对程序目录：`--setup-web /srv/exportdoc/app`。重复运行会验证原配置，不会重置密码或接管损坏配置。

默认数据库地址为 `127.0.0.1:5432`，数据库名为 `exportdoc_native`。如果数据库在另一台服务器，管理员在首次使用前调整两个连接文件的目标地址、端口及 TLS 设置，确保它们指向同一业务库。凭据文件不加入 Git，不置于 `Web` 静态目录。

## 3. 由数据库管理员建立角色和空库

新部署由 PostgreSQL 集群管理员执行一次 `RuntimeConfig/initialize.sql`。该脚本会创建独立的业务角色、NOLOGIN 所有者及维护角色，设置权限；已有同名角色／数据库时会报错，不能用初始化覆盖已有业务库。

Windows 示例，`psql` 使用实际安装位置或包内客户端：

```powershell
.\Tools\PostgreSQL\bin\psql.exe -X -h 127.0.0.1 -U postgres -d postgres -v ON_ERROR_STOP=1 -f .\RuntimeConfig\initialize.sql
```

Linux 可由能读取配置文件的管理员通过标准输入执行：

```sh
sudo -u postgres psql -X -d postgres -v ON_ERROR_STOP=1 < /srv/exportdoc/app/RuntimeConfig/initialize.sql
```

远程 PostgreSQL 需改成实际连接参数，并由数据库管理员配置网络访问和认证规则。不要把超级用户或维护账号配置为普通应用账号。

## 4. 初始化应用 schema

```powershell
.\ExportDocManager.Server.exe --initialize-only
```

Linux 把可执行文件写成 `./ExportDocManager.Server`。该命令自动读取 `RuntimeConfig/maintenance-connection.txt`，执行有序、事务化的应用 schema 初始化／升级，然后退出。只有成功退出后才启动业务服务。若选择了独立数据目录，此处及后续命令均追加 `--data-root <绝对目录>`。

普通业务服务读取 `app-connection.txt`，不会读取维护连接；维护角色的 DDL 权限不授予业务角色。当前只接受全新 schema 10。旧试验库、损坏、未知或超前版本拒绝打开；本轮重建显式使用新数据库，不能修改旧库版本标记。

## 5. Windows初始化启动停止

完成上面一次性准备后，日常启动只需：

```powershell
.\ExportDocManager.Server.exe --bind 0.0.0.0:5188
```

程序自动识别相邻 `Web/index.html` 和已准备的 `RuntimeConfig`，无需重复指定前端地址、数据库密码或 `--web-root`。自定义路径仍可显式覆盖。

打开 `http://服务器局域网IP:5188`。首次用 `admin` 和自己选定的管理员密码登录，并在“连接设置”填写 `RuntimeConfig/bootstrap-token.txt` 中的一次性初始化口令。后续使用已保存的账号密码。

控制台前台运行时用 Ctrl+C 停止，并等待服务正常退出。长期运行可由管理员使用组织已有的 Windows 服务托管方式，固定程序路径、工作账号和参数；程序不自行注册系统服务。不要同时启动指向同一业务库的第二个 API 实例。

## 6. Linux服务托管

前台验证使用：

```sh
./ExportDocManager.Server --app-root /srv/exportdoc/app --data-root /srv/exportdoc/data --bind 0.0.0.0:5188
```

长期运行可配置 systemd，以下账户与路径需要管理员事先创建并授予适当权限：

```ini
[Unit]
Description=ExportDocManager
After=network-online.target postgresql.service
Wants=network-online.target

[Service]
Type=simple
User=exportdoc
Group=exportdoc
WorkingDirectory=/srv/exportdoc/app
ExecStart=/srv/exportdoc/app/ExportDocManager.Server --app-root /srv/exportdoc/app --data-root /srv/exportdoc/data --bind 127.0.0.1:5188
Environment=EXPORTDOCMANAGER_BUSINESS_TIME_ZONE=Asia/Shanghai
Restart=on-failure
TimeoutStopSec=210
UMask=0077
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

此例绑定本机供 HTTPS 代理访问；如果需要局域网直接访问，改为 `0.0.0.0:5188` 或指定网卡地址。配置后由管理员执行 `systemctl daemon-reload`、`systemctl enable --now exportdoc`，并检查服务日志及 `http://127.0.0.1:5188/readyz`。

## 7. 局域网与公网域名

同一服务支持局域网 IP 和公网域名，前端调用同源 API，不需要为每个访问地址重新构建。局域网访问需放行网页端口。公网访问还需域名解析、可用的公司外网入口和 HTTPS 反向代理；没有公网入口时可使用 VPN。数据库只接受应用服务器和受控管理端的连接。

Nginx 大包传输示例见 [Docker 指南的网络配置](./Docker容器部署与启动指南.md#3-局域网-ip-与公网域名)。浏览器直接读取剪贴板需要 HTTPS；普通 HTTP 下可使用键盘粘贴。代理应同时转发网页和 API，不单独发布数据库或 `RuntimeConfig`。

## 8. 备份、迁移、恢复及升级

系统设置的“备份与恢复”统一提供日常灾备、WebDAV／S3 异机副本、整机迁移和恢复校验。日常灾备默认关闭。配置保存后按业务时区运行，关闭时不启动定时线程。完整加密包不设置固定总容量额度，但需要足够的磁盘空间及传输时间。

恢复先在网页校验并暂存。停止 API 后，使用相同目录执行：

```powershell
.\ExportDocManager.Server.exe --restore-pending
```

Linux 改用相应可执行文件，并保持原 `--app-root`／`--data-root` 参数。程序只在此维护模式读取维护连接。成功后再启动 API，失败保留现场，不能删除待恢复标记来绕过检查。

大包也可从服务器本地文件直接导入，密码从管理员准备的私有文件读取：

```sh
./ExportDocManager.Server --app-root /srv/exportdoc/app --data-root /srv/exportdoc/data --import-migration /srv/exportdoc/import/company.edmmigration --package-password-file /srv/exportdoc/private/restore-password.txt
```

运行前必须停止 API；命令获取独立维护锁，完成校验、暂存和恢复。详细操作、异机副本权限及验证边界见[备份迁移与恢复指南](./服务器备份迁移与恢复指南.md)。

升级时先保存完整备份及部署配置，停止 API，再替换程序和只读资源，保留 `App_Data`／独立 DataRoot 及 `RuntimeConfig`。执行 `--initialize-only` 完成兼容升级，成功后启动。不要用新包覆盖业务数据或把旧数据库删掉重新初始化。

## 9. 排查顺序

- 无法打开网页：检查进程、绑定地址、网页目录、端口及防火墙。
- 数据库连接失败：核对应用连接文件及 PostgreSQL 日志；不要改用 SQLite。
- 初始化／升级失败：使用独立维护连接，确认角色成员关系和 schema 版本。
- 备份失败：查看文件任务和灾备状态，检查磁盘、客户端工具、存储连接及权限。
- 恢复后不能登录：使用备份中的账号密码，并核对恢复结果；目标临时账号已随数据库替换。

Windows 本机验收与 Linux／ARM64 部署验收分别记录；对应平台运行证据见[平台矩阵](./多平台与多架构支持矩阵.md)。
