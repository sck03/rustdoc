# 当前架构事实

> 核对日期：2026-10-07。本文只描述当前 Rust 分支；历史 C# 验收不证明 Rust 功能等价。实施证据见[进度](./程序改进重构进度文档.md)，功能验收范围见[迁移核对表](./Rust原生功能迁移核对表.md)。

## 运行形态与职责

| 产品 | 界面与宿主 | 业务服务 | 数据库 |
| --- | --- | --- | --- |
| 桌面 | Tauri 2 + React 19 | 进程内共用 Rust HTTP 服务 | SQLite |
| 网页 | 同一 React 前端 | Rust HTTP 服务 | PostgreSQL 18 |
| Docker | Rust HTTP 同源提供 React 静态资源 | Rust HTTP 容器 | 独立 PostgreSQL 18 容器 |

正式桌面为 `apps/export-doc-tauri`，网页为 `apps/export-doc-web`，HTTP 组合根为 `apps/export-doc-server`。Node 用于前端构建和开发验证，API 契约及客户端由 Rust 生成。Slint、egui、C# 服务/测试/工程以及旧 .NET 容器部署已从本分支移除；`origin/tauri-csharp-net10-backup` 和 Git 历史保留行为对照，Rust 仓库使用自身 `.git`，不再依赖旧本地 C# 目录，删除重复源码不代表全部业务差距已验收。仍使用的 OpenAPI、单一窗口参考数据及报表夹具保留，不能将 EF、Scriban、Chromium 或数据库 v19 描述成 Rust 实现。

正式桌面交付 **Document 单证版**和 **Sales 业务员版**。单证版是主力，优先完成资料、制单、校验、模板、Excel/PDF 输出与备份恢复；业务员版定位个人外贸工作台。账号/组织/权限、行政人事及 OA 的正式团队使用场景属于 **Full 多用户版**（React + Rust HTTP + PostgreSQL 18）。2026-09-30 按用户要求，本地脚本另可显式生成 **Full + SQLite 单机测试便携包**，用于完整界面布局、公告通知及 OA 登记流程测试；与正式两版使用独立程序/数据目录。未验收业务和 PostgreSQL 多用户能力仍须各自验证，不删除历史业务数据。

`export-doc-contracts` 保存从官方 OpenAPI 生成的 DTO、路由和权限契约；`export-doc-domain` 处理纯业务规则；`export-doc-engine` 组织用例、认证、任务和能力；`export-doc-storage` 负责 SQL、事务与 SQLite/PostgreSQL 适配。Excel、报表、HS、邮件、汇率等按 crate/feature 分工。页面只组合展示，查询、草稿和平台操作分别位于 hook/model/service 与 Tauri 平台适配器。

## 数据、路径和并发

当前 Rust 数据库版本为 `export_doc_storage::SCHEMA_VERSION = 7`，最低可升级版本为 5。版本 5 建库 SQL和已发布的 5→6 步骤保持不变；6→7 增加列表、模板历史与任务索引，以及 PostgreSQL 的受管 JSON 查询函数，不改写业务记录。新库和已有库共用有序事务迁移，失败回滚；已有空文件、损坏库、版本 4 及更早试验库、C# 库或超前版本明确拒绝，不覆盖重建。PostgreSQL 通过独立维护账号升级，普通 API 校验版本和查询函数权限；恢复维护补回必要的业务角色权限。

SQLite 位于 `DataRoot/Database/exportdoc-native.db`，WAL/SHM 等伴随文件同目录，实例锁位于 `DataRoot/Locks/native-instance.lock`。记录、图片二进制、用户模板、模板版本、设置和审计均保存在业务库。根目录已有受支持数据库时，在新旧实例锁内通过 SQLite 快照完整搬入 Database；只升级快照，原库及伴随文件归档到 `Backups/DatabaseLayout/<唯一目录>`；两处同时有数据库或只有伴随文件时拒绝猜测。PostgreSQL 使用同一语义存储接口。

`RuntimePaths` 由组合根注入 AppRoot/DataRoot。受管日志为 `DataRoot/Logs`，运行缓存为 `DataRoot/Cache/Native`，WebView profile 为 `DataRoot/WebView`。内置模板与字体来自只读 AppRoot；用户文件模板位于 DataRoot/Templates。完整边界见[路径清单](./运行目录与路径存储审查清单.md)。

正式团队拓扑为一个 Rust API、一个 PostgreSQL 18 业务库、多个浏览器用户。PostgreSQL 默认使用 4 个业务连接的有界池，另有独立实例锁连接；SQLite 保持一个连接。读取可以并行，事务写入保留统一协调、同连接执行和事务内权限复核。连接等待可取消且有时限，观察到实例锁或连接失效后停止继续办理；健康检查不争抢业务连接。HTTP 保留 16 个执行名额，并允许 16 个有界公平等待名额，避免持续请求让其它会话反复被拒绝。配置与验收见[脚本说明](../scripts/README.md)。

通用资源列表、报表模板与历史、任务列表由 storage 执行权限、筛选、排序、计数和分页；计数及当前页共用一个 SQL 快照。列表按正式响应契约投影字段，保留精确十进制、布尔值、缺省字段和显式 null 的区别；原来返回数组的契约仍返回完整数组，内部按批读取。模板共享受众在分页前过滤，版本恢复定向读取正文；任务按唯一编号定位，启动恢复只扫描活动任务，历史清理在存储侧选出到期或超额记录后分批办理。部门名称补全只读取实际引用的负责人。

发票、付款、文件任务、综合查询、主数据、审计日志、单一窗口、业务资料、待办、公告、通知、图片资源和用户模板目录共用页码同步 hook：仅在当前查询成功且请求结束后同步页码。接口仍返回请求页码时，依据同次响应的总数和每页条数校正越界页。缓存建议退页但本次查询尚未重新读取时，先刷新核实，保留普通页面的缓存复用。上一页占位数据和正在刷新的旧缓存不能回写页码或取消新页请求；刷新失败保留错误及请求页，记录减少后的页码修正和记录增加后再次翻页分别验证。

管理员可通过生成契约中的 `/api/diagnostics/metrics` 读取 HTTP/连接池等待、耗时分布、失败与拒绝计数，以及活动和保留任务数量。契约 API 响应提供服务器生成的 `X-Request-Id`；脱敏操作日志位于 DataRoot/Logs 下的 `requests.jsonl` 和轮转文件，只记录操作名、关联号、状态和耗时，不记录凭据、SQL或请求正文。日志有界排队并批量写入，丢弃与写入失败均有计数；业务审计仍由数据库事务保存。指标、并发和故障演练的实际范围见[进度](./程序改进重构进度文档.md)，连接池不改变单 API 部署边界。

Compose 日常只运行 `application` 与 `postgres` 两个服务。API 通过内部 `database` 网络的 `postgres:5432` 连接数据库；PostgreSQL 不发布宿主端口，也不连接外部 `web` 网络。React 和 API 共用 HTTP 入口，TLS 反向代理由部署环境提供，仓库 Compose 不额外内置代理或前端容器。非容器网页包连接独立 PostgreSQL 服务，数据库可运行在容器、独立主机或受管服务中，浏览器均不直连数据库。

数据库数据卷 `postgres_data` 仅挂给 PostgreSQL；`app_data` 保存主密钥、用户文件模板、任务输出与备份，API 和独立恢复容器共享。公开 Docker 入口先完成构建，再停止 API、等待 PostgreSQL 就绪、运行一次性初始化/升级或恢复容器，成功后单独启动 API；失败不继续启动。维护服务属于显式 profile，普通 API 不持有维护凭据。数据库迁移仍由 Rust 存储层统一执行，Compose 不复制 SQL 或引入新版本合同。

权限按 resource/action/dataScope 解析，模板发布状态与共享受众另行限制。认证、桌面令牌与许可证依赖生成的 endpoint metadata；缺少授权或未知能力拒绝执行。数据库和文件故障保持 503，明确不存在为 404，版本冲突为 409，校验为 400，权限为 403，繁忙为 429，超时为 504。

账号权限按独立配置、指定共享分组、岗位默认分组依次选取一个来源；空独立权限不回退到岗位。未保存修改的内置分组（系统种子版本 1）读取当前岗位默认，管理员保存后固定使用其配置；独立账号、自定义及已编辑分组不自动补授。关闭模块同时收紧最终权限与导航，依赖不能重新放行。默认分组修改也撤销其继承账号会话；管理员权限由身份固定决定。Full 新账号默认普通员工，提供本人付款报销、个人票据模板设计打印和人事/行政自助服务，普通员工进入申请工作页；各岗位沿用相同导航分组，付款报销打印固定在工作台。人员私密档案、发票、报关另行授权。配置复用 records 和 schema 7；详见[账号与权限规则](./公司行政协作设计与验收.md)。

导航、搜索、首页和直接地址共用权限判断；单证类页面按具体查看/操作/管理动作控制，管理不隐含编辑。发票/付款编辑和输出再按记录所属范围限制；停用分组的有效权限为空，切换账号权限来源保留额外模块限制。模块与操作核对见[导航说明](./导航与页面简化说明.md)。

桌面随机回环端口与访问令牌由 Rust 宿主管理；令牌通过受限 IPC 获取，不写入 URL。浏览器不获得数据库凭据或任意本机文件操作。任务使用当前权限、取消和超时边界，正式输出路径来自用户选择。

桌面确认退出后，由后台线程停止共用 Rust HTTP 服务及任务，再销毁 Tauri WebView 窗口并退出；重复退出请求等待同一次清理，不能提前放行。Windows 的 wry 控制器销毁会调用 WebView2 Close；程序不按进程名批量结束系统中的 WebView2。实际平台证据见[桌面验收](./Rust桌面平台适配与验收.md)。

## 模板、设计器与 PDF

付款报销、文件任务及模板管理属于跨岗位共享能力，保留原资源键以兼容已保存授权。Full 各普通岗位默认可填写、查看和打印本人付款报销，并复制/设计自己的 PaymentVoucher 模板；Finance 默认查看和输出公司范围付款单，编辑仍限本人。ExportDocument 模板、字段目录、内容与输出另检查发票数据域权限，普通员工不获得出口发票或报关能力。可用模板目录的读取独立于设计/维护，PDF 导出派生本人任务读取；只读付款或输出权限不派生候选项写入。OA 审批、财务接收和付款报销打印仍分别记录，打印不代表审批通过或已付款。

商品字段可直接拖到 A4 画布，保留独立 X/Y、大小、文字和边框；`item.*` 只在主体区域逐件输出，共用最小行距，长内容撑高整行、顺延同列下方字段并由 Rust 分页。设计画布只编辑一行，普通字段与商品字段分别选择，高级组件入口默认收起。默认发票采用独立商品字段及单独的表头/线条，TOTAL 与分列合计同一行并在末页跟随正文；金额与单价沿用统一精确数值格式。发票号、唛头等单据信息独立于商品循环，按所属图层的首页/重复规则输出。普通表格、合并表头和高级组合明细保留；自由商品字段与高级明细表不可混用，已有用户复杂模板不自动改写。

只接受 `.dtpl` 文件，容器包含格式标记、长度及 SHA-256；内部文档为 V3 JSON。API 为保留 OpenAPI 兼容字段名仍使用 `contentHtml` 等字段，但内容是结构化 JSON，不是任意 HTML。旧 HTML、V2、裸 JSON 文件和损坏容器均拒绝导入。

六份内置模板由 `scripts/lib/default-report-designs.mjs` 生成，`Builtin` 读取同一份 `.dtpl`；没有第二套硬编码票面。React 自由画布修改同一文档，Rust 统一测量、分页并生成 SVG，krilla 编码正式 PDF。PDFium worker 负责已有 PDF 的预览、提取、OCR 页图和合并。

发票与装箱单共用右移、右对齐的号码/日期标签。默认装箱单仅保留外框与唛头分隔竖线，并延伸到设计高度；货品各列不画内部竖线，合计行单独使用虚线上边。表格和普通线条复用同一虚线间距。设计器同步保存高度延伸与合计边框配置，原用户模板未设置时保留原行为。

样例与当前单据预览都经过 Rust 排版；有设计权限时两者使用当前画布草稿，预览不保存模板或单据。预览按随包字体将字形转为矢量轮廓，并保留页面文本描述及等比例 viewBox，不依赖浏览器安装字体。数值与单位、币种与金额按直接连写输出（例如 `1110CTNS`、`USD11.00`）；独立金额字段和高级明细合计支持可选币种格式，普通网格支持标签直接前缀。

设计器支持 A4 横竖版、四类图层、普通网格合并/斜线/竖排/勾选、循环明细、组合字段分栏、显隐、首页/续页行数、首页唛头、末页合计及页脚跟随。发票与装箱单可隐藏 PO/款号，商品间横线默认关闭；金额与单价、装箱单的数量/重量/体积均按明细底部基线对齐，长款号与空 PO 不破坏对齐。付款报销只使用 Payment/Payee 数据。具体编辑说明见[设计器](./新版报表设计器进度参考文档.md)，版式和分页验收见[PDF 方案](./Rust统一V3模板与原版PDF验收方案.md)。

设计器插入策略独立于 React 页面：点击、拖放、工具栏和粘贴复用商品排版互斥规则，容量检查使用最终目标图层；失败保留原稿并显示原因。图层打印选项随改名、显隐和锁定操作保留，支持撤销/重做。旧版无调用的摘要、字段统计及 HTML 预览占位实现已移除；现用 Flow 组件和结构校验继续保留。

明细表属性分为商品列、表格样式、分页与高级；表头/正文和整表边框不再藏在合计设置内。列及组合片段仅编辑当前选择，列增删复制和模式切换由纯模型处理，复制保留空行规则及说明/合计/小计配置。位置、输出和低频排版默认折叠，保留同一 V3 文档、草稿与 Rust 排版，不转换已有用户模板。

图层面板与组件/字段资源面板分模块；图层导航位于纸张外，保持可读字号，按实际设计带定位。编辑默认适合宽度，整页视图、组件边界及选择仅属于会话状态，不改打印文档。高度/打印设置折叠，文字不溢出组件，表格手柄与缩放后的短字段拖动保持可操作；细节见[设计器](./新版报表设计器进度参考文档.md)。

数据库模板使用草稿、已发布、停用、归档状态和 ExpectedVersion。个人模板保存后保持 Draft/Private，只有本人可直接打印、导出，无需发布；共享须主动发布并设置受众，共享原稿只读，修改先复制或明确收回共享。文件模板维护及全局默认仅管理员办理，数据库全局默认须 Published/All，更换默认后才能修改、停用、归档或收回共享。内容与生命周期同时复核所有者/管理员及当前权限，较大数据范围不授予维护他人模板的权利。文件模板使用内容及显示名称生成的 revision；编辑内置模板创建副本。文件变更与回滚共用 DataRoot/Locks 下的模板存储锁，失败只恢复本次捕获的文件及目录清单；回滚失败保留恢复快照并明确报错。

私人模板直接入口以明确的模板编号同步选择；详情先返回、目录后返回时不清空当前选择，避免已编辑却无法保存/预览。付款和单证设计复用相同规则，当前权限与草稿保护继续生效。

受控图片使用 PNG/JPEG，按 SHA-256 去重，内容和上传归属在业务库中。读取校验所有者或可见引用，模板图片还校验对应出口/付款数据域。引用只来自正式唛头/印章字段与模板资源清单，普通备注或备用字段中的资源编号不构成授权。文件模板、数据库模板及历史引用都阻止回收；回收与文件变更使用同一存储锁。资源清单、图片摘要和大小在保存及输出时再次校验。当前图片支持范围以 Rust 校验为准，不能沿用旧 C# 支持 GIF/WebP 的说明。

发票可以独立上传单证章和报关章，无需先关联出口商档案；上传写入受控图片库，点击保存发票后持久化引用。选择出口商档案会带入其印章，随后修改只属于当前发票。发票印章的 null/缺省值继承关联档案，空字符串明确不盖章；单据包分别携带发票及档案图片，权限、回收和恢复沿用同一受管存储边界。

报表字体由各服务实例显式持有并按需加载，预览、PDF 及后台任务共享同一字形库和有界测量缓存。同步排版结束或异常时恢复调用方字体绑定；不全局缓存宿主字体路径，不允许其它实例初始化覆盖当前报告的字体。缺失随包字体保持 503，连续导出不重复加载字体文件。

## API、依赖与交付

HTTP 正文解码独立于请求调度和业务调用，路由总量与读取限额共用上传类型判定。multipart 按块检查单文件、PDF 剩余总量和 64 KiB 参数限制，在读取超出数量限制的文件或重复参数之前拒绝请求；保留原二进制上传与 JSON 契约。文件/请求容量超限返回 413，参数无效或不完整请求返回 400，取消和超时仍由共用请求作用域管理。

会议室、物品与六类 OA 共用申请办理入口，资源流程仍独立管理预约时段、预留、发放与归还。同公司资源目录供有查看权限的员工选择，申请内容仍按本人/部门/公司范围读取。Full SQLite 资源记录默认显示全部状态；历史列表和待办保留申请快照，不随资源属性变化重写。产生领用记录后固定物品单位及归还类型，无库存变化的操作不递增库存版本。消耗品发放即完成，不计待归还或离职欠领。逐级审批、代理和附件目前属于六类 OA；站内通知另覆盖会议室/物品的提交及修改重审、获批、交接、归还和办理分工交接，具体边界见[行政与人事](./公司行政协作设计与验收.md)。

业务授权统一执行生成契约的 `requiresLicense`，无效/过期注册码保持拒绝状态，七天试用到期后不能绕过 React 调用业务 API。账号/权限版本变化撤销旧会话；桌面更新 IPC 验证管理员会话并在安装前复核。团队授权使用持久安装身份，不因容器 HOSTNAME 重建而变化；桌面灾备迁往另一设备仍须按机器绑定重新注册。

SQLite 灾备恢复在 DataRoot 实例锁内、数据库打开前执行。独立加密包包含数据库、主密钥和用户模板，统一进行类型/版本/摘要/大小与路径校验；替换前保存原文件并记录恢复日志。版本 5 起的备份可恢复后升级；SQLite 普通恢复先升级快照，灾备升级纳入文件恢复回滚范围，成功后才移除待恢复标记。PostgreSQL 普通备份使用 custom-format dump；完整服务器迁移包另包含主密钥和用户模板。恢复须先停止 API，由独立 `--restore-pending` 维护命令持同一数据库实例锁执行并升级 schema；业务账号不获得建表、属主或集群管理权限。失败保留安全备份与待恢复标记并拒绝正常启动。命令和边界见[脚本说明](../scripts/README.md)。

WebDAV 下载以固定大小缓冲区写入受管暂存文件，复用存储层离线 SQLite 校验后原子移入 Backups；不把整份备份重新读入内存，也不占用业务数据库连接。成功、失败和取消均清理本次暂存文件及校验产生的 WAL/SHM，清理失败明确报错。任务只记录导入结果，完成后通过备份列表使用，不产生空的任务下载文件。文件模板目录只有确实不存在时视为空；损坏配置、非目录根路径和读取故障拒绝继续办理，不覆盖成新目录配置。

`/openapi/v1.json` 是唯一业务契约事实源。`export-doc-contracts::openapi` 保留冻结的官方 .NET 导出 `reference_openapi.json`，由 Rust 组合新增能力；回归逐项比较原端点、schema、认证及错误元数据。`generate-api-client.ps1` 从同一文档生成 React/Rust 客户端和策略；生成器位于 `export-doc-contracts/examples/generate_clients.rs`，直接调用 Rust OpenAPI 组合器，不依赖 Node 或 .NET SDK。禁止手改生成结果。

行政 OA 独立于原付款数据和报表：人事管理包含档案、通讯录、请假与加班；行政办公包含会议室、物品、费用报销、出差、采购与通用申请，工作台提供申请与审批中心。请求、附件、历史和权限按同一公司边界处理；报销仅移交独立财务软件，不记账或付款。新 OA 列表/历史使用存储层过滤与分页，员工调岗/离职检查未结申请。详见[行政与人事](./公司行政协作设计与验收.md)。

员工档案与六类 OA 申请在填写时选择图片/PDF，一次点击保存资料及附件；后台依次使用版本控制的写入和上传接口，部分失败保留已保存记录和待上传文件，不把分步请求宣称为一个数据库事务。人员档案新增私密文档附件，复用业务库、备份与档案详情权限。普通通讯录权限不能下载证件或文档。人员改名、调岗同步关联账号，离职停用账号并使旧会话失效；返聘不自动恢复登录权限。

通用记录保存只接收生成的请求 DTO 字段，防止通过额外 JSON 字段注入人员账号关联、附件引用等服务端状态。账号、人事、OA、单据、客户跟进、供应商关联、商机及业务附件的相关写入在事务获取后复查当前账号和权限；登录校验期间账号变化拒绝签发会话，续期保留原会话的权限版本。

业务资料附件预览绑定当前资料；离开详情时取消进行中的读取，迟到结果不能重新打开预览或串到其它资料。共用异步操作 hook 在作用域变化及卸载时取消，在操作成功或失败后都复查取消状态，防止旧请求错误出现在新资料上。行政、人事、OA 与公告操作在收到有效成功结果后先同步当前界面，再刷新共享列表/待办缓存，避免刷新删除或筛除当前详情后才执行过时回调；请求尚未完成时离开页面仍取消后续界面操作。预览复用受管 Blob URL hook，在更换和关闭时释放内存。

Full 提供公司公告与持久站内通知：公告支持公司/部门受众、草稿/发布/撤回/归档、置顶、有效期、附件及按发布版本确认阅读；提交审批、通过/驳回、作废和办结/移交在原业务事务中生成个人通知。通知按事件与接收人去重，列表/未读数在数据库分页前复查当前公司和业务权限，已读不改变审批状态。复用现有 records/files 与备份。正式用于 Web/Docker 多用户版，本地 Full SQLite 测试包也可打开和验证；Document/Sales 仍无入口，管理员直接调用同样拒绝。详见[行政与人事](./公司行政协作设计与验收.md)。

OA 默认保留按岗位权限的单步审批；管理员可按公司和申请类型选择指定 1–10 位审批人或部门负责人逐级审批。提交时保存审批步骤快照，规则和组织后续修改不改写在途申请；只由当前步骤及有效的直接代理办理，全部通过后才成为 Approved。代理有起止时间与停用控制，保留原审批人、实际办理人和代理编号；申请人可手动催办，每份申请每小时最多一次。待我审批按当前步骤在存储分页前过滤；审批中的负责人纳入人员交接。Full SQLite 测试版允许管理员关联人员账号以验证组织流转，默认单步仍保留登记语义。

办理分工覆盖具体印章、证明、IT/维修等事项、会议室及物品组，每项指定 1–10 人，任一位办理即可，审批独立执行并保留实际操作人。普通办理人员在动作授权后，只额外读取获批并分配给自己的记录和附件；公司范围完成/发放权限不能绕过明确分工，管理员可在本公司接管。人员变更接续未结业务并记录交接及通知，历史内容不重写；引用中的分工不可删除或改变类别。六类 OA 获批后同时保留申请人跟踪和办理人待办；资源已结束或已归还退出待办理，通知区分交接与办结。共用 engine::handling，配置与记录复用 schema 7 的 records，不新增数据库、服务或第三方依赖。

人员更换关联账号前检查人员和原账号的未结业务；候选账号因关联而变更部门时同样检查，避免绕过交接。任职变动立即执行，日期不得晚于公司业务日期。已完成的请假、出差和加班继续参与同人时段冲突检查，防止办结后重复登记；不新增薪资、假期余额或会计结算。

人员、OA 和公告的受控文档附件支持 PDF/PNG/JPEG、DOC/DOCX、XLS/XLSX。Office 文件只保存和下载原文件，不执行宏或解析为正式业务数据；通过现有 ZIP/CFB 容器校验类型、容量及损坏内容，拒绝扩展名伪装。每文件 10 MiB、每记录 20 个/50 MiB 的边界保持；工号继续全系统唯一。

费用报销提供财务接收视图及审批中心待接收队列，最终获批时通知具有接收权限的财务；Finance 默认可按 complete 权限的数据范围读取已批准/已移交记录及凭证并登记接收，OfficeManager 默认审批，Admin 可执行两步。普通查看权限不因此扩大到他人草稿，财务队列和通知在存储分页前过滤当前状态与范围；批准被作废或撤销读取权限后，旧通知不能绕过权限。接收仍为 HandedOff，仅记录资料交接，不记账、不支付，原付款单和报销打印单保持独立。

公告管理列表直接提供草稿继续编辑入口；从未发布的草稿可经版本校验、公司/发布管理权限校验与原因确认后删除，附件同事务删除，审计保留；发布过的公告仍归档并保留回执。人员档案按任职、工作联系与可折叠私密资料分区；六类 OA 登记共用单框人员检索，按姓名/工号从在职人员中选择，提供加载、无匹配、失败重试及键盘选择。

Cargo/npm 清单和锁文件以及 `eng/native-runtime-packages.json` 决定 Rust 交付依赖。Tauri/WebView、SQLite 属于桌面依赖；桌面不携带 PostgreSQL 服务端适配器、Node 或 .NET。PDFium/ONNX 原生归档与许可按固定清单准备，NuGet 仅作为归档来源。

Windows 便携版在系统/资源预检、后端及主 WebView 窗口创建成功后，后台回收本包 `WebView2Runtime` 离线安装目录；安装与清理共用互斥保护，失败记录日志并在后续成功启动重试。仅删除已知的三个普通文件及空目录，不递归删除，不触及系统运行库、Loader、用户 profile、开发仓库安装资源或原始压缩包。启动失败、安装取消或待重启时保留离线安装器；清理后的目录迁往缺少 WebView2 的设备须重新取得完整包或安装微软运行库。

入口和工作流见[脚本说明](../scripts/README.md)。Windows 批量入口及三端桌面 Actions 的 All 生成 Document、Sales；单版、安装器和默认启动为 Document。本地 `build-windows-desktop-run.cmd -Edition Full` 可单独生成 `ExportDocManager.Tauri.Full` SQLite 测试便携包，独立 `fulltest` 包身份不进入正式发布矩阵/更新频道，Administration 参数继续拒绝。Document 和 Full 默认提供 OCR/单证模板；Sales 保留字体/PDFium。后端按产品及权限契约限制管理员和普通账号，Document/Sales 不开放 OA 与账号权限管理。共享 Rust 代码未全部按版本从二进制剔除。系统级签名和 Apple 公证不执行；Tauri updater 信任合同保留，正式签名升级另验。

本机测试、真实 PostgreSQL、桌面窗口、其它 OS/架构、Docker、浏览器兼容和实体打印分别记录。通过编译、路由或旧版测试，不等于所有功能及所有平台已验收。
