# 2026-11-18 业务一致性与响应资源治理

## 实施范围

- 商机页面拆为页面组合、受控草稿模型、查询/命令工作区、编辑表单和按需历史。保存保留不可编辑报价字段，并合并服务端版本与提交期间续编；保存、重新加载、阶段流转、归档、切换和客户资料入口共用现有作用域命令。
- 归档目录使用 `includeArchived`，归档详情只读；历史直接使用 `beforeId/limit`、`items/nextCursor` 新契约，最多 200 条一页。详情和历史使用同一关联客户权限检查。普通权限依赖会扩展引用能力；回归使用现行显式数据范围限制，验证限制不能被历史入口绕过。
- Storage 复用 GenericQuery 游标及字段投影，SQLite/PostgreSQL 的完整 schema 18 增加 `records_opportunity_history_page`。模型指纹更新，旧实验库/备份不迁移、不静默接受。
- 发票保存消费 `pendingHsFeedback`，同次提交内相同反馈去重，验证或持久化失败回滚发票和反馈。成功回读不保留待提交反馈；重复创建、版本冲突不增加计数。
- HTTP 普通 JSON 编码后按实际 Vec 容量预留响应预算，与预览共享 128 MiB；单 JSON 最多 64 MiB，直到传输结束、断线或超时释放。预览另用两个在途传输名额，按实际输出容量计费。小响应使用匹配长度的管道/复制缓冲；JSON 不占文件下载名额，采用生成契约的执行期限。文件下载期限、Range、取消和关闭继续共用原传输模块。
- 运行诊断中的资源指标只在展开时查询，展示连接池、写入等待、任务输入/输出、排队和响应内存；后台页遵守现有轮询策略，折叠后回收缓存。健康状态使用服务端 `Healthy` 值。目录直接采用 `application/data`、访问采用 `read/read-write`、必需性采用 `required/optional`；四个核心目录完整显示，SQLite 为必需，字体/OCR 为可选。未知目录仍可见并明确报告元数据异常，依赖状态与就绪值矛盾也提示异常；旧分类和重复说明不再保留。

静态无前端方法引用不等于无效功能。下载票据通过返回的 URL 调用，健康/就绪探针用于部署；命令回执用于明确查询执行结果，前端的正常重试继续使用相同命令键。单一窗口的文件/上传传输、导出复核与资源申请的历史文档接口保留对应业务/宿主边界，不据此新增独立按钮或删除历史材料。运行指标已有正式界面消费者。

业务规则仍在 Domain，事务与反馈编排在 Engine，SQL/索引/游标在 Storage，HTTP 只管理传输资源。Tauri 继续适配宿主，React 使用既有字段样式、页签、折叠区、令牌和 680/1180 断点。未增加运行依赖、持久化缓存或后台服务。

## 容量语义与多用户边界

诊断中的请求和缓冲预算均按服务实例计算，不能用来代表用户人数、数据库体积、文件大小或进程总内存。界面分别显示 HTTP 执行/等待请求、文件缓冲预算和 JSON 缓冲预算，并保留必要的计量说明。自动化夹具截图中的排队 3、响应缓冲 32 MiB、拒绝 1、超时 2 是构造样例；实际桌面记录直接读取运行 API。

| 项目 | 当前实例容量及作用 |
| --- | --- |
| HTTP 执行/等待 | 各 16 个名额；等待最多 5 秒，超载拒绝。异步文件任务与这两个名额分别管理。 |
| 文件下载传输 | 8 个在途名额；文件流使用至多 64 KiB 复制缓冲及 64 KiB 管道，不把整个磁盘文件读入内存。 |
| 文件处理缓冲 | 独立 128 MiB；部分数据库内容和即时 PDF/Excel/ZIP 在生成与发送期间持有内存预留。 |
| JSON 响应缓冲 | 独立 128 MiB；单响应上限 64 MiB，直到发送结束/断线/超时释放。报表预览另外受两个在途名额保护。 |

现有部分生成下载仍按最坏情况预留整个 128 MiB，生成期间会阻止另一项同预算操作，输出后按实际容量缩小；不能宣称所有文件输出已流式化。这是明确的并发验收边界，不能以本批单机和慢读测试证明任意多人负载足够。Full PostgreSQL 上线前须按实际用户数、目录体积及导出频率验证请求等待、拒绝率、响应延迟和进程 RSS；数据库、OCR、报表模型及 WebView 另有内存占用。本批未扩大这些默认容量，也未将缓冲预算冒充进程内存限制。
