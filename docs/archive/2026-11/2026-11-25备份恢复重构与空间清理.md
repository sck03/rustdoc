# 2026-11-25 备份恢复重构与空间清理

## 范围和设计

用户授权完成前次分析中的修复、同步文档、必要验证、清理无用测试产物，并普通快进交付 main；不要求全量门禁。

- SQLite 普通备份是真正后台任务；恢复校验和暂存沿用任务最终授权、审计和持久化标记，退出重开后替换数据库。恢复完成不再查询恢复前管理员，消除成功后 404。数据库之外的文件对象按快照清单暂存，防止等待重启期间被回收。
- PostgreSQL dump 完整解码预检使用受控进程并丢弃 SQL 输出，不执行该 SQL；失败不安排恢复。单独快照及外部迁移包上传均复用完整灾备的最终授权、审计和任务提交确认，取消或失败不遗留有效恢复标记；普通快照沿用受管恢复目录，安全副本及失败现场保留。
- 前端只保留一次恢复状态提示，维护指引明确当前仅支持 schema 18、不自动升级旧库；测试夹具同步独立归档列表接口。
- 计划状态与归档分页分开；保留 1–365 份时都能浏览。缺失、损坏归档显示原因并禁用操作，健康归档与设置不被阻断。仓库根异常仍真实报错，不伪装成空列表。
- SQLite 存储容量回调与 PostgreSQL 流式写入接入共享磁盘预算；进程取消、超时和资源清理仍由共同受控进程模块负责。
- 桌面增加显式离线灾备命令，先取得实例锁再验证和安装，可恢复损坏的当前数据库；不建立旧 schema 兼容分支。
- 删除在线同步恢复路径、Storage 中仅供该路径使用的恢复接口，以及完成任务包装和会话清空方法；生成 API 始终由原生契约投影。无依赖版本和 schema 变化，无新增持久化库或缓存服务。
