# 前端视觉与产品命名规范

核对日期：2026-10-31。适用于同一套 React 前端的桌面、网页和 Docker 运行方式。部署及权限以[当前架构事实](./当前架构事实.md)为准，具体入口见[导航说明](./导航与页面简化说明.md)。

## 产品名称

| 形态 | 界面产品名称 | 版本说明 |
| --- | --- | --- |
| Document 正式桌面 | 外贸单证管理 | 单证版 |
| Sales 正式桌面 | 外贸业务工作台 | 业务员版 |
| Full 网页 / Docker 多用户 | 业务协同平台 | 协同版；部署文档另行说明部署方式 |
| Full + SQLite 本地测试 | 业务协同平台 | Full 单机测试版，窗口标题明确标注 |

“业务协同平台”覆盖单据、客户业务、人员组织、资源和 OA，名称不限定外贸，也不把 Docker 这一部署技术放入普通用户标题。相比“业务单据协同平台”范围更完整，相比“综合业务协同管控平台”更简洁。`ExportDocManager` 保留为现有工程系列标识；包目录、可执行文件名、应用 identifier、数据库目录和更新频道不因显示名称变化而迁移。

前端名称集中在 `app/productEdition.ts`，桌面打包名称集中在 `scripts/product-editions.json`。导航、登录、浏览器标题及 Tauri 窗口使用对应版本信息，自动化合同检查两份展示配置一致。Full 测试包不进入正式桌面发布矩阵。

## 配色与层次

采用用户选择的蓝灰商务风：浅灰蓝页面、白色工作区、深蓝导航，主要操作使用深蓝底白字。状态用成功绿、警告橙和错误红，并始终配文字或图标；状态色不作为普通品牌装饰。

| 用途 | 共享 token / 色值 | 使用规则 |
| --- | --- | --- |
| 主操作 | `--edm-primary-600` / `#245da8` | 保存、提交等主要动作；一组操作突出主次 |
| 导航底色 | `--edm-primary-900` / `#1a2d46` | 左侧主导航及紧凑导航 |
| 页面底色 | `#f4f6f9` | 白色内容区外的背景 |
| 正文与辅助文字 | ink / neutral 系列 | 层级由字号、字重、间距及明度共同表达 |

颜色集中维护在 `styles/theme/color-tokens.css`，共享控件负责按钮、输入、焦点与禁用状态；业务页不各自复制色值。移除登录页持续动画、装饰网格和大面积渐变，减少无信息阴影。沿用现有图标、字体与组件，不引入新 UI 库。

## 页面与导航

- 工作概览置于工作台首项；保留已有七组任务导航、查找功能、权限过滤和各版首页。复杂业务仍在原模块内完成。
- 组织与任职先选择单位，右侧按“公司与部门 / 任职与岗位 / 单位身份与授权 / 审批统计”处理。只显示获授权分区；第一次进入才加载，当前单位内切换保留输入。切换单位重新建立工作区，避免串用公司状态。
- 权限方案默认只显示第一个模块分类，搜索跨分类，清空搜索回到默认分类。每张卡显示已授权动作数，详细规则按需展开，发布和应用放在编辑之后。查看、操作、数据范围、发布版本及绑定仍分别控制。
- HS 七项导航在所有知识页面统一单行；窄屏在导航内部横向滚动，不挤压正文或把整页撑宽。
- 登录页左侧交代产品与三项用途，右侧保留账号、密码及登录；高级连接设置按需展开，窄屏依次排列。桌面启动先显示中性准备状态，读取实际版本后才显示对应登录名称，避免单证版/业务员版短暂出现 Full 标题。
- 通用目录使用 `ListWorkspaceHeader`：第一层为标题、数量及主要操作，第二层为搜索和筛选，所选记录的批量操作另成一行。发票、付款、客户、供应商、商机、基础资料和待办采用同一结构，保留各自查询、分页、权限及草稿逻辑。
- 销售概览优先显示“跟进与成交”，“经营分析”按需打开。摘要表按内容占高，不套用业务目录的大块空白；具体跟进和预计成交可直接进入对应记录。新手指引折叠，不长期挤占工作区。
- 申请目录按“人事与考勤 / 费用与出行 / 行政与资源”分组，并支持关键词、分类筛选。审批首页优先显示有任务或加载错误的分类；零任务分类收起但保留入口。
- 文件任务默认查看任务进度，“新建文件任务”展开批量报表及 PDF 工具，收起后保留已输入内容。业务资料在桌面显示目录表格，在手机显示资料卡片；进入详情后管理版本和原件。
- OCR 顶部明确“粘贴图片 / 开始识别”，“复制文本”放到识别结果旁。图片缩放、拖动与结果对照保留。

## 全模块结构审查

本批以真实导航、源码结构和宽窄屏画面共同审查。重构依据是任务顺序、信息密度与误操作风险；已有清晰任务边界的页面保留专业结构。下表的“保留”表示本批的结构决定，不表示仅通过截图就重新验收了全部业务。

| 模块与页面 | 本批决定 | 依据与保留的交互 |
| --- | --- | --- |
| 登录、三版启动与页头 | 重排、统一名称 | 产品说明与登录分栏，高级连接收起；同一版本的网页和窗口名称一致 |
| 主导航与功能查找 | 调整概览顺序，保留七组任务域 | 工作台、客户与供货商、单证与申报、人员与组织、申请与资源、资料与工具、系统管理；权限过滤、功能搜索和窄屏收起继续有效 |
| 单证概览 | 首次指引折叠 | 金额按币种分组、近期单据和业务待办保留，避免新手说明占据首屏 |
| 销售概览 | 按工作/分析拆分，摘要表收紧 | 跟进与成交优先，阶段与金额分析单独查看；具体行进入原记录 |
| 我的待办 | 统一目录头和筛选 | 来源、到期状态清晰分开，办理仍进入原业务 |
| 公司公告、站内通知 | 保留列表/详情及未读状态 | 公告阅读、确认、发布和通知来源已分别组织，不合并成第二个审批中心 |
| 发票目录 | 动作、筛选、勾选操作分层 | 新建/导入/刷新、搜索、跨页选择与批量报表互不混排 |
| 发票编辑与预览 | 保留专业页签和折叠分区 | 单据头、明细、装箱、附加内容及预览涉及连续制单；保留表格编辑、保存续编、中文输入、草稿与金额规则 |
| 付款报销打印目录 | 统一目录头和筛选 | 新建和搜索分开；打印凭证继续与 OA 费用报销独立 |
| 付款编辑与 PDF | 保留任务页签 | 付款资料、打印内容、备用字段与预览已有边界，保留自由文本和私人模板 |
| 客户目录 | 分离动作/筛选/所选操作 | 导入、导出、新建；搜索与状态；选中后再显示批量操作和取消选择 |
| 客户资料、联系人与跟进 | 保留目录/详情分离 | 客户主资料、联系人和跟进已有独立视图，继续保留版本冲突与未保存提示 |
| 商机与报价 | 统一目录；详情保留 | 消除重复说明；目录、资料、报价与阶段历史各有入口，保留正式流转动作 |
| 供应商目录 | 统一目录头和筛选 | 新建、导入导出和查询分开；联系人、产品和评价仍在供应商内处理 |
| 业务资料与附件版本 | 桌面目录表格、移动卡片 | 横向比较名称、单据、客户/业务标记、分类和版本；原件、版本确认、元数据与删除理由不简化 |
| 基础资料各分类 | 统一列表结构 | 客户、出口商、商品、港口、银行等沿用分类导航和专业字段；HS 所选动作独立呈现 |
| 统计查询 | 保留常用/高级筛选 | 常用日期和业务条件先展示，低频条件可展开，保留明细与原币汇总输出 |
| 单一窗口、产地证、托单及词典 | 保留业务导航与详情 | 批次、映射、交接和回执是连续专业任务；不把本地工作站配置塞入普通制单列表 |
| HS 知识七页 | 统一单行内部滚动导航 | 检索、目录、历史/年度资料等入口不换行挤压内容，专业表格和维护规则保留 |
| 报表模板目录、设计和预览 | 保留独立工作区 | 模板目录/输出默认值/导入导出已分开；设计器继续用图层、属性、表格及独立预览 |
| Excel 模板与托单 | 保留四个任务卡片 | 导入模板、空白托单、Excel 转托单、已保存发票托单用途明确；高级路径默认收起 |
| OCR | 调整动作位置和文字标签 | 先输入图片、再识别、结果旁复制；不改变原图对照和可取消操作 |
| 装柜模拟 | 保留配置/货物/结果链路 | 柜型、方案、货物编辑与三维结果有明确依赖，保留高级规则、自动分析和保存加载 |
| 今日汇率 | 保留报价优先结构 | 来源时间、过期状态与常用币种报价同页，来源说明按需展开 |
| 邮件发送、投递记录与模板历史 | 保留任务视图 | 编写/投递记录分开；模板草稿、版本历史和恢复继续独立操作 |
| 文件任务 | 查看进度优先、新建按需展开 | 保留工具草稿、任务取消/重试、下载和实际输出错误 |
| 申请与审批首页 | 分类目录、搜索、任务优先 | 发起、审批进度和待办理分别呈现；零任务收起，错误保留可见 |
| 各类申请、会议室与物品 | 保留共用申请详情与资源视图 | 申请内容、材料、流程、签署与办理事实已分层，资源选择/库存/日程各保留专业展示 |
| 人员档案与通讯录 | 保留按用途区分 | 通讯录只展示工作联系信息，档案与正式人员变动不挤在同一公开卡片 |
| 组织与任职 | 左单位、右任务分区 | 公司部门、岗位任职、身份授权、审批统计按权限延迟加载；切换单位清除旧上下文 |
| 流程管理 | 保留折叠定义和图形编辑 | 各已发布流程、模拟、日历、代理及办理分工已有独立分区；保留草稿/发布和在途版本边界 |
| 账号、权限方案与授权来源 | 分类、搜索、详情按需展开 | 首分类默认显示，搜索跨分类，动作数量可见；发布与应用置于编辑之后 |
| 系统设置、审计、关于/许可/更新 | 保留分类和独立页面 | 设置按需加载并保护草稿，审计筛选/导出独立；更新仅桌面可见 |

未增加运行依赖、第二套 UI、业务状态或通用 JSON 编辑器。`TaskViewPanel` 只负责首次挂载与会话内保留，业务权限与查询仍由原模块管理；对模块切换、长名称、键盘、390px 及实际文件操作分别回归。

## 参考与验证边界

OA 的产品定位与流程组织参考[泛微](https://www.weaver.com.cn/)、[致远互联](https://www.seeyon.com/)、[蓝凌](https://www.landray.com.cn/)的公开资料。跨业务的信息组织同时参考[金蝶](https://www.kingdee.com/products/)、[用友](https://www.yonyou.com/)、[飞书多维表格](https://www.feishu.cn/product/base)的公开产品入口；这些商业产品未取得内部系统进行完整评测，不将其描述为“公认完美”。

可核验的设计规范采用 [Ant Design 布局](https://ant.design/docs/spec/layout-cn)、[数据展示](https://ant.design/docs/spec/data-display-cn)及 [Arco Design](https://arco.design/react/docs/start)。实际落实到固定导航与弹性内容、8px 间距、按重要性/频率/关联性编排、筛选和分页配套、长文本处理、空态以及低频信息折叠。复用自身 React/CSS 组件，不引入整套组件库或商业品牌素材。

第一阶段巡检 39 个实际导航路由、1440 / 390 两种宽度共 78 个画面，页面横向溢出、页面运行错误和错误提示均为零；其中部分画面处于加载态，只作为导航巡检证据。第二阶段使用示例发票、中英文长客户名、供应商、跟进和商机验证目录与销售概览，并检查申请分类、新建任务收起后的输入保留、实际业务资料版本操作。专项回归另检查主申请按钮白字、HS 七项横排、组织分区延迟挂载/输入保留/键盘操作，以及权限分类异步加载。

共享主题变化需审查并更新 84 张视觉基线；像素阈值仍为 0.5%，继续执行文字、几何、交互和无障碍断言。完整批次结果和本地证据目录记录在[验收台账](./OA重构验收与功能保留台账.md)，不得把截图巡检扩写成全业务重新验收。

系统 IME 候选窗仍需 Windows 真机人工检查；浏览器文本输入测试不代替系统候选窗。其它 OS / 架构、实体打印、Docker daemon 和生产容量保留各自验收边界。
