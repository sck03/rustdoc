# 2026-11-25 项目审查重构与清理

本批从 `93b25091` 开始，落实已确认的导入、草稿保护、报表分页、付款模型和工作台查询问题。用户授权实施、必要回归、清理已失效的测试产物并合入 GitHub `main`；按要求未运行全工作区完整测试，不建立旧程序或旧数据库兼容链。

## 实现与职责边界

| 范围 | 本批结果 |
| --- | --- |
| 客户／供应商导入 | Domain 提供统一初始状态，客户为“潜在客户”、供应商为“考察中”。文件指定其他状态时给出行错误，后续状态变化仍走独立业务动作。 |
| 联系人权限 | 导入主要联系人同时检查联系人创建和设为主要联系人权限；预检、预检持久化及正式提交刷新当前授权，撤权后不能借旧预检创建联系人。重复或无效行不产生联系人，不要求无关创建权限。 |
| 导入开销 | Storage 接收最多 5000 个候选名称，以单个 JSON 参数和当前数据范围查询规范化重名，不再将整个目录逐页读入应用。解析、预检序列化和摘要计算在写事务外完成；提交在事务内复查并消费一次性快照。 |
| 导入界面 | 两类目录共用 `DirectoryImportPreview`，复用现有字段、表格、分页控件和设计令牌；支持全部／错误／重复／可导入筛选与 30、50、100 行分页，仅挂载当前页，末尾错误行可以查看。现行预检返回的是最多 5000 行的有界快照，本批没有增加不必要的第二套分页 API。 |
| 组织草稿 | 公司、部门负责人的变更判断同时比较人员和任职编号；同一个人切换任职后关闭窗口也会提示未保存修改。 |
| 模板分页 | React 插入、粘贴和保存校验与 Rust Domain 采用相同的有效输出条件；有输出的商品明细表不能与独立 Flow 分页符组合。模板接收及原生排版入口共用领域校验，移除排版后段的重复拒绝逻辑。不输出的组件不参与分页。 |
| 付款货物 | `goodsItems` 是唯一货物输入，删除顶层 `goodsName`、`quantity`、`quantityUnit` DTO 字段及旧输入回填逻辑。付款列表直接展示明细品名；报表仍从明细数组派生同名模板字段，这些模板字段仍是有效功能。 |
| 发票工作台 | 共享授权、公司和优先版本筛选；数据库统计全历史状态数量，最近记录及各状态待办限量读取，金额仅读取本月／上月所需字段并按 200 行游标批次计算。金额继续用 Rust 精确十进制，不引入 SQLite 浮点汇总。所有查询处于同一读取快照。 |
| 无效代码 | 通用 `workflows` 删除不可达的报表模板发布、共享、停用、恢复、归档及克隆分支；正式模板模块及版本历史能力保留。只供测试使用的预检封装限定在测试构建内。 |

发票商品多时的**自动分页继续有效**：仍按行高、首／续页行数、重复表头等设置续页。本批限制的是“商品明细表旁另放独立分页符”这一原生排版器没有支持的组合，普通正文独立分页符仍可用；没有将长发票改成单页或截断商品行。

契约修改来自 `native_contract` 并通过正式生成器同步 OpenAPI、Rust DTO、运行契约及 React 客户端。独立契约对照明确记录删除的三个付款输入字段，其余端点元数据保持原契约。没有升级依赖，也没有修改数据库 DDL、schema 版本或模型指纹。

- 其中 121 个目录为同一编译身份已被新完成会话替代的增量产物，72 个文件为 Cargo 指纹确认的测试可执行文件及调试／依赖信息，另外 50 个目标为已结束的临时测试目录、数据库、界面输出和日志。

- 首轮有 7 个已停止的浏览器测试缓存目录报告“目录不是空的”；再次检查剩余文件均属于原清单且未变化后定向重试，最终全部 243 个目标删除成功，无失败目标。
