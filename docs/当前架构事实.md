# 当前架构事实

> 事实基线：2026-09-06。本文是部署、开发和审核时唯一需要先阅读的现状说明；按日期排列的旧文档只记录当时的决策与证据，不可用来推断当前路径、数据库版本或接口行为。

## 产品形态

- 桌面端、浏览器服务器版和容器版共用同一套领域模型、应用服务、API 契约和 React Web 界面。
- 后端项目统一目标框架为 `net10.0`。`global.json` 以官方稳定 SDK `10.0.302` 作为最低基线，通过 `latestFeature` 且禁止 preview，允许同一 `10.0` 产品线滚动到更新的稳定 feature band（包括 `10.0.400/401`），但拒绝较低版本、`10.1` 和 .NET 11；GitHub Actions 使用由该基线推导的稳定 `10.0.x` 通道。框架/NuGet 依赖继续精确锁定运行时、EF Core 和 SQLite servicing `10.0.11`，Npgsql EF Core Provider 使用 `10.0.3`，ONNX Runtime 使用 `1.29.0`，不使用通配包版本或开放范围。
- 后端依赖按可裁剪能力拆为核心 `ExportDocManager.Infrastructure` 与三个独立模块：`ExportDocManager.Infrastructure.Excel`、`ExportDocManager.Infrastructure.Browser`、`ExportDocManager.Infrastructure.PdfOcr`。核心项目不再直接引用 ClosedXML、ExcelDataReader、Playwright、PDFsharp、PDFtoImage、PdfPig、ONNX Runtime 等重依赖；API 只通过 `IExportDocCapabilityModule` 发现已随包程序集，缺失模块注册明确的“不支持”服务，不在核心层保留重复实现。
- 容器采用 `Nginx Web + ASP.NET Core API + 隔离 Chromium Browser + PostgreSQL 18` 四服务拓扑。API 与 Browser 运行层使用 `debian:trixie-slim`，Web 只承载静态资源和反向代理并使用轻量 `nginx:1.30.4-alpine3.24`；数据库固定 `postgres:18.4-trixie`。Debian 原生 `chromium`、`chromium-sandbox` 和 Noto CJK 只安装在 Browser 镜像，API 镜像不再携带浏览器。API 与 Browser 都以 UID/GID `10001` 运行；API `cap_drop: ALL` 且启用 `no-new-privileges`，只有 Browser 获得 Chromium 命名空间沙箱所需的 `SYS_ADMIN`，仍禁止 `--no-sandbox`。Browser 不接入 PostgreSQL `backend` 网络、不接收数据库/维护账号/主密钥/首次启用令牌，只通过独立 `browser` 网络向 API 提供内部 CDP `9222`；API `5188`、Browser `9222` 和 PostgreSQL `5432` 均不向宿主发布。Browser 使用 512 MiB `/dev/shm`，并以只读方式读取 API 的 `Cache/ReportPdf`；自身 profile/缓存写入 `runtime/browser`。默认资源档位为 API `2 CPU / 2 GiB / 512 PID`、Browser `1.5 CPU / 1536 MiB / 512 PID`、PostgreSQL `2 CPU / 2 GiB / 256 PID`、Web `0.5 CPU / 256 MiB / 128 PID`。API 通过 Microsoft 官方 Debian 13 仓库配置包安装最新稳定 .NET/ASP.NET Core Runtime `10.0.x`，PostgreSQL 客户端来自 `trixie-pgdg` 的 PGDG 18；容器构建按 BuildKit `TARGETARCH` 将 .NET restore/publish 映射到 `linux-x64` 或 `linux-arm64`，API 从已锁定的官方 NuGet 缓存直接复制当前 RID 的唯一 `libonnxruntime.so`，不依赖引用项目输出传播。MCR 当前没有稳定 Trixie SDK/ASP.NET 标签，因此构建层使用官方稳定 `10.0-noble` 通道，并在镜像内拒绝 preview、其它 minor 和其它 major。
- 桌面单机使用 SQLite；办公室/浏览器/容器团队版使用 PostgreSQL 18。项目尚未投产，不为 v1—v13 数据增加兼容迁移层；当前空库基线为 `v14`，以资源/动作/数据范围授权为唯一持久化权限事实，并包含规范化身份键、公司/部门组织目录、统一乐观并发、服务端导入预览、模板生命周期历史和报表图片资源归属/引用记录；不带有效版本标记的开发库直接拒绝启动。
- SQLite 单机桌面版首次账号仍为 `admin`、密码为空；Tauri 登录页为方便单机使用只预填账号 `admin`，不预填密码。普通浏览器/PostgreSQL 团队版不预填任何账号或密码，空库首次管理员仍必须由 `admin` 使用 8—128 字符密码和一次性部署令牌初始化。
- PostgreSQL 容器全新部署采用四角色最小权限模型：`POSTGRES_USER` 只负责数据库容器首次初始化；`exportdoc_owner` 为 `NOLOGIN` 所有者角色；`exportdoc_app` 是普通 API 业务连接，只具备表的 `SELECT/INSERT/UPDATE/DELETE`、序列使用和例程执行权限，明确为 `NOCREATEDB` 且不能执行 DDL；`exportdoc_maintenance` 是独立维护登录角色，具备 `CREATEDB` 并被授予 owner 角色，可在首次建表、结构初始化、备份验证和恢复时 `SET ROLE exportdoc_owner`。四个角色必须互不相同，普通请求不会使用初始化管理员或维护账号。
- PostgreSQL 团队版的后台任务快照存入业务库，但全新部署允许 API 在首次管理员登录建表之前先通过进程就绪探针。后台任务存储初始化只把 PostgreSQL `42P01`（任务表尚不存在）识别为“等待首次建表”并从空内存目录启动；连接失败、权限错误和其它数据库异常仍阻止启动，不会把基础设施故障伪装成空任务列表。
- SQLite 与 PostgreSQL 都执行单 API 实例约束。SQLite 使用 DataRoot 下受管锁文件；PostgreSQL 使用由数据库身份稳定派生的 advisory lock，并由专用长连接持有和周期探测。锁连接丢失时主动停止 API，避免同一业务库被多个后台任务 Runner 重复消费。
- 浏览器安装器和容器安装器把 PostgreSQL 客户端、OCR、浏览器等工具放在程序运行目录或职责隔离的镜像层；业务数据、配置、日志、缓存、备份、模板和密钥均位于 `DataRoot` 或管理员指定的数据盘。容器 Browser 镜像不包含 PostgreSQL 客户端和应用 secrets。
- 容器 HTTP 安装默认只绑定 `127.0.0.1`，并写入 `EXPORTDOCMANAGER_ALLOW_INSECURE_DISASTER_RECOVERY=false`。管理员只有在可信办公网/VPN中显式指定非回环 IPv4 后才会开放 HTTP 端口，敏感恢复还必须另外传入授权开关；HTTPS 默认绑定 `0.0.0.0`，静态证书 overlay 会替换而不是追加基础端口。模式切换使用各自安全默认值，不继承另一模式的绑定地址。

## 权限、组织与多用户边界

- 账号界面使用“权限方案”表示岗位授权组合，“功能模块”表示具体业务资源。方案目录和模块操作区采用紧凑布局，按宽度自动分列并支持分类/搜索；编辑、复制及保存只提交可配置业务授权，技术依赖仍由服务端派生，筛选不会丢弃隐藏模块的草稿授权。内部 PermissionTemplate API 与持久化契约不变。

- API 与业务数据范围共用有效权限解析器。非空权限快照的缺项始终拒绝；只有未分配权限模板且尚无有效权限的内置岗位才解析岗位默认值，停用、缺失或空授权的已分配模板不会回退。导航在模块列表缺失时直接拒绝，报表业务域同时检查对应发票/付款查看权限，财务账号默认进入付款模板域。

- 权限模板的唯一事实是 `resourceKey + action + dataScope`。数据范围固定为本人、部门、公司、全部；“仅查看 / 日常操作 / 完整管理”只用于界面快捷勾选，不再作为持久化授权事实，也不会让未覆盖的新模块默认获得管理权限。非法资源、动作、范围、角色或产品版值均拒绝保存或启动，不做静默降级。
- 账号与权限界面在原模板管理基础上拆分客户、联系人、跟进、商机、报价、供应商、供应商联系人、供货关系、供应商评价、邮件模板、邮件外发、报表模板、模板图片资源、发票输出、付款/报销输出及系统能力；每个动作独立选择数据范围。界面同时显示模板直接授权、技术依赖继承和最终有效权限，停用模板仍可识别和安全回显，模板与用户保存均使用 `ExpectedVersion` 防止两个管理员互相覆盖。
- 导航菜单、直接路由、页面按钮和 API endpoint metadata 使用同一 capability 目录。权限未加载、加载失败、未知动作和未声明业务 metadata 一律 fail-closed；预览、打印、PDF、ZIP、邮件外发、导入、导出、发布、共享、恢复和删除不再由 HTTP 方法或笼统模块等级代替。后台任务重试会按原始操作重新检查当下权限，撤权后不能借旧任务继续执行。
- 公司和部门来自当前业务库中的组织主数据，不再接受账号页自由文本。部门必须属于所选公司；组织、账号、权限模板和领域聚合共用规范化唯一键与乐观并发。PostgreSQL 团队版按所有者、部门、公司或全部范围过滤；销售主管获得哪个范围必须显式配置，不因拥有销售工作区自动查看全公司数据。
- 灾备、服务器迁移、用户/权限管理和系统策略仍是身份限定的技术能力，普通岗位模板不能直接委托。灾备与迁移同时要求 Full 管理员身份、正确产品模式、安全传输、重新认证、一次性敏感操作票据、明确确认文本和完整审计；系统级 Authenticode、Developer ID 与 Apple 公证仍不执行。
- 当前正式多用户拓扑是“一套 PostgreSQL 18 + 一个 API 实例 + 多个浏览器用户”；SQLite 只支持 Tauri 桌面单机。单实例锁、会话撤销和数据库授权支持该边界，但不宣称多 API 高可用或跨实例实时协同。

## 报表设计器 V3

- 报表可视化设计器唯一运行时是 React 19 + TypeScript 的 `ReportDesignerV3Workspace` 自研自由画布；后端仍是 .NET 10 C#，负责模板、字段目录、预览和最终 HTML/Scriban 安全校验。旧 Luckysheet/iframe/独立静态设计器、V2 schema 和 SRP 不再作为运行时入口；不带 V3 标记的经典 HTML 仍作为独立高级 HTML 运行时保留，供熟悉 HTML/CSS/JS 的人员维护，不进入 V3 画布。
- V3 页面固定为 A4：竖版 `210 × 297 mm`、横版 `297 × 210 mm`，坐标使用 `1/100 mm` 整数。Header、Body、Footer、Overlay 图层、Flow 结构化 AST、重复页眉/页脚、重复表头、keep-together、pinned footer 和受控分页均由同一 schema/exporter 表达。
- V3 支持 Text、Field、Image、Rectangle、Line 及 Row/Grid/Conditional/DetailTable/PageBreak Flow；多选、拖动、八方向缩放、复制、删除、图层、撤销/重做、网格吸附、对齐和水平/垂直均匀分布均在统一 mutation helper 中执行，并受锁定、页面边界、最小尺寸和元素上限约束。拖动开始时一次性计算所选元素包围盒、页面约束并缓存对应 DOM 节点，动画帧只更新 `translate3d` 合成层位移；提交或取消后清理临时 transform/`will-change`，复杂模板拖动不再逐帧扫描全部图层和查询节点。
- `Grid` 在界面中作为“普通表格”提供，适合付款单、报销单、报关单等固定票面：普通用户可从空白表格、标签/内容表单、审批签字栏开始，直接增减行列、选格、向右/向下合并、拆分、调整列宽/行高、设置竖排文字、勾选组、字段和边框。画布中的每个单元格使用整表唯一且仅编辑器可见的命中 ID，点击任意行列都会同步右侧“当前单元格”选区，正式 HTML 不携带该属性；整表和单格字号、对齐、粗体、内边距及边框都即时写入预览与导出，折叠边框的相邻共享边同步开关、颜色、粗细和线型，Flow 外层不再显示或应用一组会被内部结构覆盖的重复通用样式。循环商品行仍使用“明细表（自动重复）”，避免把固定表格和业务明细循环混为一类。Header/Footer 设计带可在图层面板输入毫米高度，也可拖动画布分隔线或用键盘调整；隐藏后不占画布且不输出，Body 自动占满剩余 A4 高度并保留最小可编辑区域，打印最小高度仍是独立设置。
- 图片只允许字段绑定或受控 `resourceId`。普通用户可在右侧图片属性栏上传 PNG、JPEG、GIF 或 WebP；物理文件继续按 SHA-256 去重写入 `DataRoot/Templates/Resources/V3`，单个不超过 32 MB、总数不超过 1000 个，逻辑归属、上传声明、模板引用、版本引用和回收状态写入当前业务库。资源读取必须通过模板所有者、共享范围、引用关系和报表资源 capability 的对象级授权，不能仅凭资源 ID 或哈希下载。模板只保存受控资源元数据，不接受任意 HTTP、文件路径、静态外链或客户端路径；预览、HTML 和 PDF 渲染前由后端严格校验 schema、资源清单、文件头、媒体类型、大小及 SHA-256，缺失或无权资源直接失败，不输出假占位。
- 不带 V3 schema 的旧模板保持高级 HTML 运行时，打开 V3 设计器时只在内存中生成一次性 A4 草稿并要求人工确认，原 HTML 不会静默覆盖；确认保存后才转换为 `version: 3`，否则继续按经典 HTML 预览和输出。带 V3 标记的模板只接受 `version: 3`，V2/SRP 不作运行时回退。报关单、付款单、报销单、发票、合同和装箱单分别按出口/付款业务域与 A4 横竖版组合验证。
- 当前路由的 `reportType` 是 V3 字段域、图片字段和导出的权威；嵌入 schema 类型不一致时保留为可修复安全草稿，不按错误类型写回。旋转元素使用局部坐标包围盒进行页面夹紧和八方向缩放，Inspector 可直接编辑角度；Body 图层的静态元素与 Flow 元素重叠会给出阻断前的明确提示，避免把固定定位误当成流式排版。
- 用户报表模板使用草稿、已发布、停用、归档四态，内容保存、发布、共享、停用、恢复、归档、复制、导入/导出和资源操作分别使用独立命令及 `ExpectedVersion`；生命周期命令不再携带整份 HTML，避免把未保存草稿意外写入。经典文件模板的文件、清单和设置更新由跨进程锁、同目录原子写入与失败回滚协调，多个请求不能再生成同秒重名包或留下半提交状态。

## 2026-09-01 文件系统和持久化最终收口

- `ControlledFileSystemEnumerator` 区分不存在目录与不可访问目录，并按目标文件系统大小写语义排序；清理、复制、灾备、模板包和 PDF 合并在操作前后都拒绝符号链接、junction 与其它 reparse point，受控后序遍历一旦发现越界风险立即失败，不把安全错误伪装成空目录。
- COO/ACD 保存返回实际递增后的 `DraftRevision` 与 `SourceBaselineHash`，handoff manifest 绑定该结果；客户端派发 operation/lease/attempt/digest 和重启恢复保持幂等。后台持久化写入失败会让 readiness fail-closed，数据库、文件和外部工具故障继续按 503/504 分类，不降级成普通业务冲突。

## 领域模型与时间契约

- 通知人使用三态领域模型 `NotifyPartyMode.None / SameAsConsignee / Separate`。`SameAsConsignee` 是单据输出边界的投影规则，不把当前收货人名称或地址复制到客户/发票的通知人字段；只有 `Separate` 才允许保存独立通知人名称和地址。Web 编辑器、API DTO、业务验证、Excel 导入、发票复制、主数据和报表/Excel 输出共用这一规则，非 `Separate` 模式在提交和持久化前清空独立字段。
- 业务自然日统一为 `DateOnly`，包括发票日、船期、付款日、收款日、预计成交日、授权到期日和查询日期范围；具有时区意义的创建、更新、审计、会话、任务、回执和外部抓取时间统一为 `DateTimeOffset`。Domain、Application 与公开 API/OpenAPI 不再暴露 `DateTime` 属性。
- SQLite 的 `DateTimeOffset` 时间点统一保存为 UTC ticks 并恢复为零偏移；PostgreSQL 使用带时区时间点语义。源码中仍出现的 `DateTime` 仅限 Excel 原生单元格、文件系统时间和第三方模板互操作边界，不得进入领域持久化或公开契约。

## 运行目录

`DataRoot` 下的主要目录是 `Database`、`Config`、`Security`、`Files`、`Templates`、`SingleWindow`、`Marks`、`Backups`、`Exports/Browser`、`SupportPackages`、`Logs` 和 `Cache/BackgroundJobs`。`IAppPathProvider` 位于 Application 契约层，`RuntimeAppPathProvider` 必须由启动组合根显式注入 AppRoot/DataRoot，不再提供无参构造或静态全局路径入口。路径提供器只解析路径，不在属性访问时创建目录；API/Tauri 启动先检查绝对路径、文件系统根和全部现存祖先中的符号链接/联接点，通过后才创建运行目录并做写入探测。路径字段只保存相对路径，写入、读取和迁移前后继续检查目录边界。只有系统盘时可以使用系统盘上的专用可写目录，不强制要求第二块磁盘。

单一窗口参考目录使用依赖注入的 `SingleWindowReferenceCatalogSnapshotStore` 保存实例快照；没有静态 loader、静态缓存或全局事件。字段映射器、校验器和服务从当前作用域/实例读取不可变快照，因此测试、多个宿主和未来多租户扩展不会通过进程级全局状态互相污染。

容器运行根额外包含 `runtime/postgres`、`runtime/api-data`、`runtime/browser`、`runtime/letsencrypt` 和 `runtime/acme-webroot`。`runtime/browser` 只保存可重建的隔离 Chromium profile/缓存，不属于完整业务迁移的必需数据；API 临时报表目录 `runtime/api-data/Cache/ReportPdf` 对 Browser 只读挂载。外层运行根为 root `700`，API/Browser 目录为固定 UID/GID `10001` 的 `750`，PostgreSQL 数据目录由 `999:999` 管理并保持 `700`。

Tauri sidecar 不再先保留随机端口再释放。API 直接监听 `127.0.0.1:0`，启动成功后把带 schema、实际回环地址和进程 ID 的短生命周期端点文件原子写入 `DataRoot/Cache/Sidecar/`；Tauri 校验文件大小、结构、进程 ID、回环地址和健康探针后立即删除。端点文件不能位于 Cache 以外，也不能经过链接类路径。

桌面 DataRoot 迁移使用确定性目录树清单，清单包含相对路径、空目录、文件大小和逐文件内容 SHA-256 的汇总摘要；源目录、同盘 staging 和激活后的目标目录摘要一致后才切换配置并删除旧目录。仅比较文件数和总字节数不再视为有效迁移校验。

桌面绿色便携版使用同一套 `portable-runtime.json` 契约，但不强行拆开平台原生容器：Windows ZIP 内为主程序和完整资源树；Linux tar.gz 内为经过解包复验的 AppImage；macOS ARM64 tar.gz 内为完整 `.app`。Windows 从程序资源根识别标记，Linux 从 AppImage 标准 `APPIMAGE` 环境定位包外标记，macOS 从 `.app` 的父目录定位包外标记；程序资源仍留在 AppImage/`.app` 的原生只读布局，所有业务写入统一进入解包目录旁 `App_Data`。交付包不得预置数据库、密码、许可证、日志或用户配置，复制完整解包目录即可备份和迁移便携数据。Windows 便携版在创建 Tauri 窗口前由 Rust 启动层检查操作系统和 WebView2 Runtime；缺失时优先使用程序根 `WebView2Runtime/` 下随包提供的微软 Evergreen Standalone Installer，经用户确认后执行并重新检测，未随包提供时显示官方安装地址。该安装器属于忽略的第三方发布资产，不写入 Git；便携版仍不启动 NSIS，升级时退出程序、替换新便携包中的程序文件并保留原 `App_Data`。安装版原有签名 updater 流程不变。

## 服务器迁移

服务器迁移包为 schema `2` 的 `.edmmigration` 加密包。职责由以下组件隔离：

1. `ServerMigrationPackageGenerator`：收集受控运行数据、生成 manifest、压缩和加密。
2. `ServerMigrationPackageValidator`：限制大小/路径/ZIP 条目、校验清单和 SHA-256。
3. `ServerMigrationDatabaseRestorer`：调用随运行目录提供的 `pg_dump`/`pg_restore`/`psql`，验证产品库、创建安全备份并恢复数据库。
4. `ServerMigrationFileTransaction`：准备安全副本、原子切换配置与业务文件并支持回滚。
5. `ServerMigrationRecoveryStateMachine`：在建立数据库连接前按持久化阶段执行验证、备份、数据库恢复、文件切换、完成或回滚。
6. `ServerMigrationDeploymentCertificateAdapter`：明确排除 TLS/Certbot 证书，证书由目标部署重新签发。

恢复状态为 `pending → validating → safety-backup → applying-database → applying-files → completed`；数据库与文件切换全部完成后先持久化明确提交点，再写成功安全审计。提交后的审计失败只记录到 stderr，不会回滚已经一致的数据；失败审计同样是 best effort。提交点之前任一中断进入回滚并记录可操作状态；若回滚不完整或 marker 已标记人工恢复，后续启动必须 fail closed 并抛出 `ManualRecoveryRequiredException`，不得在数据库与文件可能混合的状态下继续提供 API。迁移包不包含许可证、机器绑定状态、日志缓存或部署证书。

恢复状态机的清单、逐文件摘要和主密钥兼容性检查位于独立 validation partial；主状态机只负责编排和回滚，避免验证规则重新积累到单一大文件。

## API 错误契约

应用服务使用分类异常：

| 分类 | HTTP |
| --- | ---: |
| `ServiceValidationException` / 无效输入 | 400 |
| 只有显式 `ResourceNotFoundException`（或明确的业务 `KeyNotFoundException`） | 404 |
| `PermissionDeniedException` | 403 |
| `ServiceBusyException` | 429 |
| `ResourceConflictException` / `ServiceConcurrencyException` | 409 |
| `InfrastructureServiceException`、数据库/网络/文件依赖不可用 | 503 |
| `ServiceTimeoutException` | 504 |
| 未分类异常（带 `X-Correlation-ID`） | 500 |

数据库离线、文件系统故障和 WebDAV/外部工具故障不得再包装为普通业务冲突。未分类的 `FileNotFoundException`/`DirectoryNotFoundException` 也按依赖不可用返回 503；只有服务明确标记为资源不存在时才返回 404。API 端点和全局安全中间件都复用同一个映射器；上传超限单独返回 413，客户端取消返回 499，受控 OCR/浏览器/Excel 队列繁忙返回 429，明确的内部任务超时返回 504，其他依赖取消或不可用返回 503。

## 可空契约与 OpenAPI

Domain、Application、Infrastructure、API、客户端生成器和四个 .NET 测试项目均已启用完整的 C# 可空引用类型分析（`Nullable=enable`）。可能查不到记录的查询返回 `T?`，调用方必须显式处理 `null`；不使用项目级 `NoWarn`、批量 `!` 或虚假非空返回掩盖契约问题。Release 全解决方案构建以 0 个可空警告为门禁。

`/openapi/v1.json` 是唯一业务契约事实源，由 .NET 10 官方 `Microsoft.AspNetCore.OpenApi` 的 `AddOpenApi`/`MapOpenApi` 根据 Minimal API 元数据生成；`/swagger/v1/swagger.json` 直接映射同一个官方 `v1` 文档。原约 1.28 万行手写 paths/schemas/factory/catalog 和过渡响应补齐器已删除，不保留兼容叠加层。TypeScript 生成器在工作区临时 SQLite 数据根启动真实端点图，通过 keyed `IOpenApiDocumentProvider` 读取官方文档，完成后删除临时数据；端点迁移优先使用 `TypedResults` 和联合结果类型表达成功及可静态分类的失败响应，仅对框架没有专用正文结果类型或异常映射产生的动态状态保留最小 `.Produces<T>`。当前已迁移认证、许可、设置、仪表盘、付款、查询、邮件模板、销售机会、用户管理、权限模板、发票数据维护、客户/出口商/收款对象/商品/港口/单位、候选项和单一窗口签发机构/操作中心/生产企业资料模块。结构门禁检查 operationId、内部引用、路径参数、请求体、关键 Header/Query、所有业务操作 2xx Schema、已迁移模块响应 Schema 和旧手写目录不得回归。

`ApiEndpointAccessMetadata` 是认证、桌面访问和许可证要求的唯一事实源。三个中间件只读取已匹配 endpoint 的 metadata，不再通过 `/api` 前缀或路径白名单猜测；未映射地址保持 404，`/api/auth/me`、`renew`、`logout` 等授权过期后仍需访问的端点由映射处显式声明。OpenAPI transformer 使用同一 metadata 生成 Bearer/Desktop security requirement，文档 server 固定为同源 `/`，不写开发机端口、反向代理外部地址或重复的全局 security。业务工作区/权限模块仍是独立授权维度，不与“是否需要登录”混为一张路径表。

匿名健康探针分为两个用途：`GET/HEAD /livez` 只表示进程能够响应，永远不触碰数据库、目录或浏览器；`GET/HEAD /readyz` 在 2 秒上限内并行检查数据库连接、核心运行目录和配置的远程 CDP 浏览器，任一项不可用即返回 503，并且只输出稳定的检查名和状态，不泄露连接串、异常或服务器路径。需要完整诊断的 `/healthz` 仍按原有受保护/脱敏边界处理。

服务器绝对路径不是浏览器业务数据。备份、WebDAV、PostgreSQL 维护、服务器迁移、持卡机恢复、系统日志、授权存储、模板存储诊断、健康诊断和后台任务响应只在有效桌面令牌通道返回绝对路径；浏览器管理员保留逻辑文件名、可用状态和操作结果，路径字段为空，界面显示“服务器受管目录/文件”。

## 请求热路径

- .NET 10 源码层只采用有明确收益的现代基础库能力：私有同步闸门使用 `System.Threading.Lock`，静态只读目录使用 `FrozenDictionary/FrozenSet`，无自定义配置的 Web JSON 序列化复用 `JsonSerializerOptions.Web`。这些改动不增加 NuGet 包，也不改变公开 API 或持久化格式。
- HS 知识搜索把查询 n-gram 每次请求只生成一次，同义词按预计算最长匹配执行且归一化保持幂等；候选评分不再为每个候选重复排序同义词、重复生成查询特征或通过 LINQ 分配交集迭代器。跨平台文件名非法字符由 Domain 共享策略统一判断，普通合法名称直接返回原字符串，避免各层重复获取平台字符数组和生成临时字符数组。
- 授权服务使用 30 秒线程安全状态快照；普通受保护请求不重复读取平台锚点、计算机器身份或改写授权文件。同一自然日内不更新 `LastRunDate`，机器种子和 Windows 本机密封镜像仅在内容变化时写入。
- PostgreSQL 网络模式的会话验证使用最多 30 秒、最多 10000 项的进程内快照；注销、用户停用、改密和权限修改通过会话撤销立即清理本实例缓存。后台清理按会话 ID 游标分轮续扫，达到 10000 项批次上限后会从上次位置继续，扫描到末尾才归零，避免低 ID 有效会话长期挡住高 ID 过期记录。多实例部署仍以数据库为事实源，缓存最长一致性窗口为 30 秒。
- Web 后台任务默认从 1 秒开始轮询并退避到 5 秒；页面隐藏时暂停请求，重新可见后继续。不依赖 Redis 或消息队列。
- API 请求频率使用按资源档位配置的令牌桶，每 6 秒平滑补充并继续叠加独立并发上限；登录额度按来源地址隔离，已认证业务请求按会话隔离，避免共享出口网络中的不同用户互相占用额度。
- 任务中心对活动任务每 2 秒刷新，页面隐藏时暂停、重新聚焦时立即刷新，并在全部任务进入终态后停止轮询。任务持久化失败会原子撤销内存快照、清理受控部分输出并释放用户/全局队列配额，不留下无法查询的幽灵任务。
- 任务中心筛选保留输入草稿以避免逐字请求，但清空关键词、切换状态/页大小和点击刷新都会先提交当前筛选；刷新按钮在有草稿时应用筛选后再查询，普通用户不需要额外按回车才能回到全部任务。
- 发票与付款服务的数据库查询、事务、保存、复制、状态流转、报表生成和 API 入口统一传播请求或后台任务取消令牌；SMTP 发送和连接测试也支持取消，并分别使用 60 秒和 30 秒内部超时。客户端主动取消保持 499，内部超时为 504，数据库、SMTP 和其它基础设施不可用为 503。
- 单一窗口 COO 附件最多 20 个，单个不超过 8 MiB、合计不超过 20 MiB；Base64 通过 `XmlWriter` 分块写入，不再把整个附件读成 `byte[]`。邮件最多 10 个附件，单个 10 MiB、原始合计 18 MiB；PDF 合并为 2—50 个文件，单个 50 MiB、合计 100 MiB，并禁止输出覆盖任一输入文件。网页、桌面和后台任务复用同一组校验，任务执行前会再次确认文件边界。
- 中国银行汇率页面返回 HTTP 200 但缺少预期表格，或已配置币种没有任何可解析数值时，视为上游协议/基础设施故障而不是成功空结果。PostgreSQL 模糊检索使用与实际 `upper(column) LIKE '%TOKEN%'` 查询一致的 `upper(...) gin_trgm_ops` 表达式索引；SQLite 继续使用无新增依赖的稳定回退。
- 登录失败状态最多跟踪 20000 项，过期项定期回收，容量满时优先淘汰最旧且未锁定状态；全部状态均处于锁定期时安全拒绝新增失败尝试。PBKDF2 哈希只接受 100000—1000000 次迭代，防止损坏或恶意哈希制造无界 CPU 消耗。
- 客户、出口商和收款对象的业务选择器使用带取消、300 ms 防抖和服务端分页的远程检索，不再因旧非分页接口的 200 条安全上限漏掉第 201 条以后的档案；当前已选记录按 ID 单独读取。港口等管理列表继续服务端分页；计量单位数据量受业务约束且表格需要完整候选，明确请求受权限约束的完整集合。
- 自定义候选项按类型只返回最近 500 项，再恢复为时间正序供界面使用；重复判断由数据库执行 `AnyAsync`，不会为一次输入把同类型全部历史记录物化到进程内存。
- 汇率源只允许不带账号、query 或 fragment 的公开 HTTPS 地址；每次请求及每一跳重定向都重新校验 DNS，生产 `SocketsHttpHandler` 的实际连接回调再次解析并把套接字固定到已验证公网地址，关闭代理和自动重定向，避免 DNS 重绑定或系统代理把请求带入内网。响应上限 5 MiB、总时限 30 秒、重定向最多 5 次；调用方取消返回 499，内部超时返回 504，DNS/TLS/HTTP/流故障返回 503。
- 本地 Playwright 浏览器在最后一个报表/OCR 浏览器操作结束后默认空闲 120 秒自动回收，下一次请求再按需启动；新操作会取消待执行回收，远程容器 CDP 不由 API 擅自关闭。空闲时间可在 1—3600 秒受控范围内配置，避免桌面长时间保留 Chromium 进程和内存。
- 装柜分析一次最多 200 行、100 万件和 5000 个实际模拟装载单元；默认最多并行 2 个分析、排队 5 秒、单次计算 10 秒，均有受控环境变量边界。取消令牌贯穿候选生成、碰撞/承重/重心计算，超时返回 504、容量繁忙返回 429，防止异常输入长期占满 CPU 和内存。
- Excel 往来单位提取使用独立的公司名/地址文本分类器，地址判断按完整地址 token 而不是公司名中的普通子串执行，公司后缀使用线性 token/HashSet 判断，不再让超长文本进入带时限正则。实际附件 `2026YH027备货单.xls` 复核结果为客户英文名 `Reason Brand Inc`、客户英文地址 `3 WEST 35TH STREET 10th FL.，New York, NY 10001` 且商品 3 行。实际附件 `报关数据.xls` 的通知人识别为 `SAME AS CONSIGNEE` 并复用客户地址，商品款式描述可拆出中文品名与 `品牌名：...`；纯数字、单据标签和商品表头不会再误作通知人。Rust sidecar 与 .NET 内置/混合分析链路均有同类回归，避免名称含 `Brand` 等词时被误判为地址。
- Excel 导入统一执行 25 MiB 原包、2048 个 ZIP 条目、单条目 64 MiB、解压总量 256 MiB、64 个工作表、单表 10 万行/512 列和全工作簿 100 万个实际逻辑单元格上限；`.xls` 与 OpenXML 共用逻辑配额闸门。旧 `.xls` 只按每行最后一个实际非空值计入单元格预算并裁掉尾部全空行，不会再把格式化空白区域误计为百万单元格，也不会为整片空白区域分配对象数组。OpenXML 行号和 `A1` 引用必须完整、正整数且不能溢出，不能用超大行号绕过配额。格式/内容错误分类为 400，文件权限、I/O 和分析器依赖故障保留为 503，未分类程序错误不再被吞进成功响应的通用错误字符串。

## 文件输入与文档生成边界

- Excel 主明细表与后置补充表使用同一通用布局模型。复合/多行表头先按完整表头路径修复款号、英文品名、数量、箱数等列；工作簿后部如存在包含中文品名、品牌、成分/英文品名和 HS 编码的补充表，则按规范化的 `PO + 款号`，或在款号唯一时按款号合并，不依赖文件名、客户名、固定行号或某一家公司的模板。真实附件 `2026JHJ011 报关数据.xlsx` 已完整走上传预览 API：发票号 `2026JHJ011`、客户 `SPORTS GROUP DENMARK A/S`、75 条明细、总箱数 2650；`EA211395` 得到英文品名 `women's knitted sweatshirts`、中文品名 `化纤制针织女式非起绒套头衫`、品牌 `ATHLECIA` 和 17 箱。该附件只因源表缺少出口商中文名保留业务校验提示，不属于解析失败。
- OCR 剪贴板、拖放和浏览器文件输入使用有界二进制请求体，不再经 JSON/Base64 放大；预览使用 Blob/Object URL。桌面本机路径预览由受桌面令牌保护的 API 流式返回，源图片不复制到系统临时目录、数据库或默认输出目录，页面卸载和替换图片时撤销 Object URL。
- 装柜 PDF 由后端统一 HTML/PDF 渲染能力生成。浏览器版把临时文件放在 DataRoot 受管缓存并随流式响应完成后清理；桌面版只写用户在原生保存对话框中明确选择的 `.pdf` 路径。前端不再携带 `html2canvas`、`jsPDF` 及其 DOM/Base64 桥接，Tauri 也不再拥有专用 PDF 解码写盘命令。
- PowerShell 公共外部进程执行器统一提供两小时默认上限、可配置 watchdog、60 秒心跳、并发读取 stdout/stderr、超时进程树终止、退出码传播和显式/当前 PowerShell 工作目录解析。非捕获命令继承当前控制台实时显示原生进度；捕获命令使用异步双流读取，不会因缓冲区填满卡死。GitHub 长任务同时设置 job/step 上限，Linux 包探针逐项输出分组和失败退出码。

## Web 维护页与样式层

“系统设置 → 维护 → 团队库”由编排组件和四个独立面板组成：数据库备份、数据库恢复、完整迁移、后台任务状态。页面只在进入对应分类时加载相应 chunk，长任务使用后台状态和短期 Range 下载票据，不把大文件整体读入浏览器内存。

下载票据按运行端采用两条安全通道：普通浏览器票据绑定同源 `HttpOnly`、`SameSite=Strict` 会话 Cookie，复制单独的下载 URL 不能绕过当前浏览器会话；受信任 Tauri 桌面端通过桌面访问令牌签发不依赖跨源 Cookie 的票据。登录、退出和账号会话撤销会废止对应旧票据，票据仍绑定用途、资源、用户和五分钟有效期，不写 LocalStorage、数据库或磁盘缓存。

工作区布局由视口宽度和关键内容区可用宽度共同决定；设置中心在左侧分类导航占用空间后仍按内容区断点收缩网格，避免中等宽度窗口横向溢出。操作能力同时考虑输入设备。手机宽度始终保持轻量限制，中等宽度设备在检测到支持 hover 的精细指针（鼠标或触控板）后可启用导入导出和高级工具，但密集工作台与批量管理仍要求更宽屏幕。提示文案与实际能力使用同一 profile，避免功能已开放却仍要求“使用桌面端”。

任务中心已拆为页面编排、任务创建面板、任务表格和状态展示模型；模板包服务已拆为编排、目录清单、包 I/O/验证和合并策略四个 partial。HS API 路由按导入、联网、CRUD 和共享 helper 拆分，入口文件只保留目录注册；Tauri 桌面命令按文件选择、PDF、打开路径拆分，运行路径按配置、便携包识别、Sidecar 路径和测试拆分，其中 `runtime_portable.rs` 独立负责 `portable-runtime.json`、AppImage 与 macOS `.app` 包外根定位。OpenAPI 仅保留三个小型官方基础设施文件：顶层文档转换器、Swagger 落地页和 nullable schema 转换器；业务 paths、参数、请求体和响应 Schema 全部来自端点元数据。Web 发票表单按基础信息、往来单位、扩展字段、贸易条款和唛头明细拆为独立组件，发票明细编辑器再把选区、焦点、键盘导航、虚拟滚动和列隐藏清理抽入 `useInvoiceItemsGridInteraction`；单一窗口参考词典把工具栏、Excel 导入、编辑表格、右键菜单和别名对话框移入独立视图组件，`AgentConsignmentPage.tsx` 也把表单分区与明细面板移入 `AgentConsignmentPanels.tsx`，主协调器降至约 556 行。COO 页面把草稿更新、签发机构/生产商操作和商品编辑动作移入专用 hook，主页面降至约 631 行；装柜工作区主编排降至约 182 行，项目、配置、工具栏、货物表和结果各自成组件，伪 3D 投影、数学、渲染块合并及可视化模型分层维护，不同优先组或装载区域不再错误合并。报表模板管理与报表设计使用独立路由和轻量路由壳，共享状态协调器但分别组合管理面板与设计工作区；Rust OCR 将图像预处理和识别解码从进程入口拆开。Rust Excel 分析器按工作簿读取、单据字段识别、表格分析、模型和测试拆分，`main.rs` 只保留进程入口与数据模型。Web 应用壳拆为 `App.tsx`、`AppWorkspaceRoutes.tsx` 和 `webSessionStorage.ts`，其中 `lazyNamed` 通过条件类型保留每个懒加载组件的真实必需 Props；设置页、发票编辑页和报表模板设计器分别把面板目录/默认值、持久化操作和编辑动作抽入独立模块。源码规模门禁除专项组合外，还覆盖 .NET、Web、Rust、测试、自动化和 workflow 的全仓库默认单文件上限、聚合上限及相对基线增量，并为 COO、装柜和报表模板管理组合设置专项上限，统一排除生成目录，防止未列入白名单的新大文件绕过治理。

PDF 页面像素回归通过 DevTools 附加到 Chromium 内置 PDF Viewer frame，等待文档页数就绪后调用 Viewer 的页导航并复核当前页；多页样本的截图 SHA-256 不能全部相同，避免 `#page=N` 未生效却仍重复验证第一页。Viewer 控制已拆入独立脚本模块，真实 18 页基线与纸张/墨迹指纹共同参与门禁。

基础样式入口 `src/styles.css` 仅保留按主题排列的 `@import` 清单；全站表单网格、筛选栏、详情网格、行操作、隐藏控件和通用模态框等工作区原语固定由 `styles/theme/workspace-primitives.css` 随应用壳加载，不得寄存在任何 lazy route 中。报表、单一窗口和装柜等重量级专属规则仍通过 `styles/routes/*.css` 随对应路由加载，设置页运行诊断使用独立 `runtime-diagnostics.css`，单一窗口运行规则使用独立 `single-window-runtime.css`。供应商评价规则已从主题 token 层移到 `styles/business/supplier-assessments.css`，发票客户/出口商/通知人布局移到 `styles/business/invoice-parties.css`；主题层只保留跨业务设计令牌和壳层原语，避免业务页面样式再次改变全局级联。`global-style-contract.html` 会在不访问这些懒加载路由的条件下直接验证公共布局，并由静态门禁阻止公共选择器重新回流。基础、仪表盘、主数据、审计查询、工具、邮件和任务样式分别位于 `src/styles/*.css`；原先 1580—2655 行的 `theme.css`、`businessFeatures.css`、`reportWorkspace.css`、`responsiveOverrides.css` 已变为有序导入清单，实际规则按主题/业务/报表/响应式职责拆入 `src/styles/theme`、`business`、`report`、`responsive`，单个模块不超过 800 行并保持原级联顺序。源文件行数由 `test:source-size-governance` 门禁限制。

## 2026-08-20 当前增量事实

- .NET 普通构建是无 RID 的 portable 图；所有 native 发布必须显式提供 RID，并从 `eng/nuget-runtime-locks/<RID>/` 读取已提交 lock。当前覆盖 Windows x64/ARM64、Linux x64/ARM64、macOS ARM64；Sales API 另有裁剪依赖图。NuGet 全局包目录和 HTTP 缓存由仓库/CI 环境指向工作区，不依赖系统 C 盘默认缓存。
- 可选能力模块只依赖 Application 定义的轻量注册接口；ASP.NET Core DI 适配仅存在于 API 组合根。发布目录通过程序集约定自动发现能力模块，模块缺失即表示对应产品版不携带该依赖，不在核心层复制实现或加入兼容分支。
- SQLite 设置只表示 `DataRoot/Database/` 下的一个简单数据库文件名；任意绝对路径、相对子目录和 Windows 保留设备名均无效。数据库、备份和离线还原使用同一 resolver，运行数据不会因设置中的路径字符串写往系统盘或工作目录外。
- 跨平台文件名统一采用 NFC、Windows/Linux/macOS 共同非法字符、尾部点/空格和 Windows 设备名规则。Tauri 路径身份则按平台文件系统安全边界处理：Windows 大小写不敏感，Linux/macOS 大小写敏感，且在目标尚不存在时也能完成词法边界判断。
- Windows 安装器明确选择 Evergreen WebView2 bootstrapper；WebView2 仍属于 Windows 平台管理的系统运行组件，不把固定版运行时复制到业务 DataRoot。项目程序、OCR/Excel sidecar、浏览器资源、数据库、日志、缓存和用户文件仍分别随 AppRoot/DataRoot 管理。
- 依赖升级后的最终本机验证将以 .NET `1070/1070`（Domain `54`、Application `164`、Infrastructure `523`、API `329`）、React 19 Web 构建、Tauri/OCR/Excel Rust `62/8/14`、五个 RID 的 Full/Sales 锁定还原及依赖/工作流/路径静态门禁为准。Chromium PDF 使用短 `r-<随机名>` 临时目录，避免 Windows 深路径失败；Firefox/WebKit 仅手动触发。系统级签名、公证、真实 Docker/PostgreSQL 和目标平台真机不据此声明已验收。

## 2026-08-26 发票单据包默认项事实

## 2026-08-25 报表模板与导出设置事实

## 2026-08-25 邮件可靠投递事实

- 通用邮件与发票单据邮件使用稳定投递键和请求 SHA-256 指纹。相同键、相同内容已经成功时幂等返回；相同键对应不同内容时明确冲突；SMTP 已开始但结果不确定时不自动重发，避免连接中断造成重复邮件。
- `EmailDeliveryRecords` 只在当前 SQLite/PostgreSQL 业务库保存投递键、请求指纹、来源、当前用户、收件人、主题、附件数量、状态和时间，不保存正文、附件路径、SMTP 密码或附件内容。最近投递记录按业务数据权限显示；邮件正文使用 `text/plain + text/html` multipart alternative。
- 发票单据邮件继续只读取发票/报关数据域并使用运行数据根临时 PDF；付款/报销不接入邮件。空库 schema 现为 `v11`，包含单证草稿并发令牌、客户端派发租约以及 CRM/供应商/商机并发与规范化字段；不增加 v10 迁移或双读代码。

## 2026-08-24 报表模板管理与设计事实

- `#/reports/templates/manage` 是报表模板管理入口，集中负责报表类型与文件/用户模板选择、我的/共享模板、默认模板、新建、显示名称、物理文件名、删除和模板包导入导出。`#/reports/templates` 只承担当前模板的可视化设计、高级 HTML、预览、保存、撤销和重做，并提供“返回模板管理”；两个路由通过明确的 `reportType`、`template` 或 `userTemplateId` 深链传递当前选择。
