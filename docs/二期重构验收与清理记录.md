## 检索与资源选型

采用子串语义和有界规范化缓存。普通静态正文在 64 KiB 边界内保存按 UTF-8 键序的紧凑 JSON，普通词与结构化关键字使用同一表示；大正文、身份和流程继续完整/权威读取。没有引入生产 FTS 表、pg_trgm 扩展或第二套检索服务。

双库正式计划为同一 10,000 发票、另 3,000 任务/HS/模板记录和 1% 超过 64 KiB 正文的匿名样本。PostgreSQL 结构化检索中位值从 5,118.97 ms 降到 1,168.61 ms；同批两次写入阶段从 40,983.2 ms 增到 54,010.0 ms。SQLite 当前空关键字列表约 1.59 ms，中文短词约 1,486 ms、稀有标记约 3,051 ms；这些是本机 Debug 驱动/实际数据库测量，不作为生产延迟承诺，也不将候选五倍目标写成普遍达成。

独立索引原型另按 10,000 个规范化文本进行评估并验证更新、删除、回滚。SQLite 默认 FTS 对中文单字/双字返回 0，原子串返回 10,000；trigram 额外约 11.65 MiB，常见词/结构化串较扫描慢，稀有编号约 23.07 → 0.80 ms。PostgreSQL trigram 额外约 1.07 MiB，稀有编号约 5.42 → 1.33 ms，短词/常见串收益有限。原型表/扩展仅在隔离数据库事务中创建并回滚。保留现有检索的决定依据准确性、读写和空间成本；首屏及混合容量分别验收。

2026-11-04 首批入口静态导入与 modulepreload 集合分别计算 JS/CSS，采样 JS 约 139 KiB gzip、CSS 约 6.8 KiB gzip，入口样式源约 1,008 行。2026-11-05 使用真实页面载入资源集合复测，完整字节、交互和内存结果见下表；两种采样集合分别保留。
