# 2026-11-26 授权有效期显示与清理

用户反馈终身授权页面显示 `9223372036854776000` 和 `+262142-12-31`，要求统一其余有效期与未注册状态、保持架构和设计规范、仅做必要测试，并清理无用生成物后合并交付 main。

## 原因与改动

Engine 用 `i64::MAX` 和 `NaiveDate::MAX` 表示终身，超出原 int32 契约及 JavaScript 精确整数范围；前端直接展示天数，只能识别四位年份，因而未覆盖 Rust 的扩展年份。正式授权过期和无效注册码也被同一布尔字段显示为“试用到期”。

- 在原生契约增加 `licenseState` 六种状态，`daysRemaining/expireDate` 支持 null。只修改 native_contract 并运行正式生成器；冻结契约通过独立、明确的差异夹具验证，端点认证／权限／容量元数据不变。
- Engine 的状态查询与注册审计删除最大值哨兵；有效期继续使用业务时区、防回拨有效日期和签名校验。正式授权到期当天有效，次日阻断；无效或过期注册码不能恢复试用。
- React 的 `licenseStatusModel.ts` 只负责展示映射，页面继续复用作用域命令、共享详情网格和现有设计令牌。删除旧日期猜测函数、已注册时的试用天数和重复提示；无效授权保留具体原因，读取失败明确显示错误。

| 情况 | 页面状态 | 剩余天数 | 到期日期 |
| --- | --- | --- | --- |
| 终身 | 已注册（终身授权） | 永久有效 | 永不过期 |
| 一年／多年 | 已注册（定期授权） | 非负整数＋天，包含当天 | 实际 YYYY-MM-DD |
| 定期到期当天 | 已注册（定期授权） | 1 天 | 当天日期 |
| 正式授权过期 | 授权已过期 | 0 天 | 原截止日期 |
| 未注册且试用有效 | 未注册（试用中） | 7 至 1 天 | 安装日＋6 天 |
| 试用到期 | 未注册（试用已到期） | 0 天 | 原试用截止日 |
| 无效注册码／设备绑定变更 | 授权无效 | — | — |

不通过剩余天数反推“一年／三年”购买期限，因为现有签名只包含到期时间；统一显示“定期授权”和真实截止日。注册格式及已存注册码保持有效，无数据库 schema、依赖或配置变化。Tauri 内嵌前端、网页服务与客户端须使用同步生成的新版本；本次源码提交不等于已有安装包或 Docker 实例已更新。
