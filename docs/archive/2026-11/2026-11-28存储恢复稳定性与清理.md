# 2026-11-28 存储恢复稳定性与清理

## 实施范围

本批承接项目分析，按用户授权直接完成修复并交付 main。保持 Tauri/React 共用 HTTP 应用服务、Domain/Engine/Storage 边界，保持 schema 19，不增加依赖和旧库兼容。没有把未运行的完整测试或外部设备验收计为通过。

| 问题 | 当前行为与边界 |
| --- | --- |
| 已完成恢复重开后被保护标记锁住 | 新维护进程重新进入 Locked；未结束或有切换工件进入 Interrupted；不复活进程内预检计划。结束后的恢复请求被拒绝，独立工件清理仍可执行且保留终态。 |
| 维护页刷新丢失会话 | GET ResumeMaintenanceSession 校验现有 Cookie，返回内存 CSRF；跨源和缺少 CSRF 的写入继续拒绝。没有 LocalStorage。 |
| 归档切换后清理失败误报未提交 | 切换前建立既有 FileUploads 日志；任务返回 PartiallyCommitted、已切换数量和处理方法。回收预检列入旧副本，核验正式副本后幂等清理；沿用对象级互斥，与同一文件上传冲突时返回 429 并保留源文件。日志损坏、位置不明或介质变化不自动删除。 |
| 完整性核验误寻址 | verify_object 使用对象的正式归档位置，主库与归档库共用同一校验。 |
| 取消覆盖已提交事实 | TaskOutput 明确是否已执行持久化业务动作；已提交或结果不明的任务不会被后来的取消重标为“未发布”。普通文件输出仍按原事务化发布合同取消。 |
| 处置复核只见汇总 | 契约返回理由及最多 100 条冻结明细，前端呈现文件/单位/类别/日期/容量并确认核对；申请人隔离、期限、引用/暂停/政策/版本重校验继续在后端事务执行。 |
| 后台任务查询错误卡住界面 | 共享 useTrackedJob 使用统一重试/轮询策略；提供重新查询、任务中心、停止跟踪，停止跟踪不取消任务，不自动重发写入。 |
| 设置间版本未刷新 | 归档刷新文件库及保留数据；仓库维护刷新备份计划和恢复点；编辑草稿保留原版本用于并发检查。 |
| OA 发布样例重复、错误不具体 | 以含 catalogRevision 的同一快照比较和保存；公共错误展示字段、节点/阶段/对象和建议，避免丢失已分类原因。 |
| 仓库回收重复扫描/重复读块 | 目录名称索引仅在 OS 排他锁生命周期有效，最多两百万名称，逐项操作继续检查介质/路径；标记最多一百万对象，每个共享块读取校验一次。完整恢复和 Verify 仍保留全文件摘要检查。远端读取保护及逐删除锁检查继续有效。 |
| 无需采样却写容量状态 | GET 复用 15 分钟采样，修改策略强制采样；保留时间戳提示和后台采样。 |

保留审批拆入 retention/review；归档收尾扩展现有 journal，未引入第二套数据库或日志机制。替换三处页面的重复任务跟踪，删除 GC 旧的全量内容 Visitor，未为没有字面客户端调用但有动态分派的端点建立删除规则。

源码规模治理在职责拆分后审查并更新原生生产与测试聚合基线，单文件上限、排除规则及增长额度不变。最终原生生产为 125878 行、测试/示例为 39220 行，相对本批起点分别增加 627/175 行；新增内容用于持久化收尾、部分提交语义、独立复核及其回归，不声称源码总行数减少。前端和自动化基线未放宽，全部规模规则通过。

- 原生契约库 9 项测试通过；生成器 `-Check` 确认 781 个操作、749 个 schema 的 OpenAPI、Rust 和 React 投影一致。契约差异通过独立审核夹具声明，不修改冻结历史合同。
- `cargo check --locked -p export-doc-server`、同工程 `--no-default-features`、`cargo fmt --all --check`、React 类型检查与 Web 构建通过。
- 前端样式治理、无障碍合同、API 请求合同、并发反馈、后台任务轮询合同和新增治理页面生命周期专项通过；覆盖永久查询错误停止轮询、读回执恢复、跨面板版本失效、卸载/身份切换、复核清单、样例去重和错误上下文。
