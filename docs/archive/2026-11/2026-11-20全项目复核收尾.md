# 2026-11-20 全项目复核收尾

基于 `1f1a2d22`，按用户确认的整批修复、文档同步、清理与 main 交付要求实施。上一轮只读审查发现的问题以实际源码和本次验收为准，不恢复 C#、旧数据库迁移或旧 API 接受链。

## 实现

- 混合 PDF：文档打开一次，逐页检查原生文字与图像/Form 对象，需要时渲染整页 OCR，保持页面顺序并补回未识别的原生文字。不再用整篇 20 字阈值决定是否跳过所有扫描页。
- OCR：一次信用证任务复用一个模型进程；父进程的有界帧通道限制单页输入/输出，退出、错误和取消统一关闭进程树及管道。Windows 继续使用 Job Object，Unix 子 OCR 留在 PDF 进程组内，外层终止可覆盖所有后代。最多 50 页、2 亿渲染像素、50 万字符，任务和单页均有期限；不把原生库隔离等同于 RSS 硬上限。
- 错误与权限：PDF 输入/依赖/超时分别保留 400/503/504，缺可选能力为 501；GIF 从信用证选择器和后端接受列表移除。信用证导入和审核统一使用发票操作授权，模板/资源权限不再是前置条件；独立冻结权限对照覆盖每个动作、角色及产品版。
- 组织与职责：独立选项投影按单位、名称/代码分页，另查询已选标签，替代候选中的 500 部门截断。职责承担人的项目限制可编辑、保存、回显；明确项目范围复用同一选择器，跨页选择不丢失。停用项目只允许保留原有同任职关系，不能新分配；正式历史关系仍不得删除。
- OA 职责闭环补充：项目限定职责的发布检查不再用缺少项目的虚构申请提前否决；先验证来源引用，再由带真实项目/任职的发布样例和提交解析责任人。项目负责人、Leader 成员和普通成员的有效参与判定复用 Storage 规则，修正负责人未重复登记为普通成员时不能承担项目职责的问题；账号动作权限与当前任务资格仍独立校验。新增错任务签署与职责到期后签署拒绝的共享 SQLite/PostgreSQL 回归。
- 手册：更新 OA 管理员/用户正文与 PDF，新增《项目程序操作说明》，解释职责分工、账号授权、明确数据范围与节点分派的区别，保留原截图来源日期；三份 PDF 使用同一生成器和受管字体，逐页渲染检查。
- 设计器：正式 JSON 数字类型与 Rust 一致，拒绝部分解析字符串、空文本和非整数；可视化输入的中间文本与模板文件校验各自处理，保留安全草稿，不将归一化结果伪装为合法原文件。
- 响应资源：保留执行前预留与读请求 8 MiB 余量，分为四个容量队列，类内顺序等待，避免大请求队首挡住可容纳的小请求。信用证响应 4 MiB、OCR/登录 8 MiB，其它未证明可缩小的契约仍保留原上限。
- 查询与清理：启动账号检查复用 `record_exists`；Excel 只按权限批读出口商名称，发现第二个不同名称即停止，避免加载全部档案正文。删除重复文字/逐页 OCR 进程入口、无消费者的部门候选 DTO/字段及前端模板权限耦合。

SQL 留在 Storage；React 使用既有 OfficeField/Pagination、设计令牌和断点；原生契约统一生成 OpenAPI、Rust DTO、权限/容量元数据及客户端；当前为 751 个操作、707 个运行契约模型，OpenAPI 共 714 个 schema。没有依赖升级或 schema 18 结构变更。
