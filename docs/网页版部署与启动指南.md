# 网页版部署与启动指南

> 按 2026-10-13 的服务参数与打包脚本核对。本文讲不使用 Docker 的 Full 网页服务。其他人仍只用浏览器；希望少配置数据库和进程时，可先读[Docker 指南](./Docker容器部署与启动指南.md)。

## 1. 网页版由什么组成

一份 Web 服务包包含 Rust 服务程序、React 网页、模板、字体、PDF/OCR 资源，以及备份恢复使用的 PostgreSQL 客户端。**它不包含 PostgreSQL 数据库服务器**，需另外准备 PostgreSQL 18。

| 内容 | 作用 | 本文示例 |
| --- | --- | --- |
| AppRoot | 解压后的程序和只读资源 | Windows：`E:\ExportDoc\Web\App`；Linux：`/srv/exportdoc/app` |
| DataRoot | 主密钥、用户文件模板、任务、备份、日志 | Windows：`E:\ExportDoc\Web\Data`；Linux：`/srv/exportdoc/data` |
| 私有配置目录 | 连接文件与首次管理员口令 | Windows：`E:\ExportDoc\Web\Runtime`；Linux：`/srv/exportdoc/runtime` |
| PostgreSQL 数据目录 | 真正的业务数据库 | 由 PostgreSQL 服务配置，独立于上面三个目录 |

这些路径可按数据盘规划调整，但每次启动、升级和恢复必须使用原 DataRoot。不要让浏览器连接数据库，也不要将私有配置放进 `Web` 静态资源目录。

## 2. 取得正确的服务包

1. 打开 [GitHub Releases](https://github.com/sck03/rustdoc/releases)，选择明确的版本和操作系统/架构。找名称类似 `exportdoc-web-版本-系统-架构` 的包，不能使用 `desktop` 桌面包。
2. 当前发布矩阵为 Windows x64、Linux x64/ARM64、macOS ARM64；Windows ARM64 和 Intel macOS 没有对应 Web 服务包。目标定义不等于所有平台都已通过现场验收。
3. 核对附带的 SHA-256，再解压到新的独立程序目录。Windows 可用 `Get-FileHash 压缩包路径 -Algorithm SHA256`，Linux 可用 `sha256sum 压缩包路径`。
4. 找到包内 `exportdoc-native-web-server.json`，确认版本、平台及 OCR 标记。应能看到 `ExportDocManager.Server.exe`（Unix 无 `.exe`）、`Web/index.html`、`Templates`、`Resources` 和 `Tools/PostgreSQL`。

没有现成包时，由维护人员按[工作流手册](./GitHub%20Actions工作流用途与运行手册.md)构建，或在已配置 Rust/Node/PowerShell 7 的源码根目录运行：

```powershell
pwsh -NoProfile -File scripts/package-native-web-server.ps1 -Configuration Release -NoPause
```

默认输出 `artifacts/native-web-server`。正常交付保留 OCR；`-WithoutOcr` 只用于明确不提供识别的测试包。**使用已经打好的包不需要安装 Rust、Node 或 .NET。**

## 3. 准备 PostgreSQL 18 和三个角色

### 3.1 安装或取得数据库

- Windows：从 [PostgreSQL 官方下载入口](https://www.postgresql.org/download/windows/)取得 18.x 安装程序。记录安装目录、数据目录、端口和数据库管理员密码；安装时把数据目录明确放到数据盘。本文使用端口 5432、程序目录 `E:\ExportDoc\PostgreSQL18`。
- Linux：按 [PostgreSQL 官方 Linux 安装入口](https://www.postgresql.org/download/linux/)为自己的发行版安装 18.x 并启动数据库服务；确认实际数据目录和服务名。不要为了本文覆盖已有数据库集群。
- 已有独立数据库/受管 PostgreSQL：请管理员提供一个新的空数据库及下述角色，确认版本为 18。不要用业务程序的普通账号兼任超级管理员。

在数据库的 SQL 客户端执行 `SHOW server_version;`，结果应为 18.x。应用只连接一个数据库，不负责安装 PostgreSQL 服务。

### 3.2 在全新部署中创建数据库和角色

下面的角色名称与 Docker 一致，便于以后迁移：

| 角色 | 用途 | 权限边界 |
| --- | --- | --- |
| `exportdoc_owner` | 持有表和数据库对象 | NOLOGIN，不直接登录 |
| `exportdoc_maintenance` | 初始化、升级和恢复 | 可切换到 owner；不是超级用户 |
| `exportdoc_app` | 日常业务 | 读写业务表，没有建表、建库或管理角色权限 |

由数据库管理员打开 `psql`。Windows 示例：

```powershell
& 'E:\ExportDoc\PostgreSQL18\bin\psql.exe' -h 127.0.0.1 -p 5432 -U postgres -d postgres -W
```

Linux 本机常见入口是 `sudo -u postgres psql`。下列内容粘贴到 **psql 提示符**，不是 PowerShell/Bash：

```sql
\set ON_ERROR_STOP on
CREATE ROLE exportdoc_owner NOLOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE;
CREATE ROLE exportdoc_app LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE;
CREATE ROLE exportdoc_maintenance LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE;
GRANT exportdoc_owner TO exportdoc_maintenance;
\password exportdoc_app
\password exportdoc_maintenance
CREATE DATABASE exportdoc_native OWNER exportdoc_owner ENCODING 'UTF8';
\connect exportdoc_native
REVOKE CREATE ON SCHEMA public FROM PUBLIC;
GRANT USAGE, CREATE ON SCHEMA public TO exportdoc_owner;
GRANT USAGE ON SCHEMA public TO exportdoc_app;
ALTER DEFAULT PRIVILEGES FOR ROLE exportdoc_owner IN SCHEMA public
    GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO exportdoc_app;
ALTER DEFAULT PRIVILEGES FOR ROLE exportdoc_owner IN SCHEMA public
    GRANT USAGE, SELECT ON SEQUENCES TO exportdoc_app;
\q
```

两个 `\password` 命令会分别要求输入密码并再次确认，输入时不回显。使用不同密码并安全保存。每一条语句都应成功；出现角色/数据库已存在时先核实是否正在使用，**不要删除或重建来消除报错**。这组命令只用于新部署，日常升级不再执行。

数据库与应用同机时可只监听本机。数据库在另一主机时，由管理员配置 `listen_addresses`、`pg_hba.conf`、证书和防火墙，仅放行应用主机；浏览器不需要 5432 权限。本地示例使用 `sslmode=disable`；跨不可信网络应使用 TLS。当前 Rust 连接使用 `sslmode=require` 时验证系统信任的服务器证书，随包客户端对应 `verify-full`，证书名称及信任链必须正确。

## 4. 建立私有配置

Windows 创建 `E:\ExportDoc\Web\Data`、`E:\ExportDoc\Web\Runtime`；Linux 对应 `/srv/exportdoc/data`、`/srv/exportdoc/runtime`。由实际运行服务的专用账号拥有，程序目录给予读取/执行权限，数据目录给予写入权限。

在 Runtime 中创建两个 **UTF-8、无 BOM 的纯文本文件**，各自只有一行。下面的密码是说明占位符，要换成第 3 节设置的真实密码：

`app-connection.txt`：

```text
host=127.0.0.1 port=5432 dbname=exportdoc_native user=exportdoc_app password='替换为业务角色密码' connect_timeout=10 sslmode=disable
```

`maintenance-connection.txt`：

```text
host=127.0.0.1 port=5432 dbname=exportdoc_native user=exportdoc_maintenance password='替换为维护角色密码' connect_timeout=10 sslmode=disable
```

两个文件的主机、端口、库名必须相同。使用 libpq 连接串时，密码中的单引号及反斜杠要用反斜杠转义；不熟悉此语法时可采用随机十六进制密码，避免把空格或引号写错。不要把连接串粘贴到浏览器的“服务器地址”。

Windows 在 PowerShell 7 生成首次管理员口令文件，已有文件时不要覆盖：

```powershell
$runtime = 'E:\ExportDoc\Web\Runtime' # Linux 改为 /srv/exportdoc/runtime
$tokenFile = Join-Path $runtime 'bootstrap-token.txt'
if (Test-Path -LiteralPath $tokenFile) { throw '初始化口令已存在，请保留原文件。' }
[IO.File]::WriteAllText($tokenFile, [Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32)), [Text.UTF8Encoding]::new($false))
```

Linux 也可在已准备好的 Runtime 中使用 OpenSSL 生成，无需为了运行 Web 服务额外安装 PowerShell；以下命令拒绝覆盖已有文件，报错时先排查再继续：

```bash
(umask 077; set -o noclobber; openssl rand -hex 32 > /srv/exportdoc/runtime/bootstrap-token.txt)
```

Windows 在目录“属性 → 安全”中只保留运行账号、必要管理员及 SYSTEM 的访问；Linux 可将 Runtime 设为 0700、文件设为 0600。这些文件需要受保护的备份，不提交 Git、不通过网页下载、不放在系统公用临时目录。

## 5. Windows：初始化、启动、停止

使用 **PowerShell 7**。下面变量需要在每个新终端重新设置，路径以实际解压目录为准：

```powershell
$app = 'E:\ExportDoc\Web\App'
$data = 'E:\ExportDoc\Web\Data'
$runtime = 'E:\ExportDoc\Web\Runtime'
$server = Join-Path $app 'ExportDocManager.Server.exe'
$env:EXPORTDOCMANAGER_POSTGRES_CONNECTION_FILE = Join-Path $runtime 'app-connection.txt'
$env:EXPORTDOCMANAGER_BOOTSTRAP_TOKEN_FILE = Join-Path $runtime 'bootstrap-token.txt'
$env:EXPORTDOCMANAGER_POSTGRES_OWNER = 'exportdoc_owner'
$env:EXPORTDOCMANAGER_BUSINESS_TIME_ZONE = 'Asia/Shanghai'
```

### 首次建表或程序升级时

先确认原 API 已停止。只在这一维护进程提供维护连接：

```powershell
$env:EXPORTDOCMANAGER_POSTGRES_MAINTENANCE_CONNECTION_FILE = Join-Path $runtime 'maintenance-connection.txt'
try {
    & $server --app-root $app --data-root $data --initialize-only
    if ($LASTEXITCODE -ne 0) { throw '初始化/升级失败，请检查错误，暂勿启动业务服务。' }
} finally {
    $env:EXPORTDOCMANAGER_POSTGRES_MAINTENANCE_CONNECTION_FILE = $null
}
```

成功时命令结束并返回终端，退出码为 0。它只处理 Rust 的数据库 schema，不会打开浏览器、创建登录管理员或启动长期服务。

### 日常启动

```powershell
& $server --app-root $app --data-root $data --web-root (Join-Path $app 'Web') --bind 127.0.0.1:5188
```

看到 `listening on 127.0.0.1:5188; database=PostgreSQL 18` 后保持该终端运行。在浏览器打开 [http://127.0.0.1:5188](http://127.0.0.1:5188)。

`--web-root` 不可漏掉：服务不会凭程序旁有 `Web` 文件夹就自动提供网页。终端一直占用是正常现象。停止时按 **Ctrl+C**，等待命令结束再更新或恢复；不要用按名称批量结束进程的方式停止其他实例。重新开机后需再次执行日常启动命令。

这份 EXE 是控制台 HTTP 服务，不是 Windows Service 程序，不能直接用 `sc create` 注册。需要无人值守、系统重启自启时，可选择 Docker 方案，或由系统管理员使用经过验证的进程托管方案；本文不把关闭终端后仍运行当作已实现功能。

## 6. Linux：初始化与长期运行

以下是已经解压好 Linux 包、数据库和角色已就绪时的示例。管理员先准备专用 `exportdoc` 系统账号，使其可读程序及配置、可写 DataRoot。路径必须是普通目录，不能用软链接指向另一版本：

```bash
sudo useradd --system --no-create-home --home-dir /srv/exportdoc --shell /usr/sbin/nologin exportdoc
sudo install -d -o exportdoc -g exportdoc -m 0700 /srv/exportdoc/data /srv/exportdoc/runtime
sudo chown -R exportdoc:exportdoc /srv/exportdoc/runtime
sudo chmod 0700 /srv/exportdoc/runtime
sudo chmod 0600 /srv/exportdoc/runtime/*.txt
```

账号已存在时跳过 `useradd`；Runtime 文件仍按第 4 节填写。程序包应保留归档中的执行权限。解压 App 目录不要包含旧 DataRoot，不对真实数据库目录执行递归改权。

在原应用停止时初始化/升级：

```bash
sudo -u exportdoc env \
  EXPORTDOCMANAGER_POSTGRES_MAINTENANCE_CONNECTION_FILE=/srv/exportdoc/runtime/maintenance-connection.txt \
  EXPORTDOCMANAGER_POSTGRES_OWNER=exportdoc_owner \
  /srv/exportdoc/app/ExportDocManager.Server \
  --app-root /srv/exportdoc/app --data-root /srv/exportdoc/data --initialize-only
```

命令必须以 0 退出，失败先排查。先用前台方式检查启动：

```bash
sudo -u exportdoc env \
  EXPORTDOCMANAGER_POSTGRES_CONNECTION_FILE=/srv/exportdoc/runtime/app-connection.txt \
  EXPORTDOCMANAGER_BOOTSTRAP_TOKEN_FILE=/srv/exportdoc/runtime/bootstrap-token.txt \
  EXPORTDOCMANAGER_BUSINESS_TIME_ZONE=Asia/Shanghai \
  /srv/exportdoc/app/ExportDocManager.Server \
  --app-root /srv/exportdoc/app --data-root /srv/exportdoc/data \
  --web-root /srv/exportdoc/app/Web --bind 127.0.0.1:5188
```

检查成功后 Ctrl+C 停止，由管理员保存以下 systemd 单元为 `/etc/systemd/system/exportdoc.service`。该文件是系统服务配置；业务数据仍位于 /srv/exportdoc：

```ini
[Unit]
Description=ExportDocManager Web
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=exportdoc
Group=exportdoc
WorkingDirectory=/srv/exportdoc/app
Environment=EXPORTDOCMANAGER_POSTGRES_CONNECTION_FILE=/srv/exportdoc/runtime/app-connection.txt
Environment=EXPORTDOCMANAGER_BOOTSTRAP_TOKEN_FILE=/srv/exportdoc/runtime/bootstrap-token.txt
Environment=EXPORTDOCMANAGER_BUSINESS_TIME_ZONE=Asia/Shanghai
ExecStart=/srv/exportdoc/app/ExportDocManager.Server --app-root /srv/exportdoc/app --data-root /srv/exportdoc/data --web-root /srv/exportdoc/app/Web --bind 127.0.0.1:5188
Restart=on-failure
RestartSec=5
TimeoutStopSec=210
KillSignal=SIGTERM
UMask=0077

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now exportdoc
sudo systemctl status exportdoc --no-pager
curl --fail http://127.0.0.1:5188/readyz
```

日常停止用 `sudo systemctl stop exportdoc`，启动用 `sudo systemctl start exportdoc`，日志用 `journalctl -u exportdoc -n 100 --no-pager`。不要在 systemd 已启动时再运行一份前台 API。

macOS ARM64 包使用同一组 Unix 参数，可先按前台命令验证；长期托管由对应平台管理员配置 launchd，本文的 systemd 命令不适用于 macOS。

## 7. 域名与 HTTPS

同一台服务器上放置反向代理时，应用继续只监听 `127.0.0.1:5188`。浏览器只访问代理提供的一个 HTTPS 站点，React 与 API 同源，不需要另外运行 Vite 或配置第二个前端服务器。

服务器管理员准备域名、DNS、合法证书和 Nginx。下面配置中的域名与证书路径须换成真实值：

```nginx
server {
    listen 443 ssl;
    server_name docs.example.com;
    ssl_certificate     /srv/exportdoc/tls/fullchain.pem;
    ssl_certificate_key /srv/exportdoc/tls/privkey.pem;

    client_max_body_size 260m;
    client_body_timeout 300s;
    location / {
        proxy_pass http://127.0.0.1:5188;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

先 `nginx -t` 校验，再重载代理。根据本机 Nginx 服务配置办理证书续期和 HTTP 跳转 HTTPS。证书/代理配置不在迁移包中，须单独备份。若代理也运行在容器中，`127.0.0.1` 指那个代理容器本身，应由管理员改成实际可达的应用地址。

应用部署在域名根路径；没有验收把它放到 `/exportdoc/` 子路径下的前缀改写。代理的 260 MiB 上限只是传输上限，应用仍按文件类型执行自己的容量和超时规则，不会因此接受超大业务文件。

只做可信局域网试用时，可把应用 `--bind` 改为服务器固定内网 IP:端口并配置内网防火墙；正式提供公网访问前完成 HTTPS。

## 8. 首次登录与日常验收

1. 用 `admin` 和自己设定的 8–128 字符密码登录；展开“高级连接选项”，首次填 Runtime 中 `bootstrap-token.txt` 的“管理员初始化口令”。
2. “服务器地址”保持当前站点地址，不填 PostgreSQL 地址。后续登录无需初始化口令。
3. 查看版本、授权状态和数据库类型；应为 PostgreSQL。按公司/部门/人员顺序配置并关联账号，再安排实际岗位权限。
4. 创建一条测试记录，刷新后重开；试一次附件上传下载、模板预览和 PDF 输出。
5. 按[备份与恢复指南](./服务器备份迁移与恢复指南.md)创建并下载备份，在隔离目标做一次恢复演练后再正式使用。

## 9. 更新与故障排查

更新顺序为：停止同事录入 → 下载备份和完整迁移包 → 停服务 → 将新包解压到新目录 → 指向原 DataRoot/Runtime → 用新程序执行 `--initialize-only` → 成功后启动并检查。新目录必须保留全部资源；不要只替换 EXE，也不要把旧 DataRoot 覆盖进新包的 Web 目录。

更新前记录旧程序目录。新程序未动数据库就启动失败时，可排除配置/资源问题；数据库已升级后不能直接降级程序，应按恢复指南在兼容的隔离目标验证旧备份。

| 报错/现象 | 处理 |
| --- | --- |
| 网页 404 或只有 API 可用 | 检查 `--web-root` 和 `Web/index.html` |
| 团队版必须配置业务连接 | 检查 `EXPORTDOCMANAGER_POSTGRES_CONNECTION_FILE`，不要把维护账号用于日常服务 |
| 普通 API 没有管理/建表权限要求 | 按第 3 节分离角色；不要为了省事使用 postgres 超级用户 |
| 数据库版本不支持 | 只支持 PostgreSQL 18 与 Rust schema 5 起的升级；不改版本号、不删除已有库 |
| 已有实例/锁 | 停止重复 API；同一数据库只运行一个服务 |
| 路径、权限或资源错误 | 使用受管绝对目录，检查服务账号、链接、完整字体/PDF/OCR/客户端资源 |
| 数据库恢复已暂存 | 停服务，执行 `--restore-pending`；不是再次 `--initialize-only` |
| 日志出现数据库失联并停止 | 修复连接/实例锁问题后重启，先核对上一笔操作是否已经保存 |

不要同时设置同一连接的直接环境变量与 `_FILE` 变量，服务会明确拒绝。修改文件不会让正在运行的服务自动切换数据库，须在维护窗口停止、核对并重新启动。服务的请求日志位于 DataRoot/Logs；详细运维参数见[脚本说明](../scripts/README.md#连接池运行指标与容量验证)。
